# MVK10230 Diagnostic R5 — Windows x64

**Назначение:** первая безопасная диагностика живого приёма данных оригинального прибора МВК01 по **TCP/10230**. Код самостоятельный, написан на Go по подтверждённым Native R3/R4 и оригинальному IDR MVKView. Присланный ранее `mvk_tcp_reader_v2` не использовался.

## Запуск

Для обычного запуска достаточно дважды щёлкнуть по `MVK10230_Diagnostic_Windows_x64.exe`: приложение последовательно запросит IPv4, время приёма и подтверждение `YES`. Никаких BAT/PowerShell/установки Python для работы с прибором не требуется. Окно остаётся открытым до нажатия Enter. Рекомендуем первый тест **15 секунд** в согласованное безопасное время.

По умолчанию результаты складываются в `%USERPROFILE%\Documents\MVK10230_Tests\TEST_...` (если папка «Документы» отсутствует — `%USERPROFILE%\MVK10230_Tests`). Изолированный каталог создаётся на каждый запуск; старые результаты не перезаписываются.

Возможен запуск из консоли:

```text
MVK10230_Diagnostic_Windows_x64.exe -ip 192.168.1.83 -seconds 15 -approve
```

Точный IP надо указать по данным вашей сети, `192.168.1.83` — только пример, **не установленный адрес МВК**. При необходимости:

```text
MVK10230_Diagnostic_Windows_x64.exe -ip 192.168.1.83 -seconds 30 -approve -out C:\MVK_Tests -max-mb 512
```

**Офлайн-проверка без прибора:**

```text
MVK10230_Diagnostic_Windows_x64.exe -replay DEMO_SYNTHETIC.raw -out OFFLINE_TEST
```

Для архивного replay разрешён только заранее сохранённый полный поток «прибор → клиент», начиная с границы кадра. Программа не собирает TCP-сегменты из PCAPNG: эта работа ранее выполнялась отдельным Native R3. Её `.raw` — именно последовательность прикладных байтов после TCP.

## Какие файлы создаются

| Файл | Содержимое |
|---|---|
| `MVK10230_TEST_RESULTS.zip` | Удобный единый архив всех результатов (кроме самого ZIP) |
| `incoming.raw` | Точно те байты, которые программа получила из TCP, без пересчёта и фильтрации |
| `chunks.csv` | Время получения, смещение и размер каждого фрагмента `Read` |
| `frames.csv` | Тип, длина, номер кадра, канал, частота дискретизации, индекс отсчёта |
| `aux4700.jsonl` | Декодированные 43 третьоктавные полосы, 24 СКЗ, 24 пика, 24 размаха и статус каждого АЦП |
| `events.log` | Диагностические события и предупреждения |
| `summary.json` | Машинный отчёт: статистика, частоты, SHA-256 raw-потока, ошибки |
| `summary_ru.txt` | Русскоязычный итоговый отчёт |

Временные отметки формируются **часами компьютера при вызове чтения TCP**, а не временем АЦП прибора. Файлы не должны применяться для точной межсеансовой синхронизации.

## Что декодируется

- Идентификация (тип `0x00000001`).
- АЦП: тип `0xFF800ADC`, кадр 1052 байта, 256 значений `float32`, каналы 1–8.
- Тахометры: тип `0xFF8001AC`, кадр 284 байта, 64 значения `float32`, каналы 9–10.
- Структурированные регистровые пакеты `0xFF800C0D`, включая 4700-байтный AUX4700 и 32800-байтный полный снимок 0x4000 регистров.
- Служебные ответы `0x00010FF0` (ACK), `0x00010FFF` (отказ) — только приём, без инициирования операций.
- Накопление счётчиков, контроль последовательности и допустимых частот, проверка границ записей; отклонение неподтверждённых заголовков.

При первой ошибке формата программа прекращает **интерпретацию**, но **продолжает побайтно сохранять входящий поток**. Это предохраняет от ложных результатов при неизвестном формате кадра. Полный поток ограничен по умолчанию 256 МиБ, а сеанс — 300 сек максимум.

## ОГРАНИЧЕНИЯ

1. Это **первый Live-тестер**, а не полная замена MVKView или промышленный интерфейс управления.
2. Не формирует BIN/TSXML/VALUES/TABLE оригинальной программы: калибровка `FRange` и точная логика записи в R5 не используются. `incoming.raw` нельзя переименовывать в `.bin` и выдавать за результат MVKView.
3. Не отправляет даже команду запуска измерения. Если прибор ничего не передаёт до принятия команды, тест покажет отсутствие данных. **Это не означает, что соединение с прибором или оригинальная программа неисправны.**
4. Само открытие TCP-соединения может изменить доступность МВК для других клиентов; подключайте только с разрешения ответственного специалиста.
5. При противоречивой/повреждённой структуре кадра программа сохраняет входящие байты, но не угадывает дальнейшие границы сообщений.
6. Windows executable собран кросс-компилятором Go для Windows x64 и прошёл проверку формата PE; **фактический запуск на Windows и реальном оборудовании ещё предстоит проверить**.
7. Результаты могут содержать данные измерений и параметры системы. Не публикуйте их открыто.

## Верификация

- Автоматические тесты Go: **8/8** прошли, в том числе локальный TCP-сервер, проверяющий отсутствие отправленных клиентом прикладных данных.
- `go vet`: без замечаний.
- На первых 20 МиБ двух независимых реальных PCAPNG после реконструкции Native R3: **51 060 кадров, 36 AUX4700**, ни одной ошибки формата.
- Независимая проверка содержимого AUX4700: **33 408 совпадающих значений и статусов** (`18×8×(43+24+24+24+1)` для каждого из двух захватов).
- В первом тесте («83 спектр») восстановлен полный снимок регистров 32 800 байт. Во втором захвате `1111` старт соединения не записан и первоначального полного снимка нет.

Для повторения с кодом, установленным Go, из папки исходников: `go test ./...`; сборка Windows: `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o MVK10230_Diagnostic_Windows_x64.exe .`. Команды сборки предназначены для разработчика, **обычному пользователю они не требуются**.

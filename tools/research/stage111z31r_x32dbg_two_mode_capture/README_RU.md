# MVKView 1.0.47 — Stage111Z31R: один захват двух спектров x32dbg

**Вид:** локальный исследовательский пакет Windows (исходники + `Prepare-Capture.ps1` + единый `CAPTURE_BOTH.txt` после подготовки + `Verify-Capture.py`).

**Статус:** исходная трасса выведена из пользовательского `Projects.7z`/`mvkview.idp` (оригинальный `GetSpectrum`, `_Unit115`). **Сценарий не запускался на живом оригинальном Windows-процессе; проведены только локальные статические и синтетические проверки.** Это первая испытательная версия, а не принятое оригинальное измерение.

## Цель, два прохода

- **А — обычный спектр:** исходный SpectrumType = 2 («Линейный ВС», скорость), EnvelopeCode = 0 («Без фильтра»).
- **Б — огибающая:** тот же SpectrumType = 2, EnvelopeCode = 20, **в меню оригинала пункт «1окт 16 кГц»** (октавный фильтр с центральной частотой 16 кГц), **той же архивной записи/АЦП**. Это не фильтр на 20 Гц.
- Исходная Fs = **65536 Гц**; у кода 20 табличная промежуточная частота = 65536 Гц, но FIR I/Q с 2× децимацией даёт **выходную Fs = 32768 Гц**. FFT N задаётся при подготовке (по умолчанию 262144; при недостатке истории можно подготовить пакет с `-N 65536`).
- Б требуется *более длинная* исходная история, чем А. Поэтому сравнивается **конечная абсолютная позиция**, реальные совпадающие последние N Float32, а не одинаковый старт двух окон. При отличии конца или данных проверка **не заявляет same-window**, но оба отдельных расчёта сохраняются для диагностики.

## Самое короткое применение

1. Распаковать ZIP, например в `C:\MVK_TOOLS\Z31R`. Не копировать оригинальный EXE в пакет.
2. Дважды щёлкнуть **`Prepare-Capture.cmd`** (Windows PowerShell 5.1, подготовка **не запускает** x32dbg). Создаётся новая папка вида `C:\MVK_CAPTURE\Z31R_YYYYMMDD_HHMMSS_xxxxxxxx`, внутри отдельные `A`, `B` и **один** `CAPTURE_BOTH.txt`.
3. Открыть исходный `MVKView.exe` **в x32dbg**, пройти обычные **System/Entry/Attach breakpoints до работающего GUI**, открыть сохранённый **BIN/TSXML** прибора №83 (АЦП4). С устройством соединяться **не нужно**. В оригинальном окне выбрать АЦП4, SpectrumType «Линейный ВС», FFT N=262144, Fs=65536, «Без фильтра». Если программа не допускает такой FFT для архива, сначала использовать `-N 65536` при подготовке нового пакета.
4. **Отключить старые пользовательские точки останова**, особенно `007D154B`, `007D17E7`, `007D1900` (старые TAG/NAG/V6). Пауза x32dbg **F12**, только после загрузки GUI. В нижней командной строке x32dbg ввести **первую строку `scriptexec` из `RUN_ME.txt`**, например:

   `scriptexec "C:\MVK_CAPTURE\Z31R_...\CHECK_READY.txt"`

   Этот сценарий **не делает run и не сохраняет измерений**. В логе должна появиться `Z31R_READY_OK`. При `FAIL_OPCODE` адреса или версия не совпадают — ничего не обходить.
5. Повторно **F12 Pause**, затем выполнить **вторую строку `scriptexec` из `RUN_ME.txt`**:

   `scriptexec "C:\MVK_CAPTURE\Z31R_...\CAPTURE_BOTH.txt"`

   Теперь x32dbg автоматически остановится на **первом** `007D14AA`. Если ничего не происходит, в оригинальной MVKView пересчитать спектр (через её интерфейс) с кодом 0.
6. **Не нажимать F9 вручную**, пока сценарий выполняется. x32dbg последовательно отработает 6 точек, сохранит файлы А и выдаст модальное сообщение **PLAIN capture finished**. Нажать OK: программа возобновится. **Только затем** в оригинальном GUI включить огибающую **«1окт 16 кГц» (код 20)**, оставить «Линейный ВС» и пересчитать спектр. Сценарий автоматически соберёт ещё 6 точек в B.
7. Дождаться строки **`Z31R_BOTH_COMPLETE`**. Если появилась любая **`Z31R_FAIL_*`**, прекратить попытку, **не пропускать ошибки** и сохранить папку с частичными файлами и Log x32dbg.
8. Проверить физические снимки, из каталога распакованного инструмента:

   `py -3 Verify-Capture.py "C:\MVK_CAPTURE\Z31R_..." --report "C:\MVK_CAPTURE\Z31R_...\verification.json"`

   Утилита использует **только Python 3 стандартной библиотеки**, без NumPy, сети, подключения к прибору, GitHub и прав администратора. Если Python не установлен, просто передать личную папку захвата: проверку можно выполнить в ChatGPT при загрузке ZIP.

   Выход `0`: **два набора физически корректны, один end и совпали общие исходные Float32**; `2`: оба корректны, но **не одна и та же выборка**; `3`: данные неполные/повреждены/не соответствуют параметрам. Даже код `0` **не удостоверяет совпадение original Win32 ↔ Native BIN** без отдельного сопоставления исходного архива.

9. Архивировать созданную папку (`Compress-Archive` или обычный ZIP) и приложить **в этот чат**, не в GitHub. При необходимости вместе с архивом прислать исходный BIN+TSXML, если они у тебя остались; SHA256 при подготовке можно сохранить заранее через параметры `-ArchiveBin` и `-ArchiveTsxml`, это **не загружает файлы наружу**.

### Подготовка другого N, АЦП, режима

В каталоге инструмента, PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Prepare-Capture.ps1 -Adc 4 -N 65536 -SpectrumType 2 -Root C:\MVK_CAPTURE -ArchiveBin "C:\Data\MVK00000083-ADC4.bin" -ArchiveTsxml "C:\Data\MVK00000083-ADC4.tsxml"
```

Допустимые N: 4096, 8192, 16384, 32768, 65536, 131072, 262144. Уровень ADC — **заявление оператора**, по адресу хранения в оригинале номер канала криптографически не доказывается. Выбор Fs в этом пакете фиксирован 65536 и требует такого же оригинального архива; другие Fs — отдельный контракт, не подставлять произвольно.

## Какие файлы сохраняются

В каждой папке `A` и `B`:

- `input_normalized_pre_dc.bin`: Float32 после чтения original ring `/FRange`, **до DC/FIR** (`007D14AA`). Это **не** исходный нативный BIN и **не** подготовленный к FFT массив.
- `storage.bin` (56 байт), `ring_head.bin`, иногда `ring_tail.bin`: исходные **Float32 из оригинального кольца**, до деления `/FRange`; два фрагмента точно реконструируют окно с учётом маски и перехода через конец ring.
- `input_after_dc.bin`: после удаления среднего, ещё до FIR (`007D14B8`).
- `before_fft.bin`: после FIR, перед `GetSpectrum` FFT (`007D153D`), ровно N Float32.
- `power_before_mode.bin`: после FFT, перед интегрированием (`007D154B`), N/2 Float32.
- `power_after_mode.bin`, `display_y.bin`: исходный полный расчёт после выбора режима (`007D17E7`), N/2 Float32 каждый.
- `params_pre_dc/after_dc/pre_fft/after_fft/after_y/final.bin` (все 60 байт), `summary_triplet.bin` (12 байт из `[EBX+30]`), `frange.bin` (4 байта). Отдельные x32dbg Params snapshots не заменяются текстовым log.

В корне: `capture_config.json`, `RUN_ME.txt`, `capture.log` (если версия поддерживает RedirectLog), `capture_log_snapshot.txt` (SaveLog) и операторский `verification.json`.

## Как учтены прежние ошибки

1. **System/Entry breakpoint не GetSpectrum:** подготовка возможна только после загрузки GUI. В начале проверяются сигнатуры всех 6 точек из предоставленного IDP: `14AA=8B4B04`, `14B8=8B4308`, `153D=8B4B04`, `154B=8B4328`, `17E7=33C0`, `1900=33C0`. Если версия оригинала/ASLR не совпадает — отказ до сохранения дампов.
2. **V5 `mem.valid(pointer)` дал ложное отрицание:** здесь не используется как единственный gate для динамических данных. Используется `mem.base(start)`, `mem.base(last)`, проверяется размер/переполнение, совпадение памяти с одним allocation region. Если диапазон слишком сложный/уходит в другую область памяти — безопасный отказ вместо рискованного `savedata`.
3. **V6 начинал на `007D154B`, пропуская исходный буфер:** новый сценарий встаёт на `007D14AA` перед DC и сохраняет исходные Float32 отдельно. При старте внутри `GetSpectrum` — безопасный отказ.
4. **Перепутанные нити/стек/архивное окно:** на всех 6 остановках сверяются EIP, TID, EBX, EBP, storage, код огибающей, режим, конец `[EBX+20/24]`. При разных источниках или скрытом переключении — немедленная остановка.
5. **Tag2 и Tag3 ранее имели разные `[EBX+20]` при одинаковом FFT:** для пары 0/20 в конце проверяются не только `LastProcessedPos`, но и реальные Float32 в общем суффиксе (A последние N ↔ B последние N). Если не совпали, статус `NOT SAME WINDOW`; старые Power/Y ничего не доказывают об одинаковом исходном кольце.
6. **Лог раньше содержал только перенаправление:** x32dbg пишет *физические* файлы Params + 12-байтную тройку и дополнительно пытается сохранить отдельный log. Верификатор не подменяет отсутствующий log выдуманным подтверждением TID: оставляет `x32dbg_marker_text_present=false`.
7. **Недостаточная/перезаписанная история:** проверяет `FValidPos`, `FRxPos`, размер и маску кольца, целочисленность/границы, запрещает беззвучное дополнение нулями и пересоздаёт уникальный каталог без перезаписи.
8. **Фильтр меняет частоту:** отдельно ожидается output Fs=65536 для А и 32768 для Б, но RAW Fs обоих =65536. Значения `display_y` разных режимов обработки **не должны быть побитово одинаковы**.
9. **Старые работы не повторять:** FFT, FRange, коэффициенты FIR, Tag0–3 Power→Y уже приняты на своих эталонах. Цель — получить оригинальное *same-window* соединение стадий.

## Ограничения и безопасность

- Скрипт **не модифицирует EXE/память**, не пишет прибору, не открывает сеть, не меняет обработку оригинальной программы. `savedata` и локальные логи пишутся только в `C:\MVK_CAPTURE` (или выбранную локальную папку).
- **Оригинальный x32dbg-runtime здесь не запускался.** Логика проверена по исходному IDR/IDP и по синтетическим тестам, поэтому реальный пользовательский захват остаётся необходимым.
- Если `mem.base` с точки зрения твоего x32dbg видит разные регионы, НЕ отключать безопасность без обсуждения соответствующего указателя/диапазона и проверки чтения.
- Даже при PASS этим пакетом **не выполнена** автоматическая привязка к первому/последнему индексу сохранённого BIN/TSXML; для этого нужна отдельная проверка буфера архива. Не подставлять SHA нашего BIN вместо оригинального SHA как доказательство.
- Ни один байт оригинального EXE, IDP, PAS/DFM, архивов прибора или скриншотов не входит в этот пакет и не должен попадать в публичный CI.

## Локальная QA разработчика

В комплект включены `tests/test_stage111z31r_offline.py`. Проверка только генератора/валидации:

```powershell
py -3 -m unittest discover -v -s .\tests
```

Пакет проходил локально 14/14 синтетических тестов и сверку 6/6 коротких original-IDP сигнатур. **Никаких PASS по живому оригинальному x32dbg или same-run BIN этим тестам не приписывать.**

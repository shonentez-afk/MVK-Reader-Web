# Stage 108 — Native R6.1: Ethernet Live + 8-канальная запись BIN/TSXML + VALUES/TABLE

**Дата:** 2026-10-29. **Статус:** реализовано, проверено офлайн на 2 реальных сессиях МВК №84, локально на TCP loopback. **Живой запуск этого нового EXE на Windows/приборе ещё не проведён.** Исходная успешная R5.1 аппаратная проверка остаётся действующей.

## Цель

Соединить проверенный Native R5.1 приёмник с автономным Stage107 R6 export без отдельной программы и без дополнительных сетевых команд. В одном исполняемом файле: выбранный Ethernet → TCP/10230 → постоянная запись исходного потока → **параллельная запись восьми калиброванных временных BIN** → независимая проверка по исходному RAW и SHA256 → атомарная публикация BIN/TSXML/VALUES/TABLE после завершения сеанса.

### Обмен с прибором

**Неизменённый цикл:** `DialContext(tcp4:10230)` → `Read`; никакого `Conn.Write` или другого прикладного запроса МВК. Никаких Modbus/502, настройки частоты, изменения конфигурации или Flash. Оператор вручную выбирает проводной Ethernet с определённым IPv4; Windows сокет привязывается одновременно через `Dialer.LocalAddr` и Winsock `IP_UNICAST_IF`; неверный интерфейс не заменяется автоматически. TCP SYN/ACK и сетевые ACK не являются прикладными командами.

Обычный режим запуска — двойной щелчок по Windows EXE; пользователь вводит IP, длительность и адаптер, разрешает испытание `YES`. Для безопасной предварительной проверки доступен `-list-interfaces`; для анализа уже сохранённых RAW — `-replay` без сети.

## Как происходит запись

1. При первом ID264 и полном регистровом снимке 32800 B извлекается личный gain каждого АЦП из того же сеанса. До калибровки готовые BIN не пишутся.
2. Каждый пришедший ADC1052 содержит **256 float32 одного канала**. Исходный `incoming.raw` сохраняется в точности; из данных по каждому АЦП при приёме строятся `float32(raw * gain)` и записываются в закрытую `.stage108_live_calibrated_pending/ADCn.bin.partial`.
3. Контролируются число отсчётов, непрерывность счётчика с шагом 256, частота, изменение gain и чувствительности, NaN/Inf. Ошибка переводит приложение в безопасный `capture_only`, оригинальный RAW всё равно записывается, но BIN не публикуется.
4. При штатной остановке (время, лимит, команда оператора) исходные журналы закрываются, сохраняются SHA256 RAW и исходный диагностический ZIP.
5. Встроенный Stage107-парсер **заново, независимо от временных BIN** валидирует весь RAW и CSV кадров, повторно вычисляет все 8 BIN и извлекает оригинальные AUX4700 для VALUES/TABLE. Если последний кадр прерван штатным таймером, допускается исключить только явно указанное количество байт его неполного хвоста (они остаются в исходном RAW и SHA256).
6. Каждый временный BIN сверяется с независимым пересчётом **по размеру, SHA256 памяти и SHA256 реально записанных на диск байтов**. Только после этого одновременно публикуется папка `BIN_TSXML_VALUES_TABLE_RECONSTRUCTED/`.
7. `STAGE108_EXPORT_STATUS.json` содержит `EXPORTED`, `FAILED_CLOSED`, `REFUSED` или `DISABLED`; при отказе готовые BIN/CSV не появляются, сырой поток остаётся для проверки.

**Побайтная идентичность с MVKView-экспортом той же самой сессии всё ещё не доказана.** Готовые BIN — калиброванный float32; повторно умножать на gain нельзя. VALUES/TABLE содержат значения оригинальных регистров, но время получения кадров задаётся ПК; пользовательская текстовая обработка статусов, точное округление MVKView и ручные события TABLE в исходнике не полностью восстановлены.

## Проверка на реальных данных №84

| Параметр | TEST1 R5, 11:33 | TEST2 R5.1, 11:41 |
|---|---:|---:|
| Вход `incoming.raw` | 69 675 600 Б | 69 679 808 Б |
| Получено кадров | 84 846 | 84 850 |
| ADC1052 | 61 420 | 61 424 |
| AUX4700 / VALUES | 60 / 60 | 60 / 60 |
| BIN, TSXML | 8 + 8 | 8 + 8 |
| Временные BIN сверены с RAW | 8/8 | 8/8 |
| Побитово сверено float32 | 15 723 520 | 15 724 544 |
| AUX-чисел VALUES сверено | 33 600 | 33 600 |
| Расхождений | 0 | 0 |

**Общая независимая проверка: 31 515 264 сравнений (31 448 064 отсчёта + 67 200 значений), ноль несовпадений.** BIN всех 16 каналов побайтно совпали с результатами отдельного Stage107; все численные столбцы VALUES также идентичны. При этом системное время PC в новом replay отличается от старых тестовых захватов, поэтому строки времени VALUES намеренно не сравнивались как равные.

АЦП7/8 на этих записях несут статус `0x400`; присутствие BIN не означает исправности линии датчика.

## Программа и ограничения

- Windows x64 EXE: `MVK_Native_R6_1_Stage108_Windows_x64.exe`, автономно, без Python/BAT/Go на рабочем ПК.
- Linux QA: Go 1.23.2; автоматические тесты Go, go vet и race; чистая кросс-сборка под Windows. Локальное TCP loopback испытание: 0 байт исходящего прикладного payload + один законченный 8xBIN/TSXML экспорт.
- Способ использования см. `START_HERE_RU.txt`.
- Для первой Windows Live-проверки повторить **30 секунд с Wireshark** на одном разрешённом приборе. Не запускать оригинальный MVKView параллельно с новым TCP-клиентом без отдельного подтверждения безопасной многоклиентности.
- Конкурентные соединения, reconnect, длительная работа и аппаратный Windows runtime нового EXE ещё не исследованы. Реконструированные TABLE и тахометрические BIN требуют следующей отдельной проверки, где имеется оригинальный экспорт MVKView того же сеанса.
- **Stable MVK Reader Web v0.3.40 не изменена.** Исходники только в исследовательской ветке.

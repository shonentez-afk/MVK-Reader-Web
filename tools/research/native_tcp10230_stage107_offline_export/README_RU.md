# MVK Stage 107 / R6 — автономный офлайн-экспорт 8×BIN/TSXML + VALUES/TABLE

**Дата:** 29 октября 2026. **Статус:** обработаны обе настоящие 30-секундные записи прибора `10.13.42.84`; оригинальный серийный номер в регистровом снимке — `MVK00000043`. Это два различных идентификатора: .84 является концом IP, а 00000043 — заводским серийником.

Данная программа **не подключается к сети**, не содержит отправки команд, не меняет конфигурацию МВК01 и не модифицирует стабильную MVK Reader Web v0.3.40. Исходные Native R5/R5.1 не меняет. Источник экспортирования — уже принятый поток TCP/10230 `incoming.raw` и его парные `summary.json`/`frames.csv`.

## Запуск на Windows 64-bit (без BAT/PowerShell/Python/Go)

1. Распакуйте исходный `TEST_....7z`, полученный от R5/R5.1, обычным архиватором. Внутри найдите **конечную папку**, где рядом находятся три файла: `incoming.raw`, `frames.csv`, `summary.json`.
2. Дважды щёлкните `MVK_Stage107_Offline_Exporter_Windows_x64.exe`.
3. Вставьте полный путь к папке с тремя файлами. В следующем поле укажите **новую** папку результатов либо нажмите Enter для имени `<исходная папка>_EXPORTED_STAGE107`.
4. Укажите **UTC-смещение часов компьютера во время захвата**, например `+07:00` для предоставленных записей 29.10.2026. Это смещение необходимо только для человекочитаемых времён CSV и TSXML; времена TCP из frames.csv остаются UTC.
5. Подтвердите `YES` и дождитесь сообщения `SUCCESS`; окно останется открытым до Enter. Если данные некорректны — вывод `FAIL CLOSED`, готовая папка результата **не создаётся**. Вводы и материалы оригинальных тестов не меняются.

Командная строка (не обязательна):

```text
MVK_Stage107_Offline_Exporter_Windows_x64.exe -test-dir "C:\tests\TEST_..." -out "C:\MVK\EXPORT_84_A" -offset +07:00
```

Либо укажите раздельно `-raw`, `-frames`, `-summary` и `-out`.

## Выходные файлы

* **8× `.bin`**: для АЦП1–8, каждый — только float32 LE откалиброванного ускорения в м/с², без TCP-заголовков и последовательностей. `converted = float32(float64(rawFloat32)*float64(currentSessionGainFloat32))`.
* **8× `.bin.tsxml`**: копируется последовательность оригинальных XML-полей (windows-1251, en-US, From/To, FrequencyPerChannel, ChannelNumber, Units, DataLength, DataOffset, InternalChannelGain). `To` рассчитано точно из числа полученных отсчётов; `DateTime` использует **конец захвата R5/R5.1**, а не неизвестное время нажатия кнопки записи MVKView. Фактический gain указывается с высокой точностью, оригинал мог округлять его.
* `VALUES_ALL_ADC_RECONSTRUCTED.csv`: те же **73 названия граф на канал**, что в предоставленном оригинальном VALUES CSV MVKView; 8 каналов × 73 + время = **585 столбцов**. Данные идут непосредственно из AUX4700 по 60 циклам; метка времени — **час компьютера при получении 76-байтного TACH/PARAM после AUX**, не DSP-синхронная временная метка.
* `TABLE_LAST_AUX_RECONSTRUCTED.csv`: снимок последнего цикла AUX, 8 АЦП и тахометрические регистры. Это **не аналог реальной команды пользователя «Сохранить TABLE»**, которая в этих записях отсутствует.
* `TIMELINE.json`: кадровые индексы и UTC-времена соответствующих AUX4700 и последующих ticks, для точной проверки provenance.
* `EXPORT_AUDIT.json`: SHA256 входного RAW и готовых файлов, per-channel gain, Fs, индекс и количество отсчётов, служебный статус датчика, сопроводительная оговорка о точности.
* `README_RU.txt` — короткое предупреждение, закодировано windows-1251.

## Правила точности и безопасности

* Начальный 264-байтный `VAST_MVK` + полный 32 800-байтный снимок регистров **обязательны**. Если поток начинается посреди сеанса или отсутствует калибровка, экспорт запрещается.
* Программа **побайтно проверяет весь RAW по SHA256 и каждый кадр по `frames.csv`**. Каждый из восьми счётчиков АЦП должен увеличиваться ровно на 256; канал, частота, длина и float32 обязаны быть корректными. Изменение gain или чувствительности во время сеанса останавливает экспорт. Директория публикуется только после полной проверки и записи всех файлов.
* Прибор №84: статус `0x400` на АЦП7/8 обозначает **подозрение на обрыв линии/превышение напряжения датчика**. BIN сохраняется для аудита, но **не означает корректное измерение вибрации**.
* Численные поля VALUES/TABLE взяты из регистров DSP, но **локализация статусов и округление вывода могут отличаться от оригинального MVKView**. Для неизвестных текстов ошибок сохранён числовой hex-статус, чтобы не выдавать предположение за восстановленный GetValueText. Строка «Наличие импульсов на входе» у тахометра пока остаётся пустой.
* Побитовое совпадение с оригинальным BIN, полученным MVKView **именно во время этих двух захватов**, ещё не проверялось, потому что таких исходных файлов нет. Независимое побитовое совпадение с математическим преобразованием *RAW этого сеанса × K этого сеанса* подтверждено для всех отсчётов.

# MVK Ghidra 12.2 — автономный пакет исследования оригинала (без MCP)

**Задача:** за один запуск собрать из локальной Ghidra 12.2 пакет декомпиляций, ассемблера, XREF и имеющихся структур для восстановления вычислительного ядра и интерфейса MVKView.

## Запуск

1. Распакуйте этот архив.
2. Скопируйте `MVK_Export_IDR_Research.java` в `%USERPROFILE%\ghidra_scripts` (туда же, где уже лежит рабочий `MVK_Import_IDR_Labels.java`).
3. В Ghidra откройте исходный `mvkview.exe` в окне **CodeBrowser**; его базовый адрес должен быть **00400000**. Метки IDR в проекте уже импортированы.
4. В **Window → Script Manager** нажмите обновление списка и запустите **MVK_Export_IDR_Research.java**.
5. Выберите **папку для экспорта**, например `C:\MVK_Export`. Скрипт создаст *новую* папку `MVK_Ghidra_Research_YYYYMMDD_HHMMSS`; имеющиеся файлы не перезаписывает.
6. По окончании в консоли появится `MVK EXPORT: DONE: <папка>`. Заархивируйте **созданную папку** в ZIP и приложите **к этому чату**, чтобы можно было сразу сверять расшифровку и менять ядро и UI вместе.

## Что экспортируется

- `manifest.json`: данные текущего EXE, количество успешных операций и ошибки; **не обещает паритет оригиналу**.
- `functions.csv`: индекс экспортированных функций и путей к их `.c`, `.asm`, `_variables.csv`.
- `functions/XXXXXXXX.c`: C-подобный текст декомпилятора Ghidra, если функция определена.
- `functions/XXXXXXXX.asm`: инструкции с адресами и байтами (до 1200 инструкций на функцию).
- `probes.csv`: проверка известных точек IDR, в т.ч. внутренних ветвей GetSpectrum и code20.
- `outgoing_references.csv`, `incoming_calls.csv`: статические графы ссылок и вызовов.
- `referenced_strings.csv`: строки данных, на которые имеются ссылки из экспортируемого кода.
- `structures.csv`: уже определённые структуры Ghidra (не придумывает типы).

В экспорт по умолчанию включены функции `TMvkChannelStorage.GetSpectrum`, `GetSignal`, `ProcessBufferChunk`, `TMVKThread.Execute`, `QueueCommand`, `SetRate`, обработчики `bTaskConnectClick`, `pbAdcPaint`, `pbSpectrumPaint`, кнопки записи, `PagesChange`. Включаются также ограниченные исходящие вызовы по адресу в диапазоне пользовательского кода; **верхний предел 64 функции**, глубина 1.

## Ограничения и безопасность

- Работает в стандартном Ghidra **Java Script Manager** — **Python, PyGhidra, MCP, сетевой доступ и права администратора ChatGPT не нужны**.
- **Никаких изменений EXE, Ghidra project, запуска MVKView, TCP-соединений, команд измерения или записи на прибор**. Экспортируются только результаты статического анализа.
- Поля C-декомпиляции, вызовы Delphi и вычисления `float10`/x87 нужно дополнительно проверять по `.asm`.
- Уже существующие названия IDR — подсказки, не доказательство точности прототипов или графа исполнения.
- В публичный репозиторий **нельзя автоматически загружать полученный ZIP**, так как он содержит реконструированные фрагменты оригинального исполняемого кода и потенциально чувствительные строковые данные. Передавайте ZIP приватно через чат.
- Если в `.c` выводится `Decompilation unavailable`, соответствующий `.asm` всё равно сохранён. Если важный адрес не оформлен в Ghidra как Function, он помечается как `LABEL_OR_UNDEFINED`, и экспортёр **не создаёт функцию автоматически**. Это предохраняет базу анализа от непроверенных изменений.

## Проверка результата

Для Windows PowerShell из папки с результатом (если установлен Python):

```powershell
py "C:\путь\к\распакованному\архиву\verify_export.py" "C:\MVK_Export\MVK_Ghidra_Research_YYYYMMDD_HHMMSS"
```

Для нашего восстановления особенно нужны `007D13D4.c`, `007D13D4.asm`, `00807A98.c`, `00809330.c`, `00809400.c`, `00848E78.c`, `00846AD4.c`, `0084C910.c`, а также индексы ссылок.

# MVK IDR Bridge — автономная база восстановления оригинальной MVKView

**Назначение:** превращает предоставленные пользователем `mvkview.idp` и экспорт `Projects.7z` (129 PAS, 3 DFM, 1 DPR) в локальную SQLite-базу и подключает её как **MCP-сервер только для чтения**. Оригинальная программа не запускается, а подключённый прибор не затрагивается.

## Статус

- Реально разобраны IDP v3 **заголовок и таблица сегментов** — не все внутренние записи IDP.
- Из восстановленных PAS индексируются процедуры с машинными адресами и прямые ассемблерные `call`.
- Из DFM индексируются формы, компоненты, свойства и назначения `OnClick`/`OnChange` и других событий.
- Имена обработчиков связываются с функциями по точному имени класса и методу, вызываемые функции — по адресам или однозначному имени.
- Результат не является оригинальным исходным проектом, не подтверждает динамическое выполнение функций и не заменяет численное тестирование.

## Запуск построения на Windows / Linux

Понадобится Python 3.10+ **без сторонних зависимостей**. `Projects.7z` распаковать системным архиватором (например, 7-Zip). Пример для PowerShell:

```powershell
py tools\mvk_idr_bridge\idr_bridge.py `
  --idp "D:\MVK\mvkview.idp" `
  --sources "D:\MVK\Projects" `
  --db "D:\MVK\idr_kb\mvk_idr.sqlite" `
  --out "D:\MVK\idr_kb"
```

В `--sources` укажите каталог, непосредственно содержащий `mvkform.dfm`, `_Unit128.pas`, `_Unit115.pas` и остальные PAS. При использовании готовой базы ниже этот этап пропускается.

Файлы результата: `mvk_idr.sqlite`, `manifest.json`, `AUDIT_RU.md`, `event_handlers.csv`, `forms_components.csv`, `ghidra_labels.csv`.

## MCP (любой клиент, поддерживающий локальные stdio MCP-серверы)

```json
{
  "mcpServers": {
    "mvk-idr": {
      "command": "py",
      "args": [
        "-u", "D:\\MVK\\mvk_idr_bridge\\mcp_server.py",
        "--db", "D:\\MVK\\idr_kb\\mvk_idr.sqlite",
        "--sources", "D:\\MVK\\Projects"
      ]
    }
  }
}
```

`--sources` необязателен: без него все поиски, карты обработчиков и граф вызовов работают из SQLite, а инструмент `idr_code` покажет, что исходный файл не предоставлен.

Сервер реализует MCP stdio JSON-RPC `initialize`, `tools/list`, `tools/call`, `ping` с `protocolVersion 2024-11-05`; все результаты — текст JSON. MCP-клиент должен запускать процесс, а не подключаться к нему через HTTP. Предусмотрены только read-only инструменты:

| MCP tool | Назначение |
|---|---|
| `idr_stats` | Параметры IDP и числа извлечённых записей |
| `idr_search` | Поиск методов, компонентов, обработчиков |
| `idr_forms` | Дерево компонентов одной из трёх DFM-форм |
| `idr_component` | Точные события, свойства, адрес обработчика |
| `idr_event_chain` | Компонент → обработчик → ограниченный статический граф |
| `idr_function` | Исходящие и входящие статические вызовы функции |
| `idr_trace` | Ограниченный граф прямых вызовов от заданного адреса |
| `idr_callers` | Из каких процедур вызывается заданная функция |
| `idr_code` | Строки восстановленного дизассемблерного листинга |

**Безопасность:** MCP не может кликать, запускать «Измерение», писать память, включать Frida, отправлять TCP-пакеты или менять файлы исходной программы. IDR-проект и расшифровка используются только как данные.

## Важные точки MVKView

- `mvkform/../bTaskConnect` → `Tmvkform.bTaskConnectClick` (`00848E78`) → `sub_00846AD4` (`00846AD4`) с `EDX=2` по восстановленному листингу.
- `bTaskView` → `Tmvkform.bTaskViewClick` (`00848E84`) → та же функция с `EDX=1`.
- `TMvkChannelStorage.GetSpectrum` (`007D13D4`) имеет прямые вызовы по `00848200` и `0084FB03` в `_Unit128.pas`.
- Эти ссылки доказывают структуру статического кода, **не** то, что прибор запускался или расчёт был выполнен.

## Интеграция с Ghidra

`ghidra_labels.csv` содержит адреса и имена 25k+ восстановленных функций. С помощью скрипта `ghidra_import_labels.py` (Script Manager → New → Python/Jython → вставить содержимое) можно нанести имена на подходящую программу, открытую в Ghidra. Скрипт **создаёт лишь метки в текущем Ghidra-проекте**: не создаёт функции и не меняет EXE. Перед использованием проверьте, что `ImageBase` в Ghidra — `00400000`, адреса валидны, а для программы взят EXE соответствующей версии.

`GhidraMCP` затем сможет запрашивать декомпиляцию по уже размеченным адресам; автоматический импорт меток через GhidraMCP отдельно не реализован.

## Хранение

В GitHub сохраняется **только программа построения/доступа и примеры**, не 42 МБ реконструированного кода и не оригинальный `mvkview.idp`. Файлы SQLite и CSV генерируются локально из материалов пользователя; готовый архив базы предоставляется отдельно в этом чате.

## Ghidra 12.2: автономный экспорт и локальный Harness/Hermes

- [MVK_Export_IDR_Research.java](MVK_Export_IDR_Research.java): Java-скрипт для Ghidra 12.2 CodeBrowser. Без MCP сохраняет ограниченные (до 64 функций) декомпиляции, xrefs, инструкции и структуры в локальную папку. **Не модифицирует EXE и не отправляет команды прибору**.
- [README_GHIDRA_OFFLINE_RU.md](README_GHIDRA_OFFLINE_RU.md): запуск, файлы результата, ограничения и приватная передача ZIP.
- [verify_export.py](verify_export.py): локальная проверка структуры выгрузки.
- [HARNESS_MCP_RU.md](HARNESS_MCP_RU.md): локальное подключение уже установленного GhidrAssistMCP 3.0.0 к Harness/Hermes через `http://127.0.0.1:8080/mcp`, без OpenAI Tunnel. У LaurieWired/GhidraMCP release 2.0 готовый ZIP ориентирован на Ghidra 12.1.4, не на 12.2.

Сами исходные EXE/IDP/PAS/BIN/DFM и декомпилированные данные остаются локально и **в GitHub не публикуются**.

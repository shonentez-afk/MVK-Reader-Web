# Повторная проверка AUX160 -> AUX4700 и постоянных парных полей

Дата 2026-10-26. Два реальных RAW (12 секунд каждый), полностью офлайн. Разбор выполнен по границам кадров (длина из заголовка), сравнение чисел — как исходных uint32 битовых шаблонов float32.

## Текущие поля: подтверждено

На приборе A, ADC 2/3/4/6/7/8: для каждого из 12 AUX160 совпадение с **последним кадром AUX4700, предшествующим AUX160 по смещению файла**. Схема: AUX160 +32 = AUX4700 index 55; +48 = index 66; +64 = index 47; +80 = index 46. Получено 6 x 12 x 4 = **288/288 точных совпадений**. Со следующим более старым кадром совпадений 0/288. Исправлено ошибочное описание лага и логика выбора кадра в `tools/raw_offline_audit/verify_aux160_exact_mapping.py` (исходный вариант подбирал ближайший и вычитал 1).

Для ADC1/ADC5 прибора A переменные значения AUX160 равны нулю (диагностические флаги датчика). Для B переменные и постоянные поля AUX160 всех восьми каналов нулевые. Совпадения нуля с нулевыми расчётными полями B не являются доказательством полезного отображения.

## Постоянные поля +40, +56, +72, +88

- Прибор A, ADC2/3/4/6/7/8: каждое из четырёх полей остаётся побитово неизменным во всех 12 записях; всего 24 канальных значения и 288 наблюдений.
- Ни одно из этих 24 ненулевых константных значений **побитово не совпадает** с каким-либо из 144 полей AUX4700 этого же канала на протяжении всех 24 его кадров.
- Пример ADC4: +40=4.66681576; +56=4.65205336; +72=0.36384010; +88=7.96381283.
- Прибор B: 4 постоянных поля равны 0 на всех восьми каналах в исследованной короткой записи.

**Интерпретация пока открыта:** опорные показатели, сохранённые значения или пользовательские пороги — возможные варианты. Постоянство в течение 12 секунд и отсутствие побитового совпадения с AUX4700 не позволяют выбрать один.

Для независимого подтверждения природы констант целесообразно повторить анализ уже записанных более длительных PCAPNG с корректным TCP reassembly и проверить, сохраняются ли значения по каждому каналу при длительном изменении вибрации.

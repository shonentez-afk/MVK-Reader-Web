## 2. Главный результат — найдено исходное статическое слово 0x1332

На этом этапе проверен сам приватный файл `mvkview.idp` (формат `IDR proj v.3`, 11 сегментов), не только реконструированный `System.pas`. Проанализирована структура заголовка проекта: 4 DWORD на запись секции и строка имени **заданной длины** (не C-строка), после таблицы подряд хранятся отображения исходных сегментов.

Адресный расчёт по оригинальной карте:

| Поле | Установлено непосредственно из оригинального приватного IDP |
|---|---|
| `.text` | VA `00401000`, размер `004BE000`, начало данных файла `00000128` |
| `.itext` | VA `008BF000`, размер `00003000` |
| `.data` | VA `008C2000`, размер `00013000`, смещение в IDP `004C1128` |
| Глобальное слово FPU | **VA `008C2028` = `.data+0x28`, файловое смещение `004C1150`** |
| **Исходное значение в файле** | **`0x1332` (little-endian WORD)** |

Проверены соответствующие инструкции внутри той же карты оригинального кода: `System.@FpuInit` VA `00409570` (`FNINIT / WAIT / FLDCW [008C2028]`); `Set8087CW` VA `00407664` (запись этого адреса, `FNCLEX / FLDCW`); `Get8087CW` VA `00407674` (`FNSTCW`). Отдельно проверена инициализация `TMvkChannelStorage.FRange` в конструкторе VA `007D0A61` значением IEEE Single `1.0`.

Декодирование статического `0x1332`: **precision-control PC=64 бит**, **rounding-control RC=round-to-nearest**, маска исключений `0x32`. Это не `0x037F`, ранее наблюдавшееся на тестовом Linux-процессе. Разница по masked exceptions имеет значение для поведения в исключительных состояниях.

**Граница доказательства:** подтверждено именно **слово в исходном образе и путь загрузки при `@FpuInit`**. Не подтверждено, что на работающей Delphi MVKView непосредственно перед `_Unit128:0084B631` программа не вызывала `Set8087CW`. Следовательно, `original_process_runtime_cw_verified=False`. Фактический `FRange` выбранного канала тоже неизвестен, несмотря на конструкторный default 1.0.

## 3. Нативная проверка нового CW и особенность зарезервированного бита 6

В независимом исследовательском C-пробнике x87 появился отдельный режим `--source-static-cw`: подгрузить статическое `0x1332` в **изолированном процессе**, выполнить 28 полностью синтетических проверок (семь значений, четыре типа спектра), затем восстановить предыдущее управляющее слово.

На тестовой платформе `FLDCW(0x1332)` с последующим `FNSTCW` показал `0x1372`: аппаратура установила зарезервированный бит 6 `0x0040`. Это **не изменение PC или RC** и не означает неверное содержимое IDP. Пробник сравнивает значимые биты CW, а также проверяет восстановление исходного слова при выходе.

**Новый численный контрпример** (только SYNTHETIC, не оригинальное измерение): `FRange=10`, режим спектра `3` (множитель 100) → число `1000` перед округлением.

| Режим вычисления | Синтетическое вычисленное GraphDefaultVScale |
|---|---:|
| Python `math.log10` float64-кандидат | **1000** |
| x87 `FLDLG2/FYL2X` при исходном статическом CW на тестовом CPU | **2000** |

У x87 дробная часть логарифма `1000` оказалась **положительной величиной порядка `2.17×10⁻¹⁹`**, тогда как Python `math.log10(1000)` дал ровно `3`. Это переключает ветку исходного алгоритма. Отличия могут зависеть от реализации процессора, FPU environment и поведения оригинальной Delphi, поэтому **нельзя просто исправить Python на 2000 без независимого оригинального эталона**.

Значит Stage111U-кандидат нуждается в явном предупреждении об уязвимых граничных точках. Сейчас добавлены диагностические флаги `native_x87_extended_log10_integer_decade_risk`, `native_x87_single_comparison_threshold_risk`, `original_x87_boundary_requires_runtime_reference`; все флаги оригинальной runtime parity остаются `False`.

## 4. Реализовано и проверено

- `mvk_compatible/private_original_cw_idr_audit.py`: **приватный офлайн-аудитор** структуры IDR v3, секций, статического WORD и соответствующих инструкций, включая конструктор `FRange`. Выводит только производные поля CW/PC/RC, **не выводит приватный путь, исходные байты, исходники или дампы**. Файл IDP не требуется в GitHub/CI.
- `mvk_compatible/tests/test_private_original_cw_idr_audit.py`: полностью синтетические секции без приватного кода; проверяет подмену CW, испорченные opcodes, неправильную сигнатуру, сокращённые данные, symlink и отказ от ложной аттестации.
- `mvk_compatible/native_probe/x87_graph_vscale_probe.c`: новый режим `--source-static-cw`, сохранение и восстановление FPU control word, отдельная обработка аппаратного reserved bit6.
- `mvk_compatible/tests/test_x87_graph_vscale_native_probe.py`: проверка исходного статического CW на CPU и отчёт о расхождении на синтетическом `1000` вместо ложного утверждения точной идентичности.
- `mvk_compatible/core/spectrum_graph_default_vscale_idr_candidate.py`: теперь содержит проверенные static CW/PC/RC и флаги возможной ошибки `float64 log10` около целых декад и ступеней 2/5. **Не** подменяет `FRange`, DSP или оригинальную вертикальную калибровку.
- `mvk_compatible/desktop/main_window.py`: отображает `исходное CW=0x1332 (PC64, runtime не измерен)`, предупреждение на опасной границе x87; реальный Qt ViewBox по-прежнему исследовательский.
- Расширены тесты Qt и `test_graph_vscale_source_cw_provenance.py`, без включения защищённых данных.

**Локально:** полный имеющийся изолированный исследовательский набор Stage111U/V/W — **79 PASS** (в том числе нативный GCC x87-пробник, приватный IDP-аудитор на синтетике, Python model/компаратор). Реальный `mvkview.idp` локально успешно проверен именно новым аудитором; в GitHub попадут только код/синтетические тесты, оригинальный файл останется приватным.

## 5. Открытые вопросы и переход к Stage111X

1. Проверить полный CI Linux/Windows Qt/Windows verified-dist EXE для **точного** Stage111W программного SHA. Независимо скачать и сравнить реальный EXE с SHA256SUMS, проверить `BUILD_VERIFICATION.json`.
2. В частном **работающем оригинале MVKView** без подключения прибора получить `Get8087CW` непосредственно перед `_Unit128:0084B631`, текущий `TMvkChannelStorage.FRange` выбранного канала (+0x04) и итоговый `GraphDefaultVScale` (+0x62C), режимы спектра 0–3 и соседние Single на границах 2/5/10/1000. Не коммитить оригинальные значения.
3. Проверить точный Delphi `@TRUNC`/x87 (включая **разницу при `log10(1000)`**) и функции `00447DB8/00447DF0/00447EF8` под настоящим runtime CW. Только после независимой эталонной сверки можно переключать фактическую Qt Y-ось с исследовательского кандидата на оригинальный алгоритм.
4. Параллельно восстановить `FormatFloat`, `CursorString`, TPaintBox.Canvas.Font/PPI/PixelRect и численный `GetSpectrum/FRange/Narrowband` на одном исходном архивном окне. Стабильный `main`, Web v0.3.40, прибор и оригинальные PAS/DFM/IDP/BIN/PCAPNG без отдельного разрешения не менять.

**Итог:** статическое исходное FPU CW и его связь с оригинальным `@FpuInit` восстановлены напрямую; поведение *работающей* программы и полная численная идентичность остаются отдельной, ещё не завершённой задачей.

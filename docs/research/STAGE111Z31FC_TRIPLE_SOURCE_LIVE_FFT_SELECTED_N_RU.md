# Stage111Z31FC — исходный bSpecLines и живой GetSpectrum: N без автоматического уменьшения

17 ноября 2026 г. Ветка `research/stage111-mvkview-desktop-20261029`.

## Реальная совместная сверка трёх приватных источников

Открыты в одном исследовательском сеансе `mvkview.idp`, `Projects.7z` и `mvk_idr(1).sqlite`. Контрольные SHA бинарного IDR, четырёх Pascal/DFM файлов архива и индексных таблиц совпали. SQLite `PRAGMA quick_check(1)=ok`. В публичный репозиторий **не** переданы исходные IDP/SQLite/PAS/DFM, сырой трафик, IP пользователя или секреты.

- `_Unit128.pas`, метод обновления PageSpectrum `00848148`, участок `0084819A..00848200`: `TButton.Tag` переключателя `bSpecLines` индексирует таблицу `gvar_008D3450` и заполняет `TMvkChannelStorageCalcParams.Count` **выбранным N**, затем вызывает `TMvkChannelStorage.GetSpectrum` `007D13D4`.
- `mSpecLines1Click 0084C4C8` фиксирует выбранный Tag и вызывает обновление PageSpectrum. `_Unit115.pas` `GetSpectrum 007D13D4` использует запрошенное целое количество отсчётов вплоть до `0x40000=262144`; `CheckDataAvailability 007D1998` проверяет реальную историю, а не подменяет N ближайшим меньшим.
- Исходная таблица шести Tag значений `gvar_008D3450`: `262144, 131072, 65536, 32768, 16384, 8192`. Комбинированный входной приёмник имеет 8 ADC + 2 TACH; живой график спектра рассчитывается по ADC, не по TACH.

## Исправленный сквозной путь Go → Core → Qt

Ранее Native Go отдавал лишь 8192 последних отсчётов ADC, а Core автоматически выбирал NFFT=8192 даже при видимом исходном пресете `65536`. В результате интерфейс показывал `bSpecLines=65536`, но численно вычислял **другой спектр**, с неверным `Δf=Fs/8192`.

1. **Go**: расширена исключительно вторичная ограниченная, уже калиброванная Float32 preview ring с 8192 до **65536 реальных отсчётов на ADC** (8×256 КиБ, 2 МиБ суммарно); каждый byte берётся только после успешного исходного `LiveBinSpool` write. Сигнальный TCP, RAW, spool и контрольные суммы исходных экспортов не изменяются. ZIP публикуется атомарно как прежде; при ошибке preview запись прибора продолжается.
2. **Python Core**: отдельное `n_fft` из источника `bSpecLines` проверяется без неявного downshift, zero-padding и повтора FRange. Вычисление использует ровно выбранный N, или строго отклоняется при недостаточной истории; принятие Float32, SHA, частоты и границ источника сохраняется.
3. **Qt**: в `_render_live_spectrum` передаётся `int(spec_n.currentData())`; при изменении `bSpecLines` во время LIVE происходит перерасчёт текущих подтверждённых отсчётов, частотный шаг `Δf=Fs/N` отображается от реальной Fs. При N=131072/262144, пока текущей истории недостаточно, **предыдущий спектр удаляется**, выводится состояние ожидания, а не ошибочный N=65536 или 8192.
4. Обновлены Go wrap/SHA регрессии, Core N/Δf и real Qt QWidget смены 65536→32768→131072→65536. Тесты синтетические: промышленный МВК01 не подключался.

## Границы подтверждения

Результат — **проверяемый Live FFT кандидат**, а не установленная численная идентичность Delphi. Пока ограниченная вторичная preview ring позволяет в Qt корректно считать исходные пресеты N=8192..65536. Пресеты N=131072/262144 **не вычисляются**, пока не восстановлены и не проверены большие окна реального оригинального буфера; они показывают честное ожидание. Точный `GetSignal/GetSpectrum`, Win32 x87/FFT, аппаратная WriteData/WriteValues, original GUI pixel parity и физический энд-ту-энд остаются открытыми: `original_delphi_compatibility_verified=false`.

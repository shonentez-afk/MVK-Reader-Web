# Stage 51 — исправление модели записи BIN (2026-10-28)

Проверено непосредственно по оригинальным IDR Pascal листингам `_Unit125.pas` и `_Unit115.pas`.

**Результат:** `0x008020A8` не копирует память; она устанавливает указатель `TRecordMemoryStream.FMemory` равным указателю, полученному из `TMvkChannelStorage.AllocBufferChunk`, и обнуляет позицию. Оба объекта делят одну область памяти.

Последовательность:
1. `0x007D1B40..0x007D1B45` — вычисление адреса из `PAdcFloatData`, `0x007D1BF3` — возврат указателя.
2. `0x008081F6` — `AllocBufferChunk`; `0x00808203` — вызов привязки `0x008020A8`; `0x008020A8..B0` — запись указателя в `TmpStream.FMemory`, а не memcpy.
3. `0x00808229` — `TIdIOHandler.ReadStream` записывает в этот буфер.
4. `0x0080828C` — `ProcessBufferChunk(ApplyRange=true)`; `0x007D23D1..E1` — умножение float32 на `FRange` **в том же массиве**.
5. `0x008082D6..DE` — `TFileStream.Write` читает `TmpStream.FMemory` **после** масштабирования, поэтому BIN содержит масштабированные отсчёты.

**Исправление Stage 50:** гипотеза о независимых памяти TmpStream и кольцевого буфера оказалась неверной. Противоречие с ранее подтверждённым соотношением `BIN≈raw_tcp*K_Modbus` для пар ADC4 двух приборов устранено на уровне потока данных. При этом присваивание `FRange=K_Modbus` статически ещё не прослежено: источники FC03 и `InternalChannelGain` нельзя автоматически объявлять одним полем.

Проверка 8/8 статических опор + автономная демонстрация shared memory. **Синхронное численное сравнение PCAPNG/BIN не повторялось** в Stage 51. Оригинальный EXE и PCAPNG не опубликованы.

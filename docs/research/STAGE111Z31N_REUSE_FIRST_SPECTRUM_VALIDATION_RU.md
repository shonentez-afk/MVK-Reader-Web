## ДОПОЛНЕНИЕ 05.11.2026: старые BIN→оригинальный СКРИН и same-Power/Y PNG УЖЕ сравнивали

Этот блок основан на восстановленной истории операторских сообщений (самих пользовательских BIN/PNG **нет** в текущем репозитории/CI, и данные здесь **не пересчитывались повторно**), а также на отчётах [Stage111Z14](STAGE111Z14_ORIGINAL_SPECTRUM_SCREENSHOT_PIXEL_REFERENCE_RU.md), [Stage111Z31B](STAGE111Z31B_FIRST_QT_SCREENSHOT_1920_VISUAL_AUDIT_RU.md), [Stage111Z31C](STAGE111Z31C_WINDOWS_150_PERCENT_DPI_QT_SOURCE_VISUAL_PARITY_RU.md).

1. **23.10.2026, прибор №83, АЦП4:** пользователь предоставил **сохранённый BIN/TSXML и скриншот спектра оригинальной MVKView**, обозначенные как одно измерение. Прямо сравнивали **численные показатели исходного скриншота** с FFT того самого сохранённого BIN: пик **37.5944 Гц (BIN) против 37.59 Гц (оригинал)**, амплитуда **4.157 против 4.176 мм/с** (~0.46%), СКЗ **4.611 против 4.620 мм/с** (~0.2%). **Это уже выполненная прикладная same-measurement BIN→original-screen проверка на одном АЦП**, хотя не сохранён новый полный покомпонентный Y-vs-original CSV/график. Уточнение: PCAPNG прибора №83 записывался **в другое время**, чем соответствующий BIN, и не может использоваться как доказательство битовой синхронизации; №84 — другой аппаратный случай.
2. **21.10.2026, прибор №44, АЦП1, `MVK00000044-ADC1-2026-04-29--17-27-39.bin`:** ранний парный набор BIN/TSXML и оригинальных экранных чисел по заявленной пользователем записи: оригинал **9.29 мм/с / 14.5 Гц / 6.37 мм/с**, расчёт из BIN **9.2902 мм/с / 14.25 Гц / 6.3791 мм/с**. Это сравнение численных итогов, **не** полных 131072 бинов и не идентичность разных экранных реализаций. Посторонний `SPEC-FREQ` CSV пользователь **исключил как эталон** — не возвращать его.
3. **01–05.11.2026, исходный Tag0 x32dbg:** пользовательский **оригинальный скриншот** из [StageZ14](STAGE111Z14_ORIGINAL_SPECTRUM_SCREENSHOT_PIXEL_REFERENCE_RU.md) и **наш Qt скриншот** из [Stage31C](STAGE111Z31C_WINDOWS_150_PERCENT_DPI_QT_SOURCE_VISUAL_PARITY_RU.md) действительно относятся к **ОДНОМУ оригинальному спектру `Power/Y`**, `N=262144, Fs=65536, FRange float32=43FF4853`, видимый курсор **3800 Гц/−55.32 дБ**, вывод **6.89/3800/0.7786**, и на Qt источник проверенного Y загружался **напрямую из локального x32dbg-reference manifest**. Нормализованное отличие курсора при переносе к Qt geometry ~**0.53 Qt px X / 0.21 Qt px Y**, принято для этой пары изображений. **НО это отрисовка уже готового оригинального Y, минуя получение спектра из BIN**. В отдельном раннем [Stage31B](STAGE111Z31B_FIRST_QT_SCREENSHOT_1920_VISUAL_AUDIT_RU.md) был Qt скрин **ДРУГОГО архивного BIN АЦП1** с −1.746 дБ; его тогда правильно признали не сопоставимым с оригинальным Tag0 −55.32 дБ. Старую ошибку несоответствующих скринов не повторять.

**ИТОГ:** Некорректно утверждать, что «никаких проверок BIN по скриншотам» или «никаких сравнений на одинаковых спектральных данных» не было. Оба типа проверки **были**. Открыто более узкое: **универсальная end-to-end bitwise same-window приёмка полного оригинального Y от сохранённого BIN во всех режимах/каналах**, оригинальная/Native пара BIN **одного сетевого сеанса**, и original-runtime FIR envelope same-window. Эти факты НЕ отменяют принятые старые сравнения. **Нового BIN или скриншота лишь ради повторения названных проверок не требовать.**

## Что реально НЕ закрыто на дату аудита

1. **После уже выполненной BIN→скрин проверки №83 АЦП4 и №44 АЦП1** всё ещё требуется **полный набор бин-к-бину исходного Y против нашего на одной производственной записи BIN/TSXML** со всеми согласованными channel, ADC, Fs, N, end-of-window, FRange, mode, units и, для envelope, code. Старые x32dbg оригинальные full 4-mode массивы покрывают конкретные snapshot-состояния, но автоматически не привязаны к текущему архиву Native. Инструменты локального сравнения Stage83, Stage27, Z29C2 уже реализованы. Не создавать их заново.
2. **Огибающая original same-window:** нужен оригинальный результат pre/post-FIR или full Y того же входного окна с подтверждёнными EnvelopeCode/FRange. Предыдущие 6493/6493 — *не* оригинальный результат работающей Windows-программы.
3. **Другие реальные сочетания N/Fs/ADC/Gain/Units:** source-формулы и синтетические тесты есть, но исходная полноценная sweep-аттестация не закрыта.
4. **Курсор/масштаб после произвольного zoom/pan и вторая серия:** исходные процедуры изучены и частично проверены screenshot; точных UI цифр во всех режимах нет. **Пиксельные формы шрифта не блокируют согласно явному решению пользователя**.
5. **Оригинальный MVKView BIN vs Native R6.1 BIN, same real session:** [Stage27A](STAGE111Z27_ORIGINAL_NATIVE_SAME_RUN_BIN_TSXML_COMPARATOR_RU.md) компаратор существует, синтетические проверки PASS; Stage27B оригинальная одинаковая запись **не проверена**.

## Правило следующего этапа

**НЕ начинать заново FFT, Power→Y, FRange, шкальные таблицы, курсор, FIR коэффициенты, source graph.** Продолжать только конкретную открытую верификацию с оригинальным выходом и совпадающим входным окном, envelope runtime/редкие N, затем исправлять фактические отклонения. Если исходного артефакта нет, не переобозначать исходно VERIFIED как UNKNOWN; выполнять code inspection и тесты новых условий отдельно. Сохранить приоритет: **СПЕКТР (числа + график, без font pixel perfection) → ВРЕМЕННОЙ СИГНАЛ → РАСЧЁТНЫЕ ДАННЫЕ → СТРАНИЦЫ**.

**Публикация:** только это резюме без private PAS/IDP/DFM/измерений/скриншотов.

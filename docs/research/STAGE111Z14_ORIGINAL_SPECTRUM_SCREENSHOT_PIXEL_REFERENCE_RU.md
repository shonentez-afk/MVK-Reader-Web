**Дата:** 01.11.2026. **Ветка:** `research/stage111-mvkview-desktop-20261029`.
**Продукт:** единый автономный Windows MVKView Compatible (Qt/PySide6), не старая Web-архитектура.

## 1. Получен original-runtime визуальный reference

Оператор передал **настоящий PNG скриншот 1920×1080** программы «ТПО МВК 1.0.47» с открытой вкладкой **«Спектр»**, исходной записью из Stage111Z.10/Z.13 и курсором у основного пика.

**Сам PNG остаётся локальным приватным пользовательским материалом; в GitHub, CircleCI и CI fixtures не опубликован.** В открытой ветке хранятся только производные численные факты и тесты.

Наблюдаемые элементы:
- Меню слева: `Без фильтра`, `Логарифмич.`, `1/4 Гц/лин`, `25600 Гц`, `150 дБ`.
- CursorString / hint слева: `3800 Гц` и `-55,32 дБ`.
- Отдельный summary: `СКЗ спектра 6,89 м/с2`, `Пик спектра 3800 Гц / 0,7786 м/с2`.
- Отдельные кнопки `Копировать` и `Сохранить`, широкая белая область графика, плотный **чёрный** спектр, серая сетка, подпись X `Гц`, подпись Y `дБ`, оси X `0…25600 Гц` и Y `-150…0 дБ`.
- Pink/green native XOR crosshair, что видно по разному цвету линии на белом фоне и на тёмной кривой.

Это тот же численный случай:
`N=262144`, `Fs=65536 Hz`, `XScale=3E800000` (0.25 Hz/bin), `OutputMean=40DC8F5E`, `OutputPeakX=466D8095`, `OutputPeakY=3F475279`. В Stage111Z.13 original Copy из той же записи дал `6,89 / 3800 / 0,7786`; новый скриншот подтверждает, что эти значения также **видны на экране**.

**Не путать:** `-55,32 дБ` — текущая координата курсора по логарифмической шкале, а `0,7786 м/с2` — отдельная линейная физическая амплитуда, рассчитанная в summary. Они не должны быть численно равны.

## 2. Численная проверка ГЕОМЕТРИИ по приватному PNG

Результаты независимого локального чтения полноразмерного изображения (не уменьшенного предпросмотра чата):

| Поле изображения | Значение |
|---|---|
| Full screenshot | 1920 × 1080 px |
| Plot border global (L,T,R,B) | **605, 193, 1639, 911** |
| Внутренняя ширина/высота осей между границами | **1034 × 718 px** |
| Вертикальная magenta линия | **global X=758** |
| Горизонтальная magenta линия | **global Y=458** |
| Цвет по белому фону | RGB **(255,127,255)** |
| Цвет по чёрному спектру | RGB **(0,128,0)** |

По линейной геометрии подписанных осей, без чтения скрытого TCanvas:

```text
Xpred = 605 + (3800 / 25600) * (1639-605) = 758.484375 px
Ypred = 193 + (55.32 / 150) * (911-193) = 457.7984 px
```

**Наблюдаемое отклонение от позиции на PNG: X=0,484375 пикселя, Y=0,2016 пикселя.** Получено совпадение в пределах 1 px для двух **уже округлённых на UI** значений.

**Ограничение:** это проверка геометрии *пользовательского скриншота оригинала*, а не сравнение отрендеренного Qt с original TCanvas и не доказательство правильных `itosM/C` / `stoiM/C`, отступов, font metrics или Win32 DPI в общем случае. Другая ширина окна потребует нового screenshot/current geometry.

## 3. Визуальная проверка алгоритма TQGrapher

Stage111J восстановил `Series.DataSize=TRUNC((NFFT/2)/1.28)`. Для данного оригинального случая:

```text
N/2 = 131072 power bins
DataSize = TRUNC(131072/1.28) = 102400 displayed series bins
XScale = Fs/N = 65536/262144 = 0.25 Hz per bin
Last valid center = (102400-1)*0.25 = 25599.75 Hz
Right plotted axis boundary = 102400*0.25 = 25600 Hz
Nyquist = 32768 Hz (НЕ правая граница оригинального графика)
```

PNG с надписью `25600 Гц` подтверждает **правую границу 25600**, а не предыдущую QT-кандидатную границу `25599.75`. Это 0.25 Hz различие, но именно оно влияет на выбор xticks/геометрию и принципиально не должно дополняться фиктивным 102401-м отсчётом.

Исходный x87/GDI-кандидат Stage111P задаёт `VCL clGreen = RGB(0,128,0)` и `pmXor`. По белому пикселю XOR с зелёной компонентой 128 даёт `RGB(255,127,255)`, по чёрному — `RGB(0,128,0)`. **Оба цвета реально обнаружены в данном original PNG**. Это сильное независимое подтверждение нашего исходного GDI XOR-алгоритма на двух цветах. Нельзя аппроксимировать настоящий XOR одной фиксированной фиолетовой линией при полном графическом переносе.

Source `cursor_string_candidate(3800,-55.32,x_name='Гц',y_name='дБ',decimal_separator=',')` формирует `3800 Гц\r\n-55,32 дБ`: соответствует тексту, видимому на screenshot. **Внутренний original CursorString clipboard/CRLF байтово не получен**; доказаны только отображаемые числа/слова.

## 4. Исправления в Windows Qt Desktop и регрессии

До этого Windows Qt-кандидат рисовал spectrum trace цветом `#176c92` (сине-зелёный) и устанавливал `_spec_visible_max_hz` по **центру последнего отображаемого бина** `25599.75`, а не по крайнему значению оси `25600`. Это отличалось от оригинального screenshot.

В source-derived `core/tqgrapher_display_idr_candidate.py` добавлено **отдельное** поле `grapher_axis_end_frequency_hz` = `DataSize*XScale`, при сохранении прежних `grapher_last_index` и `grapher_last_frequency_hz`. В `desktop/main_window.py`:
- `_spec_visible_max_hz` использует `grapher_axis_end_frequency_hz` вместо центра последнего бина;
- spectrum trace использует **чёрную линию** `#000000` вместо сине-зелёной `#176c92`.
- Внутреннее количество отображаемых данных строго остаётся `DataSize=102400`. FFT/физические расчёты/работа с BIN **не изменялись**.

Тесты:
- `tests/test_stage111z14_original_screenshot_cursor_geometry.py` — реальные derived screenshot pixels, обе геометрические ошибки меньше 1 px, exact source display endpoint 25600 vs last stored bin25599.75, candidate cursor 2 visible lines, synthetic XOR colors white/black.
- `tests/test_tqgrapher_display_idr_candidate.py` — новый end-axis contract на всех ранее поддерживаемых N.
- `tests/test_desktop_qt.py` — проверяет, что UI использует right **axis boundary**, а не последний sample center.
- Дополнительно прошлый Stage111Z.13 локальный Copy 4-Single / 3-field pytest теперь опубликован: `tests/test_stage111z13_original_same_click_golden.py`. Он фиксирует исходное observation 3/3 без публикации full original screen/raw clipboard.

**Чек-лист для визуальной приёмки следующего прохода:** открыть ТОТ ЖЕ архив в Qt Native на 1920x1080 с идентичной шириной/высотой UI и теми же `Tag0/N262144/Fs65536/FR43FF4853`, курсор 3800 Hz, Y -55.32 dB. Снять Qt screenshot. Сравнить пиксельный rect, xticks/yticks, plot trace density, cursor XOR на белом/чёрном, подписи и левую панель. По одному original screenshot Qt pixel-for-pixel parity не принимается.

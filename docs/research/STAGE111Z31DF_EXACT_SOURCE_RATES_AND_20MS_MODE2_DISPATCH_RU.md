# Stage111Z31DF — пять подлинных ЧД, первая команда SetRate и таймер 20 мс (Core + Qt)

Дата: 16.11.2026. **Факты взяты непосредственно из приватных mvkview.idp, mvk_idr(1).sqlite, Projects.7z/_Unit125.pas, _Unit128.pas, mvkform.dfm.** Не коммитить эти исходники, SQLite, PCAP/RAW/скриншоты в публичный репозиторий. В GitHub хранятся только производные константы, чистые модели и тесты.

## 1. Что восстановлено именно из исходных бинарных данных

Проверена адресная трансляция сохранённого в IDR v3 образа:

- Исходное значение pointer-at-data 008D3AEC -> **008D2F7C** (проверено непосредственным чтением исходных байтов; только этот адрес читает _Unit128 008457F6).
- По адресу 008D2F7C находятся ровно 5 смежных Win32 little-endian UInt32: **0x200, 0x800, 0x2000, 0x8000, 0x10000**; в десятичном виде **512, 2048, 8192, 32768, 65536**.
- _Unit128 008457F1..0084587B создаёт пять TMenuItem и каждый выполняет Insert(0): поэтому реальный порядок на экране **65536, 32768, 8192, 2048, 512 Гц**, а не порядок в массиве.
- _Unit128 00844308 начальное SelectedSampleRate берёт из пятого числа массива (0x10000 =65536).
- _Unit125 0080618E: source machine code C7 83 D0 00 04 00 **09 03 00 00**. В листинге IDR это печатается как «309» в HEX и **означает 0x309 (777 decimal), НЕ decimal 309 и не 309 Гц**. Предыдущая модель ошибочно использовала decimal 309 — исправлено.
- _Unit128 00846D24..00846D84 сначала показывает пять вкладок и pnMeasure, далее 00846DD1 создаёт TMVKThread с внутренним кодом 0x309, и 00846DDF..00846DF7 немедленно вызывает mRate1Click на popSampleRate.Items[0].
- mRate1Click 0084DEC4 читает TMenuItem.Tag; 0084DF18 вызывает TMVKThread.SetRate, который при изменении значения (00809400) ставит команду 00809364 → QueueCommand(Cmd=1, Addr=0x0E, Data=65536). Код по умолчанию 0x309 не равен 65536, поэтому **ровно одна начальная SetRate команда** должна оказаться в исходной очереди.
- Это пока **только автономная сухая модель команды**. Никакие приборные команды или второй TCP-клиент не запускались.

## 2. Исходный интерфейс 20 мс

- В приватном mvkform.dfm: tmInterfaceUpdate: TJvTimer, **Enabled=False**, **Interval=20**, OnTimer=tmInterfaceUpdateTimer.
- _Unit128 0084F7C8 вызывает ровно 00847248, где **только одна активная вкладка** получает свой обработчик: PageConfig 008472D0, PageStatus 008475BC, PageAdc 00847EAC, PageSpectrum 00848148, PageFile 0084845C или PageCalib 00848688. PageStart отдельной ветви не имеет.
- После обработки выбранной страницы, если source pnMeasure.Visible, **отдельно** вызывается 008486F4 (панель измерения).
- Таймер включается в Mode2 после создания TMVKThread, а не в момент появления вкладок. При штатном прекращении Mode2 выключается.
- Источник не гарантирует 50 новых пакетов данных/с; 20 мс — **период GUI dispatch**, не частота поступления/вычисления новых ADC/DSP кадров.

## 3. Реализация в Windows Compatible

**Core:**
- original_mode2_rate_menu_source.py: точные пять Source Tag и исходный порядок в меню, неизменяемые доказуемые константы, проверка допустимых кодов, receipt начального выбора.
- original_mode2_command_queue.py: default 0x309 (777), а не decimal 309; пять Tag теперь помечены как независимо подтверждённые.
- original_mode2_runtime_trace.py: при Native start лишь в offline FIFO строит один первоначальный SetRate(65536), помеченный «dry-run», **никаких команд Go/прибору**.
- original_mode2_interface_timer.py: точная исходная шестирежимная таблица обработчиков, PageStart=none, pnMeasure после активной страницы; период 20 мс, source receipt без поддельных данных.

**Qt (реальный операторский интерфейс без дополнительных исследовательских элементов):**
- original_measure_controls_ui.py: пять оригинальных пунктов popSampleRate в правильном порядке, первый отмечен; каждый пункт **пока запрещён** до восстановления полной аппаратной команды. bSampleRate при этом показывает только реально наблюдённую Fs Native/архива, а не обещает выполненную аппаратную смену ЧД.
- main_window.py: настоящий QTimer с interval=20 и Qt.PreciseTimer активен только после начала разрешённого Native сеанса. При каждом тике выбирает **ровно одну текущую TTabSheet**, а панель pnMeasure обрабатывается отдельно. При смене активной страницы обновляется уже проверенное локальное содержимое; тяжёлые GetSignal/FFT пересчитываются только по поступившим и подтверждённым Native preview, **не каждые 20 мс**. При Stop таймер выключается; повторное разрешённое измерение получает новый Core/timer ledger.

## 4. Приёмка

- test_stage111z31df_exact_idp_rate_menu_core.py: пять реальных чисел, обратный порядок, default 0x309, команда 65536, доказанная little-endian Indy длина 36 байт в dry-run, отсутствие сетевой отправки.
- test_stage111z31df_qt_five_original_rate_menu.py: настоящие 5 Qt QAction на оригинальной pnMeasure, checked/Tag/order и невозможность выдать наблюдаемую Fs за управляемый SetRate.
- test_stage111z31df_original_interface_timer_core.py: 20 мс и 6+1 source handlers, gate pnMeasure, строгие типы.
- test_stage111z31df_qt_interface_timer.py: реальный QTimer и четыре LIVE страницы на source DPI; Stop и вторая попытка не наследуют старый таймер.

- Qt тесты DF добавлены в четыре Windows варианта (DPI 100/150, native/offscreen), Core — в Linux и Windows full suite.

## 5. Что по-прежнему нельзя считать полным оригинальным live measurement

- Операторские пять пунктов из оригинала пока не отправляют hardware SetRate, так как Native Go R6.1 **только читает** TCP/10230; визуальная отмеченная первая частота — source initial **simulation only**.
- Оригинальная полная TCP command/ACK/handshake/ошибки/пауза ProcessBufferChunk ещё не восстановлены. Побайтовая little-endian модель 36 байт подтверждает Write(UInt32), но не полный разрешённый device transaction.
- Равенство 20ms исходного GUI и Qt диспетчера не означает 20ms обновление прибора: Native JSON/preview обновляется отдельно (~900ms).
- Оригинальная Delphi численная/пиксельная и RPM/DSP same-run parity остаётся не аттестованной.

Следующий крупный шаг: исходный протокол ответов и set_rate transaction в **закрытом** offline-эмуляторе, проверки USB/Ethernet только с отдельным разрешением оператора, и сквозная численная parity четырёх LIVE страниц на одной реальной измерительной сессии. Полный приватный IDP/SQLite/архив не публиковать.

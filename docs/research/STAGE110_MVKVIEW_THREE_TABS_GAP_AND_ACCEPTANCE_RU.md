# Stage110 — точное восстановление трёх вкладок MVKView: карта, первый код и критерии приёмки

**Дата:** 2026-10-29. **Ветка:** `research/stage41-spectrum-chain-20261028`. **Решение пользователя:** полноценно воспроизвести вкладки **«Расчётные данные», «Временной сигнал», «Спектр»** оригинального настольного Delphi MVKView, не разрабатывать ещё один упрощённый приборный декодер и не заменять штатные DSP-значения своими. Стабильная v0.3.40 не изменена.

## 1. Что реально найдено в GitHub

Исследование **уже шло**: Stage25–40 (DFM, обработчики, сеть), Stage41–53 (настоящий локальный FFT, `FRange`, шкалы), Stage55–75 (AUX4700, расчётные значения, конфигурации и тревоги), Stage76–80 (VALUES/TABLE, BIN/TSXML и открытие архива), Stage81–96 (реальный `GetSpectrum`, таблица окна Hann RMS, четыре режима, timestamp и lifecycle записи), Stage106–109 (настоящий Windows Live Native R6.1, независимая приёмка). Результаты разные по уровню доказательности: найденная строка/адрес ≠ доказанный алгоритм, синтетический тест ≠ оригинальный спектр.

**Управляющее решение:** `docs/ADR_2026_10_29_ORIGINAL_MVK_DSP_DATA_SOURCE_RU.md`: DSP МВК является источником СКЗ/третьоктав/статусов. Но `TMvkChannelStorage.GetSpectrum` оригинальной настольной MVKView действительно **самостоятельно делает графическую FFT**, поэтому для вкладки «Спектр» нужна отдельная точная реализация десктопного FFT без подмены штатных DSP регистров.

### Оригинальные компоненты и обработчики

Проверенные локальные файлы из личного `Projects.7z`: `mvkform.dfm`, `_Unit115.pas`, `_Unit125.pas`, `_Unit128.pas`, `mvkview.idp`. **Не публиковать** эти оригинальные файлы в GitHub, а в репозитории хранить только выводы/адресные якоря и собственные тесты.

| Оригинальная вкладка | Delphi-объекты / адреса в IDR | Факт / уровень доказательства |
|---|---|---|
| Расчётные данные | `PageStatus`, `tabResult`, `tabAllResult`, `chResult`/`SpecSeries`, `tabAlarmResult`, `tabStatus` | Прямые имена DFM; исходные численные поля приходят из прибора, карта AUX4700; графические обработчики и контрольные зоны исследованы не до конца |
| Временной сигнал | `PageAdc`, `tcAdc`, `pbAdc`, `bAdcHScale`, `bAdcVScale`, `bAdcType`, `bAdcEnvelopeType`, `lbAdcHint`, `lbMean` | Прямые объекты DFM; `GetSignal` в `_Unit115.pas`, `pbAdcPaint` в `_Unit128.pas`, источник BIN/сокет восстановлен |
| Спектр | `PageSpectrum`, `tcSpectrum`, `pbSpectrum`, `bSpecHScale`, `bSpecVScale`, `bSpecType`, `bSpecLines`, `bSpecEnvelopeType`, `bSpecCopyValue`, `bSpecSaveValue`, `lbSpecHint`, `lbSpecMean` | Прямые объекты DFM; `GetSpectrum 0x007D13D4`, `TDSXFastFourier.fft 0x007CC3F8`, `pbSpectrumPaint 0x0084C910`, четыре меню; численные/UX детали требуют регрессии |

Адресные опоры графики: `GetSignal` в UI `0x00847FCF`, `GetSpectrum` `0x00848200`, `pbAdcPaint 0x0084B4A4`, `pbSpectrumPaint 0x0084C910`, `mAdcType1Click 0x0084B1E0`, `mSpecType1Click 0x0084C514`, `bSpecCopyValueClick 0x0084BC28`, `bSpecSaveValueClick 0x0084BD7C`. По сетевым кадрам исходные ADC1052: 28 байт заголовка + 256×float32 LE одного АЦП; полный AUX4700 содержит восемь блоков рассчитанных значений. Протокол TCP/10230 и original DFM **не равны** типовому Modbus TCP/502.

**Степень готовности:** первый работоспособный **офлайн UI/data adapter**, но НЕ «полностью восстановленные оригинальные три вкладки». Сохранение такого разграничения — обязательная часть качества проекта.

## 3. Оригинальные источники расчётов, шкалы и статусы

- `MVK_DSP`: 43 третьоктавных ускорения, 24 RMS, 24 эквивалентных ПИК, 24 эквивалентных ПИК-ПИК, канал/напряжение/статус. Калибровка отдельна.
- `MVK_ADC_CALIBRATED_BIN`: физический временной сигнал, уже умноженный на gain в Native R6.1; не применять K вторично.
- `APP_DERIVED_FFT_MVKVIEW_CANDIDATE`: **только графическая FFT кандидата**, это не третьоктавный спектр DSP, даже если UI называет вкладку «Спектр».
- Время VALUES оригинальная MVKView тоже формирует по ПК (`0x0080672B`, `0x00806743`), оно не совпадает с точной границей кадра АЦП автоматически.
- Статус канала 0x00000400 на №84 ADC7/8 отображать как плохое состояние; не переклассифицировать из-за имеющегося float32.

## 4. Приёмочные критерии полной трёхвкладочной реконструкции

1. **Визуальная структура:** сверка оригинального DFM/доступных экранов по формам, всем элементам, подрежимам, размерам, горячим клавишам, вертикальным/горизонтальным масштабам и обработчикам. Не заменять оригинальные функции «похожими» без пометки.
2. **Численная идентичность «Расчётных данных»:** один и тот же прибор/сеанс/обновление; 8×43+8×(24×3)+статусы, напряжения, 2 TACH, контрольные зоны — 0 ошибок декодирования, округление по правилу MVKView.
3. **Численная идентичность «Временного сигнала»:** одинаковые BIN, AC/AC+DC, выбранное окно, фильтры и огибающая, положение первого/последнего отсчёта, маркеры и курсоры, включая кольцевую запись и воспроизведение.
4. **Численная идентичность «Спектра»:** для одного BIN+TSXML и одинаковой FFT длины/окна/диапазона/режима экспорт точек из оригинальной MVKView и кандидата; без подгонки сравнить сетку Hz, максимум, уровни, дБ и пики, включая нулевые, DC, узкополосные тоны и переход по границе окна.
5. **Live:** показ всех вкладок из одного чтения TCP/10230 Native R6.1; свежесть/качество, статус ошибок, потоковая запись, архив и выбор прошлой сессии; без дополнительных команд прибору.
6. **Регрессия:** сохранять старые файлы, 39/39 native R6.1 tests и Web v0.3.40 tests; новый функционал только через feature flag / исследовательскую ветку до полной приёмки.

Ключевая зависимость для **точного FFT**: оригинальный MVKView экспорт точек графического FFT из **того же BIN и тех же UI-параметров** (или запуск оригинальной программы в безопасной локальной среде и запись экспортируемого спектра). Исследование IDR сильно уменьшает неопределённость, но не заменяет численное доказательство.

## 5. Продолжение реализации — без отката к старому

- **Stage110A (выполнено в этом проходе):** исходники standalone + opt-in Web adapter, три рабочие вкладки из реальных ZIP, тесты и GitHub-фиксация; точное сохранение DSP значений, статус AUX-provenance, fail-closed.
- **Stage110B (следующий проход):** поднимаем UI в основном исследовательском Web, осмотр оригинальных обработчиков `pbAdcPaint`, `pbSpectrumPaint`, `GetAdjustedEnvelopeLength`, TChart/таблицы; воспроизводим компоненты по отдельным feature-тестам, затем проверяем по оригинальным скриншотам.
- **Stage110C:** численная оригинальная local FFT и AC/envelope по односеансным эталонам, с сохранением данных только для приватного QA.
- **Stage110D:** Live интеграция Native R6.1 → единственная очередь каналов/расчётных кадров → три вкладки и архив, затем полевой QA.

**Запрещено:** возвращаться к ошибочной гипотезе «полный оригинальный DSP нужно пересчитать в клиенте». Это не относится к локальному FFT графика оригинальной MVKView.

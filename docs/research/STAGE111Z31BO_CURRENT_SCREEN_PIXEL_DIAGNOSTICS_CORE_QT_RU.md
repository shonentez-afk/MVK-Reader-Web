# Stage111Z31BO — прямое сравнение ТЕКУЩЕГО графика с PNG оригинала

**Состояние:** единый пакет автономного Core + рабочего PageSpectrum Qt + синтетических Core/E2E/Windows DPI150 тестов. Итоговый CI результат и проверенный source SHA фиксируются после приёмки.

## Что было и что изменено

Ранее уже существовали локальный SHA-проверенный x32dbg Power/Y, source-derived составной TQGrapher bitmap (сетка → подписи → кривая → рамка), исходный pixel audit и CLI, экспорт PNG + manifest. Но для сравнения с оригинальным снимком приходилось экспортировать график и запускать отдельную команду. Qt-окно не подтверждало, что сравнивается именно текущий живой bitmap, а не устаревший PNG от другого окна.

Теперь core/original_visible_pixel_compare.py делает **одну сквозную проверку** из реальных объектов PageSpectrum:
- Повторно проверяется SHA оригинального Power и всех N/2 Float32 Y текущего экрана; проверяются N, режим Tag0–3 и Fs/Δf.
- Требуется активная составная модель «сетка + подписи + кривая + рамка». Не допускаются устаревшие bitmap_viewport_signature или другой PixelRect/bitmap size после pan/zoom/resize.
- На текущем экране используется ровно тот RGBA, который передаётся ImageItem и остаётся неизменным до результата; временная XOR-подсветка курсора в сравнение не попадает.
- Оригинальная локальная PNG-пара выбирается пользователем; размеры должны совпасть **без масштабирования, подрезания или ресэмплинга**. Для защиты от ложного сравнения требуется явное заявление оператора про АЦП, окно, FFT, режим, FRange, масштаб, размер PaintBox, Windows DPI и убранный курсор.
- Пересчитываются точные RGB-пиксели и количество расхождений >1 отдельно для PixelRect (график/сетка) и полей осей/подписей. Радиус поиска сдвига 3 пикселя — только диагностика, не приёмка.
- Генерируется временная диагностическая RGBA-карта: красный = график, оранжевый = оси/подписи, серый = разность одного RGB уровня, белый = совпало. Никакие оригинальные изображения, исходные BIN/IDP, пути и содержимое FFT в отчёт/репозиторий не передаются.

В desktop/main_window.py в исследовательском доке рядом с оригинальным Power/Y появилась видимая команда «Сравнить видимый график с PNG оригинала…», подтверждение того же окна, отдельная надпись PixelRect/оси и небольшая цветовая карта отличий. Кнопка включается только для валидного исходного TCo2Draw composite. При загрузке другого оригинала, изменении X/Y-масштаба, ширины окна, DPI-композита или возвращении к архиву предыдущий результат/изображение очищается.

В основной оригинальной панели pnSpecTools **не добавлено никаких вымышленных DFM элементов**; функции и числа ядра не отстают от реального UI. Существующие GetSpectrum, FIR, FRange Stage BN и Native R6.1 остались без изменений.

## Приёмка и пределы подтверждения

Синтетические Core тесты всех четырёх Tag проверяют точные SHA, ROI, отсев неправильного источника, совпадающие/расходящиеся изображения, маленькие ошибки RGB, отличия в подписях, stale viewport, неподходящие размеры, отсутствие подтверждения оператора и отсутствие оригинальных приватных данных в отчётах.

Windows Qt E2E (150% DPI) открывает проверенный локальный Power/Y, включает настоящее составное изображение, выбирает сгенерированный PNG, проверяет 0 расхождений/карту, второй случай с расхождениями графика и подписей, затем изменяет X и подтверждает очистку предыдущего сравнения. Скриншоты из CI **только синтетические**.

**Критический предел:** скриншот, выбранный оператором, может относиться к другому оригинальному прогону и иметь одинаковые пиксели; программно независимо подтвердить PID Win32 MVKView, физический коэффициент ADC, TCanvas/Font/DPI-awareness и полноту совпадения исходного сигнала эта функция не может. Даже «все RGB пиксели равны» означает только диагностику данной пары и НЕ делает original_gdi_canvas_dpi_parity_verified=true.

После приёмки: при доступности реального Windows MVKView на ПК оператора провести одномоментный захват пары Power/Y/DFM CursorString + очищенный PNG оригинального TPaintBox, с точно тем же набором источника/FRange/FFT/Tag. Сравнение можно сделать в работающем окне этой версии; по найденным измеренным расхождениям править математический Core + реальные Qt элементы в одном следующем крупном пакете.

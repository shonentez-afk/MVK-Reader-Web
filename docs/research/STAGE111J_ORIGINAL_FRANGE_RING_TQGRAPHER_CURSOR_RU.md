# Stage 111J — цепочка FRange исходного кольцевого буфера и TQGrapher

29.10.2026. Рабочая ветка: research/stage111-mvkview-desktop-20261029. Единое офлайн-приложение MVKView Compatible на Windows Qt; без HTTP/сервера. Main и v0.3.40 не изменять. Исследовательская версия: полная Delphi, пиксельная и реальная численная приёмка **не выполнена**.

## 1. Прямое исследование оригинального Delphi

Приватно прочитаны файлы пользователя Projects.7z (декомпилированные _Unit115.pas, _Unit128.pas, mvkform.dfm) и mvkview.idp. Исходный IDP, PAS, DFM и производственные данные никогда не отправлять в GitHub.

| Исходный адрес | Подтверждённая операция |
|---|---|
| 007D0A61 | Конструктор TMvkChannelStorage записывает FRange:Single = 1.0 — это только начальное значение |
| 007D23B7–007D23E5 | ProcessBufferChunk при FAdcDataType=1 и ApplyRange умножает входные данные на FRange и сохраняет в оригинальном float32-кольце |
| 007D14A5 и 007D0F83–007D0F8D | GetSpectrum и GetNarrowbandValue вызывают 007D2228 с флагом 1 |
| 007D22A1–007D22D4 | Для float32-кольца и флага 1 при чтении оригинал делит сохранённые отсчёты на FRange, сохраняет результат в float32 и только затем удаляет DC |
| 007D1667/16F1/17B0/185A/18F9 и 007D0FF0/109F | Оригинал умножает итоговую линейную амплитуду GetSpectrum и узкополосного анализа на FRange |
| 007D1807–007D1810 | Подтверждённый на Stage111I последовательный double/qword аккумулятор спектральной мощности сохраняется после каждого сложения |

**Коррекция интерпретации Stage111I.** Простое масштабирование готового FFT с уже откалиброванным BIN полезно как диагностика, но не соответствует полной исходной цепочке внутреннего float32-буфера. Для аналогичного оригиналу режима чтения float-кольца перед FFT требуется отдельное деление на FRange. При чистой однородной линейной цепочке деление и конечное умножение почти компенсируются (с поправкой на округление), а для логарифмического режима нет такого постмасштабирования. Подставлять FRange, автоматически найденный по численному совпадению, запрещено — это скрывало бы ошибки алгоритма.

Файл Native R6.1 BIN содержит уже откалиброванные физические отсчёты согласно текущему модулю экспорта. **Не доказано**, что они идентичны оригинальному PAdcFloatData, и неизвестно реальное поле FRange оригинальной MVKView при тех же параметрах. Поэтому два режима выбирает только оператор:

- calibrated_bin — не делить вход; Stage111I постмасштабирование остаётся исследовательским.
- original_float_storage — гипотеза FAdcDataType=1: Single(вход/FRange) до удаления DC и FFT, затем FRange в конечной амплитуде.

Оба режима помечены как кандидаты; входные BIN и приборный AUX4700 не меняются. Не эмулируются неподтверждённые другие пути FAdcDataType и Live.

## 2. Восстановление TQGrapher Spectrum

По реальным инструкциям _Unit128.pas:

- 00848297–008482B2: XScale серии = Single(OutputSampleRate / (2*OutputLength)) = Single(fs/N).
- 008482B3–008482D1: Series.DataSize = TRUNC(OutputLength/Extended(1.28)). OutputLength=N/2, следовательно оригинальная графическая серия = N/2.56 точек (4096 FFT → 1600 видимых из 2048).
- Полный N/2 сохраняется для GetSpectrum и его интегральных показателей. Оригинальный верхний бин численной суммы может быть включительным, тогда как видимая серия заканчивается индексом DataSize-1. Их нельзя бездоказательно сделать одним массивом.
- 007CA459: исходный CursorSep по умолчанию CRLF.
- 007CA903–007CAAEE: исходный CursorString формируется как форматированная частота + пробел + XName, затем CursorSep и форматированное значение + пробел + YName; при наличии второй серии она добавляется аналогично.
- 007CAB94: линия курсора вычисляется через отдельные itosM и itosC, Single-store и Round. Эту операцию нельзя точно заменять обратной функцией stoiM/C из-за округления.
- 00848268/00848282: CursorAveraging для исходного спектра 1 в режиме dB и 3 в линейных режимах; 3 = sqrt(суммы квадратов) без деления на 3.

Точные исходные координаты PixelLeft/Right, реальная локализация осей, двоичное совпадение Delphi FormatFloat (007B2090), вторая TQGRSeries и пиксельный визуальный паритет пока не приняты. Новая Qt-геометрия передаёт свои коэффициенты отдельно и не выдаёт их за оригинальные TQGrapher pixels.

## 3. Реально изменённые файлы

- mvk_compatible/core/storage_f_range_idr_candidate.py — независимый безмутационный путь float32-деления до FFT и строгие метки источника.
- mvk_compatible/core/offline_export.py — опциональный input_domain для OfflineSession.spectrum, pixel_spectrum_cursor, compare_fft_backends, narrowband; флаг original_storage_read_divided_by_range и отсутствие утверждения о происхождении внутреннего кольца.
- mvk_compatible/core/narrowband_idr_candidate.py — подтверждённое исходное деление перед GetNarrowbandValue.
- mvk_compatible/core/tqgrapher_display_idr_candidate.py — отдельные правила видимой серии, Single XScale и строки CursorString.
- mvk_compatible/core/tqgrapher_cursor_candidate.py — ограничение исходной видимой серии и независимый опциональный itos index→pixel.
- mvk_compatible/desktop/main_window.py — переключение гипотез входного буфера, ограничение графика N/2.56 и его полос прокрутки, исходная последовательность CursorString; исходная огибающая в режиме float-кольца намеренно не поддерживается без отдельного восстановления.
- mvk_compatible/reference_compare.py и triplet_reference_compare.py — явный --input-domain, диагностические отчёты без исходного спектра и без ложной аттестации.
- Синтетические тесты test_storage_f_range_idr_candidate.py и test_tqgrapher_display_idr_candidate.py, расширенные Qt и CLI тесты. Ни одного производственного отсчёта или исходных коэффициентов FIR нет в GitHub.

## 4. Границы доказательств

**Неизвестно:** оригинальное FRange каждого датчика/архива; является ли Native BIN внутренним масштабированным кольцом Delphi; собственный x87/RTL численный эталон, реальные pixel-rect and itosM/C; одинаковые временные окна, фактический оригинальный CSV/TAB и пиксельное визуальное совпадение всех трёх вкладок. Никаких исправлений исходных приборных DSP — RMS/третьоктавы только из AUX4700.

Тесты выполняются только офлайн на синтетическом сигнале. Положительный pytest или равные результаты двух кандидатных путей не доказывают оригинальную эквивалентность MVKView. Состояние Windows EXE, Run ID и реальные числа PASS добавить **только после завершения GitHub Actions success**.

## 5. Следующий этап Stage111K

1. Получить приватный оригинальный эталон на одинаковом BIN/TSXML/канале/FFT N/окне/FRange/режиме; установить, к какому типу исходного хранилища он относится, затем сравнить через оба локальных стенда.
2. По _Unit115:007CA4C8 и настоящему оригинальному скриншоту восстановить точные размеры pixel rectangle и независимые itos/stoi, затем 007B2090 Delphi FormatFloat.
3. Подтвердить локализацию XName/YName и второй TQGRSeries, отработать исходные события масштабирования и оригинальные 4 режима Spectrum.
4. Pixel-to-pixel QA трёх вкладок, затем Archive; Live только после отдельного разрешения, один Native R6.1 collector, без прикладных команд прибору.

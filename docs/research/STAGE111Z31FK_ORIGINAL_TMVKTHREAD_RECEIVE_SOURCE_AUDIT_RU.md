SQLite индекс исходных методов: `TMVKThread.Execute = 00807A98`, `TMVKThread.Create = 008060B0`, `TMvkChannelStorage.AllocBufferChunk = 007D1B08`, `ProcessBufferChunk = 007D2398`. Указанные адреса также доступны в IDP; Pascal — частично декомпиляция дизассемблирования, поэтому не все имена локальных полей восстановлены.

## Что исправлено в Stage111Z31FK

**Кодовой commit `a05d3e9`:**
- `protocol.go`: исходный переменный размер ADC/TACH в рамках допустимого сетевого envelope, вместо фиксированных 1052/284. Даже корректный пакет с нулевым payload не создаёт фиктивные отсчёты.
- `source_original_ring.go`: размером управляет реальный header; пересечение границы исходного кольца разбивается, ADC pos += `word count`, TACH pos += `word count*4`.
- `live_bin_spool.go` и `live_preview.go`: обработка **ровно принятых** Floats, dynamic `n`, без zero-fill и повторного применения `FRange`; wrap проходит как в `AllocBufferChunk`.
- `exporter.go` и `tach_raw_export.go`: полный RAW и forensic SHA/BIN/экспорт подхватывают переменную длину, а исходные байты TACH сохраняются даже при NaN-like 4-byte-pattern (это не выдаётся за калиброванный TACH).
- `source_original_rx_variable_test.go`: фрагментирование TCP между заголовками, переменные ADC/TACH payload, реальный rollover U32, crossing ring, пустой пакет, побайтовое совпадение spool/кольца/preview при n=7.
- Qt-тест отклонения старого 262144-превью при запросе Tag0=20сек обновлён так, чтобы не требовать ложного отображения 1310720 данных.

**Следующий кодовой commit** — исходные тайм-ауты 1000/5000 мс также для пассивного Task2, не только при opt-in SetRate.

## Где пока НАШЕ поведение, а не оригинал 1:1

Это принципиально: **не объявлять оригинальный приём 100% готовым**. Клиент реализован в Go, а не исполняет Delphi-процесс; приложение передаёт данные в Qt через JSON/ZIP локальные IPC, чего в исходном MVKView нет. Только ряд отдельных правил восстановлен по первоисточникам.

ОСТАЁТСЯ: полное восстановление оригинального Stage0/1/2/3 + очереди и временных режимов команд Task2; согласование `MvkSampleRate=777` при создании, исходных SetRate и фактического потока; отдельное управление `FreezeUpdate` **на уровне настоящего накопления** (не только скрытие графика); исходная обработка неизвестных/редких типов пакетов; точная `FRange` и x87 1:1; настоящие WriteData/WriteValues; единые результаты с Windows MVKView на физическом МВК01. Текущий `source_original_storage` ring следует считать **source-backed compatible candidate**, не двоичной копией.

Аппаратная передача SetRate, IP/Flash и перезапуск прибора по умолчанию остаются выключенными; никаких изменений реального оборудования без отдельного разрешения. `original_delphi_compatibility_verified=false`.

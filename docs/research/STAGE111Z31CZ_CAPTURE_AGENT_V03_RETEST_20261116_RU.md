## Диагноз инструментальной ошибки v0.3

В `WindowsBackend.screenshot()` используется `PIL.ImageGrab.grab(window=int(hwnd))`. На физических Win32 меню класса `#32768` этот путь возвращает корректный по формату, но **полностью чёрный растр**. В v0.3 не было проверки однородности изображения; поэтому чёрные PNG ошибочно попадали в успешный архив. Основное окно `Tmvkform` захватывается нормально, но его отдельная window-screenshot не содержит меню `#32768`. Для полноценного меню нужен другой источник пикселей.

## Исправление Capture Agent v0.4

1. Пиксельная проверка `#32768`: однородный растр не признаётся содержимым меню.
2. ТОЛЬКО для подтверждённого меню оригинальной MVKView пробовать `ImageGrab.grab(bbox=...)` по **физическому** DWM `DWMWA_EXTENDED_FRAME_BOUNDS`, с проверкой процесса foreground, PID каждого из трёх внутренних hit-test пикселей и запретом на широкие области. Не захватывать весь экран или другие приложения. При неудачной проверке — отказ и `popup_capture_failures`, без чёрного PNG.
3. При событии `OBJECT_SHOW` класса `TTabSheet` принудительно сохранять `page_settled` через ~0.9 с, даже если периодический опрос уже прочитал то же дерево без PNG.
4. Дополнить синтетические тесты на fallback и отказ при перекрытии окна другой программой; не делать выводов о Win32 runtime без нового локального испытания.

**Граница доказательств:** v0.4 протестирован офлайн на моках; реальный физический DPI, Win32 `WindowFromPoint` и способ захвата Delphi popup остаются **не проверены** до нового capture на том же ПК. Не включать Frida для проверки только всплывающих меню.

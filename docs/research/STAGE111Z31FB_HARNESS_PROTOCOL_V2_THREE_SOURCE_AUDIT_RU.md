## 2. Главная ошибка — неверная принадлежность диапазона `0080816B`

В оригинальном `TMVKThread.Execute` (`_Unit125.pas`):

- `00808022/27`: тип `0x00000001` направляется к `00808060`, где `00808068–00808074` только читает и отбрасывает `UInt32`, **не передаёт их в хранилище**.
- `00808029/34`: `0xFF8001AC` и `0xFF800ADC` направляются к **общей** ветке `008080EB`, а затем `0080816B` при допустимой длине.
- `0080818A` читает канал в `[EBP-24]`, индекс в байте **20** от начала кадра; `00808196` читает source rate в байте **24**. Пять слов после общего восьмибайтного заголовка: три пропускаемых, канал, частота. Переменная `EBX` здесь уже равна `(frame.length-8)/4`, поэтому `0080819E` вычисляет `payload_bytes = ((length-8)/4-5)*4 = length-28`.
- `008081AA` проверяет `channel < 10`; каналы **0–7** — ADC, **8–9** — TACH. Ветка `00808339` создаёт исключение `errInvalidPacket: Ch=...` **для `channel >= 10`**. Это не ветка TACH.
- `00808238` сравнивает rate кадра с `TMVKThread.MvkSampleRate` по `+0x400D0`, `00808244` проверяет `FreezeUpdate` по `+0x400CD`. `0080828C` — `ProcessBufferChunk`. Для тахометрических каналов при `00808251` есть дополнительная обработка через `00806030`.
- `00808294–008082A3`: первое принятое ADC0 при `WriteDataStage == 0` переводит **`WriteDataStage` (смещение `+0x40`) в 1**. Это **начало записи ADC-файлов**, не «установка подключено» или переход общей TCP-стадии.

**Последствия для `MVK_PROTOCOL_TESTS_SPEC.md`:** его `parse_data_stream(raw)` отвергает реальные ADC/TACH кадры, потому что ожидает `ptype==1`; тест считает `words = length//4` вместо `(length-8)//4` и завышает полезную нагрузку на **8 байт**; а `channel>=10` ошибочно подписан как TACH. Не запускать эти предлагаемые проверки в качестве эталона.

## 3. PARAM: 14 StatusCells — не 14 дескрипторов

- Входящий `0xFF800C0D` на `0080839E–00808443`: 5 слов служебного заголовка после `[type][len]`, последнее — **число блоков**. Для каждого блока `00808459` читает дескриптор `(wordCount<<16)|registerAddress`, проверки `00808475–008084F0`: `wordCount>0`, чётный, `address+wordCount<=0x4000`. Это числа **16-битных регистров** в блоке.
- `00808523` использует базу формы `+0x1124` и адресацию `regAddr*2` байт; оригинальный поток считывает поступившие байты через Indy в регистровый образ.
- `0080857C–0080859A`: **14 вызовов** `00805D08` для индексов `0..13` **на каждый полученный блок**. Функция `00805D08` обращается к адресу из таблицы `008D3068` и обновляет соответствующий `StatusCells[index]`, если блок покрывает этот адрес и значение изменилось. Это **не** доказательство, что в кадре 14 дескрипторов или «8 ADC + 2 TACH + 4 служебных».
- Достоверные исходные адреса 14 StatusCells (см. существующий `original_mode2_status_cells.py`): `0x1006,0x1038,0x1030,0x1032,0x2120,0x2320,0x2520,0x2720,0x2920,0x2B20,0x2D20,0x2F20,0x3004,0x3104`.
- `008085A5` (`regAddr==0x3100`) в **Task=2** вызывает `008066F0`, **если `ValuesFile` по `+0x40088` не равен нулю**. `008066F0` пишет строку `VALUES` CSV с временем и выбранными измеренными ячейками. Затем цикл `008085C2–008085DD` вызывает `00806030` для индексов `0` и `1` (сравнение/изменение тахометрических состояний). **`00806030` не отправляет команды в TCP**.
- `00808617`: **здесь** первоначальный PARAM переводит `TMVKThread.Stage 0 -> 1`, после чего `00808623–0080868E` для десяти каналов устанавливает gain и units из исходной таблицы. Переход **не ограничен только адресом `0x3100`**.
- `0080872D`: отдельный контроль `StatusCells[0] > 0` для `Task=2`, может привести к Stage3/system error. Совместимое приложение отделяет ненаблюдавшийся sentinel от реального регистра.

## 4. Очередь и исходящие слова — перепроверка

Из предыдущего Stage111Z31FA и текущего `_Unit125.pas`:

1. `00809330`: внутренний элемент `TList` — **12 байт (`Cmd: int32`, `Addr: UInt32`, `Data: UInt32`)**, в памяти, не wire-кадр.
2. `00809364` + `00809400`: SetRate ставит `Cmd=1, Addr=0x0E, Data=MvkSampleRate` при изменении значения.
3. `0080937C`: **8** последовательных `WriteUInt32`, с `magic=0xFF800C0D`, длиной, четырьмя нулями, `1`, `(2<<16)|Addr` для исходной очереди.
4. В Task=2 `00807F52` передаёт девятый `Data`-DWORD. Вместе это **36 байт для SetRate**, но функция `0080937C` сама по себе отправляет только 8 слов.
5. `00807A40` (Task конфигурации) и последовательность `00807E0E–00807E45` — другие варианты исходящего обмена; **не включать их в стандартный маршрут Measure/Task=2**, пока не сопоставлены Task mappings, интерфейсные обработчики и фактическая семантика.
6. Значения `0xF0001`, `0x10F0F`, `0x8` присутствуют как аргументы отдельных вызовов Write в ветке конфигурации; назначение («запуск потока» или «конец настройки») **не доказано**.

## 5. Сопоставление с действительным GitHub, а не локальной копией

Harness анализировал `C:\Users\...\Downloads\MVK_Reader_Web` (папку **без** `.git`), поэтому заключение «в проекте отсутствует MVK TCP/10230» нельзя переносить на действительную ветку `shonentez-afk/MVK-Reader-Web`.

В `research/stage111-mvkview-desktop-20261029` подтверждены:

- `mvk_compatible/core/original_mode2_received_frames.py` — ограниченный Source read-only фреймер; различает `TYPE_IDENTITY`, `TYPE_ACK`, `TYPE_DENIED`, `TYPE_ADCDATA`, `TYPE_TACHDATA`, `TYPE_REGISTERS`; диапазон 0..9; rate/Freeze; Stage/StatusCells.
- `mvk_compatible/core/original_mode2_status_cells.py` — 14 исходных StatusCells с точными адресами и проверкой достоверности.
- `mvk_compatible/core/original_mode2_command_queue.py`, `original_mode2_wire_word_candidate.py`, `original_mode2_task2_exchange.py` — очереди, 8+1 UInt32 Write-план, стадии, retry и dry-run. Это **не** способ незаметно включить передачу.
- `mvk_compatible/core/original_runtime_tabs.py` — пять исходных вкладок видны сразу после выбора Mode2, ещё до TCP. Состояние интерфейса следует факту нажатия «Измерение», а не доказательству соединения.
- Отдельный native Go R6.1 существует, с режимом RX-only и контролируемым opt-in SetRate; фактическая оригинальная аппаратная эквивалентность пока не принята.

**Корректная стратегия:** не перезаписывать текущий decoder предложенной ошибочной реализацией Harness. Добавить регрессию на новые ложные трактовки и продолжить только недостающие исходные механизмы и численный/GUI паритет. Изменения в Qt без подтверждённого функционального несоответствия по текущему отчёту создавали бы риск регрессии.

## 7. Открытая работа — единым крупным пакетом ядро + GUI

Следующая приёмка должна быть **не новой бесконечной декомпиляцией тех же функций**, а сравнением исходного поведения с исполнением MVKView Compatible:

- StatusCells, поля статуса в Qt и состояние `Stage0/1/3` при поступлении VALID PARAM и без него, включая статус `errOperationDenied`.
- ADC/TACH: разорванные TCP-кадры, channel 0..9, mismatched rate, FreezeUpdate, WriteDataStage 2→0→1→2, маски сохранения; параметры gain/units через `00806964`/`008069AC`, включая отсутствие верифицированной калибровки.
- Точный `VALUES` CSV (`008066F0`, триггер 0x3100), локальная запись/архив и восстановление, без выдачи AUX4700 за source VALUES.
- Read-only расшифровка интерфейсных веток ConfigIP/ConfigCalib/ConfigCh/Task 3–5, исходных окон и кнопок, строго отличая Task от состояния экрана. Поведение на настоящем приборе — отдельная неизученная граница, а не готовый паритет.
- На каждые исправления Core обновлять Qt и тесты вместе, но **без придумывания новой команды** и без переключения аппаратного TX по умолчанию.

**Статус полного восстановления:** **НЕ ПОДТВЕРЖДЕНО**. Новый Harness-документ содержит дополнительные адреса, но не демонстрирует полный рабочий wire/runtime/численный/визуальный паритет и не содержит выполненных тестов или изменений в коде.

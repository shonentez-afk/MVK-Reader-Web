## Установленный исходный механизм

- `GetValueText` при отсутствии входных данных возвращает специальный заполнитель `####`; при наличии source-клетки типа **10** и указателя `AdvancedCell` считывает исходный UInt32 из регистра с адресом в 16-битных словах. Если `Bits>0`, извлекает `(raw >> BitStart) & ((1<<Bits)-1)`, иначе использует все 32 бита; никакой Float32-конверсии.
- `GetTitleByID` в **обычном** списке выбирает **первый** точный ID, а при отсутствии отдаёт исходный формат `(0xXXXXXXXX)`, где X — восьмизначная uppercase шестнадцатеричная цифра.
- В режиме `UseCompositeTitle` выбираются **все** записи, у которых `(option_id & value)==option_id`, в исходном порядке списка, через разделитель **«, »** (запятая + пробел). При отсутствии — `---`. Повторяющиеся ID не удаляются. `AlarmAlert` использует именно составной режим: ID 1/2/4/8.
- Исходный `ResultStatus` каждого АЦП читается из `0x2000+(adc-1)*0x200+0x120`; один DWORD разбирается через **три** зарегистрированных поля: `ResultOverload` — один бит с позиции 0; `ResultBuffers` — три бита с позиции 4; `ResultSensorState` — два бита с позиции 10. Числовые списки результата взяты из оригинального IDP, а не назначены вручную по видимым значениям.
- Статус `0x00000000` означает **нулевой исходный битовый шаблон**, но сам по себе не доказывает физическую исправность датчика, отсутствие проблем с кабелем или корректность калибровки. Не использовать надпись `DSP: OK` только по нулю.
- Для `Task0` корректный 28-байтовый PARAM с `count=0` является no-op, не подтверждает получение конфигурации и не должен прерывать соединение. Только реально полученные выбранные поля привязываются к RAW/SHA и отображаются. Тип 10 показывает **исходный числовой ID + ключ**, пока перевод конкретного Delphi `TLanguage` не подтверждён.

## Что интегрировано вместе с ядром

- `original_config_semantics.py` — источник `AdvancedCell` и точные форматы title; все исходные известные семейства enum `alarm_band/state/alert`, `tacho_function`, `result_overload/buffers/sensor_state` присоединены к уже восстановленным Config/HF/Octave. Алгоритм композитного выбора общий для всех потребителей.
- `original_result_status_source.py` — из наблюдённого DWORD строит проверяемые ID трёх полей, исходный адрес АЦП, исходные ключи и метки `runtime_title_verified=false`. Без запросов к прибору и подмены переводов.
- `original_pagestatus_source.py` — существующая строка текущего АЦП теперь содержит исходный DWORD и source-ключ SensorState, не создавая дополнительных исследовательских вкладок. Нет данных — нет расшифровки.
- `native_r6_live_status.py` — удалён ложный ярлык `DSP: OK`, вместо него показывается только наблюдённый raw Status.
- `original_task0_config_live.py` + `original_config_readonly_ui.py` — принят пустой PARAM и сделан оригинально ориентированный просмотр числовых advanced-ID с указанием непринятой локализации. Конфигурационные записи, Flash и Reboot по-прежнему запрещены.

## Границы доказательства

Числовые ID и оригинальные ветви ассемблерного GetValueText доказаны совместным источником/офлайн тестами; но русский/английский перевод через `TLanguage.localize`, состав фактических приборных показаний и точные Delphi CSV-заголовки ещё не подтверждены на физическом MVK01. Ни один enum ID не превращать автоматически в диагноз `исправен/авария` без исходного перевода/приборной семантики.

Следующая аппаратная приёмка должна **на одних и тех же ADC/TACH/PARAM кадрах** сверить оригинальный Delphi и наше окно PageStatus, фактические 0x120 и 0x3100, оригинальные строки Table/WriteValues и Stop. Даты/время, FRange, GetSignal/GetSpectrum и полное сохранение файлов отдельно остаются OPEN. `original_delphi_compatibility_verified=false`.

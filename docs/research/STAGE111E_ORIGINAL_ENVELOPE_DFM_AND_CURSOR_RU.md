## 2. Математика из оригинального IDR

- GetAdjustedEnvelopeLength / 007D1158: код→тип, sampleRate div baseRate, допустимые ratio, точные величины предварительной истории и обработка ошибок.
- 007D1C48: выбор последовательности предварительных фильтров-дециматоров.
- 007D1D50: выходная длина (Length-Taps)//Decim, исходная индексная формула входа (i+1)*Decim-1+Taps-j, float32 аккумулятор.
- 007D1E70: пара квадратурных FIR на смежных коэффициентах и sqrt(I²+Q²).
- GetSignal / 007D0C30: NoDC перед огибающей, затем FRange и обратный выходной буфер.

Функция реализована как самостоятельный **исследовательский кандидат**, не как побитово принятая копия x87-кода.

## 3. Реальный исходный код

- mvk_compatible/core/envelope_idr_candidate.py: EnvelopeProfile, SHA-256 локального original IDP, envelope_plan, FIR-децимация, квадратурная огибающая, маркировка источника.
- mvk_compatible/core/offline_export.py: read-only OfflineSession.envelope() — требует достаточного количества *реальных* сохранённых отсчётов BIN для истории. Отказ вместо скрытого добавления нулей.
- mvk_compatible/desktop/main_window.py: отдельная локальная загрузка IDP и выбор одного из 31 кодов в «Временном сигнале». Без профиля режим заблокирован. Время и курсор огибающей не выдаются за оригинальные; ось подписана как относительная позиция буфера.
- Вкладка «Спектр» перепланирована по приватному mvkform.dfm: левая pnSpecTools шириной 177 px, 24px sbSpecHScroll и sbSpecVScroll с работающим изменением диапазона. Основные органы расположены в оригинальном порядке. Неизвестные оригинальные Copy/Save и спектральная огибающая пока выключены, а не имитированы.
- mvk_compatible/core/cursor_format_candidate.py: кандидат динамической десятичной точности 007B2090, NAN, 4 значащие цифры, разделитель и удаление конечных нулей. Оригинальный TFormatSettings/x87 FormatFloat и Infinity ещё не идентичны.

## 4. Локальные и автоматические проверки

- В приватном IDP проверены SHA, смещения, 10×512 коэффициентов. На **синтетическом сигнале** 4096 входных отсчётов -> 999 значений аналитической огибающей для кода 1 / 97 taps / decimation 4. Результат конечен.
- Тесты test_envelope_idr_candidate.py и test_cursor_format_candidate.py не используют настоящий IDP и содержат только **синтетические** массивы.
- test_desktop_qt.py проверяет реальные геометрические размеры инструментов, работоспособность обеих полос прокрутки, переключение профиля и отсутствие ложных функций.
- GitHub Actions выполняет core на Linux и Windows, Qt на Windows; PREVIEW EXE строится только после успешной Qt Job.

**Приёмочные результаты GitHub вписывать только после завершения workflow с exit code 0.**

## 5. Открытые различия

Побитовая x87 эквивалентность FIR и FFT; оригинальная физическая временная ось огибающей; оригинальная огибающая **вкладки «Спектр»**; точный FRange хранилища; исходная модель CursorString и реализация Copy/Save; все пункты полного визуального паритета. Стандартные приборные RMS, третьоктавы и ПИК-ПИК по-прежнему читаются **только из AUX4700 / проверенных VALUES**, не пересчитываются кандидатом.

Коэффициенты не распространять без оценки лицензии на оригинальные числовые таблицы. Программа может использовать локально собственный оригинальный файл пользователя.

## 6. Stage111F — продолжение

1. Сверить экспериментальную огибающую на одинаковом BIN, FSampleRate, EnvelopeCode, окне и FRange с настоящим выводом исходной MVKView.
2. Восстановить исходную спектральную цепь огибающей, а не делать обычный FFT без проверки.
3. Принять оригинальный TQGrapher cursor/geometric transform и FormatFloat по реальному экспортированному эталону.
4. Проверить визуальное положение органов всех вкладок и Archive; Live только после отдельного разрешения и через единый Native R6.1 Collector.
5. Перед новым чатом читать Stage111 ADR, Original DSP ADR, этот файл и docs/research/STAGE111_IMPLEMENTATION_AND_HANDOFF_RU.md. Stable main и v0.3.40 **не менять**.

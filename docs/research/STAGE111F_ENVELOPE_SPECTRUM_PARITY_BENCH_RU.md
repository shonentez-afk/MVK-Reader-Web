# Stage 111F — оригинальная цепочка «огибающая → локальный FFT», независимый стенд сравнения

**Дата:** 29 октября 2026. **Рабочая ветка:** `research/stage111-mvkview-desktop-20261029`. **Статус:** реализован и автономно исследуется кандидат, но численный и визуальный паритет оригинальной MVKView ещё НЕ принят. Не трогать `main` и стабильную v0.3.40. Не подключаться к прибору без разрешения.

## 1. Новые выводы по оригинальной _Unit115.pas / Delphi IDR

Из пользовательского приватного `Projects.7z` проверен обработчик `TMvkChannelStorage.GetSpectrum:007D13D4–007D17E7`:

| Оригинальные адреса | Подтверждённое поведение |
|---|---|
| `007D14AA–007D14B3` | Читает исходный кольцевой float32 BIN и **ровно один раз** удаляет среднее через `007D2344` |
| `007D14B8–007D14E9` | Если задан `EnvelopeCode`, вызывает `007D1C48` (FIR-децимация) и `007D1E70` (квадратурная амплитуда); **повторного вызова `007D2344` после этого нет** |
| `007D14EE–007D1515` | Частота выходного сигнала = таблица частот кода / FIR_DECIM; если огибающей нет, штатная FSampleRate |
| `007D1518–007D1546` | Получает длину уже преобразованного буфера, вызывает локальный FFT `007D1FE8` |
| `007D1558–007D15BA` | Обнуляет `max(2,Round(N/(2*output_fs)))` нижних спектральных бинов |
| `007D15DD–007D1649` | Режим 0: `10*(fn(P)-2*fn(N/2))`, при нуле `-180`; основание `fn` ещё требует паритетной сверки |
| `007D1652–007D16A2` | Режим 1: `sqrt(P/2) * FRange/(N/2)` |
| `007D16A7–007D172C` | Режим 2: дополнительный вызов `007D2164`, затем линейная амплитуда |
| `007D1731–007D17E7` | Режим 3: **два** вызова `007D2164`, затем линейная амплитуда |
| `007D2164–007D2194` | Обнуление DC и умножение мощности `P[k]` на `(159.154943091895/f[k])²`; коэффициент 1000/(2π) приводит к мм/с и мкм при последовательной интеграции |

**Коррекция предыдущего ядра:** прежде `idr_power_spectrum()` всегда удалял среднее, даже если перед ним уже прошла квадратурная огибающая. В Stage111F есть явный `remove_dc=False`. Этот параметр используется только в цепочке огибающей; штатный локальный спектр BIN сохраняет прежнее удаление DC.

## 2. Строгая длина входной истории

`GetAdjustedEnvelopeLength` оригинальной MVKView возвращает запас входных отсчётов **от переданного SignalLength**. Это не тождественно вычислению количества сырых отсчётов, необходимого для получения *ровно N* выходных после всех FIR-дециматоров.

Для исследовательской автономной проверки реализована **обратная формула** FIR:
```text
L_required = N_fft
для каждого FIR-этапа в обратном порядке:
    L_required = L_required * decimation + taps
```
Пример для code 20, fs=65536, N=1024: одна FIR-ступень (taps=51, decimation=2) требует **2099 реальных BIN-отсчётов** и возвращает ровно 1024 отсчёта. Для code 1, N=1024 требуется **4193**. Обрезание/дополнение нулями при отсутствии истории запрещено. Это корректное арифметическое обращение реализованных FIR, но **исходный алгоритм выбора временной позиции MVKView ещё не проверен**.

## 3. Код и интерфейс

- `mvk_compatible/core/fft_idr_candidate.py`: опциональный `remove_dc=False` без изменения исходных вызовов для обычного FFT.
- `mvk_compatible/core/envelope_spectrum_idr_candidate.py`: `required_original_history`, `envelope_spectrum_idr_candidate`; 4 режима, сохранение источника, полная частотная сетка, FRange, single-centering, float32-кандидат IDR или независимый NumPy.
- `mvk_compatible/core/offline_export.py`: `OfflineSession.spectrum_envelope(...)` берёт только реальные завершённые калиброванные BIN и приватный `EnvelopeProfile`, возвращает полный N/2 спектр и границы исследовательского исходного окна.
- `mvk_compatible/desktop/main_window.py`: в DFM-панели «Спектр» есть опциональный исследовательский переключатель огибающей. Он **недоступен до явной локальной SHA-проверки пользовательского mvkview.idp**. Если выбранное FFT N длиннее доступной FIR-истории, приложение выбирает максимально доступное штатное N без изменения исходных отсчётов. Оригинальный режим/коды DFM пока не приняты.
- `mvk_compatible/reference_compare.py`: автономный офлайн-стенд сравнения сохранённого оригинального двухколоночного CSV с кандидатом; исходный BIN, IDP, CSV **не уходят в GitHub**.

Старый `server.py` и исходный DSP-AUX4700 не менялись. Модуль FFT является `APP_DERIVED_ENVELOPE_SPECTRUM_IDR_CANDIDATE`, **не** приборным RMS/третьоктавным спектром.

## 4. Как выполнить приватное сравнение с оригинальной MVKView

Сначала в оригинальной MVKView получить спектр той же записи, того же АЦП, режима, кода огибающей, FFT N, `FRange`, временного окна и частоты дискретизации. Сохранить/привести его **локально** в CSV формата:

```csv
frequency_hz;amplitude
0,0;-180,0
32,0;-180,0
64,0;1,2345
```

Это **проверочный CSV-контракт**, а не утверждение, что оригинальная MVKView уже экспортирует точно такие заголовки/разделители.

Запуск на ПК (пример, без настоящих данных):

```powershell
.\.venv\Scripts\python.exe -m mvk_compatible.reference_compare --archive "C:\private\session.zip" --idp "C:\private\mvkview.idp" --reference "C:\private\mvkview-spectrum.csv" --channel 4 --code 20 --n-fft 1024 --mode 1 --end-s 0.0625 --f-range 1 --delimiter ";" --decimal "," --report-json "C:\private\stage111f_diff.json"
```

Стенд **строго запрещает интерполяцию и сопоставление с другой сеткой частот**. Отчёт содержит ошибки амплитуды, число бинов вне допусков, частотный сдвиг максимума, SHA-256 только CSV и признак того, что **оригинальная Delphi-паритетность не сертифицирована**. Отсутствие оригинального эталона даёт только синтетическую регрессию, а не claim «полная копия».

Если требуется явно зафиксировать подтверждение оператора, дополнительный небольшой JSON с `source_app: "MVKView"`, `confirmed_same_signal_and_window: true`, `channel`, `envelope_code`, `n_fft`, `mode`, `output_sample_rate_hz`, `original_csv_sha256` можно подать через `--reference-metadata`. Такое подтверждение — **декларация оператора, а не криптографическая идентификация исходной программы**.

## 5. Проверки

- Локально на **синтетическом** сигнале прочитана реальная приватная IDP с SHA-256; 10×512 FIR проверены по данным; code20 из 2099 входных отсчётов → 1024 значения и 512 конечных FFT-бинов. Эти измерительные значения и массивы коэффициентов не отправлялись в GitHub.
- GitHub CI исполняет тесты `test_envelope_spectrum_idr_candidate.py`, `test_reference_compare.py` и все существующие тесты core + Windows Qt, включая проверку реальной кнопки переключения режима.
- **Точный исходный Delphi эталон отсутствует в проекте**: численные тесты со сравнением оригинального GUI пока нельзя обозначать PASS.
- После завершения Stage111F GitHub Actions записать в начало этого отчёта SHA, run, окончательные Linux/Windows/Qt counts и EXE artifact. Не объявлять PASS при code 1.

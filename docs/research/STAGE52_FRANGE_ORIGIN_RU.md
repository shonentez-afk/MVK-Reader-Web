# Stage 52 — установлен источник FRange в MVKView

Дата 2026-10-28. Экспорт IDR `_Unit125.pas`. Результат: 10/10 адресных опор в исходном листинге подтверждены автономным скриптом.

- `0x00806964`: процедура для канала N берёт `TMvkCellList` из массива формы по смещению `0x1004+N*4`.
- `0x00806978`: адрес параметра `0x0E`; `0x0080697D`: `TMvkCellList.GetFloatByAddr`.
- Для тахоканалов N>=8 использует 1.0 (`0x00806988`), при нулевом значении тоже заменяет на 1.0 (`0x0080699E`).
- `0x0080863D`: вызов для каждого из 10 каналов в `TMVKThread.Execute`; `0x00808653`: `fstp dword ptr [eax+4]` присваивает результат `TMvkChannelStorage.FRange`.
- `0x008069C8`: параметр `0x10` и `0x0080867F`: присваивание `TMvkChannelStorage.FUnits`.

**Связь с FC03:** `docs/PROTOCOL_CALIBRATION_RU.md` уже подтверждает коэффициент `K_Modbus` по адресу `0x0100+N*0x100+0x0E` (`float32 CDAB`). Таким образом, статически найденное `FRange` считывается из **того же адреса параметра конфигурации**. Не следует утверждать, что оригинальная программа использует Modbus FC03 для получения `FRange`: у неё собственный TCP/10230 конфигурационный тракт.

**Общий результат Stage 49–52:** `TmpStream.FMemory` и кольцевой буфер делят память, `ProcessBufferChunk` применяет FRange в этой памяти до записи BIN. Спектральная ветвь имеет операции деления и умножения на FRange по соответствующим режимам.

**Не доказано:** идентичность `InternalChannelGain` в TSXML внутреннему FRange на всех записях; live-выполнение на приборе не проверялось.

Полный локальный пакет: `MVKVIEW_STAGE52_FRANGE_SOURCE_20261028.zip`. Stable v0.3.40 без изменений.

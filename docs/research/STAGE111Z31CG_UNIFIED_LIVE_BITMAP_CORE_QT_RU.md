# STAGE111Z31CG — единый TCo2Draw bitmap в действующих PageAdc/PageSpectrum

**13.11.2026. Статус:** ПРИНЯТ функциональный блок ядро+интерфейс+CI, но до полной MVKView 1.0.47 с оригинальным GDI/прибором далеко.

## Что подтвердилось в закрытом оригинале

В операторском локальном `Projects.7z/_Unit115.pas`, который оставлен ВНЕ GitHub, декомпилированный `TQGrapher.Draw` 007CAC68..007CB4AA рисует белый 32-bit TCo2Draw bitmap, горизонтальные и вертикальные серые линии по исходным `AutoH/VSpacing` и `Single`, TCanvas.TextOut, источниковую per-pixel min/max серию и чёрную рамку; затем выводит bitmap в PaintBox. Обработчик курсора `UpdateCursor` ведёт отдельный зелёный pmXor поверх картинки. Ранее Stage CF восстановил только software grid, Qt кривую/рамку рисовал отдельными слоями. Stage CG соединяет **grid + data strokes + frame** в одно программное изображение для обычных страниц. Полный original TextOut пока **не** перенесён в bitmap: действуют прежние source-derived Qt tick labels, на Windows уже существует отдельный research GDI canvas candidate.

## Реальные изменения

- `core/original_live_plot_composite.py`: новый `prepare_live_source_bitmap` принимает только конечные полные Float32 1D TQGRSeries, текущее окно X/Y, реальные x_start/x_scale/y_scale, точный SHA256 и происхождение текущего проверенного источника. Использует строго ранее аудированные `source_live_software_grid_bitmap` и `source_tqgr_series_columns`, включая `ScrWidth<0` для исходной обратной временной оси PageAdc. Накладывает все min/max-штрихи чёрного цвета, затем четыре исходные стороны рамки, не меняя численные samples/FFT. 1px внутренний кандидат края — практическое ограничение ViewBox/software blend, **не** original Win32 PixelRect parity.
- `LiveSourceBitmapTask`: пошаговое беззапросное на прибор построение в собственном буфере максимум 256 segments/step (обычный Qt 128/step); строго проверенный одинаковый SHA RGBA при 7, 31, 128, 256 strokes/step. Неполный bitmap никогда не публикуется; отмена сбрасывает состояние, не затрагивая источник.
- `desktop/source_live_composite.py`: новый `SourceLiveCompositeOverlay` у обоих реальных Qt ViewBox. После 65мс смыкания pan/zoom диапазона строит новый source snapshot порциями на последовательных Qt timer ticks, не отдаёт ранее рассчитанный bitmap новому масштабу. QImage разворачивает строки для Qt Y-up и столбцы для source reverse-X ADC, z=600000 выше обычной Qt-кривой и вспомогательной рамки, но ниже z=1e6 курсора. Отдельная старая Qt кривая не удалена: это необходимо для исходного диапазона, корректного курсора и контроля полной выборки. Неоттестованные окна явно отклоняются и отображаются прежним Qt путём.
- `desktop/source_plot_geometry.py`: публичная привязка/снятие `bind_source_tqgr_series` / `clear_source_tqgr_series`, сохранение overlays при `PlotItem.clear()`, явное отключение для исследовательского reference bitmap. `source_live_grid.py` при принятом data+grid bitmap не выполняет второй дорогой автоматический программный grid-render; независимый проверяемый CF diagnostic renderer остаётся.
- `desktop/main_window.py`: штатный спектр привязывается к **полной реально рассчитанной Core амплитуде** и ограничивается source `grapher_series_bins`, не fake last sample; PageAdc получает только реальную подтверждённую исходную обратную GetSignal (при bounded до 524288 отсчётов) или full post-FIR GetSignal Float32 с проверенными SHA/OutputSampleRate; для нераспознанного/Live/no-original-axes fallback. В 8+10 местах очистки PageAdc/PageSpectrum сначала сбрасывается старая привязка, чтобы SHA от другого BIN или другого FFT/FIR не оставался визуально. После первого нового CI выявлен точный регрессионный тест `test_qt_stage111o_no_unverified_envelope_mouse_cursor`: его старое правило требует ленивого mouse-кэша. Исправлено `33e96a70`: bitmap пользуется временными проверенными буферами, поле `_wave_hover_window` остаётся `None` до MouseMove.
- `tests/test_stage111z31cg_core_composite.py` и `tests/test_stage111z31cg_qt_live_composite.py`: слайсы против единого bitmap побайтно, обратное X, min/max и рамка, false native parity labels, невалидные input digest/ranges/scale, действующие PageAdc + PageSpectrum на одном synthetic ZIP, дата и source array SHA, pan/rebuild и cursor/XOR Qt. Новый Qt E2E добавлен в принятый обязательный workflow Windows DPI150.

## Что ещё остаётся и следующий большой пакет

- Нет исходной TCanvas/GDI TextOut растризации на **том же полном исходном PaintBox bitmap**; Tahoma/Font/PPI/строки/decimal/edge clip подтверждены как source-derived кандидаты, но не live original native 1:1.
- Отсутствует доказательство исходного Run оригинальной Win32 MVKView на том же BIN, одинаковой видимой временной позиции, NFFT/EnvelopeCode/FRange и битовых Float32/конечных курсоров; старые x32dbg дампы приняты только для конкретных окон.
- Не все ручные события и взаимодействия всех **7 страниц и 3 форм** покрыты, приборные команды вне read-only программы остаются выключены до отдельного безопасного эксперимента.
- Следующий крупный путь: получить оригинальную геометрию/шрифты Win32 GDI и полный TextOut/clipping bitmap вместе с текущим Core, затем расширить QA операций семи страниц и трёх форм без разрыва между GUI и ядром. Измерять perf в реальном окне отдельно, не жертвовать исходной математикой ради скорости.

Приватные исходные _Unit115/_Unit128, DFM, IDP, оригинальные BIN/Power/Y и исходный EXE никогда не включались в публичный commit. Техническое восстановление основано на абстрактных исходно-производных моделях.

# Stage111Z.18–Z.20 — исправления UI/UX и возврат к основной разработке

Дата: 02.11.2026. Ветка: research/stage111-mvkview-desktop-20261029. Основное приложение — автономная Windows MVKView Compatible Qt/PySide6, не Web.

## Что исправлено после аудита Stage111Z.17

**P0 UX-001 — Спектр:** девять основных видимых элементов в исходном порядке: выбор фильтра, режим, Гц/линию, горизонтальная и вертикальная шкалы, короткий курсор, СКЗ/пик, Копировать, Сохранить CSV. Исходная ширина панели 177 пикселей возвращена. Все прежние FFT/IDR/FRange/Canvas/узкополосные/экспортные исследовательские controls сохранены в скрытом справа QDockWidget, вызываемом кнопкой Исследование или Ctrl+D. Никакие расчётные функции не удалены.

**P0 UX-002 — калибровка:** для прямых BIN/TSXML физические единицы не аттестованы. Основные подписи курса и итога используют условные единицы; при Copy требуется подтверждение и добавляется явная строка НЕ КАЛИБРОВАНО, а CSV сохраняется с отдельным заголовком RESEARCH_UNCALIBRATED_HEADER. CSV двух категорий не смешиваются. Старый ZIP-R6.1 Copy остаётся трёхколоночным, численный original runtime golden Stage111Z.13 не менялся.

**P1 UX-003 — Задачи:** вместо таблицы под названием Задачи — офлайн стартовый экран: Открыть измерение, перейти к Временному сигналу, Спектру, Показателям. Исходные DSP-таблицы, третьоктавы, диагностика доступны через вложенные вкладки. Без открытого файла стартовая страница доступна, графики отключены. Connect/IP/Calib устройства не выдаются за рабочие функции.

**P1 UX-004/005 — кнопки и шкалы:** режимы Логарифмич. и Линейный ВУ/ВС/ВП названы как в оригинале, разрешение вычисляется как Fs/N с исходной подписью 1/4 Гц/лин, исходные FFT меню и ограничение истории сохранены. Начальный диапазон X до 25600 Гц при соответствующем Fs, логарифмический источник Y до 150 дБ. Это visual-only defaults, не изменение значений FFT.

**P1 UX-006 — цвет и тип курсора:** новый графический класс desktop/xor_cursor_overlay.py. Он использует Qt QPainter RasterOp_SourceXorDestination для исходного GDI clGreen XOR поверх уже нарисованной чёрной кривой. По исходным данным white XOR (0,128,0) -> (255,127,255), black -> (0,128,0). Курсор использует прежний source-derived selected BIN, численная подпись и FFT не пересчитываются. Это Qt графический кандидат, а не доказанный GDI pixel-parity без одинаковых screenshot.

**P1 UX-007/009 — сигнал и показания:** на вкладке Временной сигнал возвращены четыре главных элемента управления слева в 177px панели, короткие координаты курсора/СКЗ. Выбор окна, порядок буфера, IDP-envelope, подробности курсора в отдельном waveResearchDock. На спектре отдельные короткие cursor/summary captions, исходные огромные debug labels доступны через Inspector. Источник калибровки явно указан.

**P2 UX-015/018 — действия и язык:** в пользовательском режиме нет длинных IDR/FRange/Delphi адресов. Экспорт помечен как исследовательский CSV, не оригинальный Vendor файл.

## Контроль изменений

Новые и обновлённые синтетические Qt тесты проверяют девять controls, оригинальные размеры панелей, пять групп настроек, независимость FFT N модели, Copy/Save и non-calibrated warning, стартовую Задачи, четыре кнопки временного сигнала, inspector переключение, QImage bitwise XOR и cursor mapping. В core добавлены тесты отдельных заголовков CSV. Исходный DSP/FFT и ранее принятые операторские original goldens остались без изменений.

Source SHA для графического XOR и тестов: b6a2f7018af36ca13b69dbd6437ddb9bcfe56c50.
Первый workflow на этом SHA: https://github.com/shonentez-afk/MVK-Reader-Web/actions/runs/41376521808
Linux Core SUCCESS на первой проверке; Windows Qt и Windows EXE требуют отдельного фактического завершения, пока не проверены и не заявляются успешными.

## Что не закрыто до полной визуальной аттестации

- Реальное сравнение Qt vs original MVKView на ОДНОМ BIN, том же ADC/интервале, Fs/N/Tag/FRange, размере окна и DPI.
- Исходные tcAdc/tcSpectrum вкладки наравне с глобальным выбором ADC, полная временная шкала pnView.
- Ошибки для всех оригинальных типов BIN, комплексный worker с Progress/Cancel/Cache для больших архивов.
- Исходные пиктограммы/шрифты, шаг сетки, поддержка 100/125/150% DPI и клавиатуры; отдельные P2 визуальные задачи в реестре Stage111Z.17.
- Графический XOR использует правильную битовую операцию, но не объявляется пиксельной копией оригинала без новой пары изображений.

Эти задачи не должны блокировать независимую работу по оригинальному измерительному протоколу, но остаются открытыми в UI backlog.

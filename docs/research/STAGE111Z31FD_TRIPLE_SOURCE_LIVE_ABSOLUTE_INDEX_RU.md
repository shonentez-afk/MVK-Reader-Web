# Stage111Z31FD — исходный абсолютный Sample.Index не равен счётчику TCP-захвата

17.11.2026, branch `research/stage111-mvkview-desktop-20261029`.

## Происхождение — три источника вместе

Совместно проверены приватные `mvkview.idp`, `Projects.7z` (исходные `_Unit125.pas`, `_Unit115.pas`, `_Unit128.pas` и `mvkform.dfm`) и `mvk_idr(1).sqlite`; SHA архива/индекса совпали, SQLite `quick_check=ok`. `TMVKThread.Execute 00807A98` принимает `SampleHeader.Index` из отдельных ADC/TACH кадров; `TMvkChannelStorage.ProcessBufferChunk 007D2398` использует указатель входного кольцевого буфера, `CheckDataAvailability 007D1998` проверяет реальную историю. Это **абсолютный** приборный индекс, не количество пакетов, полученных данным новым TCP-клиентом.

В предыдущем Core `original_live_view_gate.py` проверка `preview.next_index <= status.channels.samples` сравнивала несовместимые начала отсчёта. Пример: прибор прислал свои отсчёты 1,000,000..1,065,536, а Go получил лишь 65,536 с момента присоединения. Такой поток НЕ ошибочен, однако старая проверка полностью скрывала Live FFT.

## Go / Python Core / Qt UI

- Go теперь публикует необязательный `channels[i].next_sample_index` — реально последний приборный uint32 индекс (из кадра), отдельно от `channels[i].samples` (локальное число отсчётов). Для ещё не наблюдавшегося канала поле **отсутствует**, вместо выдуманного нуля.
- Python `native_r6_live_status.validate_live_status` валидирует тип `uint32`, запрещает значение при нулевом приёме; старые sidecar без этого поля продолжают разбираться, но абсолютный индекс там остаётся неизвестным.
- Python `native_r6_live_preview` проверяет не только per-channel SHA, Fs, окно и суммарные отсчёты, но и связь абсолютной позиции preview с последним подтверждённым Go индексом. Разницу между текущим счётчиком и старой preview допускает лишь в пределах фактически полученных отсчётов.
- `original_live_view_gate` больше не сравнивает абсолютный индекс с local sample count. При несогласованном источнике **отказывает в отображении**, а при валидном позднем подключении допускает текущий график. Qt продолжает показывать исходную ось «индекс/Fs», не приписывая её системным часам; новых окон и исследовательских элементов не появляется.
- Go unit test, Python Core-протокол и проверка `gate_live_preview` воспроизводят смещение на 1,000,000 отсчётов полностью локально, без команды и подключения к прибору.

## Ограничения

События переполнения 32-битного счётчика и точный Win32 DSP ring overwrite semantics ещё требуют отдельной первоисточниковой приёмки, а не выдуманной поддержки. Одно соединение, проверенные RAW/SHA, контроль SetRate и прекращение чтения не изменены. `original_delphi_compatibility_verified=false`.

# Stage111Z.2 — битовая репетиция четырех режимов на нативном x87 с CW=0x1372

**Дата:** 30.10.2026. **Ветка:** `research/stage111-mvkview-desktop-20261029`. **Продукт:** автономная Windows MVKView Compatible (Qt/PySide6).

## Статус и происхождение

- Первичный оригинал — пользовательская офлайн-сессия **x32dbg** с исходной MVKView. Исправлена опечатка breakpoint `00848631` → `0084B631`. В этой сессии получено `FRange Single=0x43FF4853`, канал 0, и x87 CW `0x1372` **при Tag=0 до и после расчёта**. Для Tag=1/2/3 CW независимо не снят: его равенство — **допущение для репетиции**.
- Вторичный путь — локальный **GCC/x87** в отдельном Linux-процессе, повторяющий ранее source-derived порядок вычислений `FYL2X`/округления Single/`Power`; он **не является оригинальной Delphi** и не подтверждает тождество всех инструкций, состояния памяти или графики.
- Статический CW из приватного EXE/IDP: `0x1332`; фактическое чтение FPU часто показывает `0x1372` из-за зарезервированного бита 6. На локальном CPU после установки обоих значений одинаковы все 4 выхода. Только разрешённые режимы CW `1332`/`1372` допускаются в данном исследовательском CLI.

|---:|---|---|---|---|
| 0 | Логарифмическая | `43FF4853` | `447A0000` | `447A0000` |
| 1 | Линейный ВУ | `43FF4853` | `447A0000` | `447A0000` |
| 2 | Линейный ВС | `459F8D34` | `461C4000` | `461C4000` |
| 3 | Линейный ВП | `47477081` | `47C35000` | `47C35000` |

**4/4 совпадения битово** по одному рабочему `FRange`, без аттестации других диапазонов.

## Границы (только синтетика)

Проведён локальный sweep: 12 центров (`0.2,0.5,1,2,5,10,20,50,1000,2000,5000,10000`) × три соседних Float32 (−1 ULP, точно, +1 ULP) = **36 наборов** при CW `0x1372`.

- Нативный x87 vs существующий Python-кандидат: **1 отличие из 36** — при ровно `1000.0`: native даёт `2000` (`44FA0000`), Python — `1000` (`447A0000`). В локальном опыте младший ненулевой остаток log10 при native возник после extended `FYL2X`; исходный Delphi на этой границе **НЕ проверен**.
- Нативный x87 vs идеальный математический потолок ступеней 1–2–5–10: **8 различий из 36** на конкретном тестовом CPU. Это не означает программную ошибку Delphi: алгоритм хранит отдельные промежуточные значения как Single и использует x87 Extended. Например, точно представленное Float32 `0.2f` чуть больше рационального `0.2`, что даёт различие по математическому критерию.
- Существующий основной Python-кандидат **не изменяли**: без x32dbg на исходных границах заменять его нельзя.

## Что добавлено в рабочую ветку

1. `mvk_compatible/native_probe/x87_graph_vscale_probe.c`: режим `--replay-hex <8HEX-FRange> <4HEX-CW>`, читает только предоставленные аргументы, использует прежние нативные инструкции, вычисляет 4 режима, возвращает исходный CW, выдаёт вход/выход как точные HEX-биты Single. Без приборов, сети, доступа к IDP/EXE/архивам. Из соображений защиты от unmasked x87 exceptions ограничен диапазон входов `1e-8 .. 1e8`, CW строго `1332/1372`.
2. `mvk_compatible/tests/test_stage111z2_native_cw1372_replay.py`: побитовое сравнение c Stage111Z golden, проверка нормализации бит6 CW, восстановление CW, некорректные входы, неизменность старого `--selftest`.
3. Предыдущие `test_stage111z_original_runtime_golden.py` и `test_stage111z1_boundary_characterization.py` оставлены без переписывания.

## Как локально воспроизвести

```bash
gcc -O0 -fno-fast-math -mfpmath=387 -std=c11 -Wall -Wextra mvk_compatible/native_probe/x87_graph_vscale_probe.c -lm -o x87_probe
./x87_probe --replay-hex 43FF4853 1372
python -m pytest -q mvk_compatible/tests/test_stage111z2_native_cw1372_replay.py
```

На Windows с подходящим GCC результат аналогичен по интерфейсу. Для других локальных FRange подставить свои восьмизначные Float32 bits.

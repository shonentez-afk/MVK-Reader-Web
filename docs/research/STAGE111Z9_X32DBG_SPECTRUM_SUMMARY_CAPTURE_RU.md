# Stage111Z.9 — x32dbg: оригинальные GetSpectrum OutputMean, PeakX и PeakY

**Режим:** только офлайн-архив в оригинальной 32-битной Windows MVKView, x32dbg.
Действия только на чтение памяти. Стабильную программу, прибор и сеть не трогать.

## Что именно измеряем

В исходной процедуре `TMvkChannelStorage.GetSpectrum` контрольные точки:

- `007D17E7` — вход в расчёт итоговых метрик. Поле `[EBP-2C]` указывает на **N/2 исходных Single мощностей после обработки режима SpectrumType и зануления нижних бинов**. Это уже **не обязательно** тот же массив, что был на `007D154B`: для режимов 2/3 между точками интегрируются значения!
- `007D1900` — все три итоговых Single уже записаны в объект CalcParams по указателю `EBX`. Это до освобождения внутреннего рабочего буфера `[EBP-2C]`.

Оригинальные поля параметров: `[EBX+4]` = полное N, `[EBX+28]` = N/2, `[EBX+18]` = тип спектра (0/1/2/3), `[EBX+2C]` = частота дискретизации выхода Fs (целое в Гц), `[EBX+30]` = OutputMean **Single**, `[EBX+34]` = OutputPeakX **Single в индексах FFT-бинов**, `[EBX+38]` = OutputPeakY **Single**. Реальный выбранный канал — объект `[EBP-4]`, его `FRange:Single` в `[[EBP-4]+4]`.

**Важно:** OutputPeakX — индекс с энергетическим центром ±2 бина, **не частота в герцах**. Частота пика на графике вычисляется отдельно через XScale=Fs/N.

## Шаг 1 — поставить точки и открыть офлайн-спектр

На оригинальном процессе x32dbg (база образа 00400000, иначе проверить relocation) поставить:

```text
bp 007D17E7
bp 007D1900
```

Другие прежние breakpoints можно временно выключить в панели Breakpoints. Не подключать работающий прибор. Открыть один сохранённый архив и вкладку «Спектр». Не менять канал и режим в середине одного вызова.

## Шаг 2 — на первой остановке 007D17E7

Записать в заметки HEX, адрес буфера, режим, N, Fs и FRange:

```text
ebx
dword:[ebx+4]
dword:[ebx+28]
dword:[ebx+18]
dword:[ebx+2C]
dword:[dword:[ebp-4]+4]
dword:[ebp-2C]
```

Создать заранее приватную папку `C:\MVK_CAPTURE`. Для локальной численной сверки **всех режимов 0–3** (необязательно выкладывать дамп в чат) сохранить именно массив мощности ПОСЛЕ mode processing:

```text
savedata "C:\MVK_CAPTURE\summary_power.bin", dword:[ebp-2C], dword:[ebx+28]*4
```

Размер файла должен быть `4*(N/2)` байт. При N=262144 — 524288 байт. Это команда на чтение исходной памяти и запись копии на локальный диск; сама MVKView не изменяется.

Нельзя просто переименовать `after_power(1).bin` из прежнего захвата в `summary_power.bin` для режимов 2/3: прежний dump был снят **до** обработки режимов ВС/ВП. Даже для 0/1 нужен новый эталон трёх значений из ТОГО ЖЕ вызова.

## Шаг 3 — F9 до 007D1900

Убедиться, что это тот же вызов: `EBX`, `[EBX+4]` и `[EBP-2C]` те же. Считать три DWORD как **HEX IEEE754 Single**, не округлённые десятичные строки на экране:

```text
dword:[ebx+30]
dword:[ebx+34]
dword:[ebx+38]
```

Значения можно прислать сообщением вместе с режимом, N, Fs и FRange — **без** приватного исходного архива и без имён реальных объектов.

## Шаг 4 — приватная проверка на собственном компьютере

Сохранить в `C:\MVK_CAPTURE\summary_capture.json` такой JSON и **заменить все иллюстративные параметры и HEX на считанные с оригинала**:

```json
{
  "schema": "MVKVIEW_ORIGINAL_GETSPECTRUM_SUMMARY_V1",
  "summary_power_stop_va": "0x007D17E7",
  "summary_fields_stop_va": "0x007D1900",
  "fft_n": 262144,
  "sample_rate_hz": 65536,
  "spectrum_mode": 1,
  "f_range_bits": "0x3F800000",
  "summary_power_file": "summary_power.bin",
  "output_mean_bits": "0x3F800000",
  "output_peak_x_bits": "0x3F800000",
  "output_peak_y_bits": "0x3F800000"
}
```

**Числа в примере не являются измерениями оригинала!** N, Fs, режим в JSON — целые **десятичные** числа; FRange и три выходных значения — ровно 8 HEX-цифр с `0x`.

При наличии локального GitHub clone проекта с `numpy`:

```powershell
python -m mvk_compatible.private_getspectrum_summary_triplet_compare "C:\MVK_CAPTURE\summary_capture.json"
```

Сравнитель работает **только с приватными файлами**. Для каждого из трёх полей возвращает: побитовое совпадение, расстояние в Float32 ULP, абсолютное и относительное расхождение. В отчёте нет адресов файлов, сырых отсчётов, метаданных FRange/Fs или самих трёх значений. В отличие от синтетических тестов настоящий оригинал ещё не считан, поэтому `original_delphi_summary_bitwise_parity_accepted=false` остаётся.

## Источник и границы

Оригинальный приватный `mvkview.idp` read-only сверялся по SHA256 **шести оригинальных кодовых окон**. Подтверждены: `TRUNC(N/2.56)`, `max(2,ROUND(N/(2*Fs)))`, суммирование мощности с каждым сохранением в Float64, строгий первый максимум, взвешенный по мощности пик ±2 бина, итоговые Float32 по `[EBX+30/34/38]` и контрольная точка `007D1900`. Блоки исходных кодовых байтов, оригинальные паскали и архивы остаются приватными.

Следующий шаг после трёх настоящих значений — разобрать точные отличия x87 округления `Sqrt`, FRange и печатного `007B2090` / `CursorString`; нельзя подменять реальную Delphi картинкой или NumPy FFT.

# MVKView x32dbg — безопасный захват одного GetSpectrum FFT (Stage111Z.7)

**Только оригинальная Windows MVKView с уже открытым офлайн-архивом. Прибор не подключать.**

Оригинальный приватный IDP подтвердил:
- `007D153D` — перед вызовом FFT `007D1FE8`, вход уже подготовлен (DC удалён, огибающая — если выбрана); первые `N` значений Float32 по адресу `dword:[ebp-2C]`.
- `007D154B` — после возврата FFT `007D1FE8`, но до преобразования в логарифмическую шкалу или интегрирования ВС/ВП; первые `N/2` значений по тому же адресу — мощности `Re²+Im²` в Float32.
- `EBX` указывает на параметры одного вызова `GetSpectrum`; `[ebx+4]` — длина `N`, `[ebx+8]` — код огибающей, `[ebx+18]` — режим 0/1/2/3, `[ebx+2C]` — выходная частота дискретизации в Гц, `[ebp-4]` — объект канала, `[[ebp-4]+4]` — его `FRange`.

## Подготовка

Создать на локальном Windows ПК **частную** папку `C:\MVK_CAPTURE`. Не передавать дампы на GitHub, в CircleCI, и не запускать x32dbg с подключённым прибором.

В x32dbg (32-bit; исходный образ загружен по ожидаемой базе 0x00400000) установить breakpoints:

```text
bp 007D153D
bp 007D154B
```

Ранее установленные `0084B631` и `0084B882` могут перехватывать и замедлять опыт; при желании временно отключить их через Breakpoints, не удаляя остальные настройки.

## Шаг А — при остановке на 007D153D

В строке команд x32dbg выполнить **ТОЛЬКО ТЕПЕРЬ**:

```text
savedata "C:\MVK_CAPTURE\before_fft.bin", dword:[ebp-2C], dword:[ebx+4]*4
```

Это сохраняет `N×4` байт исходного для FFT буфера. `savedata` — **только чтение памяти с записью файла**, а не изменение оригинального EXE или процесса.

Записать в заметки из калькулятора x32dbg:

```text
dword:[ebx+4]                  // N, число Float32; в JSON десятичное целое
dword:[ebx+18]                 // Spectrum mode Tag 0..3
dword:[ebx+8]                  // Envelope code
dword:[ebx+2C]                 // Output sample rate Hz (после огибающей)
dword:[dword:[ebp-4]+4]       // FRange, HEX IEEE Float32
dword:[ebp-2C]                // адрес внутреннего буфера
```

Номер выбранного ADC (0..7) — по GUI, он отдельно не кодируется в EBX.

## Необязательная промежуточная проверка — комплексные FFT Re/Im

Чтобы при возможном расхождении сразу определить, виноваты сами коэффициенты FFT или только расчёт мощности, можно дополнительно поставить точку `bp 007D2088` **до начала эксперимента**. Это внутренний вызов `007D1FE8`, который отработает **между** `007D153D` и `007D154B`.

При остановке именно на `007D2088` (другая stack frame, не считывать здесь EBX-поля внешнего Params) выполнить:

```text
savedata "C:\MVK_CAPTURE\after_fft_complex.bin", dword:[dword:[ebp-8]+48], dword:[ebp-4]*8
```

Источник: `[ebp-8]` здесь — объект `TDSXFastFourier`, `[объект+48]` — указатель `FOutBuffer`, `[ebp-4]` — N. Формат — `N` последовательных пар **Float32 Re, Float32 Im** (положительный угол FFT), всего **8N байт**. Это FFT после Hann, но **до** `Re²+Im²`.

При использовании такого дополнительного файла добавить в `capture.json` отдельное поле:

```json
"complex_fft_file": "after_fft_complex.bin"
```

Это именно дополнительное поле в существующий объект JSON — без отдельной пары файлов/manifest. При отсутствии поля инструмент выполняет обычное сравнение по двум файлам.

После третьей остановки нажать F9 до `007D154B`, а затем продолжить обязательный Шаг Б. Захват `after_fft_complex.bin` необязателен, но позволяет выделить отдельно ошибку Hann/FFT и ошибки квадратичного расчёта мощности.


## Шаг Б — продолжить F9 до 007D154B

Убедиться, что это **тот же самый вызов** (то же `EBX`, ожидаемый `N`, `[ebp-2C]`). Приостановка другого канала/потока НЕ подходит.

В командной строке выполнить:

```text
savedata "C:\MVK_CAPTURE\after_power.bin", dword:[ebp-2C], dword:[ebx+4]*2
```

Размер — `N×2` байт = `N/2` Float32, потому что на этом участке заполнена только положительная половина FFT (без Nyquist).

## Шаг В — локальный manifest

Рядом с `before_fft.bin` и `after_power.bin` сохранить файл `capture.json`, например для **ИЛЛЮСТРАТИВНОГО** N=4096, режима Tag1, envelope0, Fs=65536 и FRange=1.0f:

```json
{
  "schema": "MVKVIEW_ORIGINAL_FFT_POWER_PAIR_V1",
  "before_stop_va": "0x007D153D",
  "after_stop_va": "0x007D154B",
  "fft_n": 4096,
  "spectrum_mode": 1,
  "envelope_code": 0,
  "channel_index": 0,
  "sample_rate_hz": 65536,
  "f_range_bits": "0x3F800000",
  "before_fft_file": "before_fft.bin",
  "after_power_file": "after_power.bin"
}
```

**Обязательно заменить примерные числа на реально прочитанные.** `f_range_bits` — HEX биты, не десятичная конверсия. `fft_n` и `sample_rate_hz` — JSON-числа в десятичной системе. Дампам нужны точные размеры `4*N` и `2*N` байт соответственно.

## Шаг Г — локальная проверка

В корне локальной копии репозитория `MVK-Reader-Web` с установленными `mvk_compatible/requirements-core.txt`:

```powershell
python -m mvk_compatible.private_getspectrum_power_compare "C:\MVK_CAPTURE\capture.json"
```

Инструмент проверяет структуру, размеры, Float32, отсутствие NaN, сопоставляет один и тот же подготовленный массив с оригинальной мощностью. При наличии необязательного третьего файла `complex_fft_file` также побитово сверяет знаковые Re/Im по всем N бинам до вычисления мощности. Используются `idr_float32` и NumPy как **две независимые локальные версии**, не повторно вычитается DC и не выполняется интегрирование режимов 2/3. Отчёт выдаёт только количества совпавших битов, ULP-расстояния и агрегированные относительные ошибки, НЕ сырые отсчёты/путь/биновую разметку.

При ошибке формата возвращает exit code 2 и нейтральное сообщение, не выводя приватный путь или данные.

**После проверки достаточно прислать агрегированный JSON отчёта, не оригинальные `.bin` или `mvkview.idp`.** Для воспроизведения полной численной причины по конкретному бину потребуются отдельные данные и разрешение на их передачу, но для первого исследования агрегатов достаточно.

## Ограничения

- Адреса предполагают совпадение образа оригинала с Stage111Y и отсутствие ASLR relocation; при другом image base адреса надо пересчитать. Не копировать их в x64dbg вместо x32dbg.
- `savedata` вызывается **вручную на каждой точке**, не выполнять обе команды подряд на первой остановке.
- Папка содержит реальные измерения; хранить приватно.
- Source IDP подтвердил точки capture, но **ни один действительный оригинальный GetSpectrum power pair пока не получен в этом этапе**; CI тесты используют только синтетику.
- Документация команды x64dbg: https://help.x64dbg.com/en/latest/commands/memory-operations/savedata.html

Далее: после получения агрегированного отчёта выявить ошибки по каждому типу (Hann/sin/twiddle/butterfly/float store), затем отдельно исследовать исходную точность `OutputPeakX/Y`, `CursorString` и `TQGrapher`. Ни `main`, ни старую Web v0.3.40, ни реальные приборы не менять.

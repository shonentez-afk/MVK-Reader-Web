# MVKView — передача нового результата: поиск происхождения спектра

**Дата:** 2026-11-13. **Исследование:** MVK Research MCP 0.3.4 через DeepSeek Harness Desktop, Nemotron 3.5 Super VL.

## Что получено

Оператор прислал `spectrum_input_provenance.json` и `spectrum_input_provenance_report.md`. Nemotron обследовал только заранее разрешённую папку исходных измерений, обнаружив две пары Single BIN/TSXML на АЦП 4, Fs 65536 Гц. Результат `data_gate=unresolved` достоверно отражает отсутствие связи этих пар с открытым экраном «Спектр». Экранный эталон: СКЗ 6,89 м/с²; пик 3800 Гц / 0,7786 м/с², полотно [416,196,1850,844], PNG SHA256 557aa781f5664774d38a3af12b1b73b7c73224a94c06f36b272d5648acf7ee91.

| MVK00000050 | ADC4 | 65536 | 2880768 | 43.95703125 с | 509.9 | f0f816798dbdc53fb1e24fb03920a9674c6a46f45d0e32fad69f53d58ebbd051 |

На оригинальном PNG нижний индикатор `00:00:29.990`. В основном репозитории `mvk_compatible/core/original_view_time_source.py` моделирует его как **начальное время выбранного окна** (`selected_start_seconds`) из `TTrackBar` на основании `_Unit128`. Если оригинальный runtime в этом кадре использует такую же семантику, запись MVK00000043 (25.832 с) не могла бы иметь выбранную позицию 29.990 с. Однако runtime-значение и привязка к архиву не проверены; **MVK00000050 НЕ объявлять правильной** и не исключать файл только из этой модели.

`InternalChannelGain` известен из TSXML, но фактический original runtime FRange для экранного случая напрямую не захвачен. Не принимать gain за доказанный FRange, не подгонять по ожидаемым 6.89/3800/0.7786. `fft_n`, `spectrum_mode`, `frange` и `gain` для обеих пар отчётом отмечены unknown. Отсутствие параметров в TSXML **не означает**, что ранее восстановленные алгоритмы FFT/FRange не работают: их реализация и принятые отдельные golden уже есть в основном репозитории.

## Что уже принято и НЕ повторять

- Оригинал MVKView 1.0.47 имеет реально открытый «Спектр», окно не свёрнуто, PNG 1942×1042, пиксельные границы [416,196,1850,844], 33 UIA / 58 Win32, 17 видимых / 41 скрытый.
- Уже есть независимая original Tag0 Power/Y и Qt-копия этого же Power/Y (`STAGE111Z14` / `STAGE111Z31C`), summary те же 6.89 / 3800 / 0.7786, но новый PNG НЕ доказан тем же входным временным окном BIN.
- FFT N262144 (на одном оригинальном захвате) и оригинальный Power→Y для четырёх режимов по 131072 Float32 проверялись в отдельных goldens. Архивный плотный source-derived график реализован Stage111Z31N; готовый `DirectBinSession` читает проверяемый BIN/TSXML.
- MCP 0.3.4 уже работает; новый поиск окон/скриншотов и реконструкция FFT/FRange с нуля не нужны.

## Правильный следующий крупный пакет

1. В **основной копии** (`MVK-Reader-Web`, `research/stage111-mvkview-desktop-20261029`) выполнить единый E2E архива: `DirectBinSession.open → реальный Qt refresh_spec → спектр → dense/sparse zoom/pan → cursor → Copy/Save`, используя локально *обе* найденные пары как **независимые испытательные входы**. Проверить, что вычисления из полного источника неизменны и GUI использует те же данные, без подгонки частоты/пика под экран оригинала. Никакой оригинальный BIN не публиковать.
2. При желании связать конкретный оригинальный открытый спектр с файлом — получить **независимый идентификатор выбранной задачи/архива** через интерфейс оригинала (оператор проверяет вручную; MPC не угадывает и не кликает), либо иную проверяемую provenance-связь с конкретным оконным интервалом. Отсутствие этого подтверждения сохраняет `same_bin_original_parity = DATA_GATE_UNRESOLVED`.
3. Для уже готового одинакового Power/Y сначала использовать предыдущие real original goldens при сравнении графика Qt (это другой уровень проверки и не эквивалентно same-BIN E2E). Не заменять проверку полного Y/другого FFT красивой похожестью PNG.
4. После сопоставления исправлять выявленные ошибки **в ядре и интерфейсе вместе**, без мелких PR и дублирующих FFT-кандидатов. Предыдущие корректные математические goldens сохранять.

**Рабочий ПК:** Оригинал MVKView оставлять открытым/развёрнутым при будущих захватах; сейчас дополнительные клики или MCP-захваты не требуются. MCP не управляет Qt-копией. Воспроизводить копию можно отдельно: меню «Файл → Открыть измерение (ZIP / BIN / TSXML)…» / Ctrl+O. Сначала загрузить пару MVK00000043, затем MVK00000050 по очереди. Сравнение с оригиналом пока маркировать не как доказанное 1:1, а как независимый E2E.

SHA256 предназначены для проверки соответствия файлам; не публиковать содержимое файлов.

# Stage 73 — подтверждение загрузки конфигурации MVKView

Дата 2026-10-28. Проверка оригинального IDR `_Unit125.pas` без прибора и прошивки. 21/21 инструкций прошли автономную проверку.

1. Task=3..5 выполняет передачу лишь при Stage=1: `0x00807D01`, `0x00807D0D`.
2. После отправки блоков идут команды сохранения во Flash `0xF0001` и перезагрузки `0x10F0F`; затем `0x00807E83` устанавливает Stage=2. Это ещё не успех.
3. Цикл читает тип и длину как два DWORD: `0x00807F78`, `0x00807F84`. Допустима длина от 8 до 131072, кратная 4. При нарушении `errInvalidPacket`.
4. Тип `0x00010FF0` — успешный ответ; для Task=3..5 **при Stage=2** поток завершается через `0x00808859` (проверки `0x00808088–A1`).
5. Тип `0x00010FFF` — отказ, `errOperationDenied` и исключение `0x008080E1`.
6. ConnectTimeout=1000 мс, ReadTimeout=5000 мс; обработчики тайм-аута и разрыва соединения присутствуют.

Важно: это трассировка логики приложения, не проверка фактической записи во Flash и не эксперимент с ACK прибора. Не воспроизводить команды на действующем оборудовании.

Локальная полная версия `MVKVIEW_STAGE73_ACK_STATE_20261028.zip`: `REPORT_RU.md`, `verify_stage73.py`, `TEST_RESULTS.txt`. Stable v0.3.40 без изменений. Следующий Stage74 — окончание обработки исключений и UI-статуса после WaitFor.

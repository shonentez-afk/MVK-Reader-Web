# Stage111Z.6 — четыре оригинальных Hann-бита и адресная коррекция MAX FFT

**Дата:** 30.10.2026. **Единственная рабочая ветка:** `research/stage111-mvkview-desktop-20261029`.

## 1. Итог оригинальной Windows x32dbg-сессии

Оператор прочитал четыре DWORD из массива Hann оригинального 32-bit процесса MVKView (таблица BSS по адресу `0096DA48`; индекс i хранится по адресу `0096DA48 + 4*i`). Исходный оригинальный EXE, IDP, BIN/RAW/PCAPNG или производственные архивы **не** помещались в GitHub/CI.

| Индекс | x32dbg read-only | ORIGINAL Win32 Single HEX | Native GNU x87 CW=0x1372 | Текущий до патча NumPy |
|---:|---|---|---|---|
| 1 | `dword:[96DA4C]` | **`2F80EF9C`** | `2F80EF9C` | `2F80EF9D` |
| 5 | `dword:[96DA5C]` | **`31C97664`** | `31C97664` | `31C97663` |
| 262139 | `dword:[A6DA34]` | **`31C97664`** | `31C97664` | `31C97663` |
| 262143 | `dword:[A6DA44]` | **`2F80EF9C`** | `2F80EF9C` | `2F80EF9D` |

**4/4 совпали с native x87 бит-в-бит; все четыре NumPy значения отличались на 1 ULP.** Это **операторские оригинальные runtime golden ровно по четырём индексам**, а не подлинный дамп всей 262144-таблицы. Нативный код и оригинальная Delphi исполнялись в разных процессах; CW во время исходного Hann-init независимо не считан.

## 2. Целевое изменение

В `mvk_compatible/core/fft_idr_candidate.py` введён словарь `_ORIGINAL_HANN_STAGE111Z6_BITS` с четырьмя измеренными значениями. Сразу после построения прежней NumPy-кандидатной 262144-таблицы эти четыре слова `float32` устанавливаются через `w.view(np.uint32)`, затем кэшированная таблица делается read-only.

- Изменяются **только указанные четыре индекса**, остальные 262140 в этой версии остаются прежними кандидатными значениями.
- Оригинальная `GetSpectrum` выбирает `Hann[i * (262144/N)]`. Для power-of-two FFT длиной меньше 262144 шаг чётный, четыре индекса нечётные, поэтому **ни один** из четырёх исправленных элементов не используется.
- Для максимальной FFT `N=262144` патч даёт точные оригинальные биты в четырёх измеренных позициях. Никакая полная Delphi/x87/FFT amplitude parity этим не аттестуется.
- Никаких новых драйверов, сети, подключения к прибору, внешних данных для запуска или изменения стабильной ветки `main`.

## 3. Автоматические проверки

Обновлён `mvk_compatible/tests/test_stage111z6_original_hann_runtime_golden.py`:

1. Четыре фиксированных оригинальных HEX = отдельный тестовый эталон.
2. Сравнение с результатами нативного source-derived GCC/x87 пробника `--summary` на всех четырёх индексах.
3. **Точное** совпадение `idr_hann_rms(262144)` с эталонами `uint32`, проверка защиты cached table от изменения через публичный API.
4. Для FFT `N=256,1024,4096,8192,65536,131072` проверка, что ни один patch-index не выбирается и старые NumPy-биты без изменений совпадают с результатами.
5. Существующие Stage111B..Z.5 тесты FFT/Hann тоже выполняются CircleCI.

Исходный тест `test_stage111z5_native_hann_probe.py` сохраняет широкий CPU-устойчивый порог, так как полная нативная x87 таблица оригиналом пока не аттестована.

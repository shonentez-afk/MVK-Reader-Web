# Stage111Z31DI — 14 исходных StatusCells, реальный RegisterImage, Stage3 и штатные окна Qt

Дата исследования: 16 ноября 2026 года. **Частные исходные материалы:** `Projects.7z` / `_Unit125.pas`, `mvkview.idp` (41 МБ), `mvk_idr(1).sqlite` (20 МБ), локально проверены. Сами частные PAS, IDP, SQLite, PCAP, RAW и фотографии в публичный GitHub не переносить.

## 1. Подтверждённые факты оригинальной MVKView 1.0.47

- `_Unit125.pas:00805D08`, таблица `008D3068`, содержит **14 последовательных исходных адресов DWORD**: `1006, 1038, 1030, 1032, 2120, 2320, 2520, 2720, 2920, 2B20, 2D20, 2F20, 3004, 3104` (HEX). В приватной IDP все 14 Win32 little-endian DWORD найдены как единственная полная последовательность байтов. Названия групп, восстанавливаемые `00805D87–00805E02`: «Система», «Загрузка», «*SPORT», «*SPI», `xChannel0..9`.
- `00805D4C–00805D60` обновляет ячейку только если адрес попадает в реально принятый блок регистров. `00805D6E–00805D7A` получает **два соседних 16-bit слова**, собирает исходный 32-bit DWORD из регистра памяти формы. `00805E9B–00805EA0` сохраняет актуальное содержимое в `StatusCells[i]` (после журнала изменения).
- `008061DB–008061EB` исходно инициализирует 14 `StatusCells` всеми байтами `0xFF`. Это **не физическое сообщение прибора**, а стартовый sentinel неопределённости.
- `0080871B–00808762` при `Task=2` и `Stage!=3` выполняет **беззнаковое** `StatusCells[0] > 0`; при выполнении выставляет исходный текст `thrSystemError` и `Stage=3`. Важно: буквально `0xFFFFFFFF > 0`; даже оригинальная проверка может сработать, пока исходное значение не обновилось. **Совместимый read-only интерфейс НЕ должен утверждать системную ошибку МВК01 без двух реально полученных валидных 16-битных слов**. Это осознанное разделение исходной инструкции и подтверждённого факта о приборе.
- `0080850F` разделяет обработку PARAM при `FreezeUpdate`; исходный `Stage0→1` после непустого PARAM проверяется отдельно и не эквивалентен созданию TCP-сокета.
- **Эти внутренние 14 StatusCells НЕ равны автоматически 15 строкам видимой таблицы PageStatus** («Серийный номер», «Прошивка», «Системные ошибки», «Modbus…»). Без подтверждённой карты оригинальной формы заполнять 15 отдельных полей нельзя.

## 2. Фактическая реализация

**Go Native R6.1, единственный пассивный TCP/10230 читатель:**

- `source/source_status_cells.go` хранит точные 14 адресов и читаёт каждый из уже полученного `RegisterImage` через `Uint32(addr)`. `Uint32` возвращает значение только если **оба** регистра `Valid[addr]` и `Valid[addr+1]` истинны. Никаких дополнительных запросов прибору, TCP-соединений и изменений RAW.
- `live_progress.go` публикует в **существующем атомарном** `MVK_NATIVE_LIVE_STATUS.json` ровно 14 `{index,register_address,valid,value_uint32}`. Отсутствие регистра = `valid:false, value_uint32:null` (не ноль, не `0xFFFFFFFF`). Источник `valid` — текущий приёмный `RegisterImage` только одного Go capture. Реально прочитанное `0xFFFFFFFF`, если обе половины Valid, допустимо как DWORD.
- Тесты `source_status_cells_test.go`: 14 адресов, 14 неизвестных до приёма, отдельное получение двух половин, явный ноль против UNKNOWN, реальные разные DWORD (включая наблюдаемый `0xFFFFFFFF`), полный RegisterImage 32800 байт, read-only RAW без изменений.

**Автономный Python Core:**

- `original_mode2_status_cells.py` жёстко сверяет массив, индекс/адрес/порядок, Boolean Valid, UInt32 или `null`, исходную группу входных PARAM/ACK/DENIED. Неизвестные значения не подменяются, снижение Valid запрещено в пределах одной сессии, изменение значения без новой PARAM отвергается.
- `native_r6_live_status.py` проверяет этот массив вместе с сеансом и добавляет предупреждение качества **только после** реально полученного `StatusCells[0]` >0. При UNKNOWN и при валидном нуле тревоги нет.
- `original_mode2_live_health.py`, `original_connected_status.py`, `original_measurement_mode.py` согласуют один признак системной ошибки с тем же механизмом допуска LIVE. Системная ошибка **блокирует** предварительные графики и локальную выборочную запись; полный Go RAW не меняется.
- `original_mode2_runtime_trace.py` хранит отдельное доказательство 14 ячеек и защёлкивает source system error до нового Mode2. Даже после следующего валидного снимка со значением 0 нельзя молча снова «зажечь зелёный» и включить запись. При первом положительном коде не исполняется даже **автономный** dry-run вызов исходной SetRate из FIFO в том же шаге. Физическая Delphi Stage3 **не заявлена как проверенная**.
- `original_mode2_received_frames.py` и `original_mode2_task2_exchange.py` теперь тоже моделируют сборку 16-bit половин из исходного PARAM (только при `FreezeUpdate=False`), переход в Stage3 после **реального полного** статуса 0x1006, отсутствие обработки команд в Stage3 и sticky system error в одном автономном Task2. Не создают никаких сокетов или приборных команд.

**Реальный интерфейс Qt (без инженерных экранов):**

- В **существующей** панели `pnMeasure/lbStatus` отображается действительный HEX код системной ошибки или сообщение «ранее подтверждена» при сбросившемся сыром статусе. Индикатор красный, запись заблокирована.
- Тот же Core receipt передаётся `PageStatus` и `PageFile`, без новых окон. На PageStatus существующая строка примечания сообщает, сколько из 14 StatusCells доказанно получены, и показывает код системной ошибки.
- Все **15** исходных человекочитаемых строк таблицы PageStatus остаются `—` до независимого восстановления карты. Отсутствие поддельных Firmware/MD5/Modbus данных — часть приёмки.
- `MainWindow._receive_native_live_status`, `_receive_live_preview`, `source_write_toggle` запрещают повторный допуск live-preview и локальной записи после зафиксированной Stage3 в текущем сеансе, даже если последующий реальный код вернулся к нулю.

## 3. Проверки

- Python `test_stage111z31di_source_statuscells_core.py`: адреса, исходный FF sentinel, неизвестный/нулевой/положительный код, отказ при смешанных адресах/типах/неполных значениях, монотонность, наличие двух слов, sticky Stage3, source Task2 FIFO и FreezeUpdate.
- Qt `test_stage111z31di_qt_live_source_status_cells.py`: **реальная** `pnMeasure`/PageStatus (без прибора), визуальное предупреждение от валидного регистра, 15 исходных строк остаются UNKNOWN, вызовы записи отключены, затем сырой ноль не снимает защёлку в Core и Qt. Подключено к Windows native и Qt offscreen на DPI 100% и 150%.
- Тесты Go подтверждают независимый RegisterImage/Valid для 14 адресов.

## 4. Ограничения и дальнейшая работа

- Это **доказательный read-only прием** системных значений из реальных входных пакетов, а не активный приборный запрос. Соответствие 14 StatusCells и 15 видимых PageStatus строк **не подтверждено**.
- Исходный Delphi `StatusCells` при неинициализированном `0xFFFFFFFF` и побитовом обработчике может вести себя иначе, чем наш безопасный вывод подтверждённых приборных статусов. При аппаратном same-run следует отдельно сверить момент первого полного REG image, source FreezeUpdate и переход Stage3.
- Не реализована физическая отправка `QueueCommand/SetRate`, аппаратное сопоставление ACK, source auto-reconnect, byte-exact Delphi ChannelFile/ValuesFile, численный DSP/Win32 pixel/RPM same-run parity.
- **Никаких новых приборных TCP-команд** без согласованного аппаратного допуска и проверки полного офлайн протокола.

Последняя программная приёмка DI считается успешной **только после 4/4 PASS** в Actions для точного исполняемого SHA; документационный `[skip ci]` не создаёт новый EXE.

# Stage111Z31N — правильное построение спектров из обычных архивов

**Дата:** 05.11.2026. **Ветка:** `research/stage111-mvkview-desktop-20261029`.

## Решение пользователя: приоритет инженерной точности, а не шрифта

Пользователь подтвердил: **«шрифт не важен. главное сами расчеты и вывод графиков.»** Поэтому с этой стадии **пиксельно идентичные GDI-глифы и внешний вид подписей НЕ ЯВЛЯЮТСЯ БЛОКИРУЮЩИМИ критерием** для приёмки спектра. Важны **совпадающие мощности и амплитуды, диапазоны, единицы, спектральные пики, корректная кривая при любом масштабе, курсор, усреднение, огибающая и сохранение/вывод**. Ранее созданные вспомогательные GDI исследования не удаляются, но на них больше не тратится основной бюджет разработки.

## Ключевое исправление

На Stage111Z31M исходный TQGRSeries min/max был доступен только как экспериментальное отображение уже принятого x32dbg Power/Y, а **обычные архивы и BIN** использовали непосредственную Qt полилинию. При `NFFT=262144` полный Power/Y массив содержит **131072** Float32; оригинальная `TQGRSeries` показывает только `TRUNC(131072/1.28)=102400` отсчётов до 25600 Гц при Fs65536, а при конечной ширине окна сворачивает значения по каждому экранному столбцу с сохранением обоих экстремумов.

В Stage31N источник-ориентированная отрисовка подключена **к обычному просмотру архивов по умолчанию**, без дополнительных переключателей:

1. `mvk_compatible/core/spectrum_archive_plot_projection.py`: при сжатом графике использует проверенный исходный `source_tqgr_series_columns` из Stage111Z31H, который ищет min/max в оригинальном окне индексов пиксельного столбца, соединяет ближайший экстремум первым, учитывает исходный `TRUNC((N/2)/1.28)`, `Fs/NFFT`, `ScrLeft/ScrWidth`, `ScrBottom/ScrHeight`, y clamp. **Запрещено** использовать незаметно последние неотображаемые FFT-бины для графика; **разрешено** использовать их в отдельно неизменённом оригинальном расчётном summary.
2. При достаточно крупном увеличении, когда на экранный пиксель приходится меньше ~1.5 бина, возвращается график по **полному последовательному набору видимых исходных точек**, без пропуска между ними. Для этого не пересчитывается FFT, не изменяется Float32 Power/Y/summary.
3. `mvk_compatible/desktop/main_window.py`: обновляет производную геометрию при изменении диапазона X/Y, масштаба/размера ViewBox и смене FFT/режима/архива. Один основной `PlotDataItem` хранит исходную отображаемую серию и остаётся авторитетом для курсора и экспорта; плотная кривая прорисовывается **отдельным НЕ DATA `QGraphicsPathItem`**, чтобы не создавать второй спектр и не нарушать QA-контракт `listDataItems()==1`. На sparse zoom сырая серия возвращается видимой. Исходный курсор IDR продолжает читать полный массив Float32.
4. Добавлены `tests/test_stage111z31n_graph_projection.py` и `tests/test_stage111z31n_qt_archive_graph.py` с четырьмя режимами, сохранностью узких одиночных пиков, запретом подмешивания скрытого хвоста N/2, zoom/pan, 150%-DPI Windows, синтетическим объектом принятого архива, Float32 bits/summary untouched, reference/live isolation.
5. Исторические `test_desktop_qt.py` остались **без послаблений**. Первая проба с новым `PlotCurveItem` закономерно дала 2 ошибки: Qt считал графическую подложку второй кривой данных. Это **исправлено**, данные не дублируются. FFT/Power/Y/FRange/Native R6.1 и сам оригинальный расчёт не менялись.

## Численная приёмка — что уже готово

- Stage111Z8, 30.10.2026: оригинальный операторский `before_fft(1).bin` → `after_power(1).bin`, FFT N262144, **131072/131072 Float32 exact** в том конкретном исходном окне. Не повторять без причины.
- Stage111Z30: четыре исходных mode Tag0–3, каждый Power→DisplayY **131072/131072 Float32 exact**, по три исходных summary HEX на захват.
- Stage111Z31K/L: независимый x87 Hann 262144 coeff digest и independent C/x87 FFT для шести синтетических N; это дополнительная регрессия, **не повторная оригинальная runtime-проверка**.

Не объявлять весь MVKView спектр 100% законченным: по другим N/Fs, каналам и исходным реальным архивам необходима приёмка; по режиму envelope оригинальная full-runtime проверка ещё не закрыта.

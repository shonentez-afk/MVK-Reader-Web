# Обязательное правило проекта MVK: три источника оригинала вместе

Подтверждено пользователем 17.11.2026: при каждой следующей работе по восстановлению MVKView 1.0.47 **обязательно** использовать совместно три источника из материалов проекта, не ограничиваться только PAS или SQLite:

1. `mvkview.idp` — бинарный IDR project v.3 с оригинальными адресами, символами, типами/полями и сегментами. **Внимание:** SQL-мост извлёк из IDP только header/segments; он не декодировал все внутренние RTTI/объекты проекта. Сам бинарный IDP содержит больше данных, чем одна SQL-шапка, и должен исследоваться непосредственно.
2. `Projects.7z` — приватный архив исходных Delphi-псевдо-Pascal, DFM, вспомогательных файлов. Проверять фактическую последовательность переходов, регистры/поля, тексты/форматтеры/флаги.
3. `mvk_idr(1).sqlite` — индекс original DFM events, functions, calls и source_files + заголовок IDP, полезный для пересечения графа вызовов. Индекс сам по себе не доказывает полноту реализации Qt/Core.

В текущем Project-окружении эти файлы доступны по `/mnt/data/mvkview.idp`, `/mnt/data/Projects.7z`, `/mnt/data/mvk_idr(1).sqlite`. В следующих чатах сначала искать их среди уже вложенных источников Project/Library и в рабочем контейнере, **не просить повторной загрузки**, пока действительно не проверена их доступность.

## Проверенный триединый provenance

Локально выполнена `tools/research/verify_mvk_triple_source.py`, работающая только с локальными файлами, без сети, записи в исходники и без отправки приватных байтов. Проверка **SUCCESS**:

- IDP начинается с `IDR proj v.3`, Delphi 2014, entry `008C1DC0`, base `00400000`; SHA256 и исходные размеры совпадают с `sqlite.meta.idp_header`; `PRAGMA quick_check(1)=ok`.
- Реально распакованные из `Projects.7z` `_Unit115.pas`, `_Unit125.pas`, `_Unit128.pas` и `mvkform.dfm` побайтово совпадают со своим `bytes,sha256` в `sqlite.source_files` (**4/4**).
- Шесть основных обработчиков сверены по трём источникам (бинарный символ `#address name` в IDP, `sqlite.functions/events`, маркер и тело по адресу в Pascal из настоящего архива): `bTaskConnectClick 00848E78`, `bTaskConfigIPClick 00848E6C`, `bWriteAdcClick 0084E914`, `bWriteValuesClick 0084E988`, `bWriteTableClick 0084E020`, `mRate1Click 0084DEC4`.

Запуск в поддерживаемой Linux/контейнерной среде с `libarchive`:

```bash
python tools/research/verify_mvk_triple_source.py \
  --idp "/mnt/data/mvkview.idp" \
  --archive "/mnt/data/Projects.7z" \
  --sqlite "/mnt/data/mvk_idr(1).sqlite"
```

## Для каждого следующего функционального пакета

1. **IDP:** найти оригинальные символы, поля/типы, callsites, ветки и адреса (если доступно). Не считать наличие символа доказательством поведения.
2. **SQLite:** подтвердить `functions / calls / events / components`, события настоящих DFM кнопок/форм, привязки к функциям, реальные переходы. Раскрыть граф вызовов.
3. **Projects.7z:** прочитать конкретные тела обработчиков (условия, Stage, регистры, очереди, структуры, формат `.bin`/`.csv`, время, частоту, исключения), подтвердить или опровергнуть гипотезы из IDP/SQL.
4. Составить **один согласованный контракт** Go Native + Python Core + Qt: сетевой запрос/получение, расчёты, реальная кнопка/состояние/ошибка, экспорт, отображение; не заменять восстановление сравнением интерфейса или dry-run.
5. Провести автономные тесты со стабильными source-derived кадрами, CI на Windows DPI 100/150 и Go, физическую приборную приёмку — отдельно, явно показывать непроверенные участки.

**Исходная секретность:** никогда не коммитить в публичный GitHub приватные `.idp`, `.sqlite`, `.pas`, `.dfm`, исходные `.pcapng`, `.bin`/`.raw`, XML настроек и личные пути/адреса прибора. Публичны только производные описания/адреса функций, проверенные тестовые синтетические fixtures и локально выполняемый checker без приватных байтов.

## Конкретное исправляемое расхождение

В существующем `_render_live_spectrum` использовался `provisional_spectrum` независимо от выбранного `EnvelopeCode`; `_render_live_wave` аналогично использовал `provisional_waveform`, хотя исходный Delphi меняет **сам входной сигнал** при `EnvelopeCode>0`. Выбор кода фильтра с локальным IDP мог оставить на экране обычный спектр ускорения и некорректно представить его как спектр огибающей.

Наличие SHA-подтверждённого исходного 2²¹-кольца Go **не означает**, что применены original FIR, I/Q, последовательное сохранение Float32 и x87. Оригинальная FRange применяется при записи Float32 и учитывается в иных исходных функциях; калиброванный Go spool нельзя без свидетельств принимать за оригинальный Delphi `PAdcFloatData`.

## Единый алгоритм проверки и поведение

1. `original_live_envelope_provenance.py`: исходные данные меню (N, Fs, FilterCode) и 2²¹-кольца анализируются без вторичного TCP. Для выбранного спектра отдельно вычисляются **обе** документированные длины: оригинальная `GetAdjustedEnvelopeLength` и исследовательская обратная FIR-рекурсия для ровно N выходных элементов. Они **не обязаны совпадать**; их смешение не доказывает оригинальную семантику. Отказные состояния: нет IDP, нет проверенного ring, недостаточно истории, FFT/FIR-окно после реальной фильтрации не подтверждено.
2. `main_window.py`: при выбранном EnvelopeCode1..31 **ни живой временной сигнал, ни живой спектр не могут отобразить обычный unfiltered preview или исходную нефильтрованную FFT**. Вместо старого графика показывается явная причина, ожидаемая длина истории и необходимость выбрать `Без фильтра`. Стирается stale cursor и отключаются Copy/Save для недостоверного FFT.
3. `native_capture_dialog.py`: при активном фильтре больше не запрашивает нефильтрованный FFT или временное окно из локального Go IPC так, словно оно готово для FIR. Источник IP, Task2, RAW, десять каналов, Freeze, WriteData, WriteValues, Stop и SHA исходных данных не изменены. При Tag0 запросы GetSignal/GetSpectrum остаются прежними.
4. `main_window.py`: для Tag0 показывается явная граница FRange: Go spool уже калиброван, локальная FFT использует FRange=1, оригинальный Delphi коэффициент не доказан. Нельзя объявлять повторный gain или 1:1 parity.
5. `test_mode2_original_live_fir_truth_gate.py` и `test_mode2_original_live_fir_qt.py`: Go/IP не требуется; сравниваются длины FIR, отказ при отсутствии profile/ring/history и **настоящие Qt-графики** при переключении на Code20 и обратно. В тесте Qt используется пустая *синтетическая* FIR-модель лишь для проверки UI-блокировки: она не используется в расчётах и не считается оригинальным профилем. Исходные IDP/PAS/RAW не публикуются.

### Наглядный пример честности расчётного контракта

При `Fs=65536`, `bSpecLines=4096`, `EnvelopeCode20`, первая source-формула `GetAdjustedEnvelopeLength` даёт **4198** исходных элементов, а исследовательская обратная FIR-рекурсия до ровно 4096 выходных отсчётов — **8243**. Предполагаемый пост-FIR размер на исходном пути из этих чисел нельзя объявлять автоматически равным N FFT без приёмки реального original `Params.Count` после `007D1C48/007D1E70`. Для `Code26` две длины совпадают, но это всё ещё не доказательство x87-совпадения спектра.

### Требуемое продолжение

Главный дальнейший незакрытый пакет: реализовать **исходное post-FIR кольцевое окно** с реальной `Params.Count`, пропусками/границами `FValidPos`, конкретным коэффициентом FRange, затем сравнить **один и тот же** pre-FIR и post-IQ Float32 массив с оригинальным Delphi 1.0.47, после чего допустить live график огибающей. Затем принимаются x87/FFT Power и все 4 режима Y/summary, оригинальные BIN/TSXML/CSV и аппаратные timeout/SetRate/DENIED/Stop. До этой пары: `original_delphi_compatibility_verified=false`.

**CI:** один финальный SHA должен дать 5/5 PASS (Linux Go RX, Linux Core, Windows Core/Qt, Windows QPA DPI100/150, Windows EXE). Перед этим не называть новый интерфейс принятым. Никаких команд прибору, Flash/IP/Reboot, публичных исходных Pascal, оригинального BIN, PCAP или FIR банков.

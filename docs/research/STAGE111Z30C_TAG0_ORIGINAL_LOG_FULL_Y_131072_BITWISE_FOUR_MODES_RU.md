# Stage111Z30C — оригинальный Tag0 «Логарифмический»: полный Y 131072/131072, закрытие численного сравнения 4 режимов

**Дата:** 03.11.2026. **Рабочая ветка:** `research/stage111-mvkview-desktop-20261029`. Scope — оригинальная MVKView32/x32dbg из офлайн-архива и автономный Windows MVKView Compatible. Web 0.3.40/main, прошивка, оборудование, Native Go R6.1 не изменяются.

## Оригинальное свидетельство пользователя

Пользователь зафиксировал **в настоящем оригинальном Win32 процессе**: `INT3 breakpoint at mvkview.007D17E7!`; `[EBX+18]=0` (Tag0), `[EBX+4]=0x00040000` (N 262144), `[EBX+28]=0x00020000` (half 131072), `[EBX+2C]=0x00010000` (Fs 65536), `[[EBP-4]+4]=0x43FF4853` (FRange Single 510.5650329589844). По инструкции пользователь сохранил **с одной паузы** массив `[EBP-2C]` как `power_after_mode.bin` и `[EBP-30]` как `display_y.bin` (каждый 524288 байт). В GitHub этих файлов **НЕТ**; точные оригинальные бинарные файлы остаются приватными.

Исходные вложения чата:
- `power_after_mode(3).bin`: 524288 байт; SHA256 `81456d63be57536572fc2e0fe174f57454157c41c00890233554558e74f2ce09`.
- `display_y(3).bin`: 524288 байт; SHA256 `28c605d9864e9f52a79e09e874f39243ab08b4696e2bb2c8946dab7c71467d90`.

Оба представляют 131072 Float32 little-endian, без NaN/Inf; исходный Power **неотрицателен**, два нулевых нижних бина, 131070 ненулевых. SHA Power **точно совпадает** с ранее полученным оригинальным Tag1 post-mode и исходной Tag0 Z10 полосой после обнуления первых двух бинов (это НЕ исходный pre-mode Z8 Power, который имел SHA `16ecc8...` до обнуления).

## Полная самостоятельная сверка source-derived Stage111Z30B

Текущая реализация `mvk_compatible/core/spectrum_display_source.py::source_derived_mode_display(power, n_fft=262144, mode=0, f_range=510.56503)` повторяет source-derived оригинальный путь:

```text
Offset = Float32(2 * log10(Float32(N/2))) = 10.23501968383789
Y[k]  = -180.0 Float32, если Power[k]==0
Y[k]  = Float32((log10(Float32(Power[k])) - Offset) * 10), если Power[k]>0
```

Оригинальная `00447DB8` по приватному disassembly использует x87 `FLDLG2/FYL2X` (именно `log10`), с промежуточным сохранением Float32 offset. Версия NumPy Float64 `log10` здесь уже была в проекте, **до** получения новой пары файлов; никаких коэффициентов, допущений или результативных чисел под захват не подгоняли.

**Первый исходный реальный FULL Y Tag0: 131072/131072 Float32 битово идентичны; различий 0; максимальное расстояние 0 ULP; SHA сгенерированного Y `28c605d9864e9f52a79e09e874f39243ab08b4696e2bb2c8946dab7c71467d90` равен SHA оригинального Y.**

- Бины 0/1: `Power=0`, `Y=-180.0` строго по исходному пути.
- Три других Y находятся **ниже −180** из-за крайне малого, но ненулевого Power; это нормальное поведение оригинала, **НЕ надо** глобально обрезать Y до −180.
- `min(Y)=-193.72451782226562`; `max(Y)=-55.32063674926758`.
- Максимум Power и Y — бин `k=15200`, `f=k*Fs/N=3800 Гц`, `Y=-55.32063675 дБ`; значение согласуется с ранее наблюдавшимся курсором оригинала около `-55.32 дБ`.

### Независимая пересверка трёх исходных Tag0 summary HEX из Stage111Z10

На новом `power_after_mode` существующая реализация последовательной Double-суммы и Single пикового центра ±2 дала ровно старые original-operator reference слова:

| Поле | Получено Float32 | HEX | Прежний original HEX |
|---|---:|---|---|
| OutputMean | 6.892500877380371 | `40DC8F5E` | `40DC8F5E` |
| OutputPeakX (FFT bins, НЕ Hz) | 15200.1455078125 | `466D8095` | `466D8095` |
| OutputPeakY | 0.7786021828651428 | `3F475279` | `3F475279` |

Частота энергетического центра: `Float32(15200.1455078125 × 0.25)=3800.036376953125 Гц`. Важно не путать OutputPeakY (линейная величина summary) с **отдельным логарифмическим значением графика** `-55.32063675 дБ`!

## Что всё ещё НЕ доказано

1. Нет независимой криптографической аутентификации одного процесса/потока/кадра для пользовательских SaveData; это не буквальное доказательство любого возможного оригинального режима/условия.
2. Оригинальное `Tag2 [EBX+20]=0x00290000`, `Tag3 [EBX+20]=0x003C8000`, при одинаковом pre-mode Power SHA; отдельная проверка сопоставимости **позиций архива** остаётся открытой. Не подменять её числовой идентичностью postmode/Y.
3. Требуется **TQGrapher→Qt пиксельное отображение**, X/Y scale, диапазон, zoom, cursor и отрисовка/децимация, взаимодействие UI, original plot orientation (четыре режима); другие АЦП/FRange/N/окна измерений не покрыты.
4. Так как source NumPy `log10` не равен гарантированно x87 во всех IEEE Float32 входах, побитовая эквивалентность **всей математической области** не заявляется — конкретные оригинальные массивы PASS.

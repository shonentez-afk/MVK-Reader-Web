# Stage111Z31ES — DeepSeek Harness / Ghidra read-only GetSpectrum: независимая сверка

Дата: 2026-11-17. Ветка: `research/stage111-mvkview-desktop-20261029`.

## Происхождение и границы

Оператор передал текстовый ответ локального DeepSeek Harness, работавшего через `GhidrAssistMCP` на Ghidra 12.2 с открытым 32-битным `mvkview.exe`. Harness сообщил, что выполнял только операции чтения. Результаты **не являются** полным дампом декомпиляции и не удостоверяют правильность всех x87 вычислений.

Локально результаты сверены **совместно по трём закрытым источникам проекта**: `mvkview.idp` (IDR project v3; образ `00400000`), экспорт `Projects.7z` (восстановленные `_Unit115.pas`, `_Unit128.pas`) и `mvk_idr(1).sqlite` (25 404 индексированных функций и 92 767 статических записей call). Совпадение SHA256 для двух PAS подтверждено по индексу `source_files` SQLite; сами IDP, PAS, DFM, EXE и приватная декомпиляция в публичный GitHub не передаются. **Внутренние записи исходного IDP v3 не являются полностью разобранными**: соответствие адресов дополнительно проверено в листинге PAS и SQLite, не выводится из полного IDP AST.

## Подтвержденные факты

1. `007D13D4` — `TMvkChannelStorage.GetSpectrum(var Params:TMvkChannelStorageCalcParams):Boolean` по `_Unit115.pas:17386`; исходные регистры `EAX=Self`, `EDX=Params`, выход `AL=Boolean` (в источнике `007D193E`); `void(int,int*)` — лишь неуточненная оценка Ghidra. Нет двух стековых параметров.
2. Проверка `N=[Params+04]`: `N=0` -> `False` (`007D13F9–007D13FE`); `N>0x40000` -> `Invalid FFT length` (`007D1404–007D141C`); затем `CheckDataAvailability` (`007D1426`). Ограничение минимального N в самой функции этим не доказано, оно может поступать от вызывающего интерфейса.
3. `Params+08` включает отдельную ветвь `GetAdjustedEnvelopeLength` и обработку через `007D1C48` / `007D1E70`; не называть эту ветвь «просто фильтр» без проверки коэффициентов. `Params+18` выбирает четыре исходных расчётных режима. `Params+28` получает `N/2`, `Params+2C` — выходную частоту отсчётов, которая зависит от ветки `Params+08` (обычная ветка — `FSampleRate`; другая — табличные коэффициенты).
4. Логарифмическая ветвь использует `007D15DD–007D1649`, нулевой/недопустимый положительный power bin заменяется битами `0xC3340000` (`-180.0f`). Линейные ветви через `Sqrt` и возможное одно-/двукратное `007D2164`. Полная численная эквивалентность всех режимов не доказана.
5. Структурно `Params+30=OutputMean:Single`, `Params+34=OutputPeakX:Single` **в FFT-бинах**, `Params+38=OutputPeakY:Single`, а не два одинаковых «пика». Спектральная статистика и 5-bin weighted-centroid ранее подробно исследованы в `STAGE111Z9_GETSPECTRUM_ORIGINAL_SUMMARY_AUDIT_AND_COMPARE_RU.md`; `OutputPeakX` становится частотой только после применения экранного `XScale`.
6. **Два прямых статических call site** в `_Unit128.pas` и `calls` SQLite: `00848200` внутри `sub_00848148` (`PageSpectrum` / обновление по UI) и `0084FB03` внутри `TBackgroundProcessThread.Execute` (`0084FA6C`). Возвращаемый `AL` проверяется обоими вызывающими.
7. Фоновый поток (`0084FA6C`) использует `FTaskCode`: 1 -> `GetSignal` (`0084FAA7`), 2 -> `GetSpectrum` (`0084FB03`), затем `TThread.Synchronize` (`0084FAD4`, `0084FB2D`) для синхронизации с GUI. `AddTask` (`0084FA58`) не ставит новый запрос, если `Busy=True`. Источник `AddTask`/расписание его вызовов и реальная привязка этого пути к LIVE не удостоверены; наличие второго call site **не доказывает**, что каждый live-кадр использует его.
8. `get_callers` в первом отчёте Harness вернул только `00848148`: это **неполный набор** относительно оригинального callsite `0084FB03`. Возможно, Ghidra не распознала второй блок как функцию или индекс ссылок отличается; причину пока не установили. Для audit всегда сверять `get_callers` с `get_xrefs_to`, `get_disassembly` и локальными источниками, не создавать функцию и не менять проект без отдельного решения.

## Уже существующее в Core+Qt и открытые задачи

- `mvk_compatible/core/spectrum_metrics_idr_candidate.py` реализует **кандидата** `OutputMean`, `OutputPeakX`, `OutputPeakY` на Float32 power; сохранены ограничения/признаки неаттестованного x87 паритета. По самому отчёту Harness менять формулы преждевременно.
- `mvk_compatible/core/original_measurement_pipeline.py` уже содержит source-derived Mode2, 8 ADC + 2 TACH, 20 ms GUI timer, TCP/10230, source-переходы и read-only ограничения Native; это **не доказанная** реализация оригинального writable `TMVKThread`.
- `docs/research/STAGE111Z31CU_FULL_ORIGINAL_MODE2_MEASUREMENT_AUDIT_RU.md` ранее отражал отдельный background thread и вызовы `GetSignal` / `GetSpectrum`. Новая независимая проверка это подтверждает и уточняет два callsite, а не открывает несуществовавший ранее новый алгоритм.
- **Следующий крупный этап**: получить через Ghidra READ-ONLY полную цепочку `00848E78` -> `00846AD4` -> `008060B0` -> `00807A98` -> `00807F74`, `QueueCommand 00809330`, `SetRate 00809400`, и пути `FreezeUpdate / WriteData / WriteValues` вместе с ошибками `008088A2`, `008088CE`, `008088FA`, `00808923`, а также `TBackgroundProcessThread.Execute`. Доказать байтовые поля кадров и команды по инструкциям, только тогда проектировать воспроизводимый Core+Qt. Реальный I/O, packet injection и device writes запрещены до отдельной проверки и согласования.

## Критерии приёмки исследования

- Адрес -> инструкции -> аргументы/регистры -> конкретные поля и переходы, со ссылками на instruction-address для каждого утверждения.
- Два callsite `GetSpectrum`, четыре исходных режима, bool-возврат, синхронизация фона и GUI — не терять при анализе.
- Отделить VERIFIED_STATIC, STATIC_INFERRED, RUNTIME_UNVERIFIED, MISSING_SOURCE; наблюдение GUI/прибора отдельно.
- Не публиковать приватные IDP/PAS/EXE/BIN/DFM, дампы полного псевдокода, исходные IP и операторские пути в публичном репозитории.

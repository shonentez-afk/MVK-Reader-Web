# Stage111Z.16 — прямая загрузка BIN/TSXML и устранение обрезания панели Qt

Дата: 01.11.2026. Ветка: research/stage111-mvkview-desktop-20261029.
Основной продукт: автономная Windows MVKView Compatible Qt/PySide6, не Web.

## 1. Основание

Пользователь открыл EXE после успешного возврата на GitHub Actions и передал скриншот. В левой панели спектра надписи уходят за границу, а для открытия данных требовался старый экспорт Native R6.1/Stage107 ZIP, которого у пользователя нет под рукой.

Не меняя подтверждённый расчётный FFT, реализовано два независимых улучшения.

## 2. Интерфейс

- Фиксированная ширина Qt панели спектра увеличена с 177 до 244 пикселей. Оригинальный DFM имеет 177, но текущие исследовательские Qt-элементы значительно многословнее. Это адаптация читаемости, а не пиксельная копия Delphi.
- Выключен горизонтальный QScrollArea, а длинным QLabel разрешены перенос и сжатие. Вертикальная прокрутка исследовательских настроек остаётся.
- Кнопки называются кратко: «Копировать», «Сохранить CSV», «Сверить с MVKView…», «Геометрия Canvas»; предупреждения об экспериментальном статусе в Tooltip.
- В главном меню и на кнопке открытия теперь выбирается «Открыть измерение…»: локальный ZIP, BIN или TSXML.
- В одном Qt-сеансе можно сменить исходный BIN/TSXML на прежний R6.1 ZIP, причём несуществующие АЦП отключаются и приборные значения из предыдущего сеанса очищаются.

## 3. Новый строгий reader

Файл: mvk_compatible/core/direct_bin_session.py, класс DirectBinSession.

Принимаются только ОДИН парный локальный BIN+TSXML и, по возможности, соседние АЦП **того же прибора и временной метки**. Возможные имена сопроводительного файла:
- measurement.bin и measurement.bin.tsxml;
- measurement.bin и measurement.tsxml.

Требуется ровно один TSXML с ровно одним Channels/Channel, RealDataType=Single, целочисленным ChannelFrequency от 1 до 1 000 000 Гц, DataLength как число байт Float32, DataOffset как байтовое смещение. Весь объявленный массив должен точно покрывать конец файла; никакого чтения произвольных заголовков и угадывания непроверенных форматов нет. Бинарные отсчёты little-endian IEEE754 Float32, все должны быть конечными (NaN/Inf запрещены). Предельный размер данных — 10 млн значений. DTD/ENTITY, ссылки, неоднозначные sidecar, несходство размера/частоты — отказ. SHA256 BIN и TSXML фиксируются на открытии, а затем перепроверяются при повторном использовании; это предотвращает смешивание изменённых данных.

Для распознанных имен вида MVK...-ADC4-YYYY-MM-DD--HH-MM-SS.bin автоматически связываются только существующие каналы 1–8 с тем же серийным префиксом и timestamp. Если имя нестандартное, выбирается только один файл под условным ADC1, без группировки с другими файлами.

**Ограничение:** источник содержит только объявленные TSXML Single-отсчёты. Это НЕ декодер всех возможных исходных BIN MVKView. Если реальный файл содержит иной тип, структуру, несколько каналов или неподтверждённую калибровку, импорт обязан отказать. Нельзя просто читать любой BIN как Float32.

## 4. Строгая provenance-политика

Исходный экспорт R6.1 по-прежнему требует EXPORT_AUDIT.json, VALUES_ALL_ADC_RECONSTRUCTED.csv, TABLE_LAST_AUX_RECONSTRUCTED.csv и криптографические проверки. Эти ограничения НЕ ослаблялись.

Для прямого BIN+TSXML доступны только временной сигнал и FFT с теми же уже созданными локальными алгоритмами. Исходные измерения не изменяются. Третьоктавные полосы, приборные DSP-статусы и физическую калибровку программа НЕ придумывает: вкладка «Задачи» показывает отсутствие верифицированных AUX/VALUES, ранее выведенные таблицы очищаются. В подписи временного сигнала и спектра добавлены предупреждения, что физические единицы отсчётов не подтверждены.

Только вспомогательные функции waveform_for_zip и spectrum_for_zip получили необязательный sample_provider: исходное ZIP-поведение по умолчанию не изменилось. Ни fft_idr_candidate.py, ни spectrum_metrics_idr_candidate.py не менялись.

## 5. Тесты и GitHub Actions

- mvk_compatible/tests/test_stage111z16_direct_bin_tsxml.py: только синтетические временные сигналы и фальшивые локальные XML/BIN; проверяется one/multi-channel import, чтение BIN или TSXML, смещения, частоты, источник без DSP, NaN/Inf, DTD/ENTITY, symlink, подмена файла, несовпадение групп и строгая изоляция ZIP.
- mvk_compatible/tests/test_desktop_qt.py: GUI-тест чтения одного ADC4, отсутствия данных DSP, графиков/FFT, отключения других каналов, возврата к Native ZIP и соответствия ширины панели 244px.
- Первоначально отдельный модуль GUI тестов ошибочно попал в Linux core; перенесён в Windows Qt-suite. Следующий Windows тест обнаружил несовпадение текста «BIN+TSXML» против «BIN/TSXML», затем исправлены статус и предупреждения о некалиброванных единицах.

## 6. Как проверить на собственном ПК

После успешной сборки:
1. Скачать самый свежий MVKViewCompatible_Stage111_Windows_Preview из GitHub Actions Artifacts.
2. Нажать «Открыть измерение…», выбрать соответствующий .bin либо .tsxml рядом с BIN.
3. Открыть временной сигнал и спектр, выбрать реально доступный ADC.
4. Вкладка «Задачи» должна честно писать, что AUX/VALUES DSP отсутствуют, если выбран прямой BIN.
5. При ошибке DataType, размер/частота или отсутствующий sidecar сохранить сообщение ошибки. Не отключать проверки вслепую.
6. После проверки прямого BIN можно снова открыть прежний проверенный ZIP R6.1.

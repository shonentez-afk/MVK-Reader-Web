## 2. Две подтверждённые точки наблюдения

Статическая дизассемблировка **этого EXE** и восстановленный `_Unit128.pas` независимо совпадают:

| Адрес VA (при базе 00400000) | RVA | Смысл |
|---|---|---|
| `0084B631` | `0044B631` | После выбора текущего канала, чтения `TMvkChannelStorage.FRange` и умножения на ×1/×10/×100; **до** `log10/@TRUNC`. `ESI` = форма. |
| `0084B882` | `0044B882` | Сразу после `fstp dword ptr [esi+62C]`; итоговый `GraphDefaultVScale` сохранён как `Single`. |

В первом breakpoint:
- номер канала `DWORD [EBP−4]`;
- указатель на объект выбранного канала `DWORD [ESI+0x21124+4*channelIndex]`;
- **исходный FRange** `DWORD [channelObject+0x04]` (точные 32-битные IEEE754-биты);
- режим `DWORD [[ESI+0x5A8]+0x0C]` — Tag 0/1/2/3;
- до округления `DWORD [ESI+0x62C]`;
- **фактическое x87 Control Word** — FPU-панель x32dbg, **не автоматически 0x1332**.

Во втором breakpoint:
- итоговый **GraphDefaultVScale** `DWORD [ESI+0x62C]` как hex float32;
- проверить совпадение ESI/индекса канала и при необходимости Control Word.

Для переноса адресов при иной загрузке EXE использовать **фактический module ImageBase + RVA**, не абсолютные адреса без поправки.

В исходной беседе с пользователем создан и проверен ZIP `MVKVIEW_STAGE111Y_CAPTURE_KIT_20261030.zip` (содержит только инструкции, двухточечный x32dbg script, локальный read-only EXE↔IDP verifier и пустой шаблон `MVKVIEW_RUNTIME_X87_GOLDEN_V1`). Исходные EXE/IDP/архивы **в ZIP не копировались**. SHA256 ZIP = `960ac89ac9a3446a85d194f99387fc1da0b62ba2420a28ee3d24d9b5f994887c`.

В исследовательском GitHub репозитории отдельный безопасный скрипт breakpoint находится в `mvk_compatible/research/x32dbg_spectrum_golden_stage111y.txt`, чтобы при следующем чате не потерять точные адреса. Исполняется только в x32dbg с загруженной оригинальной программой и соответствующей базой.

## 4. Границы подтверждения

**Не выполнялась** оригинальная MVKView под Windows в этой Linux-среде (Wine отсутствует); снимок из live x87 FPU и фактические выбранные `FRange`/итоговый `GraphDefaultVScale` ещё **не получены**. Статическое `.data:008C2028=0x1332` по-прежнему нельзя считать измеренным runtime CW.

Для настоящего golden пользователь должен запустить 32-битный **x32dbg** на собственном Windows-компьютере, открыть оригинальное локально сохранённое измерение **без подключения МВК**, поставить две точки и прислать два частных снимка/битовых набора. Не публиковать private source/measurements в GitHub. В коде сравнения уже есть `mvk_compatible/private_x87_runtime_reference_compare.py`, использующий схему `MVKVIEW_RUNTIME_X87_GOLDEN_V1`; даже он не аутентифицирует пользовательский ввод автоматически.

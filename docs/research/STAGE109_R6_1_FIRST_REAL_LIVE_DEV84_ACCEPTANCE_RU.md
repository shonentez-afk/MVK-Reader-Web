# STAGE 109 — первое аппаратное испытание Native R6.1 на МВК01 №84

Дата: 2026-10-29. Источники пользователя: `TEST_2026-10-29_13-32-12.643.7z` и `новый тест 84.pcapng`. Исследовательская ветка `research/stage41-spectrum-chain-20261028`. **Вердикт: LIVE RECEIVE + LIVE BIN SPOOL + FINAL EXPORT — PASS** на одной реальной 30-секундной Windows-сессии. Статус полной копии всех возможностей оригинальной MVKView — **НЕ ПОДТВЕРЖДЕН**.

## 1. Происхождение и целостность

- Исходный архив 7z, SHA-256: `e3f5574eb744710c49b8f79f1cca4d73e705c2f186f6eecd65265e971672e128`.
- Wireshark PCAPNG, SHA-256: `1d1390dc8d4f9a5d38fab89634c122977f01727c863370086a519c2f94eff841`.
- SHA-256 сохраненного `incoming.raw`: `6c40e1dc93666da1a95c9e54758115d90df710abfd2f1a48916d55f36816a03f`; совпадает с `summary.json`, `STAGE108_EXPORT_STATUS.json`, `EXPORT_AUDIT.json` и независимо с первых 69 685 884 байт реконструированного PCAP-потока.
- **Установленная программа:** `Native Stage108 R6.1 / R5.1 Ethernet receive / embedded Stage107 export 0.1`. Windows-хост, проводной Ethernet, выбор NIC index 20, IPv4/10230; прикладных команд прибору нет.

Соединение TCP установлено обычным SYN/SYN-ACK/ACK; первые приборные данные пришли после SYN-ACK приблизительно через 1,1 мс, **без клиентского прикладного запроса**. Приложение сохранило оригинальный RAW без переписывания. Дополнительные 1 288 байт PCAP **не являются доказательством потери** внутри записи: первые 236 байт дополняют штатно усечённый конечный кадр ADC6 (816+236=1052), а ещё 1052 байта — следующий ADC7; эти данные поступили у границы закрытия сессии.

## 3. Приём R6.1

- Время 30.0128155 с, штатное завершение `DURATION_REACHED`.
- `84 855` полностью распознанных кадров: ID264=1; full snapshot 32800=1; ADC1052=61 429; TACH284=15 356; AUX4700=60; PARAM160=270; REG44=7 678; REG76=60.
- Все восемь ADC @ 65 536 отсч/с, два TACH, 60 расчётных обновлений с периодом в среднем 0.500001 с по часам ПК.
- Нет внутренних ошибок фреймера, пропусков индексов ADC, NaN/Inf. 
- Последний RAW заканчивается на **816 байтах неполного ADC6** (ожидаемая длина 1052); эти 816 байт сохранены в RAW и исключены только из финального BIN согласно `VALID_FRAMES_WITH_INCOMPLETE_LAST_FRAME`. Выводы 8 каналов в общей группе закономерно разной длины на один кадр.

## 4. Встроенный LIVE экспорт R6.1

- В `STAGE108_EXPORT_STATUS.json` указано `state=EXPORTED`, `during_capture_bin_spool_verified=true`, исключено 816 байт терминального кадра. Исходный код R6.1 пишет `.bin.partial` во время приёма и сверяет **физические on-disk SHA256** с независимым полным экспортом из сохранённого RAW перед публикацией финальной директории. Само существование transient-файлов во время теста подтверждается программным журналом и логикой проверенного кода, а не независимой съёмкой диска в процессе работы.
- **8 BIN + 8 TSXML**. Каналы 1–5: 1 965 824 сэмпла каждый; каналы 6–8: 1 965 568 каждый. Всего **15 725 824** отсчёта; 62 903 296 байт BIN.
- Каждый отсчёт получен по формуле `float32(float64(raw_float32)*float64(gain_float32))`, индивидуальный `gain` из initial register snapshot той же сессии. **Все 15 725 824 float32 проверены побитово независимым NumPy; 0 расхождений.**
- `VALUES`: 60 строк × 585 столбцов (время + 8×73 значений), **33 600** численных полей проверены с учётом четырёх значащих цифр отображения; **0 расхождений** с независимо разобранными AUX4700. `TABLE`: 39 строк (без первой `sep=|`); все 240 соответствующих ячеек последнего AUX обновления совпадают с VALUES. **19/19 выходных файлов** имеют точные SHA256 из `EXPORT_AUDIT.json`.
- Всего по RAW: **15 759 424 независимых проверки отсчётов и численных значений**, плюс проверка 240 ячеек TABLE, 84 855 записей `frames.csv`, 15 765 `chunks.csv`, 19 файлов экспорта, внутренних архивов ZIP (CRC PASS). Ошибок/расхождений нет. Незавершённых `.partial` в конечном архиве не осталось.

## 5. Оборудование — не путать успешный транспорт с исправностью датчиков

- АЦП1–6: статус `0x00000000` на всех 60 обновлениях. АЦП7 и АЦП8: `0x00000400` на всех 60 обновлениях, напряжение последнего снимка около **18.96 В** и **18.85 В** соответственно — признак обрыва/превышения верхнего порога согласно прежней карте прибора; не объявлять измерения этих датчиков здоровыми.
- В последнем TABLE частота вращения обоих TACH = `0 Гц`, а поле «Х..25 кГц» по всем каналам = 0 **как приборное значение**, не как доказательство физического отсутствия ускорения выше 6 кГц; ранее на №84 наблюдались такие нули.
- Для АЦП4 текущий полный AC RMS (все частоты, без DC) **12.9328 м/с²** против **13.3666** в 11:41 (−3.25%). АЦП6 **18.3302** против **16.3548** (+12.08%). Это разные моменты измерения; разница не доказывает дефекта приложения. **Не путать AC RMS всей полосы с приборным СКЗ в 10–3000 Гц**.

## 6. Точная граница доказательства и следующий шаг

**Подтверждено:** реальный Windows Ethernet R6.1 впервые выполнил весь цикл `connect → read-only capture → stream partial BIN → verify → atomic BIN/TSXML/VALUES/TABLE`, при этом сырой TCP-поток и все проверенные численные значения сохранены корректно. **Не подтверждено:** byte-exact равенство выводу оригинальной MVKView из *той же* сессии, оригинальное форматирование всех статусов, аппаратно-синхронные метки времени VALUES, долгие записи, восстановление после обрыва сети, корректность всей DSP-математики с сырых АЦП.

**Stage110:** переходить от автономной консольной утилиты к интеграции Native-приёмника и реконструированных экспортов в исследовательский интерфейс MVK Reader Web; добавить видимые статусы отказов датчиков, качество записи и отказоустойчивость. Перед стабильным выпуском — отдельная приёмка с более долгим сеансом и сравнением с оригинальной MVKView там, где возможен односеансный эталон. **Stable v0.3.40 не изменять.**

## Как воспроизвести независимый QA

В приложенном компактном пакете `MVK_STAGE109_REAL_LIVE_AUDIT_84.zip` лежат скрипты без производственных данных: `pcap_tcp_audit_generic.py`, `independent_frame_file_audit.py`, `verify_live108_independent.py`, `check_aux_table_and_timeline.py`, JSON-агрегаты и этот отчёт. Первые три умеют проверять произвольную повторную запись с указанием локальных путей/фактического IPv4, четвёртый проверяет структуру TABLE/VALUES. PCAP и RAW в GitHub/QA-пакет не загружаются.

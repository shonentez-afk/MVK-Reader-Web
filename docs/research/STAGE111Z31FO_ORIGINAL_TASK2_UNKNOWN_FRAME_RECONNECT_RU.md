Оригинал `_Unit125.pas:008087BB..0080884C` **не прерывает** приём при неизвестном типе с корректной длиной: регистрирует сообщение, читает весь payload `(size-8)` и возвращается к следующей итерации. Исходный `00807F8B..00808019` отвергает некорректные DWORD-границы и размер.

Оригинал `_Unit125.pas:00807BE3` начинает новый сокет в Stage0; `008089BF` сбрасывает Stage после закрытия; `008089D8..008089EE` может повторно поставить SetRate в очередь; `00807E8F..00807F52` отправляет FIFO-команду через **тот же** сокет до следующего чтения. SetRate=65536 подтверждён прежним настоящим A/B PCAP (36 байт). Изменения не создают новых неподтверждённых аппаратных команд.

## Исправленный Go production

1. `protocol.go`: любой неизвестный, но структурно допустимый frame декодируется как opaque `Frame`, попадает в счётчики и RAW; subsequent PARAM/ADC/TACH больше не теряются из-за искусственного `CaptureOnly`. Некорректная длина по-прежнему fail-closed.
2. `main.go`: для каждого **нового TCP-сокета** действительно вызывается существующий `sourceLiveTask2TX.resetForNewSourceSocket` до привязки соединения. Это устраняет наследование TX Stage1 и случайный пропуск нового оригинального SetRate после реконнекта. В production `sourceTCPLedger.begin` дополнительно сбрасывает старые register validity, framer tail и старый канал preview на переходе между сокетами.
3. В `main_test.go` проверяются unknown-frame + фрагментация TCP + последующий действительный ADC + точная RAW-побайтовая сохранность + отдельный malformed-envelope refusal.
4. В `source_live_task2_tx_test.go` два локальных TCP-сокета проверяют две повторные **одинаковые** оригинальные 36-байтные передачи после **своих собственных** PARAM. В `session_export_test.go` исправлена исторически неверная фикстура: неизвестный корректный тип не является нарушением, некорректная длина — является.

**Права и контроль аппаратных изменений:** настоящий SetRate уже реализован в одном Go socket, но требует явно разрешённого активного режима. Это не ограничение на доступность восстановленной функции: операторская Qt-форма содержит отдельное подтверждение для TX и отдельное переподключение. Изменения не отправляют Flash/Reboot/IP Upload/произвольный WriteReg.

## Статус доказательства

Исходное соответствие для этих двух участков — SOURCE + тестовый localhost TCP. Не утверждать `original_delphi_compatibility_verified=true`, пока нет аппаратной проверки физического МВК01 и сопоставимой оригинальной Delphi-сессии. В частности, остаются непринятыми полный lifecycle очереди команд, точное поведение ошибок и аппаратного ACK, исходные WriteData/WriteValues, FRange/x87 и полная численная E2E-проверка.

**Для CI:** тестировать последний кодовый SHA по всем jobs (Go RX/export, Linux Core, Windows Core/Qt, Windows QPA, EXE), не засчитывать отменённые runs. Старый тест `TestStage108RefusesCaptureOnlyAndKeepsRaw` должен подавать **malformed DWORD length 10**, а не корректный unknown-frame length 8.

Приватные IDP/PAS/DFM/SQLite, исходные EXE и операторские PCAP/RAW/BIN не публиковать.

## Код нового приложения (не использует старый сервер)

- `mvk_compatible/core/signal_idr_candidate.py` — модуль без Qt, HTTP и TCP. Функция `unfiltered_getsignal` возвращает как хронологический обработанный массив, так и точно **перевёрнутый выход функции**. Выделены: удалённое среднее, среднее окна, локальный RMS, происхождение `APP_DERIVED_GETSIGNAL_NO_ENVELOPE_IDR_CANDIDATE`.
- Там же `read_ring_float32`: моделирование кольца float32 по маске; пропущенный ранний участок заполняется нулями, а при некорректных индексах/ёмкости происходит отказ. Это отдельный тестовый механизм Live storage, **не** повод дополнять обрезанный архив BIN нулями.
- `mvk_compatible/core/offline_export.py`: `OfflineSession.waveform(...,display_order='chronological'|'getsignal_buffer')`, `exact_sample(..., display_order=...)`. Курсор в перевёрнутой ветке сообщает и индекс буфера, и **реальный** исходный BIN индекс/время; никакого двойного применения K. AC коррекция ф32.
- `mvk_compatible/desktop/main_window.py`: Qt-переключатель «Архив: хронология BIN» / «Буфер GetSignal: обратный порядок», режим AC по умолчанию как оригинальный DFM, AC+DC по выбору, локальный RMS и удалённое DC. Во втором режиме ось специально подписана как **позиция выходного буфера, не физическое время BIN**. Нельзя утверждать оригинальную визуальную идентичность TQGrapher.
- `mvk_compatible/tests/test_signal_idr_candidate.py`: искусственные доказательные тесты ф32, DC, реверса, безальтернативной обработки отсутствующей огибающей, кольцевого wrap/zero-prefix, метрического курсора в обоих порядках и отказа при обрезанном офлайн BIN.
- CI `.github/workflows/stage111-desktop-offline.yml` расширен для Python core и Windows Qt; отчёт о результате брать только после проверки завершённых GitHub jobs и артефакта, не по промежуточной строке pytest.

## Важное незавершённое, не скрывать

Оригинальная огибающая — **не** простая амплитуда/модуль отсчётов. Из локального IDR:
- `GetAdjustedEnvelopeLength:007D1158` использует таблицы `8CD980`, `8D2A58`, `8CDA00`, `8CDA2C`.
- `007D1C48` выбирает фильтр/дециматор, `007D1D50` свёртку на таблице коэффициентов `8CDA58`;
- `007D1E70` выполняет квадратурную пару свёрток и модуль `sqrt(I²+Q²)`; для корректной реализации нужны коэффициенты, кратность выходных частот и эталоны.
- Пока код `envelope_code!=0` выдаёт `NotImplementedError`. **Не допускать незаметного упрощённого приближения.**

Кроме того, надо адресно проверить, как `TQGrapher` отображает обратный выход, как `GetSignal` получает позицию из режима Archive, а также точную x87 совместимость `float32` при длинных записях. Пока GUI обеспечивает *два явно помеченных порядка*.

## Дополнительные оригинальные опоры для Stage111D — TQGrapher cursor

Приватно проверен также `_Unit115.pas:007CA75C–007CAAFB` (`TQGrapher.UpdateCursor` и `sub_007CA76C`) и `_Unit128.pas:00844B90`:
- При перемещении мыши используется **пиксель** по горизонтали, а не частота или абсолютный индекс; `sub_007CABE4` считает `Trunc((pixelX-PixelLeft)*stoiM+stoiC)`, затем ограничивает индексом серии.
- Серия имеет `DataSize`, `XStart`, `XScale`, `YScale`. Формируемый X курсора = `index*XScale+XStart`; это уже позволяет рассчитать точное значение для снапа.
- `SpecGrapher.FindPreciseXValue=1` устанавливается при инициализации; если пиксель соответствует нескольким FFT-бинам, оригинал ищет **максимум** в интервале от `index(pixel)` до `index(pixel+1)-1`, а не просто ближайший бин.
- `SpecGrapher.CursorAveraging` меняется в `_Unit128.pas:00848252–0084828C` между `1` и `3`; при >1 курсор использует RMS соседних отсчётов. Подписи проходят форматирование `007B2090`, окончательные правила округления/подписи ещё предстоит сверить.
- Не путать этот спектральный **pixel-peak snap** с уже работающим в Stage111C точным **BIN-сэмплом осциллограммы**. Следующий шаг — реализовать независимо тестируемую функцию pixel-to-FFT-bin, затем подключить её к Qt. Без оригинального DFM/экранного сравнения всё ещё метка `CANDIDATE`.

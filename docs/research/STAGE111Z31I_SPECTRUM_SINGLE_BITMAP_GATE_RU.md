# Stage111Z31I — единая программная отрисовка исходного спектра

Дата: 05.11.2026. Ветка: `research/stage111-mvkview-desktop-20261029`.

## Зафиксированный порядок разработки

**Без перехода к восстановлению страниц, меню и отдельному UX-аудиту.** 1) Довести **СПЕКТР** до совпадения с оригиналом по числам, графику, шрифтам, физическим пикселям, курсору, масштабам и действиям. 2) После полного спектра завершить **ВРЕМЕННОЙ СИГНАЛ** и `GetSignal`, таймбазу и курсор. 3) Затем **РАСЧЁТНЫЕ ДАННЫЕ** и приборные результаты, коэффициенты, значения и экспорт. 4) Только после завершения указанных функций возвращаться к отсутствующим страницам и остальному UI. Ранее подтверждённые 4 режима GetSpectrum и Native Go R6.1 не переписывать.

## Перепроверка исходного алгоритма

Приватные оригинальные `_Unit115.pas`, `_Unit128.pas`, `mvkform.dfm` проверены локально из предоставленного `Projects.7z`. Оригинальные дизассемблированные файлы и измерения не публиковались.

- `007CACB3..007CACD4`: создаётся единый программный белый `TCo2Draw.TBitmap`, `pf32bit`.
- `007CACFC..007CB086`: RGB `#C0C0C0` и горизонтальная/вертикальная сетка через `TCo2Draw.LineTo`. Коэффициенты сетки хранятся как `Single`.
- `007CACE4..007CB12F`: прозрачная кисть и `TCanvas.TextOut` по исходному TFont (этот Win32-шрифт/DPI ещё не восстановлен, **не считать пиксельно совпавшим**).
- `007CB12F..007CB3E5`: две возможные `TQGRSeries`, первая — чёрная (исходный `Create` устанавливает `Color=0`), свёртка значений в min/max экранного столбца, рисование соседних штрихов в порядке ближайшего экстремума; второй ряд требует отдельной приёмки, когда DataSize ненулевой.
- `007CB3FF..007CB4A1`: чёрная 4-сторонняя рамка `PixelRect`, также через `TCo2Draw.LineTo`. После этого единый `TCanvas.Draw`.
- `007C98B4/007C9A30/007C9808`: собственный scanline AA по центральному и двум соседним пикселям. Это **не Qt QPen**.

## Внесённый код

- `mvk_compatible/core/tco2draw_raster_candidate.py`: опциональное безопасное RGB-композирование поверх **копии существующего RGBA холста** без изменения исходных входов и ранее отрисованных слоёв.
- `core/tqgrapher_composite_source_candidate.py`: один холст `white → gray grid → [TextOut ещё открыт] → black minmax TQGRSeries → black frame`. Порядок, исходные цвета и алгоритм обработки столбцов базируются на оригинале; физический PixelRect рассчитан через существующую source-derived `source_paintbox_registration` с **внешними измерениями** FontMetrics.
- `desktop/main_window.py`: **без новых вкладок и без дополнительных органов управления**. Когда на SHA-проверенном локальном оригинальном Power/Y включены уже существующие исследовательские опции «Сетка TQGrapher», «Растер TCo2Draw», «Кривая TQGRSeries», автоматически собирается **одно** RGBA Qt ImageItem. Обычная Qt-кривая в этом сочетании скрывается, чтобы не было дубля. При любом переключении старая визуализация и неизменные Float32 восстанавливаются. По умолчанию всё OFF, архив и Native не затронуты.
- `tests/test_stage111z31i_tqgrapher_composite.py`: проверка цветов, последовательности слоёв, пика среди 131072 Float32, копирования исходного холста, границ и fail closed.
- `tests/test_stage111z31i_qt_composite.py`: синтетические SHA-verified эталоны Tag0..Tag3, переключение и зум, один растр, неизменные Y и summary, отсутствие попадания экспериментального слоя в архив.
- `.github/workflows/stage111-desktop-offline.yml`: новый Qt файл участвует в отдельном Windows Qt DPR=1.5 gate.

## Что НЕ завершено: обязательные спектральные ворота

1. **Числа:** зафиксирован bitwise паритет GetSpectrum всех 4 режимов по имеющимся оригинальным данным; другие Fs/N/режимы, архив same-session, GetSpectrum для другого окна требуют доказательств, не выдавать частный PASS за универсальный.
2. **Пиксели:** пока только исходно-ориентированный алгоритм. Нужны точный Win32 runtime `TPaintBox.PixelRect`, `TCanvas.Font/TextWidth/TextHeight`, Windows PPI-awareness 150%, оригинальные Tick labels/FormatFloat, и сравнение попиксельной карты того же Tag0. Внешние измерения Qt FontMetrics — **НЕ исходный TCanvas**.
3. **Цвет/кривая:** проверить вторую `TQGRSeries` для случаев с ненулевым размером, точный x87 и `TCo2RGBA` физический порядок каналов.
4. **Работа:** подтвердить оригинальные пиксельные курсоры/crosshair, масштабы, скролл, меню спектра, экспорт/копирование, envelope и частоту по аппаратному same-run.

Не объявлять Spectrum 1:1, пока все этапы выше не подтверждены. Не просить пользователя заново получить уже сохранённые Tag0..Tag3 Power/Y. Исходники оригинала и данные пользователя не загружать на GitHub/CI.

# Stage111Z31FN — жизненный цикл исходного приёма Task=2

Дата: 18 ноября 2026. Ветка `research/stage111-mvkview-desktop-20261029`.

## Верифицированная исходная основа: три приватных источника

Сверено совместно: `/mnt/data/mvkview.idp` (IDR project с адресами и типами), `/mnt/data/Projects.7z` (декомпилированный Pascal `_Unit125.pas`, дополнительные `_Unit115.pas`, `_Unit128.pas`, `mvkform.dfm`) и `/mnt/data/mvk_idr(1).sqlite` (25404 функции, 92767 вызовов, 95 событий, `quick_check=ok`). Все 4 исходных PAS/DFM сверены с SHA256/размером `source_files` SQLite **4/4**.

По `TMVKThread.Execute` (`00807A98`, `_Unit125.pas` строки 13493–14654):

| Адрес | Доказанное действие |
|---|---|
| `00807BE3` | При создании сокетного потока `Stage:=0` |
| `00808617` | Первый содержательный корректный PARAM переводит `Stage=0→1`, без требования полного PARAM/калиброванного BIN |
| `0080872D–00808762` | Для `Task=2` при `StatusCells[0]>0` — `Stage:=3`, локализованное `thrSystemError` |
| `008080C5` | Получение ответа `DENIED` вызывает исключение `errOperationDenied` независимо от того, отправлялись ли команды |
| `008089BF` | При выходе/разъединении `Task=2` сбрасывает `Stage:=0` |
| `00808779–00808786` | `Stage=1→2` относится к `Task=0`, но НЕ к `Task=2` |
| `00808882–00808979` | Причины ошибок TCP: `errDisconnected`, `errNotResponding`, `errCannotConnect`, `errTransferError`, затем выход из соединения |

Нюанс: `StatusCells` в оригинальном Delphi инициализируется `0xFFFFFFFF`, что могло формально выглядеть как системная ошибка даже до получения двух реальных слов регистра. В нашем совместимом приёмнике такой неизвестный код **не** объявляется измеренным аппаратным отказом. Выставляется отдельный `original_unobserved_ff_sentinel_risk`, а подтверждённый `Stage=3` — только после реального PARAM с Valid[0x1006] и Valid[0x1007].

## Изменения в рабочем коде

- `source_original_task2_lifecycle.go`: независимая read-only модель для Task2, у которой `Stage` допускает только **0, 1, 3**, с переносом `last_live_stage` и сбросом `Stage=0` при конце сокета. На новом TCP-сеансе не переиспользуются старые Stage/Status0; повторные PARAM начинают новый переход. Учёт ACK остаётся временным и не приписывается исходящей команде.
- `monitor.go`: после уже сохранённого без изменений RAW и принятого кадра RX живёт отдельная Stage-модель; **пассивный DENIED также останавливает Task2 через `errTask2SourceDenied`**, а не только выдаёт предупреждение. Денial не переводит правильный кадр в `InvalidFrames` и не создаёт второй сокет/прикладную TX. В ранее разрешённом режиме SetRate доказательство TX также учитывает DENIED.
- `main.go`: каждый действительный TCP-connect начинает новый Stage0, завершение сбрасывает Stage0; оригинальные Go классы сетевых ошибок сохраняются в `last_end_reason`. Отличает операторскую остановку от сетевой ошибки.
- `live_progress.go`: атомарный текущий статус включает `source_original_task2_stage` с источником параметров, действительным Status0, классом stage/error/denial и флагами, что это **не фактически запущенный Delphi-поток**.
- `original_task2_stage_receipt.py`, `native_r6_live_status.py`: Core проверяет допустимые 0/1/3, действительные счётчики PARAM/ACK/DENIED, `source_system_status0_valid` против 14 реальных StatusCells, стадии нового сокета, отсутствие необоснованного Stage3 и поддельного физического TX. Отсутствие всего поля у старого формата допустимо, частичный/неверный — запрещён.
- `main_window.py`: на текущем `PageStatus` обновляется и очищается `sourceOriginalTask2StageProof`; новый сеанс/Stop/отказ удаляют старую Stage-доказательность. Исследовательские кнопки в пользовательский интерфейс не добавляются.

## Регрессии

Go тесты: Stage0→1 по частичному PARAM; 0→1→3 по реальному Status0=42; подтверждённая ошибка остаётся Stage3 даже если следующий PARAM очищает Status0; неизвестный FF-сентинел не считается физически измеренной ошибкой; ACK не подтверждает SetRate; после disconnect Stage0; второй сокет не наследует Stage1; пассивный DENIED завершает источник и сохраняет полные RAW байты без `InvalidFrames` или TX.

Core тесты: валидные Stage1/Stage3 и закрытый Stage0 после DENIED; новый сокет с уже старым кумулятивным счётчиком PARAM; отказ от Stage2, Stage3 без валидного Status0, фальшивой Delphi-приёмки, ошибочных bool/u64, отказа от указания FF sentinel.

CI: 5 jobs (Linux Go RX/export, Linux Core, Windows Core+Qt, Windows QPA, Windows autonomous EXE) должны пройти для последнего кодового SHA. Не считать PASS по описанию в документах.

## Ограничения

Это совместимая модель **на основе подтверждённого исходного алгоритма**, а не исполнение оригинального Delphi `TMVKThread` и не численный паритет на реальном МВК01. Очередь команд, различия сетевых ошибок, подтверждение исходных команд ACK, запись WriteData/WriteValues, FRange/x87 и полная аппаратная E2E-проверка остаются отдельными непроверенными этапами. Аппаратные команды SetRate/IP/Flash/Reboot **по умолчанию отключены**. `original_delphi_compatibility_verified=false`. Ни один оригинальный PAS/DFM/IDP/SQLite или RAW/PCAP не публиковать в GitHub.

# Stage111B — восстановление GetSpectrum: mean, float32 FFT и нулевые нижние бины

**Дата:** 2026-10-29. **Ветка:** `research/stage111-mvkview-desktop-20261029`.
**Статус:** новое автономное вычислительное ядро + Windows Qt переключатель; не принято как точный оригинальный Delphi FFT. Нет обращений к приборам, нет изменений main/v0.3.40.

## 1. Новые факты, непосредственно проверенные в оригинальном IDR (оригинальные файлы в Git НЕ копировать)

| Опора исходника | Наблюдаемое действие | Статус |
|---|---|---|
| `_Unit115.pas: GetSpectrum 0x007D13D4` | Перед FFT **всегда** вызывает `sub_007D2344` на `0x007D14B3` | подтверждено |
| `_Unit115.pas: sub_007D2344 0x007D2344` | Последовательный сумматор с записью **float32 на каждой итерации**, деление на N, вычитание среднего с записью float32 | подтверждено |
| `_Unit115.pas: 0x008C1064` | Инициализация таблицы 262144 float32 Hann RMS, делитель `sqrt(1.5)`, период 262144 | подтверждено |
| `_Unit115.pas: 0x007D1FE8` | Float32 окно -> interleaved complex FFT -> `Re²+Im²` для первых **N/2** элементов без Nyquist | подтверждено |
| `_Unit115.pas: 0x007CC198, 0x007CC3F8` | Float32 iterative radix-2, bit reversal, угол **+2π**, twiddle recurrence, ненормированная прямая FFT | подтверждено |
| `_Unit115.pas: 0x007D158B..0x007D15BC` | `Round(0.5*N/fs)` и `call 0x007B1CF0(2,value)`, затем обнуление первых `k` спектральных элементов | подтверждено |
| `_Unit114.pas: sub_007B1CF0 0x007B1CF0` | **Unsigned Max(eax,edx)**, а не степень числа. Следовательно **k=Max(2,Round(N/(2*fs)))** | подтверждено |
| `_Unit115.pas: 0x007D15DD..` | Режим 0: `10*(fn(P)-2*fn(N/2))`; при `P<=0` число `-180.0` | подтверждено; основание `fn` требует отдельного тела |
| `_Unit128.pas: 0x0084ACDB..` | Тот же helper `0x00447DB8` в алгоритме выбора 1/2/5/10 для автоматической шкалы. Согласуется с `log10` | сильный косвенный аргумент, не побитовая проверка |

Для штатной частоты 65536 отсч/с и штатных FFT N<=262144 **k=2**: первые два FFT бина нулевые, log mode выводит -180 дБ в обоих. Раньше в Stage111A занулялась только DC-ячейка, а вычитания среднего вовсе не было. Оба отличия исправлены.

## 2. Фактически реализованный код

- `mvk_compatible/core/fft_idr_candidate.py` — независимый от Qt/HTTP модуль: `mean_center_float32`, `idr_hann_rms`, `fft_idr_float32_real`, `idr_power_spectrum`. Построен с учётом указанных адресов, **не** является извлечённым проприетарным кодом.
- `mvk_compatible/core/offline_export.py`: `OfflineSession.spectrum(...,backend='idr_float32')`; `OfflineSession.exact_fft_bin(...,backend=...)`; `compare_fft_backends`. Все штатные расчётные поля **по-прежнему** читаются из AUX4700/VALUES, а не из этих вычислений.
- `mvk_compatible/desktop/main_window.py`: два явно подписанных режима **«IDR float32 · реконструкция»** и **«NumPy · контрольный расчёт»**, кнопка **«Сравнить FFT»** и сообщение о снятом среднем. Курсор берёт точный FFT бин выбранного backend (а не другой расчёт).
- `mvk_compatible/tests/test_fft_idr_candidate.py`: прогоны степени двойки, window RMS, float32 последовательного среднего, синусоид, сравнений двух backend, нулевых первых двух бинов, режима -180 дБ, проверки источника/меток.
- `.github/workflows/stage111-desktop-offline.yml`: на Linux и Windows запускаются **оба независимых core QA набора**, Windows Qt отдельно в собственном процессе. Экспериментальный EXE собирается только после PASS.

## 3. Граница доказательств (строго)

Результат синтетического сравнения с NumPy **не доказывает** совпадение с оригинальным MVKView. Компилятор Delphi/x87 использует 80-битные промежуточные регистры; использованная NumPy-векторизация сохраняет float32 на структурных границах, но не воспроизводит каждую инструкцию и порядок округления x87. Даже в режиме `idr_float32` остаются кандидаты:
- точная таблица `Cos` из Delphi/RTL;
- поведение `0x00447DB8` (log base, обработка нестандартных чисел);
- `FRange` в оригинальном `TMvkChannelStorage` и фактический входной буфер архива;
- режимы огибающей `GetAdjustedEnvelopeLength` и фильтры;
- формат/действия `TQGrapher.UpdateCursor`, оригинальный экспорт результата FFT;
- побитовая проверка на одинаковом BIN + N + типе + временном окне в оригинальной MVKView.

Новые диагностические значения помечаются `APP_DERIVED_FFT_MVKVIEW_CANDIDATE`. **Никаких тихих замен штатного DSP**; при `0x400` неисправность остаётся видимой.

## 4. Локальная и CI регрессия

Перед загрузкой кандидата локально проверены `19` существующих тестов Stage111A + `15` независимых FFT тестов = `34/34 PASS`. Для новой ревизии GitHub добавлены отдельный интеграционный тест сеанса и проверка низких бинов; окончательное число и статус **сверять по GitHub Actions**, поскольку код CI может отличаться от локального.

Первоначально Windows CI показывал `37 passed`, но job завершался с кодом 1 **после** pytest — такой прогон нельзя считать PASS. После этого разнесены Qt и core тесты по отдельным процессам; смотреть успешные job exit codes, а не только строку pytest.

# Stage107 — R6 автономный 8-канальный BIN/TSXML и VALUES/TABLE: реальные записи №84

**Дата:** 2026-10-29. **Статус:** OFFLINE IMPLEMENTED & INDEPENDENTLY VERIFIED, не объявлять полным побайтовым клоном MVKView. Стабильная v0.3.40 **не изменена**. Прибор №84 использует TCP/10230, серийник из регистрового снимка **MVK00000043**. Весь материал построен на уже сохранённых данных; **новых сетевых соединений и команд приборам не было**.

## Реально выполнено

В репозитории в `tools/research/native_tcp10230_stage107_offline_export/` лежит **полный исходный код** standalone offline Go-программы `MVK_Stage107_Offline_Exporter_Windows_x64.exe`: CLI + интерактивный запуск двойным щелчком, 8 каналов с индивидуальным gain, fail-closed экспорт, CSV CP1251, TSXML CP1251, регистровые таблицы, тесты и независимый Python/NumPy-проверяльщик. **10/10 текстовых файлов сверены по GitHub Blob SHA с локальным git hash-object**. Binary EXE и входные промышленного характера RAW/PCAPNG не загружать в GitHub.

Вход **трёхфайловый**: `incoming.raw`, `frames.csv`, `summary.json` одного и того же теста R5/R5.1; исходный SHA256, полный размер, порядок/поля всех кадров сверяются. Обязательны ID264 с `VAST_MVK` и первый PARAM32800 с полной картой 0x4000 регистров, иначе нельзя доверять калибровке. Gain = `Float32LE` из регистра ADC `0x0100+0x0100*N+0x0E`. Конверсия: `float32(float64(rawF32)*float64(gainF32))` для каждого 256-сэмплового ADC кадра. По 8 АЦП строго контролируются Fs и непрерывные индексы с шагом 256. При изменении gain/чувствительности, NaN/Inf, неправильном источнике или любом разрыве — **отказ**, частичные файлы не публикуются; весь экспорт атомарно появляется одной директорией только после валидации.

На каждый исходный тест сформировано **8 BIN + 8 TSXML + 60-строчный VALUES × 585 граф + итоговый TABLE + TIMELINE.json + EXPORT_AUDIT.json + предупреждения**. Названия 73 колонок VALUES взяты из оригинального MVKView пользователя, без внешних допущений. Данные берутся **не из имитации DSP**, а из оригинальных AUX4700, после каждого кадра фиксируется 76B tick по 0x3000/0x3100. Времена VALUES — часы ПК в момент приема этих кадров (из `frames.csv`, перевод оператором указанного UTC offset); они **не являются аппаратно синхронизированным timestamp сэмпла**. Длительность и DataLength в TSXML точно следуют количеству BIN отсчётов, `DateTime` основан на конце сеанса R5/R5.1, не на нажатии MVKView. Формат GetValueText для отказов не воспроизведён: при неисправностях остаётся HEX статус; в тахометрическом TABLE «Наличие импульсов» намеренно пусто.

## Что нельзя утверждать

1. **НЕТ точного оригинального MVKView BIN/TSXML этих же двух live-сессий**, а значит побайтовая идентичность его внутреннему BIN writer **не доказана** (доказана идентичность математической конверсии из RAW с K настоящего сеанса).
2. `VALUES/TABLE` — **восстановленный CSV-подобный вывод**, реальные регистровые числа 1:1 из AUX4700, но пользовательские кнопки, разные текстовые сообщения статуса и алгоритмы округления MVKView требуют сверки по односеансному оригинальному экспорту; время ПК не равно времени DSP.
3. Тахометрические BIN, длительное логирование, переподключения, работа с недостающей initial calibration и сменой частоты отдельно не реализованы (fail-closed). **Не отправлять** rate/modbus/config/write команды прибору ради этих проверок без отдельной авторизации.

## Совместное восстановление Go + Core + Qt

1. Go нативный приёмник поддерживает `-source-task0-config-read=true`. Режим запускается лишь с `-approve`, выбранным Ethernet `-local-ip`, конечным тайм-аутом, ограниченным RAW и локальным файлом штатной остановки. Он не создаёт исходящий SetRate/Flash/Reset, не выполняет автореконнект или BIN экспорт, и завершает с точной причиной `SOURCE_TASK0_CONFIG_READ_COMPLETE` после первого корректного непустого PARAM.
2. Исходный входящий RAW и его SHA256 сохраняются и проверяются независимо. Отдельная локальная `SOURCE_TASK0_CONFIG_IP_READ.json` содержит метаданные Task0 и только **13 безопасных IP-регистров** с точными little-endian байтами. SSID и пароль Wi-Fi в этот JSON не включаются. Сырой RAW остаётся приватным на ПК пользователя.
3. Python Core повторно разбирает входящий RAW, проверяет полный SHA, длину и счётчик PARAM, отсутствие аппаратных TX, полный список допустимых исходных адресов, достоверность каждого показанного регистра. Любое расхождение отклоняет результат целиком; отсутствующие поля остаются неизвестными.
4. Исходная кнопка `bConfigDownload` на PageConfig Mode4 подключена к отдельному асинхронному Qt обработчику. Оператор выбирает Ethernet и **явно подтверждает** разрешение на TCP/10230. После успешного Task0 существующая `tabConfigBasic` показывает только реально полученные little-endian значения, никакие виртуальные регистры не создаются. Смена IP не может унаследовать прежний ответ. Upload/Reset/Flash остаются заблокированными.
5. Автономные Go loopback, Python Core и Qt QWidget тесты не подключают физический прибор и не пересылают приватные конфигурации в GitHub.

## Что остаётся открытым

Эта работа восстанавливает **пассивную Task0 ветку чтения после выбора IP**, но не аппаратные задачи записи IP/Flash/Reset. Численное совпадение всей оригинальной `TMVKThread` Mode2, фактическая физическая передача/приём на МВК01, byte-for-byte исходные BIN/WriteValues/GetSpectrum и оригинальное полное отображение всех полей требуют отдельной аппаратной проверки. `original_delphi_compatibility_verified=false`.

Не загружать `mvkview.idp`, `Projects.7z`, `mvk_idr(1).sqlite`, PAS, DFM, исходный RAW, PCAP, пароли и реальные IP оператора в GitHub.

## STAGE111Z31FA — исходное форматирование IP и защита единственного живого TCP-сеанса

Из дополнительно сверенных `_Unit115.pas` и `_Unit114.pas` архива `Projects.7z`, индекса SQLite и IDP подтверждена цепь `TMvkCellList.GetValueWithFmt 007CF3C4 → sub_007CE6E4 → sub_007B29D4`. Исходный формат для типов 7 (IP) и 15 (Netmask) формирует запись с точками в порядке UInt32 бит 31..0. Поэтому Core отображает подтверждённый DWORD из RAW как `A.B.C.D`, сохраняя оригинальные `raw_hex_le` в проверенном локальном снимке; Modbus-порт типа 2 отображается как UInt32 decimal; непроверенные advanced IDs остаются HEX, без догадок и локальных ложных названий.

Вторая проверенная ветка: если пользователь нажал «Измерить», но ещё **не разрешил** Native TCP, повторное нажатие «Отключить» аннулирует прежнее окно согласия. Поздний ввод Ethernet/разрешения в старом окне больше не запускает сокет. Пока отдельный Task0 читает прибор, Measure не создаёт второе TCP-подключение; обратное тоже запрещено. Это защитная надстройка совместимого приложения, а не утверждение о несуществующем оригинальном TIdTCPClient. Покрыто реальными Qt-widget регрессиями, Core форматными тестами и сохранённым Go loopback. Никаких скрытых подключений/Flash/записи конфигурации.

## STAGE111Z31FB — ошибка исходного Task0 и локальный DefaultConfig.txt

В оригинальном `_Unit128.pas` `Tmvkform.bConfigDownloadClick 008495A8` после `TMVKThread.WaitFor 0084965E` проверяет `TMVKThread.StatusIsError +400CC` на `0084967A`. При ошибке исходный `TWindowMan.SpawnError 008496CD` сообщает об ошибке чтения, затем `008496D2..00849718` **проверяет и загружает локальный** `AppPath/DefaultConfig.txt` через `TMvkCellList.LoadValuesFromFile`. Если файла нет, `0084971F..00849760` выводит отдельную ошибку `errNoDefaultsFile`. При успехе показываются полученные регистры и `StatusCellList.GetValueText(0)`; поток освобождается и статус UI обновляется.

В совместимом Qt теперь имеются отдельные сигналы `readStarted`, `readCompleted`, `readFailed`. После разрешённого нового TCP-сеанса все старые device-поля **сразу сбрасываются**; неудавшееся чтение больше не оставляет прежний результат как текущую конфигурацию. Если действительный локальный `DefaultConfig.txt` присутствует рядом с исполняемым приложением, существующий Core-парсер исходного формата безопасно загружает его. На странице явно показано **«ТОЛЬКО локальный DefaultConfig.txt — ЭТО НЕ конфигурация подключённого прибора»**. Если файла нет или повреждён, значения остаются неизвестными. Приватные значения никуда не отправляются; аппаратные write/Flash/reboot не включаются. Проверка включает Core source-path и настоящие Qt-виджеты с локальным синтетическим файлом.

Ни один локальный fallback не считается сетевым подтверждением Task0 и не разрешает публикацию неизвестных значений. Оригинальная полная численная/аппаратная идентичность пока не доказана.

## Противоречия/неподтверждённые тезисы документов

1. В отчёте и `unknowns` есть утверждение/гипотеза об «одном
   оригинальном канале» в противовес «ADC 1–8 Compatible».
   **Не принимать.** На ПУСТОМ экране вообще нет каналов, и это
   ничего не говорит о числе активных ADC во время измерения.
   В source DFM/расчётах каналов есть отдельная модель. Проверять
   только на сопоставимых исходных измерениях.
2. Фраза «состояние enabled/disabled нельзя определить без нажатия»
   **не является общим ограничением**: часто доступны Win32
   `IsWindowEnabled`, `WM_GETFONT`, UIA свойства и VCL/DFM
   метаданные без какого-либо действия. Скрытые внутренние Delphi
   объекты могут не иметь доступного HWND, поэтому результат
   фиксировать как UNKNOWN, а не включать автоматически.
3. Отчёт использует «БАСТ» для логотипа и содержит
   «constantes полюсов» в одном подзаголовке; это **не
   верифицированные source runtime строки**. В присланном ранее
   сравнительном изображении пользователь видел «ВАСТ» и
   «частотные полосы и др.». Не заменять строки рабочего Qt-кода
   на явные описки документа, не скрывая разночтение.
4. Действие кнопок на самом оригинале в рамках данного захвата
   **не выполнялось**. Предположение о пути Mode2 или каких-либо
   сетевых командах не доказывается UIA. Для Qt после CP
   подтверждены только локальные Core Mode1/4/6 и открытие
   consent-only capture dialog в тесте со stub — НЕ hardware.
5. SHA256 оригинального raw PNG в `manifest` прямо равен
   `pending`, поэтому автоматическая количественная пиксельная
   парность невозможна, даже с предыдущим screenshot-composite
   двух разных окон. Оригинальный screenshot в временной папке
   оператора нельзя считать доступным на GitHub.

## Следующий правильный крупный шаг

- Взять **отдельный raw PNG** оригинального idle экрана
  (не compositor/resized, SHA256 вычислен), фиксировать desktop
  resolution, DPI, Win32 `GetWindowRect`, `GetClientRect`,
  TPageControl bounds и state до любого действия.
- Запустить НОВЫЙ CP EXE при том же разрешении/Qt scale. Снять
  native Qt screenshot и метаданные `devicePixelRatioF`,
  client/control rectangles; только затем считать пары
  геометрических/цветовых отклонений.
- Исходные TImage картинки для фона/логотипа можно загружать
  **локально, в память**, существующим приватным DFM loader.
  Для кнопок/таба нужен локальный безопасный imagelist extractor
  с provenance, не публикация vendor байтов.
- После согласия оператора исследовать **безопасные** экранные
  маршруты открытия файла и просмотра конфигурации; приборные
  измерения/Upload/Download/Reset/CalibStart/Write не запускать.
- Затем совместный Core+Qt acceptance на одном архиве для
  PageAdc/PageSpectrum, а не новая теоретическая работа по FFT/
  FRange/Power→Y, уже принятая раньше.

**Приватность:** не публиковать оригинальные пути аккаунта,
локальный каталог записи, IP-адрес оборудования как операторскую
конфигурацию, идентификаторы живого процесса или HWND,
vendor bitmap/png, оригинальный EXE/DFM/IDP/BIN. В публичной ветке
остаются только обобщённые наблюдения, контрольные ограничения
и исходно независимые Qt-тесты.

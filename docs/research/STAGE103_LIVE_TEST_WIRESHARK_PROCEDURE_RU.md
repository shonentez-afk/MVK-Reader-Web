# Stage103 — запись Wireshark при первом испытании R5.1 на приборе

Для первого испытания диагностического клиента MVK10230 R5.1 рекомендуется параллельный пассивный захват Wireshark. Задача — зафиксировать установление TCP-соединения к порту 10230, направления и объём передачи, TCP retransmissions/резкие закрытия и проверить отсутствие прикладных сообщений от клиента. Wireshark сам не должен формировать испытательные пакеты.

1. На Windows ПК с разрешением ответственного за производственную сеть запустить Wireshark и выбрать **тот же Ethernet-интерфейс**, который затем будет выбран в R5.1 (не Wi-Fi/VPN).
2. Capture filter: `tcp port 10230 and host <IP_прибора>` (заменить адрес на фактический, не включать угловые скобки); если сомневаетесь, можно выбрать только `tcp port 10230`.
3. Начать capture **до** запуска подключения R5.1 (за 3–5 с), потом выполнить R5.1 15 секунд, остановить capture после завершения.
4. Сохранить полный `MVK10230_TEST.pcapng` и отдельно `MVK10230_TEST_RESULTS.zip`; передавать приватно, не публиковать сырые данные и адреса предприятия в GitHub.
5. При возможности сделать *отдельный последовательный* capture оригинальной MVKView, не подключать обе программы одновременно к возможно одноклиентному прибору.
6. При анализе учитывать: TCP handshake SYN/SYN-ACK/ACK и TCP ACK — обычный транспортный обмен, их наличие **не означает** отправку прикладных команд MVK. Диагностический клиент делает connect→read без MVK-запросов. Проверять `tcp.len > 0` в направлении клиент→прибор. Для исключения влияния соединения соблюсти разрешённый технологический режим.

Стабильная v0.3.40 не изменяется. На момент инструкции живой тест прибора не выполнен.

| 007D17E7 | `[EBX+2C]` | `00010000` | Fs = 65536 Гц |

## 2. Структурная и численная верификация именно этого случая

- В файле **131070 ненулевых значений, ровно два нулевых начальных бина**, NaN/Infinity и отрицательных значений нет.
- Ранее предоставленный `after_power(1).bin`, снятый на `007D154B`, и новый `summary_power.bin`: **131070/131072 битовых совпадений**, различаются только бины **0 и 1**, которые оригинал занулил. Это сильная дополнительная согласованность двух этапов обработки для Tag0. Она не аутентифицирует самостоятельно Win32 процесс/вызов.
- Исходные границы summary: `first=max(2,round(262144/(2×65536)))=2`, `last=trunc(262144/2.56)=102400`. По исходному коду `sum(P[k])` идёт последовательным `Float64` (не `np.sum` с pairwise редукцией).
- Дискретный максимальный бин в расчётной полосе — **15200**; пять бинов `15198..15202`, сумма этих мощностей после исходных Single-округлений **79905.9140625**; источник weighted centroid — `sum(k P[k])/sum(P[k])`.
- Полученные derived results и побитовая сверка с тремя операторскими исходными словами:

| Поле | Original Win32 HEX | Существующий `spectrum_metrics_idr_candidate.py` HEX | Float32 ULP | Побитовое совпадение |
|---|---|---|---:|---|
| `OutputMean` | `40DC8F5E` | `40DC8F5E` | **0** | **ДА** |
| `OutputPeakX` | `466D8095` | `466D8095` | **0** | **ДА** |
| `OutputPeakY` | `3F475279` | `3F475279` | **0** | **ДА** |

Дополнительно **вычисленная**, а не прямо прочитанная с экрана исходной MVKView частота пика = `OutputPeakX × Fs/N = 3800.036376953125 Гц`.

**Ограничение:** это точный результат для **одной операторской original-runtime пары** (`Tag0, N262144, Fs65536, FRange43FF4853`). Независимое подтверждение одного и того же потока/вызова через frame/thread ID не осуществлялось; синтетические тесты CI не исполняют оригинальную Delphi. Не считать аттестованными режимы Tag1/2/3, другие архивы/датчики, исходное форматирование `007B2090`, курсоры и Canvas.

## 3. Изменения репозитория

**Исходный расчёт `core/spectrum_metrics_idr_candidate.py` не менялся**: кандидат с последовательной Double суммой и Single weighted-centroid воспроизвёл все три операторских значения без подгонки.

Новый `mvk_compatible/tests/test_stage111z10_original_summary_runtime_golden.py`:
- Хранит **только семь операторских маленьких числовых параметров/слова**, не настоящий FFT массив, EXE, IDP или архива.
- Всегда запускает synthetic/meta проверки, подтверждает float32 roundtrip трёх HEX и физическую размерность PeakX (бин ↔ Fs/N).
- Полные 3/3 на оригинальном массиве и переход `after_power → summary_power` проверяются **только если оператор явно установил локальные переменные окружения**:
  `MVK_STAGE111Z10_PRIVATE_SUMMARY_BIN`, `MVK_STAGE111Z8_PRIVATE_POWER_BIN`.
- В публичной CI обе приватные регрессии помечаются SKIP, а не «успешно проверено на оригинале».

Внимание: у прежнего `private_getspectrum_summary_triplet_compare.py` уже есть строгая локальная проверка по `summary_capture.json` — новый общий бинарный сравнитель для этой задачи не требуется. Пример JSON со словами оригинала предоставлен отдельно пользователю в чате и **не должен копироваться в CI как источник оригинальных измерений**.

Локальное повторение (PowerShell, приватные оригинальные файлы хранятся только на компьютере):

```powershell
$env:MVK_STAGE111Z10_PRIVATE_SUMMARY_BIN="C:\MVK_CAPTURE\summary_power.bin"
$env:MVK_STAGE111Z8_PRIVATE_POWER_BIN="C:\MVK_CAPTURE\after_power(1).bin"
python -m pytest -q mvk_compatible/tests/test_stage111z10_original_summary_runtime_golden.py
python -m mvk_compatible.private_getspectrum_summary_triplet_compare "C:\MVK_CAPTURE\summary_capture.json"
```

**Приватный файл** `summary_capture.json` должен хранить правильный N, Fs, Tag, FRange HEX, три исходных Output* HEX и относительный `summary_power_file`. Ни он, ни исходные `.bin` не обязаны попадать в GitHub.

# Stage 81f — аудит переданного кандидата mvkview_clone (2026-10-28)

Проверены пользовательские `REPORT_mvkview_full_clone.md`, `dsp_core.py`, `protocol_10230.py`, `clone_cli.py`, `__init__.py`. Это **отдельный кандидат приближённого DSP прибора**, не завершённое восстановление локального FFT движка MVKView. Проверка только офлайн; сетевой режим не запускался. Все четыре Python файла успешно `py_compile`, NumPy/SciPy установлены.

## Факты, полученные из приложенных материалов
- `dsp_core.py`: 43 полосы по центрам R10, границы `10^(±1/20)`, каскад декимации 65536→4096→512→64→16, Butterworth 3 вместо оригинальных фильтров, цикл СКЗ 0,5 с, интегрирование в частотной области по фиксированным диапазонам.
- `protocol_10230.py`: фрейминг 8-байтных заголовков, сборка 8 АЦП, тахо и параметров. `live_table` открывает реальный TCP сокет; запрещено запускать без отдельного разрешения.
- `clone_cli.py offline`: читает BIN только как LE float32 при жёстко заданных 65536 Гц, не читает TSXML, не проверяет тип Byte/Single или флаг нормировки. Не является совместимым со всеми вариантами архивных файлов.
- Отчёт утверждает валидацию на приборе №43 и VALUES/TABLE с точностью от долей процента до десятков/сотен процентов (отдельные полосы у границы). **Скрипты `scripts/mvk_validate.py`, `scripts/mvk_fft_hypothesis.py`, файл `scripts/validate_final_output.txt` и исходные реальные BIN/VALUES/TABLE в переданном наборе отсутствуют**; статистика пока не воспроизведена независимо.
- Отчёт одновременно утверждает «100%», но признаёт аппроксимацию Butterworth-3, погрешности +70…+228% на границах и отсутствие эмуляции низкочастотного бланкирования. Нельзя называть это полной побитовой или инженерной копией.

## Независимые офлайн-проверки в текущем сеансе
1. Успешный импорт NumPy/SciPy, компиляция 4 Python файлов.
2. `process_recording(np.zeros(32768))`: один цикл, 43 спектральные полосы, конечные нулевые значения, без исключений.
3. Все 43 Butterworth фильтра конструируются без исключений.
4. **Расхождение с уже проверенной картой регистров**: `Regs.channel_main/bands/fixed` используют `0x2000+0x100*k`, тогда как архивный AUX4700 и предыдущая карта указывают `0x2000+0x200*k`. Подлежит исправлению и регрессии до live-использования.
5. **Неточность в описании разбивки полос**: индекс 27 в коде — центр около 250.8 Гц (метка 250), а не 315 Гц, как указано в таблице/описании отчёта. Индекс 28 — около 315.7 Гц. Исправлять текст, проверить boundary/Nyquist по всем k.
6. `Regs.serial()` использует `bytes(np.uint16 array)`, что зависит от представления 16-битных слов, а не от явного протокольного разбора ASCII. Доказательств ошибки для реального серийного номера пока нет; требуется тест на точном формате документа.
7. Парсер потока безусловно удаляет первые 2 байта; для файлового replay, где эти байты отсутствуют, это может сместить границы фреймов. Нужен тест `with/without prefix`. Никакого реального TCP теста не проводилось.
8. `dc_block(x)=x-mean(x)` по всей записи не равен автоматически потоковому high-pass с состоянием; исходные фильтры и поведение переходных процессов остаются аппроксимацией.

## Разделение тракта
**Локальный FFT MVKView** (Stage81c–e): RMS-нормированный Hann, `TDSXFastFourier`, четыре спектральных режима. **Приборная обработка параметров** кандидата: отдельный 43-полосный банк Butterworth и фиксированные полосы. Их нельзя отождествлять и нельзя считать один тест доказательством другого.

## Статус и продолжение
Кандидат полезен как **независимая исследовательская реализация / тестовый оракул с известными ограничениями**, не для прямого включения в стабильную v0.3.40. Скрипт `tools/research/stage81f_candidate_clone_audit.py` сохраняет офлайн-инварианты.

Следующее: запросить `scripts/mvk_validate.py`, `scripts/validate_final_output.txt`, `scripts/mvk_fft_hypothesis.py`, **парные реальные** BIN+TSXML+VALUES/TABLE (достаточно приватно, не публиковать в GitHub); затем воспроизвести ошибки по циклам и интеграцию. Параллельно Stage81f локального FFT: найти тело log-helper 0x00447DB8 (нужен оригинальный EXE или точный дизассемблированный фрагмент). Исправления клона выполнять на отдельной исследовательской копии с QA; оригинальные файлы не коммитить, пока они не проверены. Стабильная v0.3.40 без изменений.

## 2. Новый единый план крупных функциональных пакетов

**Пакет A — полная исходная инвентаризация.** Структура трёх DFM, все компоненты/события/адреса, динамические меню, зависимости, ветви вызовов и состояния; автоматический список разрывов между исходным source-контрактом и Core/Qt. Явно различать состояния: обнаружено в IDR, восстановлено, протестировано offline, сверено с оригинальным runtime, не проверено/заблокировано.

**Пакет B — автономный Core.** Восстановить из оригинала и протестировать все семантические операции независимо от Qt: каналы/настройки/тревоги, временные сигналы, все спектральные режимы/цепи, форматы файлов и сохранение, таблицы и результаты, языки, расчёты калибровки и безопасный протокол устройства. Не менять уже побитово доказанные FIR/FFT/LOG для одного окна и Native R6.1 без причины. Никакой виртуальной аппаратной калибровки.

**Пакет C — целостный Desktop.** Три оригинальные формы, семь основных страниц, вся иерархия объектов, реальные поля/переходы/меню, настоящие связи 55 DFM обработчиков + семь возможных динамических. Алгоритмы только в Core. Приборные операции, запись настроек/калибровки включать лишь после отдельной безопасной валидации.

**Пакет D — прямая автоматическая приёмка на Windows.** Два отдельных уже запущенных приложения. Первичный read-only захват по PID из Win32 клиентского DC (без GUI automation, x32dbg, доступа к памяти и устройству); затем на локальном компьютере оператора расширить до сценарного движка UI Automation/Qt accessibility с заранее согласованным allowlist исключительно безопасных действий. Для одних и тех же данных: сравнение control tree и состояний, чисел и Float32, геометрии, пиксельных областей, курсора, масштаба, форматов и переходов. Получать diff и отчёты автоматически, не загружать приватные PNG/IDP/BIN в CI/GitHub.

**Пакет E — единая приёмка.** Все три формы/семь страниц/действия, все режимы и каналы, standalone EXE, Linux Core/Windows Core/Qt96+150, сравнение с оригиналом. Аппаратное управление и калибровка требуют отдельной операторской/стендовой проверки и не могут получить PASS по одним DFM или скриншотам.

Выполнять связанными крупными пакетами, без PR на каждый обработчик. Полное соответствие не объявлять до выполнения B–E.

### Команды на рабочем Windows ПК (по желанию оператора, не для CI)

Распаковать 7z в приватное место: 7z x "Projects.7z" -o"C:\MVK_PRIVATE\ProjectsExport"

Локальная мета-инвентаризация:

    python tools\research\inventory_original_idr_export.py --projects "C:\MVK_PRIVATE\ProjectsExport\Projects" --idp "C:\MVK_PRIVATE\mvkview.idp" --output "C:\MVK_LOG\original_structure_metadata.json"

Прямая read-only съёмка ДВУХ уже запущенных окон (оригинал и аналог):

    python tools\research\compare_running_mvkview_windows.py --original-pid ORIGINAL_PID --compatible-pid COMPATIBLE_PID --private-output-directory "C:\MVK_LOG\direct_qa"

Папка вывода должна существовать и находиться ВНЕ Git checkout. Программы уже запущены оператором, полностью отрисованы; по одному только имени окна приложения не идентифицируются. При разных размерах клиентских областей не ресайзить автоматически и не выдавать pixel 1:1. Контроль настоящих действий и интерактивная синхронизация сценариев появятся в последующих пакетах, после полного восстановления.

## 4. Что IDP/архив не гарантируют

- Получение готового оригинального компилируемого Delphi кода из IDR. Возможны потерянные локальные имена, ошибки типов, неполные control-flow и недоступные внешние зависимости.
- Реальные runtime состояния калибровки, протоколов/состояния подключённого прибора, аппаратную семантику всех команд.
- Попиксельные GDI шрифты/скейлинг 150% и фактическую оригинальную геометрию без отдельного сравнения с работающей MVKView.
- Функциональную правильность даже при идеальной похожести картинок; необходимы численные и переходные инварианты.

**Безопасность:** не запускать или продолжать оригинал через x32dbg/F9/GigaCode без нового прямого разрешения. Никакие неконтролируемые калибровочные, загрузочные или конфигурационные операции не выполнять. Не помещать приватные source/DFM/PAS/BIN/IDP/скриншоты в GitHub.

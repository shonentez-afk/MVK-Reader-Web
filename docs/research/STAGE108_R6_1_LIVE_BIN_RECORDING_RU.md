# Stage 108 / Native R6.1 — 8 АЦП: потоковая запись BIN при подключении, валидация и публикация

Дата: 2026-10-29. Ветка: `research/stage41-spectrum-chain-20261028`. Stable `v0.3.40` **не менялась**.

**Реализовано:** Native R5.1 (живая receive-only с выбранного Ethernet на TCP/10230) + Stage107 R6 Offline Exporter объединены в единую standalone Windows x64 программу `MVK_Native_R6_1_Stage108_Windows_x64.exe`. Теперь в процессе приёма RAW автоматически пишутся 8 промежуточных калиброванных `ADC*.bin.partial`. После завершения полного TCP сеанса весь RAW побайтово независимо анализируется, сверяются SHA256, последовательности ADC и полученные AUX, а физические временные BIN из Live сравниваются с отдельным replay по количеству, on-disk SHA256 и gain. Лишь после этого **атомарно** публикуется папка `BIN_TSXML_VALUES_TABLE_RECONSTRUCTED` с 8 BIN, 8 TSXML, VALUES, TABLE, TIMELINE и EXPORT_AUDIT. Нет дополнительных подключений, Modbus-запросов, команд управления или перезагрузок. Сырые данные остаются без изменений при любом исходе.

**Обработка штатного неполного конечного кадра:** если monitor summary указал точное `TailBytes`, источник завершился `DURATION_REACHED`/`SIZE_LIMIT_REACHED`/`STOPPED_BY_USER`/`REPLAY_EOF` и весь RAW совпадает по SHA256/размеру, только неполный последний фрагмент исключается из BIN (но остаётся в `incoming.raw`). Структурное повреждение/пропуск/изменение gain вызывает отказ.

**Доказательства:** Go 39/39 PASS, `go vet` PASS, `go test -race` PASS, Windows cross-vet/build PASS. Win x64 PE32+ EXE SHA256 **`2fd21c176d4a18677507d70e07f6649220382cc81b875074e0bbb7df65c36053`**. ZIP полного standalone релиза `MVK_NATIVE_R6_1_STAGE108_LIVE_ETHERNET_WIN_X64_COMPLETE.zip`, SHA256 **`2a7aa31d25e84cd43ed3b6b13564c6b062b0349464c549838bdfe37c536c9b02`**, 1 509 163 байта, CRC и 28 компонентов проверены. Архив содержит EXE, полный исходный код, оригинальные тесты, скрипт независимой проверки и инструкции; НИКАКИХ производственных RAW/PCAP/экспортированных BIN в архиве.

**Реальные источники №84:** исходный тест R5, 11:33, 69 675 600 B и исходный тест R5.1, 11:41, 69 679 808 B, каждый около 30 секунд. Stage108 replay с действующей потоковой записью по частям: 8/8 live temp BIN SHA256 == Stage107 SHA256 **на каждой сессии**. Независимый Python/NumPy проверил 31 448 064 `float32` битово и 67 200 численных AUX→VALUES с округлением: **31 515 264 сравнений, 0 расхождений**. Все 16 опубликованных BIN совпали с независимыми Stage107 по SHA256. Временные файлы удалены после опубликования; статус `STAGE108_EXPORT_STATUS.json`: `EXPORTED`, `during_capture_bin_spool_verified=true`.

**Локальный TCP тест:** синтетический поток от локального сервера, приём в Native, реальные промежуточные BIN, независимая конечная публикация 8+8+VALUES/TABLE; сервер получил 0 байт клиентских прикладных данных. Повреждение on-disk BIN в тесте → отказ от публикации и сохранение RAW. Отказ при неполных/ложных контрольных суммах, неправильных кадровых индексах, неверной калибровке и аварийном разрыве соединения.

**Обязательные ограничения:** новое R6.1 EXE пока **НЕ запускалось на физической Windows машине/приборе**, в отличие от R5/R5.1, которые уже проходили 2×30с аппаратные тесты. Калиброванный BIN математически соответствует нашим подтверждённым данным, но нет оригинального MVKView BIN именно этих же сеансов для строгого байтового сравнения. Точные моменты действий GUI и отдельные текстовые статусы VALUES/TABLE ещё не 1:1. Не внедрять в стабильную программу до приёмки.

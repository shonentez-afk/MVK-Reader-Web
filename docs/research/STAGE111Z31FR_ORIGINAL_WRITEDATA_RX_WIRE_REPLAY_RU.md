**Истинный original:** в `_Unit125.pas:0080822F..008082DE` после приёма сырого `TmpStream.FMemory` (`ReadStream`) проверяется **`MvkSampleRate == received rate`** и **`FreezeUpdate == false`**. Если оба истинны, декодер передаёт исходный буфер в `TMvkChannelStorage.ProcessBufferChunk`. При `WriteDataStage==0` первый ADC1 переводит стадию в 1, затем открытый `TFileStream` выбранного канала получает **именно полученные байты `TmpStream.FMemory`**, без применения повторного gain или нового FFT. При отключении `00809414` закрывает файлы.

Оригинальная функция создания имен `_Unit125:00809475..008095F2` использует конфигурацию `OutputPath`, выбор имени прибора (из `008069EC`), исходную метку канала, шаблон `yyyy-mm-dd--hh-nn-ss`, расширение `.bin`. `008096EF..0080980A` на завершении дописывает отдельный `.tsxml` при включённой опции. `_Unit114:007B1FA4` фильтрует допустимые символы исходного префикса. Байтовое совпадение этих файлов ещё не подтверждено реальной парой Delphi/новая программа.

## Что реально реализовано

- `mvk_compatible/core/original_write_data_wire_replay.py` читает **один исходный `incoming.raw`** по границам приложения без произвольной ресинхронизации, требует совпадения размера, SHA256, счётчика кадров, финального хвоста и десяти независимых счётчиков каналов; распознаёт переменные длины ADC/TACH и корректные неизвестные типы. Только после проверки создаёт отдельно выбранные `DATA##_ADC#_WIRE_RX_UNSCALED.bin` / `DATA##_TACH#_WIRE_RX_UNSCALED.bin` с **точными исходными little-endian байтами пакетов** и отдельной SHA каждого файла. Не применяет калибровку, не создаёт новый приборный TCP и не отправляет никакие команды. <https://github.com/shonentez-afk/MVK-Reader-Web/commit/85b030363dcc1980392a43355a291fd2d7cb1513>
- `mvk_compatible/core/original_live_write_stages.py` использует только проверенные Native Go frame marks (включая финальные auto-close), по каналу вырезает **те же интервалы** одновременно из original wire RAW и откалиброванного Native BIN. Они не подменяют друг друга: source wire имеет явную маркировку `original_rx_payload_bytes_exact=true` и `original_delphi_bin_parity_verified=false`. Для исторических статусных/синтетических архивов без RAW новый результат не подделывается; существующий совместимый экспорт остаётся работоспособным. <https://github.com/shonentez-afk/MVK-Reader-Web/commit/806c1e34257fc318522113d2520e26d7f6a3450e>
- `mvk_compatible/desktop/main_window.py` сообщает оператору число файлов исходного RX без калибровки отдельно от числа восстановленных значений. Сообщение **не обещает** полного исходного `FreezeUpdate`, source-gate, времени клика и байтовой идентичности Delphi. <https://github.com/shonentez-afk/MVK-Reader-Web/commit/8e42e83ced5ed1203bcf328cea3d6343d34f64ac>

## Регрессии

- `test_stage111z31fr_original_wire_replay.py`: два ADC-фрейма одной оси, TACH, PARAM, неизвестный тип, неполный допустимый хвост, независимые интервалы, точность байтов по float32, неверный SHA, подмена количества кадров/слов/длины, недопустимые каналы/частоты.
- `test_stage111z31fr_marked_source_wire_e2e.py`: синтетический полный набор `Go RAW + 8 ADC + AUX + NEXT-FRAME operator marks + SHA-verified ZIP`, раздельные wire и калиброванные файлы, подтверждение полного RAW SHA и отказ при изменении последнего байта. CI последнего SHA после всех коммитов должен проходить полностью, не засчитывать отменённые runs.

**Разграничение достоверности:**

1. **Точно подтверждено**: исходные RAW байты переданных ADC/TACH пакетов, длины, формальные границы, SHA, выбранные Go frame-mark интервалы.
2. **Не подтверждено 1:1**: Delphi условие `MvkSampleRate/FreezeUpdate` в каждый конкретный момент, старт на самом первом ADC1 относительно Win32 вызова, локальные timestamps, `TFileStream` точный порядок и исходные `.bin/.tsxml` имена и формат при реальном приборе. Для текущего wire replay source gate намеренно **не применяется**, потому что нет непрерывного проверяемого журнала изменений Freeze/SetRate на протяжении каждой записи. Результат нельзя выдавать за исходный Delphi `.bin` без этого последующего этапа.
3. Экспорт останется **только локальным** в принятой папке измерения. Приватные IDP/PAS/DFM/SQLite и реальные пользовательские PCAP/RAW не публиковались в GitHub.

## Принятый по исходникам алгоритм

После исходного Mode2/TMVKThread и обычного Go TCP/10230/Task2 (один источник соединения) принятые `MvkSampleRate`/`FreezeUpdate` кадры входят в исходные кольца по `2^21` элементов АЦП. `GetSignal` сначала проверяет `CheckDataAvailability` для `Params.Count`, передвигает `LastProcessedPos`, для `EnvelopeCode>0` требует дополнительную реальную историю через `GetAdjustedEnvelopeLength`, затем `NoDC`, FIR/децимация, I/Q, RMS/FRange и **обратный** конечный массив. В исходном `GetSignal` post-FIR N не обязан быть степенью двойки — это **не** `GetSpectrum` `bSpecLines`.

С Fs65536 и Code20: **HTag9 (20 мс): 1310 выбранных + 51 предыстории → 1361 реальный исходный Float32 → 655 выходных при Fs32768**; **HTag0 (20 с): 1 310 720 + 51 → 1 310 771 входных → 655 360 выходных**, все < 2²¹.

## Один большой программный пакет

- Go `sourceFIRGetSignalWindowLength` ранее уже вычисляет pre-FIR историю и валидирует `-3` **локальный IPC**, не команду прибору. ZIP-срез содержит точные реальные `ADC*.f32` и SHA, идентичность сессии, HTag, Code, SampleRate, `FRxPos`, индекс устройства. Никакого дополнительного TCP/SetRate/Flash/Reboot.
- Pure Core `source_live_filtered_getsignal`: повторное SHA-сверение, отсутствие подложенных нулей, исходная FIR структура и обратный полный `float32` массив, не более 4000 точек **только для отрисовки** (peak-preserving min/max по сегментам). Полный массив остаётся для курсора, RMS и SHA.
- Qt `SourceLiveFIRWorker`: единственная вычислительная задача в отдельном потоке, последний отложенный запрос при продолжении приёма, кооперативная отмена FIR по каждой стадии/коэффициенту при Stop, смене HTag/FIR/режима, никакой синхронной обработки 20-секундного окна в 20мс интерфейсном таймере.
- Live `PageAdc` курсор получает мышиный X (исходное `pbAdcMouseMove`) и вычисляет значение из **полного** фильтрованного обратного буфера, не из LOD. В интерфейсе явно подписано: локальный FIR/IQ-кандидат, **не Win32/TQGrapher 1:1**.
- Проверка сводной цепочки: Go ring → локальный источник и checksum → Pure Python DSP → Qt worker/курсор → STOP/invalidated session. Добавлены Pure/Qt/Go синтетические тесты и ограничения на чужие сеансы/повреждённый SHA.

## Ограничения: что пока НЕ имеет оригинальной приёмки

- `original_delphi_compatibility_verified=false`. На одном и том же реальном потоке ещё не доказан побитовый Win32 x87 FIR/FFT/RMS и точный исходный `FRange`.
- Оригинальные переходы Stage0..3, DENIED, таймаут, Stop/reconnect на **реальном приборе** и сравнение RAW/BIN/TSXML/CSV с парной Win32-сессией остаются аппаратной приёмкой.
- Точное исходное `ADCGrapher.UpdateCursor` пиксельное время/подсказка/шрифт не принято; реализована **профессиональная локальная** функция курсора с полным численным отсчётом.
- При любой утрате SHA, индексной или rate/Freeze достоверности результат убирается, нельзя показывать обычный FFT/GetSignal вместо фильтрованного.

## Правила следующего большого пакета

Не дробить по мелким субпунктам: закончить одной аппаратно-сопоставимой цепочкой `IP → Измерить → данные → полный FIR/FFT → WriteData/WriteValues → Stop`, включая негативные сценарии и исходные экспортные байты, с локальными тремя источниками. `main` не изменять, оригинальные данные не публиковать, никакие сетевые команды кроме отдельно согласованных read-only действий автоматически не посылать. Разделять `software_green` и `original_hardware_parity`.

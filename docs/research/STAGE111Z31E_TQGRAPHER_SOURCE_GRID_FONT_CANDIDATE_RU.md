## Что обнаружено в оригинальных предоставленных исходниках

Был прочитан исходный файл пользователя `Projects.7z` (дизассемблированные `_Unit115.pas`, `_Unit128.pas`); эти исходные материалы **не загружались в публичный GitHub**.

Оригинал `_Unit128.pas` в инициализации отдельного `SpecGrapher`:
- `00844B2B` устанавливает `TQGrapher.AutoVSpacing=0x0A` (10);
- `00844B32` устанавливает `TQGrapher.AutoHSpacing=0x0A` (10).
- Для соседнего `ADCGrapher` такие же исходные установки находятся в `00844AC1 / 00844AC8`. Эти поля относятся к **сетке**, а не к массиву FFT.

В `_Unit115.pas`, `TQGrapher.Draw(007CAC68)`:
- `007CAC89..007CAC99`: при положительном `AutoHSpacing` рассчитывается `HLineSpacing = Single(ScrHeight / AutoHSpacing)`, **горизонтальные** линии по амплитуде;
- `007CAC9D..007CACAF`: `VLineSpacing = Single(abs(ScrWidth / AutoVSpacing))`, **вертикальные** линии по частоте;
- `007CAD1C..007CAE3B`: проход горизонтальных линий при `HLineSpacing>0`, индексные границы с допуском extended `0.0001` (см. `007CAD35/007CAD53`);
- `007CAE3B..007CB086`: аналогичные вертикальные линии, включая отдельную ветвь для отрицательного `ScrWidth`;
- обе подписи выводятся по вызову `007B2090` с аргументом 3 и `TCanvas.TextOut`. Дополнительная перепроверка `_Unit114.pas:007B2090..007B21BC` подтвердила **ветвление `NAN`/ноль, маску фиксированной записи `0.` + нули до трёх значащих десятичных разрядов, вызов RTL `0042EE10` и удаление завершающих нулей с учётом `TFormatSettings.DecimalSeparator`**. Это восстановленная логика, но **точное RTL округление Float32/x87 на граничных значениях, runtime-параметры локали и исходный Win32 TCanvas.Font ещё НЕ подтверждены**;
- `007CACEE..007CACF9` TQGrapher копирует шрифт из переданного `TCanvas.FFont` в собственный offscreen canvas. Видимый `DFM` содержит `Tahoma/Height=-13/PPI=96`, но копирование исходного TPaintBox.Font на runtime нужно проверить отдельно.

Ни `AutoVSpacing=10`, ни Tahoma из DFM нельзя использовать как доказательство идентичности старых скриншотов: **runtime оригинальной VCL, Win32 DPI-awareness, сетка GDI/Draw и физическая PixelRect остаются открытыми**.

## Реализовано в новом этапе

1. `mvk_compatible/core/tqgrapher_grid_idr_candidate.py` — отдельный **чистый** исходно-ориентированный расчёт двух интервалов, границ и позиций сетки. На исходном фиксированном случае Tag0 `ScrLeft=0/ScrWidth=25600, ScrBottom=-150/ScrHeight=150` кандидат даёт шаг X **2560 Гц**, Y **15 дБ**, 11 линий каждой оси включая крайние. Эти значения — **расчёт из прочитанного исходного кода**, а не измеренные оригинальные позиции пикселей.
2. `desktop/main_window.py` — только для уже прошедшего SHA256 и полного Float32 исходного x32dbg Power/Y доступен opt-in чекбокс **«Сетка TQGrapher 10×10 · исследовательская»** внутри правой панели «Исследование».
3. При включении Qt axes получают явные исходно-ориентированные позиции сетки и шрифт осей `QFont('Tahoma')` с `pixelSize=13` как **DFM-кандидат**. Без подтверждённого Power/Y чекбокс недоступен и не вмешивается в обычный архив, Qt-спектр, режим Native или FFT.
4. При изменении X/Y `ViewBox` сетка пересчитывается по видимому `ScrWidth/ScrHeight` (не по ширине экрана и не по DPR). Пояснение явно отмечает неаттестованные исходные FormatFloat/GDI шрифты/цвет и пиксели.
5. При выключении чекбокса или выходе из эталона вызов `AxisItem.setTicks(None)` снимает ручные tick, восстанавливает прежний шрифт label и стандартный расчёт tick Qt. Исходные Power/Y, summary, 3/3 HEX, курсор и сам архив/Native не изменяются.

**Важно:** переключатель сознательно **не включён по умолчанию**: 10/10 — исходная инициализация класса, но графическое принятие одинакового runtime размера, исходного Form.Canvas и tick-label format отсутствует. Принудительная замена сетки в обычном архивном графике была бы недоказанной.

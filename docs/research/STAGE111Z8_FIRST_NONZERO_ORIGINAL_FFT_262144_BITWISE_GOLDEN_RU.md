# Stage111Z.8 — первая ненулевая пользовательская пара оригинального GetSpectrum и полное совпадение FFT-мощностей

**Дата:** 30 октября 2026.  
**Ветка:** `research/stage111-mvkview-desktop-20261029`.  
**Продукт:** автономная Windows MVKView Compatible Qt/PySide6, не Web/сервер.

## 1. Происхождение исследования

Оператор передал в текущую сессию два бинарных дампа `before_fft(1).bin` и `after_power(1).bin`, описанных им как исходный x32dbg capture работающей оригинальной Windows MVKView на одном вызове GetSpectrum. **Независимая аутентификация происхождения / thread / одинакового вызова по регистрам не проводилась:** в этом сообщении не передавались x32dbg register metadata, исходные executable bytes, Fs, Tag, FRange, номер ADC или отдельный файл manifest. Именно поэтому этот эталон обозначен **USER-SUPPLIED ORIGINAL-RUNTIME-CLAIMED 1 PAIR**. Нельзя переносить его на другие файлы, режимы и приборы автоматически.

**НИ ОДИН оригинальный байт**, полная waveform/power array, исходный файл EXE/IDP, BIN/RAW/PCAPNG или физический архив **не загружены в GitHub, CircleCI, Release и CI fixtures**. Изготовленные автоматически синтетические unit tests содержат только искусственные сигналы.

Первая переданная пользователем пара без суффикса `(1)` имела полностью нулевые массивы и не была пригодна для численной приёмки. Теперь переданная пара `(1)` не пустая.

## 2. Проверка формата и пригодности

| Проверка | before_fft(1).bin | after_power(1).bin |
|---|---:|---:|
| Размер файла | 1 048 576 байт | 524 288 байт |
| IEEE754 little-endian Float32 | 262144 (N) | 131072 (N/2) |
| Ненулевых элементов | 262144 | 131072 |
| NaN / Inf | 0 | 0 |
| Отрицательная спектральная мощность | неприменимо | 0 |

Оба массива содержат ненулевую измерительную информацию, поэтому в отличие от нулевой пары здесь можно проверять численное FFT, а не только сохранность формата.

На входе исходный подготовленный Float32 массив уже после удаления среднего и возможной огибающей, поэтому **повторно центрировать вход нельзя**. В обоих вариантах вычислений использовано `remove_dc=False`, original Hann 262144 с четырьмя ранее подтверждёнными x32dbg Float32 битами, шаг `262144/N=1`. На выходе сравнивалась **полная первая половина N/2 исходных power Float32, ещё без интегрирования ВС/ВП, логарифма и деления на FRange**.

## 3. Результаты реального побитового сравнения всех 131072 power bins

| Показатель | Source-derived `idr_float32` | NumPy `rfft` + Single |
|---|---:|---:|
| Полных power bins | 131072 | 131072 |
| **Побитовое совпадение с пользовательским reference** | **131072** | **733** |
| Побитовых расхождений | **0** | **130339** |
| Количество не далее 1 Float32 ULP | **131072** | **2160** |
| Median Float32 ULP | **0** | **226** |
| Max Float32 ULP | **0** | **3735436** |
| Корреляция мощностей | **1.0** | **~0.99999999999982** |

Относительное расхождение NumPy power у сильных компонент очень мало; это **НЕ** замена exact Float32 bits в требовании совместимости. Показатель Max ULP у NumPy определяется в том числе очень маломощными бинами.

**Контрольный анализ причин:**
- Если вернуть предыдущую схему обновления FFT twiddle **без промежуточного сохранения real-выражения как Single**, совпадёт только **4068 из 131072** power bins. Это указывает на принципиальную роль исправления Stage111Z.4.
- Если *только* убрать четыре адресных патча Hann Stage111Z.6 (индексы 1,5,262139,262143), **для данного конкретного массива power всё равно совпадает 131072/131072**: четыре мелких периферийных коэффициента не меняют конечные Float32 результаты для этого waveform. Это не отменяет самостоятельного подтверждения их битов в исходной таблице Windows x32dbg.
- Обычный NumPy даже при почти полной корреляции спектра совпал побитово лишь в 733 случаях. Эти различия нельзя игнорировать при достижении точного оригинального clone.

**Вывод:** впервые получено **131072/131072 побитовых совпадений полного N=262144 source-derived FFT power на одной ненулевой пользовательской паре**, что является сильным свидетельством правильного воспроизведения этого математического участка. Не является доказательством полного оригинального Windows приложения, других параметров/архивов/FRange/огибающей/каналов/численного результата курсора.

## 4. Инструмент для дальнейших пар без manifest

Добавлен отдельный read-only `mvk_compatible/private_getspectrum_raw_pair_compare.py`. В отличие от предыдущего JSON-comparator Stage111Z.7, он читает **два файла напрямую**, выводит только структурную пригодность, подсчёт exact/Ulp и агрегированные ошибки. Не пытается вывести/угадать Fs, Tag, FRange, канал и не центрирует вход второй раз. Нулевую пару маркирует как `EMPTY_INPUT_AND_POWER` и не выдаёт ложную 100%-ную аттестацию.

Синтетические тесты: `mvk_compatible/tests/test_stage111z8_raw_pair_compare.py`, включают power-of-two 1024/8192/262144, искусственный сигнал с DC, 1 ULP, нулевой вход, некорректные длины/NaN/отрицательные мощности, symlink и запрещённые исходные пути в отчёте. На CI **не используется ни один пользовательский original dump**.

Запуск на компьютере оператора с личными оригинальными дампами:

```powershell
python -m mvk_compatible.private_getspectrum_raw_pair_compare "C:\MVK_CAPTURE\before_fft.bin" "C:\MVK_CAPTURE\after_power.bin"
```

Два локальных файла всегда остаются только на компьютере; в репозиторий следует передавать лишь агрегированный отчёт.

Также добавлены `private_getspectrum_capture_preflight.py`, `tests/test_stage111z8_fft_capture_preflight.py` и защита от пустого golden в JSON-comparator `private_getspectrum_power_compare.py` с тестами. Если опять пришлют пару нулей, она не может быть объявлена верной численной приёмкой FFT.

## 6. Следующий Stage111Z.9

Теперь нет смысла менять FFT вслепую: на предоставленном N262144 source-derived алгоритм уже совпал 100% побитово. Приоритет следующий:

1. При возможности повторить ещё одну независимую original x32dbg pre/post пару меньшего FFT N=4096/8192 или с другим реальным каналом, чтобы подтвердить независимость результата от одного runtime.
2. Отдельно восстановить и проверить original `GetSpectrum` OutputMean, OutputPeakX, OutputPeakY, шкалу и единицы измерения. Получить runtime golden по этим полям, сохраняя distinction full power vs display scale.
3. Далее `CursorString`, FormatFloat, TQGrapher PixelRect и реальный графический скриншот, без подмены исходного Qt Y/Canvas без reference.
4. Сохранять complete DFM/PAS/IDP/EXE, original measurement archives и пользовательские FFT raw dumps только приватно; в GitHub — derived source/test fixtures и агрегированные факты.

Главная архитектура остаётся **единая автономная Windows MVKView Compatible**.

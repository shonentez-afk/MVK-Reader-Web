# Stage111Z31AB — физический ADC1 BIN/TSXML → оригинальный LOG GetSpectrum без расхождений (10.11.2026)

## Итог и его границы

Пользователь передал **оригинальные байты двух приватных файлов** `MVK00000043-ADC1-2026-10-29--13-32-12.bin` и `...bin.tsxml` из своей папки `BIN_TSXML_VALUES_TABLE_RECONSTRUCTED`. Мы независимо прочитали их и **физический** ранее переданный `capture_pack.zip` (Stage111Z31AA). Проверены CRC, точные SHA256, структура TSXML/Single и полная вычислительная цепочка на одном окне.

**Ключевой результат:** ровно **все 1 048 576 байт** `ring_head.bin` из x32dbg-захвата **побайтово входят в данный ADC1 BIN**, начиная со смещения **6 813 124 байт**, то есть отсчёта **1 703 281 (0-based)**. Уникальное совпадение первых 256 байт в BIN и полное совпадение 1 Миб окна: `memcmp 0 difference`. Конец окна (exclusive) = отсчёт **1 965 425**. После него до конца BIN ещё **399 отсчётов**. Источник этого захвата — **именно данные данного ADC1 BIN**, независимо от ранее *заявленного* в `capture_config.json` `adc_claim=4`.

Доказано **тождество данных BIN↔сохранённого ring**. Но факт, какой канал был выбран в GUI оригинальной MVKView, ещё **не подтверждён независимым screenshot/Win32 thread provenance**. Не считать `adc_claim=4` правильным только потому, что его записал операторский сценарий; не редактировать исторический `capture_config.json` задним числом. Возможно, соответствующая запись оказалась открыта как ADC1. Исходные измерения **не публиковать**.

## Тесты из самого BIN, а не из исходного x32dbg рабочего буфера

Источник raw для расчёта: **точный отрезок физического ADC1 BIN**, нормализованный Float32 по метаданному FRange. Независимый исследовательский Python/NumPy IDR replay использовал уже утверждённый алгоритм из `mvk_compatible/core/fft_idr_candidate.py`, без подгонки под данные.

| Шаг | Сверено, Float32 bit-exact |
|---|---:|
| Raw BIN / FRange → original `input_normalized_pre_dc` | **262144/262144** |
| float32 DC subtraction → original `input_after_dc` | **262144/262144** |
| postDC = original `before_fft` без FIR | **262144/262144** |
| Hann/IDR FFT → original `power_before_mode` | **131072/131072** |
| Low-bin suppression → original `power_after_mode` | **131072/131072** |
| LOG Power→Y → original `display_y` | **131072/131072** |

Summary `40DC8F5E / 466D8095 / 3F475279` = `6.892500877380371 / 15200.1455078125 bins / 0.7786021828651428`. Графический максимум: бин 15200, **3800 Hz**, **−55.32063674926758 dB**. Прежний GigaCode текст с `~3.28 / 524288 / 0.37` неверен; bytes сами корректны.

**Негативные проверки** для внешнего проверщика: (1) TSXML DataLength differs from physical bytes → reject; (2) неверный gain в TSXML → reject; (3) одиночное изменение байта исходного окна BIN → reject. Все три фальсификации отклонены. ZIP/CRC ранее 19/19; `capture_log_a_snapshot.txt` по-прежнему **0 байт**.

Проверялись **только** загруженные пользователем два файла; остальные файлы локальной папки на рабочем ПК не доступны из этого чата. Тестовый Python-комплект передан пользователю как приватный ZIP **без** исходных измерений. Он читает ADC1 BIN, TSXML и `capture_pack.zip`, создаёт JSON отчёт. SHA установленной локальной копии на Windows должен быть перепроверен самим GigaCode перед тестом.

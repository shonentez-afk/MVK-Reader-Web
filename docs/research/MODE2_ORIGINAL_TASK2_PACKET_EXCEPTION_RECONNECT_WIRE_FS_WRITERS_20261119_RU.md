## Первичные источники: совместная приватная сверка

Оригинальные исходные файлы и коммерческие материалы **не коммитить**. В текущей проверке использованы все три локальных файла:

- `/mnt/data/mvk_idr(1).sqlite`, SHA256 `97435654a34a69857736e21d83d7a805b976365bb540e55418fd4f564e05365c`, `PRAGMA quick_check=ok`. Функция `TMVKThread.Execute 00807A98` имеет исходный диапазон 13493–14654; проверены реальные вызовы `ReadUInt32 00807F78`, `@RaiseExcept 00808706`, `TMvkChannelStorage.InvalidateData 007D1AE0` вызывается отдельным обработчиком в `_Unit128`, НЕ из точки `Task2` retry.
- `/mnt/data/mvkview.idp`, SHA256 `77e59f98febdd7df94e71cb538a2df69ea4de4624f15b088a81c86e61bb5a438`: имена/смещения исходного `TMVKThread`: `Stage +3C`, `CommandList +34`, `StatusCells +4008C`, `MvkSampleRate +400D0`, `FreezeUpdate +400CD`, `Task +54`.

### Точный исходный путь

1. `TMVKThread.Execute` `00807F78/00807F84` — отдельные `ReadUInt32` типа и размера. `00807F8B..00807FA1`: размер 8..0x20000, кратен 4. Неверная длина → `errInvalidPacket` через `@RaiseExcept` (`00807FA1/00808706`).
2. `00808871..0080897E` — Delphi перехватывает исключения приёма, `Client.Disconnect` и `TObject.Free`; `008089A3..00808B15` — `CloseFiles 00809414`, возврат `Stage0`, исходная задержка `PauseValue`, новая `TIdTCPClient`, если поток Task2 не остановлен.
3. `00808192..0080823B` — принятая частота `Fs` — просто `uint32`. Вся полезная нагрузка читается, затем Fs сравнивается с `MvkSampleRate`. **Незнакомая Fs (включая 0) — НЕ ошибочная длина/тип пакета**: исходное кольцо и WriteData пропускают данные, RAW их сохраняет.
4. `008089A3..008089AD` — `CloseFiles` выполняется **на границе каждой TCP-попытки**, включая исключения/переподключения, а не только при финальном Stop. Перед новым сокетом незавершённые WriteData/WriteValues окна должны быть закрыты и помечены как прерванные; после реконнекта писать в тот же локальный файл нельзя.

## Что изменено в Native Go

- `ProcessChunk` сохраняет целиком каждый полученный OS TCP Read в `incoming.raw` **до** разбора протокола; последний валидный набор кадров до плохого заголовка успевает обновить оригинальный `Stage1`. Очередной 36-байтный `SetRate` перед следующей неверной длиной может быть отправлен через **тот же** TCP, даже если несколько пакетов пришли одним чтением.
- В исходном живом Task2 обнаруженный `errMalformed` теперь выдаёт типизированное `errTask2SourceInvalidPacket` и причину `SOURCE_INVALID_PACKET`; сокет закрывается. Не остаётся ошибочно «работающего» TCP без декодирования. Ошибка локальной записи отдельно классифицируется и **не маскируется под неисправность устройства**.
- `sourceTask2CaptureAddressRetry` добавил исходную причину `SOURCE_INVALID_PACKET` к допустимым основаниям повторной попытки. После реально полученного RAW повторный физический TCP допускается **только** при ранее подтверждённом `sourceAfterRAWReconnect`, как и при других сбоях. Оригинальная математическая задержка не изменена. Новые сокеты имеют независимый SHA `SOURCE_TCP_SEGMENT_NNNN.raw`, сброс `Framer/RegisterImage/Stage`; весь агрегат получает `SourceTCPMultiSocket=true`.
- Счётчики `source_task2_protocol_exceptions` и `source_task2_last_protocol_error` отражают только исходную протокольную ошибку. **Важный порядок:** при ошибке не фиксировать глобальный `captureOnly` до конца всех разрешённых попыток — иначе новый сокет больше не декодируется. При `Finalize` наличие хотя бы одной ошибки делает **весь** результат fail-closed `CaptureOnly=true`, даже если следующий сегмент полностью исправен.
- Отменено ложное правило «только пять разрешённых частот» в декодере RAW: формат исходного `SampleHeader.Rate` — любой `uint32`; вся полезная нагрузка сохраняется, но `sourceOriginalRXGate.allowedFrame` разрешает кольцо/WriteData только для выбранной Fs и `!FreezeUpdate`. Дополнительный `LiveBinSpool` также пропускает пакеты, отвергнутые исходным gate, вместо генерации выдуманной ошибки протокола.
- `sourceTCPLedger.finish` закрывает **оба** текущих локальных окна WriteData и WriteValues по исходной per-socket границе до следующего подключения. Причина `SOURCE_SOCKET_SOURCE_INVALID_PACKET` не становится `CLOSED_BY_SOURCE_THREAD` как при штатном Stop. Сбой локального закрытия помечает `captureOnly`.

## Сквозные синтетические проверки

- Одно TCP-чтение: `PARAM → неверный заголовок ADC → валидные байты ADC`; проверяется исходный 36-байтный `SetRate` **до исключения**, остановка текущего TCP, точный исходный RAW, SHA256, отсутствие ложного ADC, запрет сертификации BIN.
- Два реально открытых loopback TCP-сокета: первый имеет повреждённый заголовок, второй новую `PARAM/ADC`; на каждом отдельный исходный 36-байтный SetRate, новый Stage0, собственный сырой TCP-сегмент и SHA; при Stop вся объединённая запись отклоняется как единый исходный BIN.
- Нестандартные `Fs={0,12345,44100,65536}` на корректных пакетах: всё прочитано, в кольце только Fs65536, ни одной вымышленной протокольной ошибки.
- При аварийном выходе первого сокета оба окна WriteData и WriteValues получают исход прерывания; после нового подключения создаются **W02**, не дописывается **W01**. Проверяются реальные bytes ADC1, VALUES events, и невозможность слить два TCP-сокета в один сертифицированный экспорт.
- Старые регрессии original Mode2, 8ADC/2TACH, фильтры, графики и финальный Windows EXE запускаются вместе, без «выборочного зелёного» теста.

## Оставшиеся отличия от оригинального MVKView

**`original_delphi_compatibility_verified=false`**. Даже зелёный CI на локальном сервере не равен парной аппаратной Win32-сессии.

1. Оригинал повторяет Task2 автоматически, Native после реального RAW требует отдельного подтверждения режима реконнекта (осознанная защита промышленного прибора).
2. Деление на независимые RAW-сегменты и журнал ошибок/границ хранит больше forensic evidence, чем собственный формат оригинальных файлов; побайтовые Delphi BIN/TSXML/CSV ещё не подтверждены.
3. Исходный x87/Float32 `FRange` при приёме и дальнейшие RMS/FFT — отдельная численная аппаратно-сопоставимая приёмка.
4. Условия отказа при редких нестандартных PARAM descriptor, физические DENIED/ACK/обрывы/Stop и Win32 время закрытия нужно проверить на одном реальном МВК01 со снятым оригинальным эталоном.
5. Нельзя объявлять полноценный оригинальный приём 1:1 до аппаратной проверки, несмотря на восстановленную структуру, команды и переходы.

Не переносить приватные файлы/IDP/SQLite/Pascal/DFM/RAW/PCAP в публичный GitHub. `main` не трогать. Дальше работать **крупными интегрированными пакетами**.

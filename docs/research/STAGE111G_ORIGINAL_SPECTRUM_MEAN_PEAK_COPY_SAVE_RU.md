## 1. Принципиальная находка в оригинальном Delphi

Подробно изучена приватная `_Unit115.pas` из пользовательского `Projects.7z`. Это исследовательские доказательства, сам оригинальный PAS/IDP не переносить в открытый GitHub.

| Адрес оригинальной MVKView | Проверенная операция |
|---|---|
| `007D1558–007D1568` | Верхняя граница расчётной полосы: `Trunc(N/2.56)`, не весь N/2 до Nyquist |
| `007D158B–007D15A5` | Нижняя граница: `max(2,Round(N/(2*Fs)))`; начальные бины занулены |
| `007D17F9–007D1830` | `sum(P[k])` на диапазоне low..high с 64-битным аккумулятором; максимум `P[k]` со строгим `>`, при равенстве первый |
| `007D1832–007D1860` | `OutputMean = sqrt(sum(P)/2)*FRange/(N/2)`, итог в float32 |
| `007D1861–007D1876` | Если бин максимума <=2, `OutputPeakX=OutputPeakY=0` |
| `007D1876–007D18CC` | Для найденного максимума берётся диапазон максимум±2 бина; клип до N/2-1 |
| `007D21A8–007D2223` | **Не поиск глобального максимума!** Энергетически взвешенный индекс: `sum(k*P[k])/sum(P[k])`; обе суммы сохраняются float32 на каждом шаге; результат `OutputPeakX` |
| `007D18D1–007D18FF` | `OutputPeakY=sqrt(sum(P[peak-2:peak+2])/2)*FRange/(N/2)` |
| `_Unit128:00848297–008482B2` | `TQGrapher.Series.XScale=OutputSampleRate/(2*OutputLength)`, то есть `Fs/N` |
| `_Unit128:0084BC28–0084BD3B` | `bSpecCopyValueClick` записывает в clipboard **три числа**: `OutputMean` с `007B2090(3)`, TAB, `OutputPeakX*XScale` с `007B2090(4)`, TAB, `OutputPeakY` с `007B2090(4)` |
| `_Unit128:0084BD7C–0084C0D9` | `bSpecSaveValueClick` дописывает 3 поля через `|` в `SPEC-FREQ-yyyy-mm-dd.csv`, при создании добавляет `sep=|` и локализованные заголовки; каталог из `edLibraryPath` |

**Итог:** пик на оригинальной вкладке «Спектр» — **энергетически взвешенный центр ±2 бина**, а не просто FFT-пиксель, не максимум значений и не значение из DSP/AUX4700. Не путать два независимых алгоритма: `TQGrapher.UpdateCursor` выбирает максимум в пикселе для курсора, а `TMvkChannelStorage.GetSpectrum` рассчитывает `OutputPeakX` отдельно, по мощности исходного FFT. Это объясняет часть прежних несовпадений с MVKView.

## 2. Изменения реальных исходников

- `mvk_compatible/core/spectrum_metrics_idr_candidate.py`: расчёт полной power-полосы, строгий максимум, `OutputMean`, взвешенный центроид `OutputPeakX` и амплитуда `OutputPeakY`, сохранение float32 на структурных границах, полный provenance.
- `mvk_compatible/core/offline_export.py`: `OfflineSession.spectrum()` возвращает `spectrum_summary` из полной мощности **до экранного прореживания**. Режимы 2/3 теперь выполняют исходную интеграцию **мощности** через `007D2164`, а не приближённо умножают уже нормированную амплитуду.
- `mvk_compatible/core/envelope_spectrum_idr_candidate.py`: те же показатели добавлены для всех четырёх режимов спектра огибающей, после интеграции мощности (если режим 2/3), с локальным верифицированным IDP и без повторного снятия DC.
- `mvk_compatible/core/spectrum_summary_export_candidate.py`: три агрегированных значения в clipboard через TAB, сохранение в **локальный отдельный исследовательский** CSV `sep=|` и три поля через pipe. Оригинальные `SPEC-FREQ` не дополняет: отказывается записывать в файл с чужим заголовком, чтобы не смешать значения. Только по действию пользователя, без подключения, RAW/BIN/IDP не экспортирует.
- `mvk_compatible/desktop/main_window.py`: по DFM теперь действительно работают кнопки `bSpecCopyValue` и `bSpecSaveValue` как **явно подписанные IDR-кандидаты**. В `lbSpecMean` видны расчётное среднее, взвешенная частота и амплитуда пика с отдельным предупреждением.
- `mvk_compatible/tests/test_spectrum_metrics_idr_candidate.py`, `test_spectrum_summary_export_candidate.py`, `test_desktop_qt.py`: синтетические проверки диапазона `N/2.56`, двух соседних пиков, строго первого максимума, centroïd, f32, масштабирования FRange, pipe/tab CSV, reject оригинального CSV, Qt клипборда и локального сохранения.

## 3. Честная граница доказательств

Эта реализация полностью отделена от оригинальных **приборных** расчётов: AUX4700/VALUES остаются единственным источником штатных DSP RMS, третьоктав, Peak/Peak-Peak, статуса датчиков.

**Важные неизвестные:**
- нет настоящего `MVKView` численного эталона `OutputMean/OutputPeakX/Y` при тех же `BIN + N + EnvelopeCode + SpectrumType + Fs + FRange + оконная позиция`;
- оригинальная `FRange` и физическая исходная калибровка для некоторых архивов не проверены;
- x87 регистры Extended vs float32, float-арифметика Hann и степень точности `007B2090` ещё не приняты;
- локализованный заголовок CSV, ANSI/Unicode кодировка, дата, библиотечный путь и точный оригинальный файл Save отличаются от исследовательского Qt-диалога, это **не** паритетный экспорт;
- в таблицах Copy используется исследовательская форматирующая функция с `3/4/4` знаками, но Windows Delphi FormatFloat ещё без золотого эталона.

По имеющимся локальным исходникам `Projects.7z` и `mvkview.idp` точного оригинального CSV с **указанными совпадающими параметрами** не обнаружено. Поэтому численный критерий совместимости с оригинальной запущенной MVKView **НЕ МОЖЕТ** пока считаться пройденным. Рабочая программа — исследовательский PREVIEW, не релиз 1.0.

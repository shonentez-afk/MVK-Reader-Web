## Исходный визуальный эталон

Пользователь предоставил **отдельный screenshot оригинальной MVKView 1.0.47**
после предшествующего проявления композиции из двух окон. Файл действительно
декодирован как **1920×1020 RGBA**, DPI ≈ **143.993 (Windows 150%)**.

1920×1020, но outer Win32 `Tmvkform` имел размер **1942×1042**
и смещение **−11, −11**. Это разные пространственные системы.
Оригинальный PNG содержит локальные пути/IP/объекты и

не представлены в артефактах.

4 компактные оригинальные кнопки с собственными иконками, адрес,
локальный каталог и логотип ВАСТ внизу слева. Это именно состояние

## Доказанные оригинальные именованные ресурсы DFM

В приватном операторском `mvkform.dfm` найдена
`icAllImages: TImageCollection` с **34 именами**,
для каждого по 4–6 PNG-вариантов. В том числе:

| Исходное имя | Размер для локального Qt | Назначение |
| --- | --- | --- |
| `Gears` | 64×64 PNG | Кнопка «Измерение» |
| `Open` | 64×64 PNG | «Загрузка сигнала из файла» |
| `EditGear` | 64×64 PNG | Настройка измерительных каналов |
| `EditNet` | 64×64 PNG | Системные параметры |
| `BWHand` | 24×24 PNG | Верхняя вкладка «Задачи» |

В отличие от предыдущих процедурных
Qt-кандидатов изображения этих источников
локально сопоставлены по форме с исходными
иконками на PNG и подтверждены в DFM.
**Их бинарные данные, превью/спрайты и исходный DFM
в публичный GitHub не помещались.**

Новый `core/original_private_imagelist.py`
ограничивает входной DFM 12 MiB, PNG 512 KiB,
коллекцию до 128 элементов, имена фиксированным
списком из пяти, разрешения до 512 px; проверяет
IHDR, PNG/IEND, наличие всех имён и отсутствие
дубликатов. Из исходного DFM выбирает нужный
размер 64/24. При повреждении PNG прекращает
загрузку source icons, не подменяет их произвольными
данными.

`desktop/source_visual_skin.py` и
`desktop/original_start_ui.py` подставляют
изображения **только при явном локальном выборе
своего DFM** либо через уже существующую
opt-in переменную окружения. В обычном
публичном EXE без файла остаются предыдущие
безопасные нарисованные Qt-приближения.
При `F12 → действие «Открыть оригинальные изображения
из локального DFM…»` локальная поставка значков
в QPushButton и TabIcon происходит прямо в памяти,
без сохранения на диск.

## Почему старые BMP не используются как фон

Сам `mvkform.dfm` содержит `imBackL/imBackR`
с жёлто-янтарными палитрами. Это **противоречит
реальному запущенному MVKView**, фон на приложенном
PNG — голубой. Старый source `SourceStartBackdrop`
слепо переносил PRIVATE BMP поверх голубого
фона, если пользователь выбирал DFM. Теперь
`_looks_like_observed_blue_background` проверяет
средние пиксели отдельно для L/R; жёлтые
`TBitmap` **не заменяют** корректный голубой
fallback, хотя точный оригинальный `imLogo`
и исходные иконки загружаются. Если оператор
позднее предоставит действительно синюю версию
двух BMP, локальный loader может их принять.
Не называть старую amber DFM-палитру
выполняемой runtime-темой без доказательства.

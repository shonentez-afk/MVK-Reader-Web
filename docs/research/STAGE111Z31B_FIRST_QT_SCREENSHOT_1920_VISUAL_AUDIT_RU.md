# Stage111Z31B — первый пользовательский Qt screenshot 1920×1080: проверка применимости к оригинальной MVKView

**Дата:** 03.11.2026. **Ветка:** `research/stage111-mvkview-desktop-20261029`. **Статус:** screenshot screening / Qt internal cursor geometry near-pixel PASS; **same-source TQGrapher/original UI pixel parity НЕ ПРИНЯТ**.

## 1. Что действительно передано

Получен пользовательский PNG 1920×1080, SHA256 `8f90750d3a926d4811e2ae146a4fd78b42ad05a71ec7a565bd1d969f269118d4`. Полный PNG оставлен только в чате (публичный GitHub не содержит этого изображения). На нём показана **обычная архивная сессия BIN/TSXML**, выбран **АЦП1**, **НЕ** импортирован `MVK_TAG0_x32dbg_reference.json`. На панели исходных данных видны:
- `Логарифмич.`, `1 Гц/лин`, `25600 Гц`, `150 дБ`;
- курсор `3800 Гц`, `−1,746 дБ`;
- итог `СКЗ 7,12 усл.ед.`, `пик 4316 Гц / 0,9545 усл.ед.`;
- активные кнопки Copy/Save и надпись об отсутствии подтверждённой физической калибровки (подтверждение обычного архивного расчёта, а не режима x32dbg).

В оригинальной операторской MVKView Stage111Z14 **другое окно измерения**: Tag0, N262144/Fs65536 = **1/4 Гц/лин**, курсор 3800 Гц / −55,32 дБ, summary 6,89 / 3800 / 0,7786 (значение summary PeakY линейное, не дБ), оси 0–25600 Гц и 0…−150 дБ. Числовые различия с текущим Qt изображением НЕЛЬЗЯ трактовать как ошибку FFT/интегрирования/курсорного ядра, когда окна, N, Fs и source channel не одинаковы. Не подменять автоматический тест реального оригинального Y тем, что активный архивный BIN «похож».

## 2. Численная геометрия ТОЛЬКО полученного Qt screenshot

Локальное измерение пикселей RGB текущего PNG, **без OCR и без публикации исходника**:
- приблизительная внешняя рамка графика: x=**392..1873**, y=**195..919** px, внутренняя левая граница для affine x=**393**;
- вертикальная линия XOR: **x=613**, горизонтальная **y=204**;
- на белом фоне (613,500): оригинальный XOR ожидаемый `RGB(255,127,255)` реально наблюдается; на черной линии (613,205): `RGB(0,128,0)` реально наблюдается.
- при X 3800 Гц, видимом 0..25600 и выбранной внутренней геометрии, `x_pred = 393 + 3800/25600 * (1873−393) = 612.6875`; абсолютное отклонение **0.3125 px**;
- при Y −1.746 дБ, видимом 0..−150 и той же приблизительной геометрии, `y_pred = 195 + (1.746/150)*(919−195) = 203.42736`; отклонение **0.57264 px**.

**Это сильная проверка текущего Qt pixel-to-axis/crosshair mapping в пределах одного пикселя для ТЕКУЩИХ отображённых округлённых значений**, но не original-vs-Qt pixel parity. Координаты измерены по screenshot, не являются источником `Qt ViewBox.sceneBoundingRect`; более точные координаты нужно получить из текущего Qt в одном запуске. Original Stage111Z14 в разрешении 1920×1080 имел reference plot rect L605,T193,R1639,B911, crosshair X758/Y458, но с другими данными и другим UI placement/plot width. НЕЛЬЗЯ сравнивать эти глобальные X/Y между скриншотами при разных размеров области графика и непроверенном Windows Display Scaling (визуально масштаб может отличаться от 100%, но точное значение по одному PNG не доказано).

## 3. Подтверждённые и исправленные UI-замечания

- **UI-31B-01 (FIXED IN CODE, CI TO VERIFY):** в архивном Tag0 ось Y имела длинную машинную подпись `относительные дБ (без аттестации калибровки)`, которая визуально не совпадает с original TQGrapher коротким `дБ` и отнимает пространство. Qt теперь ставит только метку `дБ` на оси Tag0. Предупреждение об условных единицах/калибровке **сохраняется** в видимом summary, tooltip и Copy/Save provenance. Float32/Y/статистика/Native не изменены. Режимы Tag1..3 и Live не менялись.
- **UI-31B-02 (FIXED IN CODE, CI TO VERIFY):** при импорте исходного Power/Y x32dbg поверх открытого *постороннего* BIN/TSXML старый заголовок архива оставался видим и мог вводить оператора в заблуждение. Теперь заголовок **всегда** `ЭТАЛОН x32dbg · Tag… · N… · АЦП эталона не подтверждён`, даже когда ранее был открыт другой архив; выбранный АЦП в списке имеет подсказку о неподтвержденной связи с эталоном. После выхода восстанавливаются исходные заголовок, АЦП tooltip, текущий архивный FFT и primary controls. Без архива возвращается исходная пустая PageStart. Copy/Save в режиме эталона по-прежнему недоступны.
- **UI-31B-03 (OPEN):** глобальная ширина plot и DPI исходного окна не совпадают с уже сохранённым оригинальным скриншотом; менять отступы и масштаб произвольно до съёмки **одного и того же оригинального Y** нельзя.

Тест `test_stage111z31a_qt_original_reference.py` обновлён: проверяет короткий архивный Tag0 axis, явный x32dbg title, false archive ADC provenance, откат прежнего заголовка/tooltip/оси. Новые тесты не аттестуют реальную Windows картинку оператора.

## 4. Что понадобится для истинного Stage31B сравнения

**Не нужны новые x32dbg stops/сохранения BIN.** В уже собранном Windows Stage31A автономном EXE оператору:
1. `Файл → Эталон графика MVKView · Power/Y x32dbg…`.
2. Выбрать `MVK_TAG0_x32dbg_reference.json` из ранее переданного пакета. JSON должен лежать рядом с исходными двумя файлами именно `power_after_mode.bin` и `display_y.bin` со строго ожидаемыми SHA256. Если нет папки с ними, создать локальную общую папку и скопировать **без изменения содержимого**; исходные ZIP в GitHub не требуются.
3. Убедиться, что на экране явно виден **ЭТАЛОН**; в списке должно быть **1/4 Гц/лин**, `25600 Гц`, `150 дБ`, отключённые Copy/Save, поле про 131072/131072 Float32. Никаких значений из архива и мнимых подтверждений калибровки.
4. Навести курсор на 3800 Гц и прислать скриншот **1920×1080**. Желательно выставить соответствующий оригиналу 100% Windows scaling или указать фактический масштаб Windows, чтобы различать DPI/шрифты и геометрию. После этого провести Qt↔TQGrapher comparison по normalized plot canvas, grid, labels, XOR и UI.

Без выполнения шага 3 S08 (pixel-perfect Qt native vs original) остаётся OPEN независимо от успешных 4 × 131072-bit numeric goldens.

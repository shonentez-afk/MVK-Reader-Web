# Stage111Z31FI — оригинальный приём и хранение 8 ADC + 2 TACH после «Измерить»

Дата: 17.11.2026. Ветка: `research/stage111-mvkview-desktop-20261029`.

## Обязательная совместная сверка трёх приватных источников

Оригиналы проверены **локально**, материалы не копируются в GitHub.

1. `/mnt/data/mvkview.idp`: IDR project v3, 42 094 126 байт, SHA-256 `77e59f98febdd7df94e71cb538a2df69ea4de4624f15b088a81c86e61bb5a438`. Исходные символы/методы `TMvkChannelStorage` и `TMVKThread`.
2. `/mnt/data/Projects.7z`: libarchive извлёк **4/4** `_Unit115.pas`, `_Unit125.pas`, `_Unit128.pas`, `mvkform.dfm`; размер и SHA-256 каждого файла независимо совпали с записями `source_files` SQLite (проверка по basename). Приватные PAS/DFM, IDP, SQLite, RAW и PCAP не коммитятся.
3. `/mnt/data/mvk_idr(1).sqlite`: `PRAGMA quick_check=ok`; 25 404 функций, 92 767 вызовов, 95 событий; адреса/типы/поля проверены по `functions` и локальному тексту PAS.

**Проверенные original IDR адреса и точные типы:**

- `_Unit128.pas 00846C67..00846CBD` — при первом Mode2 создаются **8** `TMvkChannelStorage` c `AdcDataType=0` / `BufferSize=0x200000`, затем **2** c `AdcDataType=2` / тем же размером. Физическое выделение в оригинале происходит до `TMVKThread`.
- `_Unit115.pas 007D0988` — конструктор проверяет power-of-two, устанавливает `FBufferMask=BufferSize-1`; тип 0 выделяет `Single[0x200000]`, тип 2 — `Byte[0x200000]`; `FRxPos`, `FValidPos` имеют 64-битную семантику. `FRange=1.0` по умолчанию.
- `007D1B08` — `AllocBufferChunk` выдаёт оставшийся до кольцевого конца участок **в байтах**; ADC byte_count переводится в отсчёты в `007D2398`, а TACH тип 2 оставляет размер в байтах. `007D1AE0` — `FValidPos := FRxPos`; `007D1AF0` сбрасывает действительное окно при смене частоты; `007D1998` — доступность/переполнение, без выдуманных отсчётов.
- `_Unit125.pas 008081EA..0080828C` — единственный приёмный поток вызывает `AllocBufferChunk`, считывает подтверждённые байты и `ProcessBufferChunk`. В TACH-пакете 64 слова Float32 = 256 **байт**; `TMvkChannelStorage` типа 2 продвигает `FRxPos` на 256 элементов, тогда как сетевой `SampleHeader.Index` увеличивается на 64. `00808241..0080824B` — исходный `FreezeUpdate` подавляет запись в storage при установленном флаге. Совместимая read-only реализация пока не останавливает RAW, поэтому полное поведение FreezeUpdate остаётся OPEN.

## Что изменено в коде

- **Go Source Receiver** `source_original_ring.go`: независимое кольцо из 10 банков по (2^{21}) элементов — 8 Float32 (по 8 МиБ) и 2 байтовых TACH (по 2 МиБ). Суммарный верхний предел реальных данных — **68 МиБ** плюс уже существующий, отдельно ограниченный GUI preview (8 МиБ). Во избежание резервирования 68 МиБ в тестах и Task0 байты конкретного канала выделяются при первом доверенном кадре; логическая ёмкость/нумерация совпадает с оригиналом.
- **TACH type 2/Byte:** полный original ring принимает все 256 фактических байтов подтверждённого TACH-кадра, даже если проверка исходных четырёхбайтовых слов выявила NaN/Inf. Это не присваивает им числовой статус «исправного Float32»: отдельно существующий `tach_raw_export` по-прежнему может отклонить такой экспорт; RAW и байтовое original storage сохраняются, новый код не обходит проверку экспорта. Для числового ADC тип 0 проверка nonfinite остаётся строгой.
- `Monitor.consume` получает всё те же **один TCP** и исходные проверенные кадры. Когда verified calibrated `LiveBinSpool` активен, ADC ring получает ТЕ ЖЕ float32 bytes **после** записи в spool и SHA, без повторного FRange. Без экспортного spool или после обоснованного изменения Fs ring хранит исходные байты с **другой доменной меткой** и не подменяет их калиброванными. Каждый TACH записывается **ровно 256 bytes** из действительного пакета.
- При скачке `SampleHeader.Index`, изменении Fs, переходе raw/calibrated или nonfinite данных непрерывная история помечается недоступной (`FValidPos`), но полная принятая RAW запись **не меняется**. `FRxPos` остаётся локальным uint64, `SampleHeader.Index` — отдельным uint32 с естественным переполнением. Копирующее чтение допускает только реальное, ещё не перезаписанное окно.
- `MVK_NATIVE_LIVE_STATUS.json` расширен компактным **read-only accounting** `source_original_storage`: 10 каналов, тип/ширина элемента, позиции `rx_pos_64/valid_pos_64/first_readable_pos_64`, доступное количество, частота, domain, отдельный `next_device_sample_index`, gaps. Не содержит и не экспортирует бинарных отсчётов.
- **Python Core** `original_source_ring_receipt.py` проверяет поля, типы, `2^21` ёмкость, типовые отличия ADC/TACH, отсутствие вымышленных данных, раздельные счётчики и свежие исходные частоты. Старые легитимные JSON без поля продолжают читаться, но им НЕ приписывается новое хранилище.
- **Qt** размещает только проверенный receipt в свойстве уже существующей `PageStatus` без новых исследовательских элементов и без второго TCP. При Mode2/STOP/ошибке этот receipt сбрасывается. Текущие Live графики продолжают использовать отдельный ограниченный и SHA-проверяемый preview.

## Регрессия и осторожность

Go тестирует: десять хранилищ и их типы; 2 097 152 элементов и wrap, учёт перезаписанной истории; пропуск кадров, изменение Fs/domain, nonfinite, uint32 переполнение при uint64 хранилище; прохождение реальных synthetic `Monitor.consume`; byte identity уже калиброванного spool и кольца. Python — 10-channel proof, 2M wrap, TACH byte count, повреждённые receipts. Qt — реальную QWidget привязку и очистку при STOP/ошибке без физической сети.

CI для основного коммита: [Stage111Z31FI GitHub Actions #44065853697](https://github.com/shonentez-afk/MVK-Reader-Web/actions/runs/44065853697). Учитывать более поздний проверенный кодовой SHA, если последует фиксация тестов. **Не объявлять CI 4/4 до фактического результата.**

## Что ещё нельзя считать принятым

- Физический МВК01 и реальная оригинальная MVKView на одном трафике не сравнивались. `original_delphi_compatibility_verified=false`.
- Существующий атомарный preview по-прежнему ограничен 262 144 отсчётами на ADC. Он **не** получает все 2 097 152 элементов 50 раз в секунду: для оригинальных длинных Live GetSignal/сохранения нужных отрезков требуется отдельный **on-demand** безопасный read-only доступ к новому ring без большого периодического ZIP. Это следующий интеграционный блок; памяти Go уже достаточно.
- Сигналы времени DSP, исходное x87/FFT/FIR, точные команды SetRate/WriteData/WriteValues, `FreezeUpdate` и весь device TX/Flash/IP write остаются за пределами текущей достоверной приёмки.
- Аппаратные команды не включены, формат RAW/BIN не изменён, приватные первоисточники не опубликованы.

# Stage111Z31BT — функциональное восстановление исходной PageCalib (Core + Qt)

## Приоритет и первоисточники

Цель: восстанавливать все функции исходной MVKView, а не ещё один цикл экранных сравнений. Из приватного операторского Projects.7z прочитаны Projects/mvkform.dfm и Projects/_Unit128.pas; исходники, оригинальные BIN/IDP и снимки оригинала не помещаются в GitHub и тестовые артефакты.

Из оригинального Delphi DFM подтверждены:
- PageCalib, splCalib: левый блок 369 логических пикселей, splitter 8, правый 615;
- tcCalibParam: ОДНА вкладка; панель pnCalibTools высотой 63; bCalibStart (6,8,107,41), cbCalibGenPort (216,16,129,24); pnCalibSelect высотой 51; пять кнопок 43×35 с исходными Tag 1..5, x=6,55,104,153,202;
- tcCalibResult: ДВЕ вкладки; pnCalibResult (4,42,607,63) и три кнопки 155×41: bCalibSave x=6, bCalibClear x=174, bCalibGenerate x=342, top=8. Исходная memo logCalibResult только для чтения; исходная TStringGrid tabCalibResult первоначально имеет 2 столбца/1 строку и прячется при загрузке; bCalibClear создаёт 11 столбцов и 77 строк.

Из оригинального PAS (подтверждённые адреса):
- 00844D1C..00844FD8: исходный cbCalibSteps динамически наполняется группами **11 + 14 + 14 + 1 + 9 = 49 шагов**, затем CheckAll. Тексты зависят от реальных аппаратных массивов gvar_008D30A8... и локализации; пока показывается только тип и номер шага без вымышленных физических частот/напряжений.
- 0084C9A4 bCalibAClick: по Tag=1..5 инвертирует самый первый флажок группы и назначает одинаковое состояние всем её шагам.
- 0084CA58 bCalibClearClick: выставляет ColCount=11 и RowCount=0x4D=77, очищает всю таблицу, формирует пять заголовков групп, заголовки эталона и АЦП; не является приборным сбросом и не очищает исходный лог.
- 0084D9D0 bCalibSaveClick: записывает CALIB-yyyy-mm-dd--hh-nn-ss.csv, первую строку sep=|, затем для каждой строки 11 полей TStringGrid с завершающим разделителем |. Кодировка/порядок байт оригинального Win32 Delphi среды не приняты как 1:1.
- 0084D474 bCalibGenerateClick: читает эталон TStringGrid.Cells[2,8], восемь измерений Cells[3..10,8] и исходные коэффициенты ConfigCalibCellList.GetFloat(index=0..7). Множитель оригинального tbyte Extended — 1.001001001001... После FLD(measured*mult), StrToFloat(reference), FDIVRP ST(1),ST(0) отношение = MEASURED * MULT / REFERENCE, не обратное. Допуск исходной проверки x87 — 0.8..1.2. Затем новый gain = original_gain / ratio. Полученный float32-кандидат по IDP не является подтверждением 0 ULP исходного x87 вычисления.
- 0084DD30 bCalibStartClick: создаёт TMVKCalibThread, берёт порт генератора и запускает выбранные шаги. **Этот опасный живой обработчик намеренно не включён**: не аттестованы COM порт, генератор, порядок измерений и команды прибора.

## Единый функциональный блок

Автономное ядро: mvk_compatible/core/original_calibration_workbench.py.
- Иммутабельная модель 49 исходных флагов, пять групп и правила bCalibAClick. Реальная локальная матрица 77×11 с source-derive заголовками и пустыми значениями там, где отсутствует исходный файл.
- Безопасная загрузка оригинальных CALIB CSV: ровно строка sep=|, 77 строк, 11 значений и завершающий |; проверка ограничений размера/кодировки, SHA256, отсечение путей и ссылок. Не принимает несовместимые/частичные файлы за оригинальные.
- Реальное сохранение новой локальной таблицы CALIB CSV в исходной грамматике и независимое полное повторное чтение 77×11 с проверкой. Отказ от перезаписи и изменение исходного файла. Лог из ограниченного локального .txt/.log отображается отдельно и не выдумывается.
- Реальная локальная кандидатная арифметика по original source bCalibGenerate: каждое из восьми значений читается только из загруженного CALIB CSV, базовые коэффициенты — только из проверенного оригинального текстового PageConfig (адреса 0x20..0x2E, format char f). Проверки >0, finite, source ratio 0.8..1.2, диапазон Float32, SHA источников. Возвращается восемь проверяемых чисел и provenance. Отдельное сохранение в НОВЫЙ JSON с независимым readback, явно НЕ загружаемый в прибор.
- Нет сокетов, COM, генератора, вызовов TMVKCalibThread или TMvkCellList.InputValue/SaveValuesToFile и нет физической калибровки.

Рабочий Qt: desktop/original_calibration_ui.py, интегрирован в desktop/original_shell.py.
- Две исходные страницы (1× tcCalibParam и 2× tcCalibResult), исходные bCalibA/V/D/DR/T реально переключают 49 флагов, bCalibClear действительно очищает таблицу, bCalibSave создаёт исходный локальный CSV, bCalibGenerate вычисляет восемь числовых предложений при наличии **двух проверенных источников** (CALIB CSV и открытый ранее PageConfig); все результаты видны в интерфейсе.
- Параметры генератора cbCalibGenPort и bCalibStart видимы, но недоступны, поскольку реальный исходный TMVKCalibThread/устройство не проверены.
- Небольшая явно обозначенная офлайн-панель дополнительной загрузки CSV/логов и сохранения проекта JSON не выдаётся за DFM. Новые файлы никогда не заменяют исходники пользователя.
- Оригинальная матрица/журнал и превью кандидатов переключаются без изменения исходного измерения или конфигурации прибора. Связь с PageConfig использует именно загруженный неизменённый source baseline, а не несохранённые изменения черновика.

## Проверка

Core synthetic: точная source-структура 49/77×11, групповое переключение, сохранение/повторное открытие CSV, лог, расчёт 8 коэффициентов из row=8, float32, 0.8..1.2, отказ при изменённом источнике/перезаписи/неверной грамматике/формульных ячейках/неподтверждённой конфигурации.

Windows Qt/DPI150: реальные элементы и геометрия исходных кнопок, два режима результата, переключение 49 флагов, независимая загрузка CALIB CSV и PageConfig, вывод восьми коэффициентов, локальная запись CSV и JSON, сохранность оригинальных файлов, запрет COM/генератора/аппаратной калибровки.

## Честно не восстановлено

Оригинальный TMVKCalibThread, подключение генератора, физическая процедура калибровки и передача полученных коэффициентов в МВК; runtime-локализация и значения реальных 49 аппаратных тестов, 0 ULP Delphi x87, исходная кодировка и точные пиксельные размеры журнала/таблицы на всех DPI, реальное визуальное сравнение с запущенным оригиналом. Это рабочий автономный офлайн-конвейер, не полностью восстановленный генератор.

Следующим крупным пакетом восстановить PageStatus / PageStart, недостающие обработчики семи страниц и исходную связку native capture, сохраняя Core + Qt + Windows E2E в одном пакете. Не возвращаться к отдельным циклам сравнения FFT/PNG до реализации всего пользовательского функционала.

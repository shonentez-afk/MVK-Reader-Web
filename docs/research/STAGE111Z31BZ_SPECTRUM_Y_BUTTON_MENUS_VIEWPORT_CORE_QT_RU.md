## Причина, проверенная непосредственно по закрытым операторским источникам

Локальный операторский \`Projects.7z\` содержит \`mvkform.dfm\`:
\`bSpecVScale: TButton\`, Left=9, Top=197, Width=162, Height=41, \`Style=bsSplitButton\`, \`DropDownMenu=popGraphVScale\`, \`OnClick=bAnyDropDownClick\`. Дизассемблированный \`_Unit128.pas:0084EAF4..0084EB4C\` подтверждает: обработчик основного нажатия **вызывает Popup на меню**, а не переключает масштаб. В прежнем Qt \`MenuButtonPopup\` и \`clicked.connect(_cycle_original_vscale)\` каждая активация основного тела кнопки переключала Tag на следующий до 5, вызывая неожиданное изменение вида.

Второе реальное расхождение в подписях: \`_Unit128:0084B901..0084B958\` создаёт **численные физические значения** меню по \`GraphDefaultVScale / [1,10,100,1000,10000,100000]\`, получая единицы от \`TMvkChannelStorage.GetDerivedUnits\`; логарифмический режим использует [150,100,75,50,25,10] дБ. Ранее Qt показывал только \`÷ 1\`, \`÷ 10\`, \`÷ 100\` и не объяснял фактический текущий диапазон Y. Происхождение чисел \`008D3468/008D3480\` и исходные \`mSpecVScale1Click:0084C5AC..C748\`, \`sbSpecVScrollChange:0084C770..C800\` уже восстановлены в автономном Core.

## Изменения реализованы совместно с работающим UI

- \`desktop/main_window.py\`: первичная кнопка \`bSpecVScale\` теперь \`QToolButton.InstantPopup\`: **любое нажатие открывает оригинальное меню**, не вызывает скрытое циклическое увеличение масштаба; только активированный пункт меняет Tag, прокрутку и видимый диапазон.
- При проверенном текущем TSXML FRange или операторском x32dbg FRange меню показывает рассчитанные по настоящей модели Source \`GraphDefaultVScale\` физические численные деления. Так как полученные из оригинала аппаратные единицы \`GetDerivedUnits\` не подтверждены локальным BIN, для чисел используется явно условное \`усл.\` и подсказки с provenance; ни аппаратная калибровка, ни x87 битовый паритет не утверждаются.
- Если известного FRange **нет**, меню честно показывает \`÷ N (лок.)\`, а не выдумывает исходные физические значения. Исправлен локальный автодиапазон: исходный режим физической шкалы начинает с Tag3 (делитель 1000), а прежняя Qt модель брала полное окно спектра как GraphDefault и показывала только 0.1% максимума — отсюда «почти исчезающий» график. Исследовательский базис теперь **на весь полный Core FFT пик × 1000 × 1.2** при исходном Tag3. Он остаётся неизменным для всех шести пользовательских пунктов; исходное правило нижней привязки \`oldPosition+oldPage-newPage\` сохраняется. Это **помеченный локальный auto-fit**, а не неизвестный оригинальный FRange.
- При выборе источниковой шкалы Core по-прежнему строго использует \`source_vertical_selection\`, \`source_spectrum_vertical_view\` и \`source_spectrum_v_scr\` без изменения измерений/FFT. Реальный Qt \`ViewBox.setYRange\` совпадает с рассчитанными нижней/верхней границами, scrollbar получает настоящий Delphi Position/Page, не нормализованные Qt 0–1000.
- У существующей первичной DFM-кнопки (новых десятых виджетов не добавлено) обновляются Caption, Checked радио-элемент, точное Y:min…max, provenance, Tag и Position через ToolTip/StatusTip; statusBar сообщает, как изменился вид при реальном выборе масштаба/прокрутке.
- \`test_stage111z31bz_qt_original_y_button.py\`: реальное нажатие по телу кнопки, неизменность Tag/Y/FFT до выбора пункта, все шесть пунктов на DirectBIN с TSXML \`InternalChannelGain=6.25\` → GraphDefault=10 → Y 10/1/0.1/0.01/0.001/0.0001, автоматический нижний якорь; отдельный dB режим 150…10, без-FRange локальный авто-fit полного FFT, целостность полного source Float32 FFT SHA. Ранее BN Qt регрессия обновлена под истинный численный Caption. Никакой реальный прибор, оригинальные закрытые коэффициенты или личные BIN не используются в CI.

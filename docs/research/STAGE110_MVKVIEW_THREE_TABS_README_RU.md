# Stage110 — три вкладки оригинальной MVKView, исследовательская реализация

**Статус:** первая работающая OFFLINE-версия, **не** полная функциональная копия оригинальной MVKView и **не** стабильный релиз. Дата: 2026-10-29. База: приватный `shonentez-afk/MVK-Reader-Web`, исследовательская ветка `research/stage41-spectrum-chain-20261028`. Стабильная v0.3.40 остаётся неизменной.

Этот пакет продолжает уже выполненный reverse engineering оригинальной Delphi MVKView (Stage25–96) и проверенный реальный Live-приём Native R6.1 (Stage106–109). Он **не вычисляет собственную замену оригинальным DSP-показателям**: готовые третьоктавы, диапазонные СКЗ и эквивалентные ПИК/ПИК-ПИК берутся из AUX4700/VALUES приборного сеанса. Локально из калиброванного BIN вычисляется только отображаемый графический FFT, потому что **оригинальная вкладка «Спектр» тоже вычисляет такой FFT в настольной MVKView**.

## Запуск без подключения к прибору

Требуются Python >=3.10, `fastapi`, `uvicorn`, `numpy`. Windows или Linux. В контейнере использованы FastAPI 0.128.2 / NumPy 2.3.5.

1. Скопируйте полностью комплект Stage110 в отдельную локальную папку.
2. Отдельно создайте приватную папку, содержащую **готовые ZIP-экспорты Stage107/R6.1**: в каждом ZIP 8 BIN + 8 TSXML, `VALUES_ALL_ADC_RECONSTRUCTED.csv`, `TABLE_LAST_AUX_RECONSTRUCTED.csv`, `EXPORT_AUDIT.json`. Исходные промышленные RAW/PCAPNG не нужны.
3. Укажите переменную `MVK_STAGE110_SESSIONS_DIR` с путём к папке ZIP-экспортов и выполните:
   `python -m uvicorn stage110_original_tabs:app --host 127.0.0.1 --port 8871`
4. Откройте `http://127.0.0.1:8871/`.

**Встроенный в исследовательскую ветку Web режим (опционально):** при явном `MVK_STAGE110_ENABLE=1` тот же роутер доступен внутри уже существующего FastAPI MVK Reader Web как `/stage110/` и `/api/stage110/...`, но приложение не переподключается к прибору. Для тестового запуска используйте только локальные/закрытые архивы. По умолчанию этот режим **выключен**.

На Windows можно использовать консоль PowerShell: `$env:MVK_STAGE110_SESSIONS_DIR='C:\path\to\exports'`; `$env:MVK_STAGE110_ENABLE='1'`. Отдельную установку Python на рабочих ПК для текущего релиза R6.1 это не требует — это **исследовательский UI**, а не замена самостоятельного Native EXE.

## Что реализовано

### «Расчётные данные»
- Выбор одного из 8 АЦП, выбор одного из 60 последних обновлений из реального Stage109 №84; все 43 третьоктавные полосы и 24 приборных RMS на каждый канал.
- В режиме `Все каналы СКЗ` — приборные значения 24 диапазонных показателей на восьми каналах одновременно.
- В режимах `Все каналы ПИК` и `Все каналы ПИК-ПИК` — **реальные** 24×8 значения только при наличии `aux4700.jsonl` + `AUX_PROVENANCE.json` c SHA-256 исходного RAW. БЕЗ этих файлов выводится «—», никогда не подставляются фиктивные пики/формулы.
- Все 43 + 24 RMS для каждого отображаемого AUX-обновления дополнительно сверяются с округлённым VALUES в пределах **точного** формата `.4g`/десятичная запятая. Несовпадение -> HTTP 422 и запрет вывода.
- Состояния датчиков не скрываются: в приборе №84 АЦП7/8 со статусом `0x400` выделены как проблемные.
- Измеренные параметры помечены как `MVK_DSP`; метки времени VALUES — **часы ПК**, а не доказанная метка времени отсчётов DSP.

### «Временной сигнал»
- Отображение калиброванного BIN/TSXML без повторного применения K, выбор канала, времени, длительности, вертикального масштаба, AC/AC+DC.
- Децимация min/max с сохранением узких выбросов; указатель/экспорт CSV, расчёт СКЗ/пика по выбранному окну.
- Семантика AC как вычитание среднего выбранного окна — **локальная кандидатная реализация**, точное сравнение с Delphi `GetSignal` ещё требуется. Оригинальная огибающая и состояние ring buffer пока не восстановлены до полной совместимости.

### «Спектр»
- Четыре оригинальных пункта меню: логарифмический, линейный ВУ, линейный ВС, линейный ВП; N=1024..262144; выбор канала и окна BIN, частотного диапазона, вертикального масштаба, линии сетки, курсор, CSV.
- Исследовательский NumPy FFT с периодическим Hann RMS `w[n]=(1-cos(2πn/N))/sqrt(1.5)`, совпадающим по структуре с оригинальным `TMvkChannelStorage.GetSpectrum`/`TDSXFastFourier` согласно Stage81c; **полная численная эквивалентность оригинальной Delphi FFT ещё НЕ ДОКАЗАНА**. Особенно требуют отдельной проверки dB reference/логарифм, пик/масштаб амплитуд, интегрирование ВУ→ВС→ВП, оконные границы и меню огибающей.
- Вывод помечен как `APP_DERIVED_FFT_MVKVIEW_CANDIDATE`, **никогда не называется оригинальным приборным спектром DSP**.

## Безопасность/инварианты

- Программа **не открывает TCP-сокеты к МВК**, не вызывает Modbus 502, не меняет конфигурацию.
- Сессии выбираются только из явно заданной локальной папки, доступ по пути вне этой папки запрещён.
- Проверяются все 8 BIN одного сеанса, имена прибора/даты, 8 TSXML, SHA-256 BIN относительно `EXPORT_AUDIT.json`, конечность выборок, `DataLength`, `DataOffset`, Fs=65536.
- Готовый BIN уже физический; повторно умножать на K нельзя. Для новых приборов или других Fs менять проверенный контракт только после эксперимента.
- Ни на GitHub, ни в этот пакет не входят исходные коммерческие `mvkview.exe`, `_Unit*.pas`, `Projects.7z`, Wireshark/RAW, промышленные BIN и private test ZIP.
- Этот интерфейс **офлайн архивный**. Переключение в реальный Live на существующем Web требует отдельной безопасной интеграции Native R6.1, тестов, контроля устаревания AUX и reconnect.

## Проверка

`python -m pytest -q test_stage110_original_tabs.py` — синтетический набор **10/10 PASS**; не нужен прибор и приватные файлы.

Закрытые реальные проверки в текущем рабочем окружении: два 30-секундных архива Stage107 и один Stage109 (Native R6.1), все 8 АЦП, 4 спектральных режима каждого канала, 60 расчётных обновлений, 0 ошибок; для Stage109 дополнительно **60×8×67=32 160** точных сопоставлений AUX ↔ округлённые VALUES, включая корректное `0x400`. Санитизированная сводка: `QA_REAL_DATA_SANITIZED.json`.

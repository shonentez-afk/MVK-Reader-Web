# Stage111Z.12 — x32dbg, проверка одной и той же кнопки «Копировать»

**Цель:** сравнить исходные слова Selected Spectrum `OutputMean`, `PeakX`, `PeakY` и XScale с **текстом именно этого нажатия**, не смешивая с предыдущим backend FFT `GetSpectrum`.

**Условия:** оригинальная MVKView с локально открытым офлайн-архивом, работающий x32dbg (32-bit); прибор/производственную сеть не подключать. Адреса относятся к проверенному original IDR с базой 00400000, ASLR/rebase проверять отдельно. Все действия ниже только читают память/локальные файлы.

## 1. Остановка на обработчике Copy

В строке команд x32dbg:

```text
bp 0084BC8C
```

В оригинальной MVKView выбрать **одну** из нужных соседних записей спектра, нажать кнопку **«Копировать»**. Должен остановиться процесс на `EIP=0084BC8C` **до форматирования первого поля**. На этой точке `ESI` уже указывает на record конкретной выбранной записи; `EBX` — объект формы.

## 2. Считать 4 DWORD именно этого Copy-click

В калькуляторе x32dbg или командном поле проверить:

```text
dword:[esi+30]                           // Input OutputMean, Float32 bits
dword:[esi+34]                           // Input OutputPeakX, bins Float32 bits
dword:[esi+38]                           // Input OutputPeakY, Float32 bits
dword:[dword:[dword:[ebx+FF4]+40]+14]   // Current graph XScale Float32 bits
```

**Записывать восьмизначные HEX**, а не десятичный перевод кода DWORD. Структурная формула исходного кода:

```text
ESI = EBX + 0x908 + SelectedRecordIndex*72
CopyFrequency = Single( Single([ESI+34]) * Single(Graph.XScale) )
```

Если вложенное выражение не воспринимается калькулятором, выполни цепочку по частям: сначала `dword:[ebx+FF4]`, затем `dword:[<прочитанный адрес>+40]`, потом `dword:[<второй адрес>+14]`. Важно: здесь `EBX` не тот же объект, что в `GetSpectrum 007D1900`. У поля PeakX единицы **FFT-бин**, а не Гц.

## 3. Завершить ТОЛЬКО это нажатие

После чтения четырёх значений нажать F9, чтобы оригинальная кнопка «Копировать» закончила работу. Вставить Ctrl+V в Блокнот. Нужны одна строка и **ровно три числа с TAB** между ними. Не переключать запись между x32dbg-остановкой и Ctrl+V. Оригинальный источник `0084BC8C/0084BCAD/0084BCCF` запускает `007B2090` с точностью **3,4,4** соответственно.

В чат можно передать **четыре HEX и одну строку**, без RAW BIN/EXE/IDP и полного исходного архива.

## 4. Необязательное приватное сравнение в один клик

Если нужна локальная автоматизированная проверка, создать в частной папке `C:\MVK_CAPTURE` текст `same_click.txt` из одного Ctrl+V. Рядом создать `same_click.json` со следующей **фиктивной структурой** (все HEX являются ПРИМЕРОМ; заменить на настоящие четыре числа):

```json
{
  "schema": "MVKVIEW_ORIGINAL_COPY_SAME_CLICK_V1",
  "copy_breakpoint_va": "0x0084BC8C",
  "output_mean_bits": "0x3F800000",
  "output_peak_x_bin_bits": "0x40000000",
  "output_peak_y_bits": "0x40400000",
  "graph_xscale_bits": "0x3F000000",
  "original_clipboard_file": "same_click.txt",
  "decimal_separator": ","
}
```

Затем в корне своей локальной копии GitHub (Python+NumPy):

```powershell
python -m mvk_compatible.private_spectrum_copy_selected_record_compare "C:\MVK_CAPTURE\same_click.json"
```

Сравнитель проверяет три текстовых значения с кандидатным Delphi `007B2090` и выводит **только** boolean для каждого поля и SHA строки. Не получает архив, не требует старые N/Fs/FRange и не печатает приватные слова/пути. Выход 0: три совпали в этой записи; выход 1: несовпадение; 2: некорректная/опасная структура. Точный формат Delphi для всех чисел/округлений пока не аттестован.

## 5. Почему старые значения нельзя смешивать

Ранее x32dbg при backend `GetSpectrum 007D1900` выдал `OutputMean=6.8925`, peak-bin `15200.1455`, peak-y `0.7786`, source-derived Fs/N=0.25 и частоту `3800.0364` Гц. Но пользователь прислал **два** Clipboard-наблюдения соседних записей, где частота около **19.93–19.94 Гц**. Это не ошибка численного FFT по умолчанию: другая запись/масштаб/состояние графика не являются тем же оригинальным runtime-вызовом. Source audit функции `0084EADC` подтверждает наличие селектора record; его фактический номер в runtime при прошлых снимках неизвестен.

**Важнейшая следующая проверка** — четыре DWORD при `0084BC8C` в том же Copy-click, чтобы различить выводимость текста через форматирование и ошибочное сопоставление источников. Затем `CursorString` и `TQGrapher/Canvas`.

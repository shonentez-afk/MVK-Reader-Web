# MVKView — проверка 8 оригинальных меню спектра и данных X/Y

**23.11.2026. Ветка:** research/stage111-mvkview-desktop-20261029.
Обязательная база — восемь новых скриншотов пользователя 23.11; аппаратный МВК01 и оригинальный Win32 EXE не подключались. Архив оригинальной программы и IDR источник локально, непубликуемая инструкция _Unit128.pas 0084B4E8, 0084B901, 0084C3AC, 0084C5AC, 0084C770 прочитана совместно с эталонными снимками. Пользовательские PNG и исходные Pascal/DFM/IDP/SQLite не включаются в git.

## 1. Меню по скриншотам

- «Без фильтра» + 19 × 1/3окт + 6 × 1окт + 6 × 2окт = 32; исходные Tag0..31 и разрыв перед Tag20 совпадают с уже существующим source_original_envelope_menu.py; новые функции FIR не добавлялись.
- «Логарифмич.», «Линейный ВУ», «Линейный ВС», «Линейный ВП» = исходный Tag0..3.
- «Гц/лин» = 1/4, 1/2, 1, 2, 4, 8 при Fs=65536, в source порядке NFFT=262144..8192. Для другого Fs единицы = Fs/N; 1024 и 4096 остаются только в исследовательском инспекторе.
- «Ширина X» десять source Tags: 25600,12800,6400,3200,1600,800,400,200,100,50 Гц. Оригинальная процедура использует статический полный диапазон 25600 Гц; специально адаптированный Qt список НЕ удаляет source пункты, но блокирует те, для которых нет исходных реальных бинов (например Fs8192 → DataSize·XScale≈3200 Гц). Это улучшение без претензии на буквальный Win32 viewport ниже Fs65536.
- «Высота Y» Tag0: 150,100,75,50,25,10 дБ. Tag1/2/3: исходные физические делители 1,10,100,1000,10000,100000 на GraphDefaultVScale; меню показывает ЧИСЛЕННЫЕ значения с единицами, а не просто делители.

## 2. Согласованность физических величин

Логарифмический — **дБ**; линейный ВУ — **м/с²**; линейный ВС — **мм/с**; линейный ВП — **мкм**. При source FRange≈510.6 логика GraphDefaultVScale даёт три исходные верхние высоты (Tag0): 1000 м/с², 10000 мм/с, 100000 мкм. Выбранный при переключении физического режима source Tag3 даёт 1 м/с², 10 мм/с или 100 мкм соответственно. Это именно подписи ВЫСОТЫ графика, не пересчёт FFT.

В Direct BIN без достоверного FRange делители ранее ошибочно выводились текстом «÷1000 (лок.)». Теперь экран показывает шестёрку реальных локальных высот с номинальными единицами режима, а baseline визуального fallback выбирается безопасной лестницей 1/2/5 с запасом над пиком. Такой fallback не является оригинальным GraphDefaultVScale и НЕ подтверждает приборную калибровку. Подписи оси и курсора отображают единицы выбранного режима; в подсказках сохранены предупреждения.

## 3. Ограничение графика X реальными данными

Оригинал использует фиксированный H full=25600; Qt раньше расширял область до 25600 даже при Fs8192 и фактическом TQGRSeries конец=3200. Сейчас подписи и source Tag сохранены, но несуществующие страницы disabled; X-scroll maximum=real_data_end-page, манипуляции X не трогают массивы power/Y Float32, исходный RAW, FFT, SUM. При Fs65536 и оси 25600 original integer scroll сохраняется прежним.

## 4. Тесты и пределы доказательства

Добавлены screenshot-grounded Core и Qt acceptance tests, включая source FRange≈510.6, режимы Tag0..3, локальный без-FRange fallback, Fs65536 и Fs8192, width=100, pan, новый расчёт и ограничение недоступных частот, SHA Float32 не меняется при X/Y zoom. Результат CI проверять по актуальному SHA после пуша; успешная синтетическая проверка не доказывает отрисовку настоящей MVKView на реальном физическом приборном потоке.

**Не менять** primary branch/main, source raw, proprietary files и приборные команды; проверка только UI/CALC без TX.

## Цель и граница

**Основная цель не меняется:** собственный рабочий MVK Reader Web по TCP/10230, точный приём ADC/AUX4700 и корректный экспорт BIN/TSXML/VALUES/TABLE. Изучаемый `mvk-v3-1.0.59.siupdate` — реконструированный **DSP Blackfin** (секция A код 203040 B, секция B данные 75188 B); это дополнительный источник о вычислениях внутри прибора. Документ Modbus/TCP ред.1.0.39 с портом **502** — справочник адресов, НЕ повод менять транспорт продукта с TCP/10230.

## Проверенные технические выводы (VERIFIED по доступным файлам/байтовой арифметике)

1. Контейнер: заголовок 0x130 = 304 B; секция A 203040 B; секция B 75188 B; сумма **278532** B. Магия VAST_MVK. Наличие исполняемого кода ADSP-Blackfin и таблиц пригодно для дальнейшего анализа DSP.
2. **Исправление MD5 секции B:** лабораторный отчёт называет 0x120–0x12B «усечённым MD5», 0x12C–0x12F «неидентифицированными 4 байтами». Однако опубликованный `md5_calculated = 728607260559bb71bda3666124e48697`, а `0x12C = 0x9786e424` при little-endian означает байты `24e48697`. Значит **все 16 байт MD5_B лежат в 0x120–0x12F**. Требуется исправить `unpack_siupdate.py`: читать `d[0x120:0x130]` и сравнивать полный MD5; убрать описание неизвестного поля. Так же убрать неподтверждённое утверждение о «MD5 файла в последних 16 байтах»: исходный отчёт показывает отсутствие хвоста после секции B.
3. **Исправление ADC1052:** лабораторный отчёт 03 описывает «8×128 отсчётов». Проверенный оригинальным TCP/10230 и MVK Reader Web формат: **один ADC-канал на кадр; 28 B заголовок + 256 float32 LE = 1052 B**. Все восемь каналов идут отдельными кадрами. Формат TACH284 и AUX4700 сохраняется; 32800-B полный снимок регистров нельзя забывать.
4. Заводской конфиг: калибровка ADC `5.2191` и чувствительность датчика `0.010194 В/(м/с²)` присутствуют отдельно по восьми каналам. В отчёте ошибочно взято произведение `5.2191*0.010194=0.0532035`; корректная размерностная комбинация для масштабирования напряжения в ускорение — **отношение = 511.9776339**. Это лишь **заводской номинал**, а не персональный коэффициент подключённого прибора: брать K из текущей калибровки прибора (начальные 33064 B, gain `float32 LE` по абсолютным смещениям `836+512*N`, чувствительность `812+512*N`), как уже независимо установлено в `docs/INITIAL_STREAM_CALIBRATION_CONFIRMED_20261026_RU.md`. Для TCP ADC: `raw*K`; готовый MVKView BIN уже откалиброван, повторно `*K` запрещено.
5. **885 чисел не подтверждают единый ФНЧ:** экспортированная `table_FF802B34_885f.csv` (885 float32, sum=3.010874865) имеет относительную ошибку чётной симметрии `sum(abs(h-h[::-1]))/sum(abs(h)) = 1.87573124`; индекс сам ставит `symmetry:"-"`. Прямое DFT всего ряда (без оконной обработки, **предположение Fs=512**) даёт отношение амплитуд `|H(100 Hz)|/|H(0)|=0.58085`, т.е. **-4.72 дБ**, а не >60 dB. Следовательно, описание «это цельный 885-tap ФНЧ для децимации» **НЕ ПРОВЕРЕНО**, а при выбранных допущениях противоречит числам. Метод `analyze_tables.py` ищет лишь длинные последовательности «правдоподобных float», может объединять независимые массивы. Требуется разбиение по реальным ссылкам кода, параметрам и длинам. Равно не доказано, что произвольные 75 float по 0xFF8029F0 — единое ядро Гильберта.
6. **43 vs 42 полосы:** `protocol_1_0_39.txt` прямо перечисляет **43** полосы, от 0.63 Гц (№1) до 10 kHz (№43). Другая лабораторная реконструкция по РЭ ВАРБ.411711.112 упоминает **42** полосы, от 0.8 до 10 kHz. Обе записи существуют, без версионирования/точного сравнения DSP и отображения запрещено принудительно «согласовывать» их. Известный AUX4700 содержит **43 поля** спектра/канал, они декодируются без потерь.
7. Разделение функций: протокол описывает основной контроллер (Modbus, сеть, Flash) и DSP (измерения/расчёты). Из DSP-образа пока **не восстановлен** код сервиса TCP/10230. Обнаружение констант 65536/8192/2048 или функции `0xFFA1571A` с 55 CALL — подтверждение структурной активности, но **не доказательство точной формулы фильтрации**. 793 — инвентаризация функций-кандидатов, не все семантически реконструированы.

## Дополнительное практическое знание из других отчётов той же лаборатории

В `reports/INSTRUMENT_RECONSTRUCTION_dev83_20261027.md` и `CAPTURES_VERIFY_dev83_dev84_20261027.md` восстановлена **эмпирическая приближённая** формула для ВУ 10–3000 Гц: `RMS² ≈ E(10..2828) + 0.405 E(2828..3563) + 0.105 E(3563..4490)`. Для двух других сохранённых 15-с захватов медианные ошибки на здоровых каналах ~2.1% и 2.81%; в экстремальном спектре 84/ADC6 остаток до −21.7%. **Не точный доказанный DSP-алгоритм**; полезно как отдельный явно помеченный расчётный прототип или регрессионный эталон, а не как принудительная замена получаемым приборным AUX4700.

## Прямые рекомендации для основной разработки

1. **Приоритет 1:** провести согласованный R5.1 пассивный Live-тест по проводному Ethernet, `connect → read` только **TCP/10230**, параллельный Wireshark capture; сравнить `incoming.raw`, PCAPNG, `AUX4700`, 32800 B снимок, точные K и обработку ошибок. Не слать диагностикой никаких команд.
2. **Приоритет 2:** довести надёжное калибрование по gain текущего сеанса и многоканальный BIN/TSXML, затем VALUES/TABLE и интеграцию AUX4700 в UI.
3. **Приоритет 3:** отдельно сопоставить фактическую версию DSP на приборе с исследованной v3-1.0.59; построить таблицу `конкретная функция Blackfin → конкретные использованные слова коэффициентов`; изолированно воспроизвести алгоритмы и сравнивать с приборными значениями. До этого в UI показывать полученные прибором 43 полосы как первичный ground truth.
4. В `mvk-zai-lab/firmware-re` рекомендовать исправления описания MD5_B, структуры ADC1052, размерностного коэффициента и статуса гипотетического FIR; не менять сырые образы прошивки.
5. **Не трогать** стабильную v0.3.40, ни Flash/reboot, ни параметры приборов. Производственные PCAP/BIN не выкладывать в GitHub.

# Stage111Z31BN — вертикальная шкала FRange + переключение режима + курсор: Core и Qt вместе

**Приёмка:** код, синтетические Core/Qt тесты и Windows workflow созданы как единый пакет. Указывать SUCCESS только после фактического GitHub Actions по source SHA.

## Исходный дефект и прямое основание в приватном оригинале

В исходном Delphi _Unit128.pas (только локальный read-only анализ Projects.7z) по адресам 0084B5D3..0084B882 исходная программа строит GraphDefaultVScale из FRange выбранного канала и режима (×1/×10/×100) со шкалой 1/2/5. 0084C770..0084C800 строит **абсолютные** TQGrapher.ScrHeight и ScrBottom; для dB -Page-Position и для линейных режимов (GraphDefaultVScale - Height) - Position*Height/Page. Эти формулы были ранее исследованы в Core, но обычный Qt BIN прибавлял к ним минимум/максимум самих графических данных и поэтому показывал **другой Y-диапазон**.

Дополнительно 0084C514..0084C597 после смены спектрального режима перестраивает меню VerticalScale и вызывает 0084C5AC..0084C748. В обработчике используется старый Tag и старое Position при **новой** таблице; позиция подбирается по сохранению нижней границы. Для переключения Tag0(dB)→Tag3(physical), 100000 full / 100 page, правильная исходная позиция **99900**, а не 0. Из-за этого предыдущая Qt-реализация могла показывать только верхние 0.1% шкалы, скрывая исходные пики. Точные Qt/GDI пиксели оригинала здесь пока не доказаны.

## Одновременно реализовано

- В независимом от UI Core original_spectrum_vertical_view.py: единый источник для Y-диапазона. Повторно проверяется текущий OfflineMeasurementFlow и SHA BIN, выбранный канал, FFT/Tag, исходный V Page/Position и FRange. При положительном InternalChannelGain текущего TSXML строится абсолютная source-derived шкала — **кандидат** из loader, не оригинальная Win32 аттестация физической калибровки. Если full Y текущего экрана ранее совпал с исходным операторским Power/Y и RAW SHA, включается этот отдельный source-скоуп. Для dB используется исходный диапазон без FRange. При отсутствии обоснованного FRange для линейного графика Core возвращает None: остаётся явно помеченная локальная Qt-гипотеза.
- В mvk_spectrum_menu_runtime_idr_candidate.py: source_vertical_mode_transition для DFM-Tag, VCL Max/Page/Position и исходной bottom anchoring формулы, с отбрасыванием нецелых/вне диапазона параметров. Не подменять оригинальную логику source_vertical_selection, которая и так умеет меню Tag→Tag.
- В реальном main_window.py: bSpecVScale, вертикальный скролл и spec_plot.ViewBox теперь используют одну source-derived Y-модель; при переключении режима сохраняется исходная нижняя граница. Открытие BIN с позитивным TSXML автоматически активирует исходный V Tag соответствующего режима. Если same-window Power/Y парное сравнение на текущем графике прошло PASS, текущая Y-ось может перейти с локальной гипотезы к исходной модели FRange **без пересчёта FFT**. Поведение/границы данных через один источник, provenance отражён в уже существующем исследовательском label без добавления вымышленных элементов оригинального DFM.
- Никакое приложение к прибору и калибровка не отправляются. Float32 BIN/FFT не переписываются, метрики не рассчитываются из экранных пикселей, при смене файла/режима прежняя same-window пара сбрасывается.

## E2E приёмка и границы доказательства

Тесты Core: все Tag0..3, TSXML FRange 6.25 и режимные множители, переход 0→99900→0, исходные V скролл-границы, битовая неизменность full FFT, отсутствие фиктивного FRange, fail-closed на чужом ADC даже при одинаковом BIN SHA, безопасная перепроверка принятого original Power/Y и отказ при изменённом экранном Y. Тесты Qt в Windows/DPI150: реальный bSpecVScale, spec_vscroll, Y ViewBox, переход линейных режимов, FFT cursor без графического decimation, сохранение оси при FFT refresh, исследовательский fallback без FRange и переход Y-оси к исходной операторской паре после подтверждённого численного сравнения. Скриншоты в CI синтетические.

## Алгоритм Float32: независимые проверки на крайних значениях

На локальных независимых Python Decimal и Go strconv реализациях повторного Float32×10 FormatSpec=4 проверены **50 007** детерминированных псевдослучайных и специальных битовых значений IEEE-754 — **0 различий двух портативных кандидатов**. В репозиторий добавлены **44 фиксированных специальных IEEE-754 входа** с одинаковым SHA-256 сериализованных кандидатов для Linux Go + Python тестов: `2d473a0bef28878044163499021c74571d5072c62dc3fc839c447268b9ca31f2`. В тестах есть signed zero, subnormals, NaN, ±Inf, max finite, rounding thresholds, отрицательные и большие значения. Это стабильность наших Go/Python-кандидатов, **НЕ Win32 x87 FormatFloat byte parity**: точный оригинальный Delphi runtime пока не был сопоставлен на тех же DWORD.

Доказательства предыдущего пакета остаются: оригинальные VALUES и TABLE от 28.10.2026 имеют единственное полное совпадение **90/90** в 10:12:02.623; построенные исходный заголовок VALUES **5554/5554 bytes** и полный TABLE из уже готовых текстовых чисел **1699/1699 bytes**; обратная проверка всех **12 701** ненулевых чисел успешна. Предыдущая **CI #44677766812** на SHA fb1db25 прошла **5/5 success**, включая Windows EXE. Новая CI для данного пакета ещё не завершалась на момент документа; результат проверить отдельно по SHA.

## Связь BIN/TSXML и VALUES/TABLE не подменять автоматическим совпадением

Приватная пара BIN/TSXML (MVK00000043 ADC1, 28.10.2026) имеет 2 124 800 Float32 отсчётов по 65 536 Гц, длительность 32.421875 с, timestamp в TSXML 10:12:05 и вывод VALUES 10:11:33.623—10:12:04.623. В локальном **исследовательском** тесте временной зависимости: 0.5-секундная std-огибающая BIN при лаге +0.5 с коррелирует с одним из source поля АЦП1 («Виброускорение, Польз. 2») ~0.936; на первой и второй независимых половинах ~0.934 и ~0.943. **Внимание:** кандидат выбран после поиска по многим параметрам/лагам, поэтому эта корреляция — дополнительный признак общего измерения, **не достоверная сессия/регистровый byte-to-byte oracle**. Не включать её как доказанный one-run без оригинальной записи идентичного RX. Модуль не делает TX на прибор.

## Что не закрыто

1. Побайтовый оригинальный Win32/x87 Float32 и FormatSettings на граничных значениях и в разных локалях.
2. Динамический GetValueText всех 30 типов с исходным работающим EXE/оригинальной кодировкой DateTime и ANSI, а не только 30 source routes и 13 formatter кандидатов.
3. Полный оригинальный WriteValues без маркировки CANDIDATE при тех же реально принятых DWORD; настоящая аппаратная сквозная проверка IP → Измерить → PARAM 0x3100 → WriteValues/TABLE → Stop.
4. Подтверждение полного 1:1 между приборами и разными типами сохранённых замеров. Не смешивать по близости названий/дат.

Состояние original_delphi_compatibility_verified=false, original_delphi_values_csv_byte_parity_verified=false, physical_mvk01_e2e_verified=false сохраняется. Приватные исходные PAS/DFM, PE RCDATA JSON, SQLite, IDP, BIN, TSXML, VALUES, TABLE, RAW/PCAP не публиковать.

## Приёмка 20.11.2026: корректировка тестовых исходных битовых полей

CI #44679487266 обнаружила единственный дефект нового тестового входа: перечисление ID для ResultBuffers и SensorState ошибочно помещалось в DWORD без сдвига, тогда как исходный `_Unit125:00804A30` задаёт BitStart 4 и 10 соответственно. Декодер закономерно выдавал ID=0 ("ОК"), а тест требовал ID=1. В следующем коммите **исправлен именно тест** (RAW = ID << BitStart 0/4/10), сохранена проверка всех 41 исходных RU названий и невозможность ложного перевода. Не требовалось изменять декодер, обработку 0x3100 или файлы пользователей. Новую CI считать успешной только после фактического completion/success.

# Stage 80a — TMvkChannelStorage.GetSignal: буфер, масштабирование и СКЗ
Дата: 2026-10-28. Основа: **оригинальный IDR**, извлечённый из `Projects.7z`, файл `_Unit115.pas`. Никаких подключений к приборам.

## Непосредственно подтверждено
- Конструктор `TMvkChannelStorage.Create` (`0x007D0970+`) создаёт кольцевые буферы float или byte по типу данных, устанавливает `FSampleRate=1000` (значение по умолчанию), `FRange=1.0`, нулевые позиции `FRxPos/FValidPos`. Это **начальные**, а не обязательно фактические значения частоты и усиления.
- `GetSignal` (`0x007D0C30`) проверяет наличие данных, выбирает позицию и длину, использует `GetAdjustedEnvelopeLength` при ненулевом параметре огибающей. Чтение внутреннего сигнала выполняет `sub_007D2228` (`0x007D0CD6`), после чего возможно `sub_007D2344` и преобразования `0x007D1C48`, `0x007D1E70` при огибающей.
- `sub_007D2228` использует кольцевой индекс через `FBufferMask`; недостающую часть заполняет нулями (`0x007D2284`). Float-ветвь при установленном флаге огибающей делит отсчёт на `FRange` (`0x007D22C8`); без этого флага копирует четыре байта на отсчёт. Byte-ветвь переводит байт в значение `0..1` делением на 255 (`0x007D2321`).
- Выход `GetSignal` записывает частоту `FSampleRate` при обычном режиме, а при огибающей использует таблицы частот; переносит `FUnits`. При включённой огибающей данные умножаются на `FRange` (`0x007D0D8F`) и кладутся в выход в **обратном порядке индексов** (`out[n-1-i]`). В обычной ветви выход также записывается в обратном порядке, но без умножения (`0x007D0DEC–0x007D0DF5`).
- СКЗ считается как `sqrt(sum(sample**2)/n)`; для огибающей умножается на `FRange` (`0x007D0DD2`), в обычной ветви такого финального умножения нет. **Важно:** это подтверждает маршруты вычисления в данном методе, но НЕ доказывает размерность значения до помещения в хранилище.

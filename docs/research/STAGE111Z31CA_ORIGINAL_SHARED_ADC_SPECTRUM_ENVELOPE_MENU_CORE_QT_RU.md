## Полный интегрированный пакет

1. **Автономный Core:** \`core/original_envelope_shared_menu.py\` — 32 исходных Tag/целевых частоты/checked, radio-модель, проверка частоты **выбранного** АЦП, отдельный локальный профиль FIR; \`source_original_envelope_selection\` атомарно назначает одинаковый Tag обеим страницам; \`source_original_envelope_rebind\` сбрасывает неподдерживаемый фильтр на Tag0 при смене файла/АЦП. Оба модуля расчёта GetSignal и GetSpectrum вызываются как прежде; новые метаданные НЕ вводят фиктивный FIR, DSP, calibrated gain, спектральный пик или переписывание BIN.
2. **Реальный рабочий Qt:** оба \`bAdcEnvelopeType\` и \`bSpecEnvelopeType\` теперь \`QToolButton.InstantPopup\`, привязаны к **одному QMenu \`popEnvelopeType\`**; действия являются source Tag0..31, checked radio-выбор. Клик по телу просто открывает menu. При явном выборе Tag>0 в присутствии локального проверенного профиля программа одновременно обновляет оба исследовательско-восстановленных GetSignal/GetSpectrum (включая невидимую страницу), прокрутку/активные подписи/полные SHA-верифицированные значения. Tag0 сбрасывает обе кривые в исходный unfiltered расчёт. Прежние research ComboBox и программный \`setChecked\` сохранены для существующих специальных сценариев, но загрузка IDP больше не **выбирает молча Code20**.
3. **Кнопка X спектра:** \`bSpecHScale\` теперь \`InstantPopup\` без отдельного \`clicked→showMenu\`. Восстановлено единое поведение всех девяти source split-buttons. График/FFT меняется только на самом \`QAction.triggered\`, а не от основного клика; H-масштаб не изменяет N/2 FFT.
4. **Невозможная FIR-история/частота:** пользовательское действие проверяется в автономном Core ещё до изменения UI. Source target Fs выше текущего Fs или отсутствие локального IDP → действие недоступно, программная попытка отклоняется без изменения чисел. Недостаточная реальная история BIN в выбранном фильтре допускает лишь явный неуспех: недействительные серии обнуляются, информирование без модальных сообщений на скрытых страницах. При смене файла/АЦП Fs проверяется ещё до нового рендера и активный неподдерживаемый Tag возвращается в0.

## Приёмочные синтетические сценарии

- Core: 32 исходных Tag0..31, radio/Checked, адреса/правило второго столбца, реальный Fs8192 запрещает Code20→65536 и разрешает Code11→8192, отсутствие коэффициентов запрещает всякий FIR, невыполнимый выбор не изменяет состояние. \`source_original_envelope_rebind\` автоматически выбирает0 на новом Fs.
- Qt: один и тот же QMenu у двух реальных исходных контролов, главный клик не меняет код, все девять QToolButton — оригинальный popup-only; без IDP скрытый фильтр недоступен; локальный синтетический IDP, source ZIP: PageAdc Tag20 → реальный полный FIR Float32/ось, PageSpectrum Tag20 → FFT N/2, Tag1 обновляет скрытый PageAdc и текущий спектр, Tag0 возвращает plain, финальный BIN/ZIP SHA не меняется. Отдельно BIN/TSXML Fs8192 запрещает Code20; смена архива Fs65536→Fs8192 сбрасывает выбранный Tag20 в0 до вычислений. H-кнопка не циклирует, только QAction меняет X.
- Windows DPI150 сохранены исходные геометрические DFM шесть/девять кнопок и прежняя проверка семи страниц/трёх форм. **CI результаты фиксировать только с доказанным GitHub run SHA.**

## Ограничения честной копии

Точная локализация строк оригинального \`TLanguage\`/приватной 32-строчной таблицы **не восстановлена**: надписи QMenu являются русским source-derived fallback («Огибающая 20 · 65536 Гц»), а не оригинальными TLanguage байтами. Исходная VCL двухколоночная раскладка после Tag20 помечена в Core, но Qt \`QMenu\` не гарантирует аналогичного DFM column break: нужна отдельная визуальная реализация/приёмка. Исходный численный x87/Win32 GDI/FIR/модуль FilterBank Source не аттестован на запущенном оригинале; физические единицы и потоки оборудования не выдумываются. Остаётся общий этап восстановления оригинального интерфейса, расчётной логики и полного сквозного рабочего маршрута семи страниц/трёх форм.

# Stage111Z.5 — оригинальный генератор Hann и нативная x87-проверка

Дата: 30.10.2026. Ветка: research/stage111-mvkview-desktop-20261029.
Цель: точный автономный Windows-аналог MVKView на Qt/PySide6. Не возвращаться к Web v0.3.40.

## 1. Что подтверждено исходным приватным IDP

На локальном оригинальном mvkview.idp (IDR v3) выполнена read-only проверка **пяти машинных окон SHA256**, без передачи закрытого исходного файла, машинных байтов, BIN/RAW/PCAPNG или измерений в GitHub.

| Участок | Виртуальный адрес | Вывод |
|---|---|---|
| Инициализатор Hann | 008C1064–008C10CF, .itext | 262144 значений Single, заполняемых один раз |
| Константы | 008C10D0–008C10E0, .itext | 2π Extended 80 бит, знаменатель 262144.0 Single |
| Delphi FCOS | 00407C00–00407C0D | FCOS аппаратного x87 |
| Delphi FSQRT | 00407C58–00407C65 | FSQRT аппаратного x87 |
| GetSpectrum, оконное умножение | 007D2044–007D2088 | stride=262144/N; умножение с FSTP Single; затем положительный FFT |

Исходный массив — статически выделенная таблица в .bss с базой **0096DA48**, размер 262144*4=1048576 байт, реально заполняется во время инициализации оригинального Windows-процесса. Это **не данные исходного IDP в готовом виде**, их следует проверять в оперативной памяти Windows, а не искать как дамп коэффициентов на диске.

Алгоритм одной записи:

    angle = Extended(2π) * Extended(integer index) / Single(262144)
    numerator = Extended(1 - FCOS(angle))
    Hann[index] = Single(numerator / FSQRT(Extended(1.5)))

Между косинусом и делением исходная программа сохраняет числитель как **80-битное Extended**, а готовый коэффициент сохраняет как **Single**. Спектр меньшего размера N выбирает элементы по целочисленному шагу 262144/N.

Достоверно установлен исходный алгоритм, а не его фактические runtime биты или CW в момент инициализации. Статическое начальное CW original = 0x1332 (при чтении CPU часто 0x1372 из-за аппаратного бита 6), но **CW при самом Hann-init не снимался**.

## 2. Нативный source-derived x87-эксперимент

Новый полностью офлайн исследовательский инструмент mvk_compatible/native_probe/x87_hann_table_probe.c реализует ту же структуру FILD, FMUL, FDIV, FCOS, FSUBRP, FSQRT, FDIVRP, Extended temporary и финальный FSTP Single. GCC-литерал Extended 2π совпал битово с исходной 80-битной константой на данном компьютере (локальная сверка). Инструмент выставляет CW 0x1332 (аппаратное чтение 0x1372), восстанавливает исходное CW и не читает исходную MVKView или прибор.

Режимы:
- --summary: 14 фиксированных индексов и FNV64 массива для контроля, без полной выдачи.
- --hex-all: 262144 строк HEX float32, только в stdout; для независимого офлайн-сравнения. Не записывает файлы и не обращается к сети.

Локальный SHA/FNV synthetic: FNV64=B834BEAF46A6A52E. Это НЕ хеш подлинной таблицы оригинальной Delphi.

## 3. Результат побитового сравнения 262144 коэффициентов

На одном локальном x86_64 CPU native x87 и существующий NumPy float64-cos/float32-store в fft_idr_candidate.py дали:

| Показатель | Результат |
|---|---:|
| Коэффициентов | 262144 |
| Побитовых совпадений | 262140 |
| Отличий | 4 |
| Максимальная разница | 1 ULP |
| Индексы отличий | 1, 5, 262139, 262143 |

Конкретно два типичных края (исследовательская модель native, не Delphi runtime):
- index=1: native 2F80EF9C, NumPy 2F80EF9D;
- index=5: native 31C97664, NumPy 31C97663;
- index=262139: native 31C97664, NumPy 31C97663;
- index=262143: native 2F80EF9C, NumPy 2F80EF9D.

**Для FFT N=256, 1024, 4096, 8192, 65536, 131072 обе синтетические таблицы совпали побитово**, потому что целочисленный шаг берёт только чётные/кратные индексы. Только N=262144 включает четыре выявленные позиции. Это свойство конкретного CPU/native x87 и текущего NumPy, **не утверждение универсального аппаратного совпадения или подлинного original-runtime golden**.

Обычный FFT-путь специально **не изменён** до чтения Hann-битов из оригинального Windows-процесса. Тем самым не маскируются оставшиеся неопределённости x87, SIN/Twiddle и FFT.

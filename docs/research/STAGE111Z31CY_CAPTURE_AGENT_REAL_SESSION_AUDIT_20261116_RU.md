# Stage111Z31CY — MVKView Capture Agent 0.2: аудит реального Windows-захвата и исправление v0.3

Дата: 16 ноября 2026. Изучен предоставленный оператором приватный ZIP одной локальной сессии MVKView 1.0.47. Исходные изображения, абсолютный путь к `mvkview.exe`, профиль Windows, пользовательские измерения/память и сам ZIP **не включены в GitHub**.

## Достоверная приёмка исходного захвата

- ZIP прошёл `testzip()`, 21 запись manifest SHA256 совпала побайтово, JSONL читается без ошибок, seq 1..1269 без пропусков.
- 97,544 с от Start до Stop, 1269 записей JSONL: 1 `capture_started`, 23 `snapshot`, 1245 `win_event`.
- 19 PNG, из них только 7 уникальных хешей: 5 состояний основного окна спектра, 1 настоящее меню фильтров, 1 чёрное окно `SysShadow` (тень, не содержимое UI).
- Win32: DPI=144 (150%), Delphi `Tmvkform`, 66 дочерних элементов управления. Все 23 снимка дерева показывают активным `TTabSheet` **«Спектр»**, а объекты `TTabSheet` остальных шести страниц существуют, но скрыты. Их работа не подтверждена данным сеансом.
- Семь зарегистрированных `OBJECT_INVOKED` при работе с пятью кнопками спектра:
  1. «Без фильтра» — 1 раз;
  2. «Логарифмич.» — 2 раза;
  3. «1/4 Гц/лин» — 2 раза;
  4. «25600 Гц» — 1 раз;
  5. «150 дБ» — 1 раз.
- Семь меню реально появлялись как Win32 popup `#32768` вместе с семью соответствующими окнами `SysShadow`. Достоверный PNG содержимого есть **только у первого** («Без фильтра»): меню с 32 вариантами, группами «Без фильтра», `1/3окт`, `1окт`, `2окт`, включая «1окт 16 кГц».
- Остальные шесть открытых меню были зафиксированы метаданными (HWND, класс, прямоугольник, время), **но без PNG/пунктов меню**.
- 1104 события `OBJECT_LOCATIONCHANGE`; из них 999 относятся к `object_id=-9` (`OBJID_CURSOR`). Это шум перемещения мыши, а не 999 изменений алгоритма.
- Конфигурация наблюдения: `ui_automation=false`, `memory_read=false`, `auto_trace=false`, `trace_arrays=false`; Frida и чтение внутренних параметров **не запускались**. Никакой FFT/Power/Y или алгоритмический паритет из этого ZIP не доказан.

## Найденный корневой дефект в Capture Agent 0.2

В `CaptureSession._loop` периодический `snapshot(reason="poll", screenshot=False, only_if_changed=True)` первым обнаруживал `#32768`, обновлял `last_ui_digest` и сохранял JSON, но **не** изображение. Следующая попытка `snapshot(reason="win_event", screenshot=True, only_if_changed=True)` видела тот же digest и пропускала снимок. После закрытия меню сохранялся очередной экран спектра без popup. Это **дефект агента**, а не ошибка оператора или оригинальной MVKView.

`SysShadow` ошибочно включался как полноценное второе popup-окно и давал бесполезный чёрный PNG. Сырые события содержали только HWND; подписи кнопок пришлось восстанавливать по предыдущему Win32-дереву.

## Исправления v0.3

1. Для `snapshot(poll, screenshot=False)` с видимым и PID-валидированным popup автоматически сохраняется снимок главного окна **и** popup, до того как можно потерять видимое состояние по digest.
2. `SysShadow`/служебные/нулевые окна не сохраняются как GUI-объекты.
3. События `OBJECT_LOCATIONCHANGE` с `object_id=-9` фильтруются на выходе из WinEvent callback.
4. События целевого процесса, где HWND ранее был обнаружен в дереве, получают `control_name` и `control_class`. Иные hwnd не угадываются.
5. Добавлены четыре регрессионных сценария на синтетических Windows-объектах.

**Проверки:** 19/19 автономных Python unittest PASS (Linux окружение) до CI. Реальную проверку на операторском Windows требуется повторить с v0.3; исходный ZIP v0.2 не может доказать исправление v0.3. Для проверки: открыть каждое меню на ~2 секунды, снять ZIP и убедиться, что имеется по одному PNG настоящего `#32768` на все пять типов кнопок, без `SysShadow`.

## Границы результата

v0.3 по-прежнему не кликает на оригинальные элементы самостоятельно, не выбирает варианты меню и не читает текст всех пунктов в структурированный JSON. Для полной автоматизации по всем страницам и взаимодействиям понадобится отдельно проверенный, оператором разрешённый ограниченный UI Explorer с явным запретом аппаратных операций. Прибор не включать; оригинальные BIN/TSXML и дампы держать локально. Deep Frida-вызовы запрещено выдавать за проверенные по этому пассивному архиву.

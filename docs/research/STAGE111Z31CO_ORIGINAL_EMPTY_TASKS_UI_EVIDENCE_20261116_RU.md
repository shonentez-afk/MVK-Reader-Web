# MVKView 1.0.47 — аудит стартового экрана «Задачи» (без измерения)

Дата: 16 ноября 2026. Источники: три файла отчета Nemotron, предоставленные оператором: `mvk_original_empty_ui_manifest(1).json`, `mvk_original_empty_ui_report(1).md`, `mvk_original_empty_ui_unknowns(1).md`; проверенный актуальный код `MVK-Reader-Web` ветки `research/stage111-mvkview-desktop-20261029`.

## Проверено по документам оператора

- Оригинал `Tmvkform` открыт, не свёрнут, измерение не загружено; выбран единственный видимый пользовательский таб «Задачи».
- Сообщено о четырех видимых действиях: «Измерение», «Загрузка сигнала из файла», «Настройка параметров измерительных каналов», «Настройка системных параметров».
- Сообщено о полях IP-адреса прибора и локальной папки результатов с кнопкой обзора и о логотипе/надписи БАСТ внизу слева.
- UI Automation содержит только 10 узлов, поэтому названия/классы/прямоугольники многих элементов отражают описанное оператором изображение, а НЕ полный UIA-дамп.
- В отчете указан PNG 1920×1020, тогда как прямоугольник Win32 главного окна равен 1942×1042, со смещением -11, -11. Эти две системы геометрии нельзя непосредственно смешивать или использовать как пиксельно проверенный эталон без PNG и координат преобразования.

## Чего НЕ подтверждают переданные файлы

- Сам PNG с начальным экраном отсутствует в переданных вложениях; локальный временный путь не делает файл доступным проверяющему. SHA256 в манифесте — `pending`. Пиксельную точность координат кнопок, логотипа, цвета/шрифтов и фона пока не утверждаем.
- Наличие четырёх видимых кнопок не означает, что в Delphi существует только четыре объекта: исходная форма содержит пятую калибровочную кнопку, скрытую в обычном состоянии.
- Отсутствие восьми вкладок АЦП на стартовом экране не доказывает, что оригинал работает с одним каналом; число каналов зависит от прибора/состояния.
- Отсутствие страниц «Спектр»/«Временной сигнал» в видимых вкладках не означает, что объекты TTabSheet не существуют.
- `IsEnabled` у UIA и `IsWindowEnabled` у Win32 обычно читаются без нажатия. Фраза «нужно нажать, чтобы узнать enabled» из отчета неверна как универсальное правило.
- Точное поведение четырех действий не проверялось. Не нажимать приборные/сетевые команды без отдельного разрешения.

## Сопоставление с текущим Qt-кодом (не со старым EXE)

Текущая `source_visual_skin.py::update_runtime_tabs` **уже скрывает шесть из семи внутренних страниц до загрузки измерения**; `test_stage111z31cm_qt_source_operator_path.py` утверждает `visible_source_tabs == ['PageStart']` до открытия и `['PageStart','PageAdc','PageSpectrum']` после. Не повторять исправление семи вкладок по старым CI-скриншотам.

`original_task_ui.py` использует `OriginalStartController` из `original_start_ui.py`. Исходная DFM геометрия и handler-mode уже учтены в `original_start_workbench.py`, четыре действия видимы, пятый `bTaskConfigCalib` скрыт. Кнопки пока используют стандартные Qt/Windows иконки и семантические подписи:

| Delphi ID | Текущая Qt-подпись | Надпись оригинала по новому отчету | Замечание |
|---|---|---|---|
| `bTaskConnect` | Подключение к прибору | Измерение | Требует проверки точной исходной надписи на PNG, не менять device safety |
| `bTaskView` | Просмотр измерений | Загрузка сигнала из файла | Точная маршрутизация пока отдельно не подтверждена живым нажатием |
| `bTaskConfigCh` | Настройка каналов | Настройка параметров измерительных каналов | Длинная строка и пиктограмма требуют геометрической проверки |
| `bTaskConfigIP` | Настройка IP | Настройка системных параметров | Не осуществлять сетевую запись/подключение |
| `bTaskConfigCalib` | Калибровка | На экране не показана | Уже скрыта в Qt, сохранить внутренний объект |

Также `lbStartSourceIP` показывает «IP-адрес МВК:», тогда как в отчете оригинала «IP-адрес прибора:»; `lbStartLibrary` показывает «Каталог записей...», тогда как оригинал — «Папка хранения результатов измерений:». Изменение текста/ширины должно быть синхронизировано с компоновкой и Core-параметрами. Элементы локальной библиотеки и диагностические строки уже специально скрыты в обычном режиме — не удалять их функции, но не делать их видимыми без нужды. Изображения стартовой страницы доступны через опциональный локальный DFM picture loader; публикация приватных рисунков/ресурсов в GitHub недопустима.

## Приоритет следующего шага — ОДНА парная приёмка пустого экрана

1. В оригинальном MVKView оставить открытой только вкладку «Задачи», без измерения. Ничего не нажимать и не сворачивать.
2. Сохранить **реальный ранее снятый PNG из временной папки** в постоянную локальную папку, вычислить SHA256. Если файл пропал, один раз снять его заново плагином `dsh-computer-use-win`, `windowTitle`/PID/HWND уточнять через `list_windows`, не использовать временный HWND из прошлого запуска.
3. Вручную запустить актуальную **Qt-копию без измерения** (если её еще нет), не запускать прибор и не открывать архив. Сделать отдельный PNG того же физического размера и DPI, назвать и проверить SHA256. Не перепутать Qt-окно с оригиналом.
4. Выполнить **визуальную попарную** проверку: число вкладок, четыре кнопки, подписи/иконки, расположение полей, папка, логотип, фон, размеры, шрифты, отступы. Отдельно считать `IsEnabled` без кликов, если UIA/Win32 позволяет; если нет — null/unknown.
5. Дать файл `original_vs_compatible_empty_ui_diff.md` и таблицу результатов с путями **только локально**. В публичную ветку — обезличенное описание различий и тесты; оригинальные PNG, локальные пути, IP, DFM/IDP, устройство не публиковать.

**STOP после сравнения.** Переключение вкладок, раскрытие настроек, загрузка BIN/TSXML и действия с прибором здесь не разрешены. После сравнительного отчёта — единый функциональный Qt-пакет *PageStart UI + безопасные Core маршруты + операторские тесты*, а не повторное восстановление FFT или очередной поиск файлов измерения.

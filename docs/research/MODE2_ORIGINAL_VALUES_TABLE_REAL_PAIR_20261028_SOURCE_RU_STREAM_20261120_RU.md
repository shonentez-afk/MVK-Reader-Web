## Совпадение измерений доказано самими значениями, а не именами

VALUES имеет **63 строки**, время от 10:11:33.623 до 10:12:04.623. **220 колонок**: Время + АЦП 1/3/6 × (43 SPEC + 6 RESULT + 24 BAND) = 219 измерительных значений. Тики: 37 × 500 мс, 13 × 501 мс, 11 × 499 мс, 1 × 498 мс.

TABLE содержит 30 RESULT/BAND строк по этим же трём АЦП, отдельную пустую строку, заголовок TACH и 6 пустых TACH измерений. Все **90/90** текстовых ячеек TABLE совпадают с одним уникальным тиком VALUES — **10:12:02.623**. Из остальных 62 тиков лучший даёт лишь **23/90**. Timestamp TABLE из имени: 10:12:02, отклонение до соответствующего тика 0.623 с. **Классификация: verified_same_snapshot**.

**Нельзя автоматически считать любые ранее загруженные BIN/TSXML этой же сессией.** Для других пар необходим тот же анализ уникального 100%-совпадения, а не сходство имён и даты. Несовпадение пока значит «не доказано», а не строгое доказательство разных сеансов.

## Формат чисел по реальному VALUES

Всего 13 230 числовых ячеек, включая 529 нулей. Все **12 701 ненулевых** значения имеют не более 4 значащих цифр; при проверке текст → ближайшее Float32 → исходный формат FormatSpec=4 → текст с запятой **12 701/12 701** воспроизводятся. Это сильная проверка исходного способа округления в пользовательской выборке, **НЕ побитовое доказательство** исходных Float32 регистров и не проверка Win32 x87 на граничных значениях.

## Реализация

1. Новый локальный QA модуль mvk_compatible/core/original_values_table_pair_qa.py с CLI через python -m mvk_compatible.core.original_values_table_pair_qa VALUES.csv TABLE.csv. Он проверяет исходные кодировку, строки, 73 поля каждого канала, уникальность полного совпадения и временное окно. Возвращает только безопасные SHA, счётчики, имена и timestamp; при неоднозначности — separate_or_not_proven. Не делает device IO. Негативные тесты охватывают иные данные, дублированные одинаковые тики, иной день, UTF-8, CRLF и symlink.
2. Дополнительный native Go поток SOURCE_Wxx_VALUES_3100_RU_PROFILE_CANDIDATE.csv создаётся **на том же реально принятом 0x3100**, использует 2 русские строки заголовка, source порядок SPEC43/RESULT6/BAND24/TACH6, локальные переводы только для доказанных ID, CP1251, запятую, CRLF. Исходные SOURCE_Wxx_VALUES_3100_RECEIVED.jsonl, RAW_LAYOUT.csv, TEXT_CANDIDATE.csv остаются без замены. Новый companion получает audit: SHA полного файла, SHA каждой строки, счётчики и размер. Неполное значение остаётся UNKNOWN и НЕ подменяется 0 или ####.
3. Дополнительные Go тесты: 219 полей для 3 АЦП, точная CP1251 кодировка заголовков, source RU Advanced, запятая, неизвестные DWORD, независимая SHA запись/Stop.

## Граница доказательства

Новый RU CSV — **source-layout candidate**, не сертифицированный оригинальный Delphi WriteValues по живому DWORD. Формат CP1251/запятая/строки/названия и один общий TABLE-VALUES снимок подтверждены реальными CSV; parity для всех 30 GetValueText, оригинального Win32 округления, полной активности прибора и BIN/TSXML remains false.

Следующий крупный пакет: paired original MVKView/compatible для 0x3100, original TABLE candidate RU с тем же набором data-checked units и names, локализованные исходные 30 типов в runtime, одна аппаратная сквозная приёмка. Никаких новых замеров для проверки уже имеющихся файлов не требуется.

## 3. Неподвижные ограничения исследовательского тестера

- Только **IPv4 TCP/10230**. **Не** Modbus 502. Соединение само активирует поток по подтверждению оператора.
- Режим `DialContext -> SetReadDeadline -> Read`, без `Write/Send`, без изменения sampling rate/Flash/IP/DSP. Обычные TCP ACK при захвате Wireshark не являются прикладными командами.
- Сетевой интерфейс выбирается оператором из списка активных IPv4-адаптеров; `net.Dialer.LocalAddr` плюс Windows `IP_UNICAST_IF` удерживают исходный сетевой интерфейс. Невозможность привязки => явная ошибка без fallback.
- Программа сохраняет `incoming.raw` (исходные байты **не BIN**), `chunks.csv`, `frames.csv`, `aux4700.jsonl`, `events.log`, `summary.json`, `summary_ru.txt`, архив `MVK10230_TEST_RESULTS.zip`.
- Не является полноценным сеансным recorder BIN/TSXML; текущие R4 записывающие модули остаются исследовательскими и не внедрены в R5.1.

## 4. Первый полевой тест (оператор, только с согласованием)

1. На Windows ПК, подключённом к сети МВК01 проводным Ethernet, в разрешённом технологическом окне установить и проверить подключение сетевой карты без дополнительных команд к прибору.
2. Запустить Wireshark, выбрать **тот же Ethernet**, capture filter `tcp port 10230`. Начать запись до подключения R5.1 (ориентир 3–5 с).
3. Запустить `MVK10230_Diagnostic_R5_1_Windows_x64.exe` двойным щелчком; указать **фактический IPv4 прибора** (не копировать адрес из примера), выбрать **15 секунд**, затем **физический Ethernet-интерфейс**, проверить IPv4 и подтвердить `YES`.
4. После завершения теста остановить Wireshark. Приватно передать `MVK10230_TEST_RESULTS.zip` и полную `MVK10230_TEST.pcapng`.
5. Не запускать оригинальную MVKView одновременно с новым подключением, если прибор/технологическая сеть не гарантируют безопасную многоклиентность. Для сравнения — отдельная последовательная сессия с собственным PCAPNG.

## 5. Что проверяем по полученным данным

- TCP SYN/SYN-ACK/ACK, адреса и выбранный исходный NIC, начало потока **без клиентского TCP payload**; отличать транспортные TCP ACK от аппликативных команд.
- Побайтная сверка `incoming.raw` с потоком `device:10230 -> client` из PCAPNG; отмечать потери, ретрансляции и усечение/неполный последний кадр; не объявлять отсутствие сетевых потерь только по успешному декодированию кадров.
- Идентификационный кадр 264 B, полный 32800 B снимок (если присутствуют), ADC1052 (8 каналов, 256 float32 LE/кадр), TACH284, AUX4700, EVENTS/VALUES. Статусы и частота Fs=65536 сравниваются с фактическими данными, а не назначаются по умолчанию.
- Индивидуальный gain брать только из проверенного блока **текущей** сессии; не смешивать прошивочный номинал с персональной калибровкой.
- Возможны `NO_DATA`, `CONNECT_FAILED`, `FRAMING_ERROR_RAW_SAVED`: ни одна из этих ситуаций не оправдывает автоматической отправки команд.

## 6. Невыполненное / honest status

**Реальный Windows runtime и подключение к работающему МВК01 ещё НЕ ПРОВЕРЕНЫ**. Linux loopback-тест подтверждает отсутствие исходящих прикладных данных, но не заменяет проверку `IP_UNICAST_IF` в WinSock Windows. Без разрешённого полевого опыта не объявлять режим Live подтверждённым.

Следующий результат, который объективно меняет готовность: `MVK10230_TEST_RESULTS.zip + MVK10230_TEST.pcapng` с согласованного теста. После этого можно переходить к Native R6 — устойчивому многоканальному BIN/TSXML, CSV VALUES/TABLE и UI-цепочке, не нарушая стабильную v0.3.40.

# Stage111Z31EM: локальная приёмка BIN/TSXML по каналам

Прежний строгий SAME-RX мог посчитать файловый пакет полным при одном ADC BIN и произвольных совпадающих байтах с ролью TSXML. Если оператор включил TACH, его файлы вообще не требовались. Теперь локальный компаратор проверяет одно указанное окно WriteData и его полный набор выбранных каналов.

## Что проверяется

- В исходном WriteData отдельный BIN у каждого выбранного канала: ADC1–8 (Single) и TACH1–2 (Byte, Count, gain 1). При включённом TSXML у каждого BIN свой `.bin.tsxml`. Sidecar должен ссылаться на этот BIN, содержать правильный номер, тип, байтовую длину, согласованную частоту, длительность по типу данных и нулевое смещение.
- Для исходных BIN проверяется фактическая форма имени с меткой канала и корректной локальной датой/временем. В оригинале время берётся отдельно при открытии каждого BIN; соседние имена могут отличаться даже датой. Время в TSXML берётся отдельно при закрытии. Компаратор сравнивает эти два признака по отдельности, не выводит значения времени в отчёт и не делает вывод о часовом поясе, времени клика, физическом приборе или общем источнике по имени.
- Сравнение по-прежнему использует байты, SHA-256 и первое отличие; проверка метаданных не заменяет совпадение. Исходные и совместимые файлы не меняются, не переименовываются и не отправляются. Имена, исходные данные и значения часов не записываются в отчёт. Служебные Go-имена остаются прежними.

## Манифест строгой проверки

К прежнему локальному JSON-манифесту добавляется `"write_data_channels": [1, 9]` (в этом примере ADC1 и TACH1). Для каждого выбранного канала задаются две строки `files` с одинаковым `source_writer_channel`: для ADC это `ADC_BIN_F32`, для TACH — `TACH_BIN_BYTES`; вторая строка — `TSXML_CP1251`. Например, две строки для TACH1:

~~~json
[
  {"kind": "TACH_BIN_BYTES", "source_writer_channel": 9,
   "reference_name": "DEMO-TACH1-2026-11-24--10-00-00.bin",
   "candidate_name": "DEMO-TACH1-2026-11-24--10-00-00.bin"},
  {"kind": "TSXML_CP1251", "source_writer_channel": 9,
   "reference_name": "DEMO-TACH1-2026-11-24--10-00-00.bin.tsxml",
   "candidate_name": "DEMO-TACH1-2026-11-24--10-00-00.bin.tsxml"}
]
~~~

Указывать каналы по фактическому выбору оператора, не по тому, какие файлы оказались под рукой. Для строгой полной проверки нужны также обе копии исходного TCP RAW, GetSignal, промежуточные стадии спектра, Y Tag0…3, Power Tag2/3, VALUES и TABLE, как раньше. Окно с отключённым TSXML или неизвестной маской можно сравнить в обычном режиме, но оно не закроет полную строгую проверку. Старый режим byte-only и его коды 0/2 не меняются; ограничение полноты применяется к `--require-complete-same-raw` (пакет неполон: 3).

Проверки моделируют выбранные ADC+TACH, переход даты между двумя открытиями, пропуск выбранного TACH, чужой номер/тип/размер/имя BIN в совпадающих XML, некорректные часы и файловое отличие при неизменном RAW. Это синтетическая приёмка инструмента; реальный Win32/x87, ANSI и условия прибора/Stop остаются отдельной проверкой на одном эталонном потоке.

# ADR-2026-10-29 — Stage 111: MVKView Compatibility First / единое Desktop-приложение

**Статус: ПРИНЯТО пользователем 2026-10-29.** Предыдущее решение `docs/ADR_2026_10_29_ORIGINAL_MVK_DSP_DATA_SOURCE_RU.md` продолжает действовать; этот ADR его **дополняет**, не отменяет.

## 1. Причина

У MVK Reader Web v0.3.40 накопились фундаментальные функциональные и архитектурные расхождения с оригинальной MVKView. Объём знаний существенно изменился после Stage25–96 и Stage106–110B: доступны исследовательские выводы по исходным Delphi-обработчикам, DFM/IDR, форматы BIN/TSXML и штатные результаты DSP (Native R6.1 / AUX4700). Поэлементное «допиливание» v0.3.40 не обеспечивает управляемую доказательную совместимость.

**Решение:** сначала независимое функционально и численно проверяемое воспроизведение оригинальной MVKView (приоритет трёх вкладок), затем развитие собственной MVK Reader Web поверх общего вычислительного ядра. Версию v0.3.40 заморозить как исторический базовый прототип; не изменять `main` и не подменять стабильные релизы.

## 2. Тип приложения

**Основной продукт — единое Windows Desktop-приложение, а не локальный веб-сервер с браузером.** GUI: Qt/PySide6 + pyqtgraph для точных измерительных графиков, курсоров, масштаба и таблиц. Бизнес-логика и вычисления — отдельный Python-модуль без импорта Qt/HTTP. Рабочая программа устанавливается и запускается обычным образом. В исследовательской версии допустим запуск из исходников (`python -m mvk_compatible`); отдельная сборка и установщик не принимаются до Windows QA.

Архитектура:

```text
mvk_compatible.desktop (PySide6 + pyqtgraph, собственное окно)
     |       расчетные значения / осциллограмма / спектр / архив
     v
mvk_compatible.core (без Qt, FastAPI, HTTP, сети и команд)
     |                       |
     +---- OfflineExport ----+---- candidate local MVKView FFT
     |                              (APP_DERIVED, НЕ DSP)
     +---- future Native R6.1 read-only Collector adapter
     |
     +---- future Web/API adapter (опционально, НЕ запускать по умолчанию)
```

**Один Collector на прибор**; доступ к оборудованию только после отдельного разрешения. Никаких подключений, автообнаружения, Modbus/502, отправки команд или записи настроек в Stage111. Открывать только файлы пользователя в режиме чтения.

## 3. Источник истины и качество

- 43 третьоктавные полосы, 24 RMS, доступные PIK/PIK-PIK и статусы показывать из оригинального DSP через проверенные AUX4700/VALUES, без локального приближённого пересчёта.
- ADC1052 -> Native R6.1 K **текущего сеанса** -> откалиброванный BIN. Не применять K повторно.
- Локальный `GetSpectrum`/FFT оригинальная программа вычисляет сама. Четыре режима и цепь Hann RMS/float32/scale восстанавливать адресно. До численной сверки с MVKView всегда метка `APP_DERIVED_FFT_MVKVIEW_CANDIDATE`; не выдавать за идентичность.
- Отмечать проблемы целостности, отсутствие AUX, устаревший статус, 0x400, неопределённую временную базу. Любые ошибки происхождения — fail-closed.
- Сохранённые промышленные BIN/RAW/PCAP и оригинальные DFM/PAS/IDP **не включать** в Git и пакеты передачи.

## 4. Границы проекта

- `research/stage41-spectrum-chain-20261028` и существующий Stage110 — источники анализа, не место новой реализации.
- **Новая ветка:** `research/stage111-mvkview-desktop-20261029`.
- **Новый каталог:** `mvk_compatible/` (не заменяет `MVK_Reader_Web/reader_web`). Архивный импорт и вычислительное ядро должны работать в unit-тестах без GUI/сети.
- Модули Stage110 допускается перенести и отделить от FastAPI **с сохранением атрибуции и пометок кандидата**; тесты и контрольные примеры для численных сценариев обязательны.
- Веб-доступ позже реализуется как дополнительный адаптер через тот же core, не как обязательный процесс/localhost-порт/браузер.
- Windows PySide6 приложение создаётся как native Qt GUI; возможна последующая компиляция/упаковка, но первый Stage111 НЕ является Windows installer.

## 5. Приёмка без ложных заявлений

1. Эталонное поведение исходной MVKView изучено по оригинальным обработчикам и подтверждено скриншотами/экспортами при тех же настройках.
2. Проверены все штатные элементы: три вкладки, подсекции, каналы, 4 режима FFT, курсоры, шкалы, навигация, фильтры/огибающая, статус и архив.
3. Численная проверка CSV/FFT/скопированных координат производится по одинаковому BIN и окну. «График визуально похож» не считается численной приёмкой.
4. Статусы `VERIFIED_ORIGINAL`, `APP_DERIVED_CANDIDATE`, `NOT_IMPLEMENTED` не смешивать. Отдельно оформлять пробелы в эталонах.
5. Тесты core + интеграции + Windows GUI; реальные необезличенные данные никогда не публиковать.
6. До завершения этой приёмки `MVKView Compatible 1.0` не присваивать и v0.3.40 не заменять.

## 6. Ближайшая реализация

- Stage111A: самостоятельная `mvk_compatible.core` для Stage107/R6.1 ZIP, прямые DSP значения, калиброванный BIN, независимые функции waveform/FFT (кандидат); безопасная валидация; CLI проверки; автоматические тесты.
- Stage111B: desktop Qt с тремя вкладками, выбором канала/окна/среза AUX, графиками, точными курсорами; пока только архив.
- Stage111C: адресная паритетная проверка оригинального `GetSpectrum`, `GetSignal`, фильтров/огибающей и поведения `TQGrapher`; эталонные регрессионные тесты.
- Stage111D: единственный Native R6.1 Collector, Live/Archive и длительные тесты только при отдельном разрешении; затем упаковка Windows.

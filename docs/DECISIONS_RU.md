# Архитектурные решения и ограничения — актуально 2026-10-29

## ПРИНЯТО: исходные данные и оригинальные расчёты МВК

**Канонический документ:** [ADR-2026-10-29 — оригинальные данные DSP являются источником истины](ADR_2026_10_29_ORIGINAL_MVK_DSP_DATA_SOURCE_RU.md). Его правила имеют приоритет над историческими планами моделирования DSP.

- **ПОЛУЧЕНИЕ ДАННЫХ РЕШЕНО** в проверенном режиме: реальный Windows Native R6.1 на МВК01 №84, TCP/10230 read-only, 8 ADC, 2 TACH, AUX4700 с 43 третьоктавными полосами и штатными расчётными показателями, начальные калибровочные регистры.
- **Для СКЗ, скорости, перемещения, штатных полосовых значений и статусов получать и показывать значения DSP прибора напрямую из AUX4700.** Не заменять приблизительными вычислениями из временного сигнала. Ошибки старого метода 10–3000 Гц (до ~25%) не являются дефектом этого пути.
- ADC1052: 28 B заголовок + 256 raw `float32 LE` одного канала; 65536 сэмплов/с на канал для проверенных сеансов. Физическое ускорение `raw * K`, K из полного начального снимка регистров **этого же** TCP-сеанса; BIN второй раз не масштабировать.
- **Только новые** высокоразрешающие FFT, признаки и ML из RAW допустимы как отдельно помеченные `APP_DERIVED`. Если AUX отсутствует/невалиден — не подменять его расчетом незаметно.
- Любое значение должно иметь прибор, канал, единицы, источник, диагностический статус и качество. Статус `0x400` на ADC7/ADC8 прибора №84 показывать как предупреждение, не считать наличия waveform доказательством исправности.
- Один Collector на прибор, много браузеров; `TCP Connect → Read` без команды запуска, без записи TCP/502, без смены конфигурации. Физические испытания только с разрешения.
- Стабильная v0.3.40 не изменена; новая основная программа строится поверх подтверждённого Native R6.1 с обязательной регрессией.

## Незакрытые вопросы (НЕ возвращаться к разработке приёмника с нуля)

- Полевой тест длительной записи и reconnect; испытания других приборов; уточнение статусов и тахометра под нагрузкой.
- Сопоставление TSXML/VALUES/TABLE и форматирования с оригинальной MVKView в *той же* сессии; аппаратная синхронизация времени.
- Полноценная интеграция с MVK Reader Web и её тестирование; хранение сырых данных, управление качеством и архивом.

## Безопасность и сохранность

Не отправлять неподтверждённые прикладные команды, не писать Modbus, не подключать прибор без согласования. Не публиковать производственные PCAPNG, BIN, конфигурации, базы и секреты. При ошибке непрерывности/K/снимка регистров сохранять исходный RAW и не выдавать непроверенный экспорт за успешный.

**Приоритет для новых чатов:** читать `START_NEW_CHAT_RU.md` и данный ADR; правила до 2026-10-29 о «необходимости сначала научиться получать DSP-расчёты» и обязательном приблизительном собственном пересчёте считать историческими.

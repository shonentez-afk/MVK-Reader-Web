# Архитектурные решения и ограничения

## Подтверждённые рабочие принципы
- Сохранить исходную архитектуру и UX основной программы, не заменять прототипом Stage 24.
- Разделить TCP/10230 (сырые временные отсчёты) и TCP/502 (Modbus FC03 расчётные данные).
- Единый Collector Server на прибор; браузеры не должны устанавливать каждое собственное соединение к TCP/10230.
- Отображать «Live» и «Archive» из соответствующих источников, не выдавать устаревшее последнее измерение за актуальное.
- Для сырых PCAPNG применить per-device/per-ADC коэффициенты, записывать источник и время калибровки.
- BIN в физических единицах не подвергать повторному пересчёту.
- Для работающей SCADA исключить команды записи Modbus. Реальные подключения — только по согласованному тесту.

## Отдельно подтверждено испытанием 2026-10-23
- Ответы FC03 float32 читаются с перестановкой слов CDAB.
- `A+0x02` — чувствительность, `A+0x0E` — внутренний коэффициент пересчёта.
- Для АЦП4 двух МВК01 результат TCP/10230 * K практически совпадает с BIN.
- В успешных PCAPNG первые данные появились до полной 36-байтной клиентской посылки.

## Гипотезы, НЕ считать подтверждёнными
- Достаточно ли одного TCP connect без любых прикладных отправок для появления потока.
- Значение 36-байтного сообщения клиента в полном протоколе.
- Ограничение ровно одного клиента TCP/10230 — наблюдается пользователем, но не тестировалось в отдельных экспериментальных режимах.
- Полная идентичность интегрированных Windows-пакетов и опубликованного исходного дерева до сверки.

## Правило изменения этого журнала
На каждую существенную перемену добавлять дату, эксперимент/источник, что подтверждено и что осталось гипотезой. Никогда не превращать предположение в факт без проверки.

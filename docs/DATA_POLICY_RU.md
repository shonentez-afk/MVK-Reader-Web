# Хранение результатов и безопасность

## В Git
Исходники Python/JS/CSS/HTML, конфигурационные *шаблоны* без производственных настроек, тесты, инструкции, воспроизводимые декодеры, небольшие обезличенные фикстуры, файлы зависимостей. Документация для переносов между чатами и фиксация версий.

## Не помещать в Git
Полные `.pcapng`, `.bin` и ZIP рабочих записей, SCADA/производственные IP-адреса в конфигурационных файлах, реальные базы SQLite с данными предприятия, токены/пароли, секретные параметры среды, виртуальные окружения, временные логи.

Большие эталонные захваты хранить в отдельном закрытом хранилище, в Git только SHA256, псевдоним прибора, отметку калибровки и проверенные ожидаемые результаты. Если понадобится Git LFS, сначала отдельно проверить права, квоты и политику хранения данных.

## Релизы
Для каждого тега должны быть: проверенный исходный commit, версия, CHANGELOG, перечень пройденных тестов и Windows-пакет. **Не публиковать релиз из одного README и документации.**

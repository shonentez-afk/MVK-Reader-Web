# Stage13 — ADC6: временная серия VALUES vs BIN (2026-10-27)

## Основание и исходные данные
Загружены 61.0390625-с BIN АЦП6 (SHA256 `1eccd0857c4c222299a7c9a09d67bfd316adc76616acd730a93ffa2049aba41d`) и файл `VALUES-2026-10-27--10-34-13(1).csv`. Файл VALUES: **124 строки измерений**, с 10:34:13.911 по 10:35:15.410, шаг примерно 0.5 с, CP1251, 74 колонки. Параметры ускорения: колонки «Виброускорение, 10..3000 Гц», «10..2000 Гц» и «10..1000 Гц». Временные метки VALUES подтверждены содержимым CSV, но не подтверждают аппаратный timestamp BIN.

## Метод и воспроизведение
Предположено, что начало BIN приходится на 10:34:14.000 (имя BIN) и первый VALUES имеет относительное время -0.089 с. Это ориентир, **не строгая синхронизация**. Для метки VALUES взят предшествующий интервал BIN длиной 1/2/4 секунды; окно boxcar, detrend constant, scipy.signal.periodogram scaling=density, интеграл PSD на [10, верхняя граница), RMS в м/с². Скрипт: `tools/adc6_values_alignment/compare.py`. В качестве ориентира получено:
| Окно | Совпадающих точек | BIN медиана, 10–3000 | MVKView медиана, 10–3000 | Медианное построчное отношение BIN/MVKView |
|---|---:|---:|---:|---:|
| 1 с | 120 | 2.87306 | 3.5375 | 0.80388 |
| 2 с | 118 | 2.87182 | 3.5385 | 0.80539 |
| 4 с | 114 | 2.86753 | 3.5420 | 0.80654 |

Для окна 2 с медианы ускорения BIN 10–3000/2000/1000 Гц: 2.87182/1.91782/1.67255; MVKView: 3.5385/2.2005/1.6265 м/с². Медианные построчные отношения: 0.80539/0.87219/1.02837. Коэффициенты корреляции по времени для этих полос: около 0.400/0.314/0.499 соответственно.

## Выводы и ограничения
**Подтверждено:** VALUES содержит регулярный временной ряд, а не только отдельные TABLE snapshots. Простая замена 1/2/4-секундного окна не объясняет устойчивую разницу около 20% в 10–3000 Гц при выбранном номинальном выравнивании.
**Не подтверждено:** часы BIN, задержка вычислительного тракта MVKView, точная привязка каждой строки VALUES к отсчётам, тип и АЧХ фильтров. Корреляции умеренные и не позволяют принимать точную синхронизацию. Не объявлять доказанным расширенный cutoff до 3.3 кГц, хотя cutoff-sweep уже выполнен в другом отчёте.
**Далее:** офлайн-проверка лагов по диапазонам и сравнение с документированными фильтрами/описанием алгоритма MVKView; без подгонки на одно совпадающее число. Не требовать нового измерения до использования имеющегося VALUES.

# MVK01 Unified Decoder — Stage 4: двоичный транспорт Collector (26.10.2026)

Независимый модуль `collector_binary_transport.py`, исходники с тестами в выдаваемом пользователю архиве `MVK01_UNIFIED_DECODER_STAGE4_20261026.zip`. В репозиторий внесён **отчёт**, архив и новый код ещё не импортированы в production. Основная MVK Reader Web v0.3.40 неизменна.

## Контракт

Пакет `MVKT` v1: `magic 4 + version u8 + kind u8 + reserved u16 + offset u64 + payload_len u32 + CRC32 u32`, всё LE. За 24-байтовым заголовком — **неизменённый** байтовый блок VAST_MVK либо исходный MVK кадр. Проверяются порядок, тип, диапазон длины, CRC32 и непрерывность байтовых смещений. `replay_events` подаёт callback калибровку, АЦП (256 float с gain, 65536Hz), AUX4700, AUX160 и тахометры без загрузки всей записи. Ни один прибор не опрашивается.

Формат компактен в сравнении с JSONL с массивами измерений, но **больше оригинального RAW** из-за 24-байтовой обёртки на кадр. Не путать с компрессией.

## Ограничения

Это только **офлайн-интерфейс**, не production Collector Server. Нет авторизации, сети, автоматического переподключения, межклиентской очереди, таймштампов, контроля нагрузки. Replay требует полный начальный заголовок VAST_MVK. Назначения отдельных AUX остаются непроверенными. CRC32 не заменяет защищённый транспорт. Дальше: sample_counter-based timestamps, live-source abstraction без подключения к прибору, тестирование backpressure и устойчивости к потере/частичному потоку.

# Архитектурная карта MVK Reader Web

Основано на просмотре сохранённых исходников в GitHub 2026-10-26. Это карта компонентов, а не заключение о работоспособности в сети.

## Точки входа
| Путь | Роль |
|---|---|
| `MVK_Reader_Web/START_READER.py` | Локальный запуск `integrated:app` через uvicorn на `127.0.0.1:8080`. **Не запускать до завершения контрольного теста подключения**: приложение может включать фоновые задачи Collector. |
| `MVK_Reader_Web/integrated.py` | Интеграция интерфейса и роутеров; проверять перед любыми изменениями маршрутизации. |
| `MVK_Reader_Web/reader_web/server.py` | Исходный офлайн API BIN/TSXML, SQLite-архив, выдача HTML и графиков. Версия компонента в исходном коде может отличаться от версии всего продукта. |
| `MVK_Reader_Web/collector/service.py` | API Collector Server, жизненный цикл опроса и планировщика. |
| `MVK_Reader_Web/collector/core.py` | Состояние приборов, сбор данных и хранение. |
| `MVK_Reader_Web/collector/scheduler.py` | Планировщик опросов. |
| `MVK_Reader_Web/collector/decoder.py` | Декодирование расчётных данных опроса. |
| `MVK_Reader_Web/signal_bridge/api.py` | API ранее импортированного офлайн-слепка восьми каналов, форма сигнала/спектр. |
| `MVK_Reader_Web/signal_bridge/mvk_decode.py` | Низкоуровневая обработка блоков МВК. |
| `MVK_Reader_Web/signal_bridge/signal_processing.py` | Фильтрация и вычисление спектров. |
| `MVK_Reader_Web/signal_bridge/import_capture.py` | Офлайн-импорт сетевых захватов. |
| `protocol/mvk_calibration.py` | Независимый модуль подтверждённого чтения калибровки. |

## Основные потоки данных
- **Файловый:** BIN + TSXML → `reader_web/mvk_core.py` → SQLite/локальный архив → веб-интерфейс.
- **Офлайн PCAPNG:** захват → `signal_bridge/import_capture.py`/`mvk_decode.py` → сохранённые отсчёты → `signal_bridge/api.py`/`signal_processing.py` → графики.
- **Расчётные данные по TCP/502:** Modbus FC03 → Collector → SQLite/текущий статус → API и вкладка «Расчётные данные».
- **TCP/10230 Live:** схема ожидает отдельного подтверждения поведения прибора. Не включать и не считать проверенной.

## Сеть и сохранность
- TCP/10230: особый источник сырых данных. Passive-тест ещё не выполнен.
- TCP/502: разрешённые диагностические FC03 без команд записи.
- Нормальный доступ пользователей: один Collector/сервер — несколько браузеров; не создавать отдельные подключения к 10230 на каждый браузер.
- Конфигурации приборов и БД не публикуются.

## Как поддерживать документ
При изменении архитектуры обновлять этот файл и `docs/DECISIONS_RU.md`. Для поиска функции использовать исходники и тесты, а не полагаться только на эту схему.

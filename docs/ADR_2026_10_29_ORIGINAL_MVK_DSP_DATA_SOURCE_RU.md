# ADR-2026-10-29 — получение данных МВК01 решено; оригинальные результаты DSP — источник истины

**Статус:** ПРИНЯТО (архитектурное решение и проверенный baseline приёма).  
**Дата:** 2026-10-29.  
**Обязательно читать перед разработкой:** `README.md`, `START_NEW_CHAT_RU.md`, `docs/DECISIONS_RU.md`, этот ADR и [Stage 109](https://github.com/shonentez-afk/MVK-Reader-Web/blob/research/stage41-spectrum-chain-20261028/docs/research/STAGE109_R6_1_FIRST_REAL_LIVE_DEV84_ACCEPTANCE_RU.md).

## 1. Главный итог — больше не возвращаться к старой проблеме

**Задача получения исходных измерений и штатных расчётных результатов непосредственно из работающего МВК01 технически решена и проверена на реальном устройстве №84.** Native R6.1 успешно работает в режиме read-only на Windows с проводным Ethernet, самостоятельно подключается по TCP/10230, принимает временные отсчёты восьми АЦП, два тахометрических канала, AUX4700 со штатными результатами DSP и начальный снимок регистров. Он записывает RAW и восемь BIN/TSXML, VALUES и TABLE.

**Архитектурный запрет для основной программы:** не заменять полученные от прибора штатные СКЗ, виброскорость, виброперемещение, полосовые/третьоктавные результаты и диагностические статусы собственными приближёнными расчётами из RAW. При наличии корректных данных DSP показывать и архивировать **именно оригинальные приборные значения**. Прежние ошибки до ~25% при попытке независимо имитировать верхнюю частотную границу 3000 Гц не нужно «чинить» в основном пути отображения, поскольку этот путь больше не должен пересчитывать штатные приборные показатели.

Реверс-инжиниринг прошивки и алгоритмов DSP — **отдельная исследовательская задача**, не блокирующая MVK Reader Web и не являющаяся условием запуска штатных отображений.

## 2. Фактически проверенная схема данных

```text
МВК01, DSP выполняет штатные измерения и вычисления
       │
       └── Ethernet TCP/10230, одно read-only соединение Collector
            ├── ID264 + исходный снимок регистров 32800 B (K по каждому АЦП)
            ├── ADC1052 × 8: 28 B header + 256 × float32 LE одного канала
            │     └── исходный сигнал → RAW → K текущего сеанса → BIN (м/с²)
            ├── TACH284 × 2: тахометрические данные (нужна отдельная
            │     приёмка работы с реально подключённым импульсным датчиком)
            ├── AUX4700: оригинальные расчёты DSP по всем 8 каналам
            │     ├── 43 штатных третьоктавных значения
            │     ├── штатные СКЗ и другие расчётные параметры
            │     └── диагностические статусы, в том числе 0x400
            └── технические регистровые сообщения/отметки обновления
                    ↓
         Collector Native (R6.1 как проверенная отправная точка)
                    ↓
         MVK Reader Web: Live, графики, архив, экспорт, диагностика
```

Использовать **один Collector на прибор**, а браузерам предоставлять общий обработанный поток, не открывать новое TCP/10230 соединение на каждый браузер. В проверенных сеансах поток начинается **после TCP Connect, без клиентского прикладного payload**, без проприетарной команды запуска. Не вводить отправку неизвестных команд, запись Modbus/502, Flash или изменение частоты по умолчанию. Новое подключение к реальному оборудованию — только с разрешения пользователя/ответственных.

## 3. Контракт происхождения значений — неизменяемый

| Данные в UI/архиве | Единственный штатный источник | Допускаемый дополнительный расчёт |
|---|---|---|
| СКЗ виброускорения в заданных прибором диапазонах | AUX4700 / оригинальные регистры DSP | Не подменять формулами FFT/Welch |
| Виброскорость, виброперемещение и другие штатные полосы | AUX4700 / оригинальные регистры DSP | Не подменять аппроксимациями |
| 43 третьоктавных значения | AUX4700 (номиналы по карте прибора) | Не выдавать локальный FFT за оригинал |
| Диагностические статусы датчиков/каналов | Оригинальные поля состояния | Не скрывать неисправность из-за наличия отсчётов |
| Временной сигнал | ADC1052 → индивидуальный K из начального снимка **этой** сессии | Сохранение без изменения/двойного масштабирования |
| Тахометр | Оригинальные каналы TACH284 и проверенные регистры | Уточнять степень подтверждения при отсутствии импульсов |
| Подробный FFT произвольного разрешения, новые признаки и ML | Исходный временной сигнал | Разрешено, но **обязательно метка «расчёт приложения»**, отдельно от DSP |

Для каждого значения или набора хранить/передавать происхождение: прибор, канал, время и источник (`MVK_DSP` / `MVK_ADC` / `APP_DERIVED`), единицы, диагностический статус, качество кадра, происхождение коэффициента K. Пользователь не должен принимать локальный расчёт за подлинное значение DSP.

**Если AUX4700 отсутствует, устарел или статус канала плохой:** показывать отсутствие/невалидность оригинального результата и предупреждение. Не подменять его «примерно таким же СКЗ» незаметно. Дополнительный расчёт можно отображать отдельной подписанной серией; он не отменяет исходный статус.

Сохранять **RAW без исправлений и домыслов**. BIN записывать с K именно текущего сеанса; исходный TCP `float32` не следует считать уже откалиброванным. Наоборот, готовый экспортированный BIN уже в физических единицах, **K повторно не применять**. Неполный терминальный кадр при штатной остановке оставлять в RAW, но не выдавать его за полный BIN. При нарушении непрерывности/калибровки — fail-closed, с сохранением диагностических данных.

## 4. Доказательства на реальном оборудовании — Stage 106–109

- Stage106: два 30-секундных Live-сеанса №84, Native R5 и R5.1, пассивный приём, 8 АЦП, 2 TACH, по 60 AUX обновлений; независимая проверка регистровых расчётов.
- Stage107: офлайн-экспорт 8 BIN/TSXML и VALUES/TABLE на двух реальных RAW; независимая побитовая валидация.
- Stage108: единый Native R6.1 с потоковой записью BIN, проверкой временных файлов и атомарным экспортом; 39 тестов и офлайн-повтор №84.
- **Stage109 — аппаратное подтверждение R6.1 под Windows:** 30.0128 с на №84; 69 685 884 B сохранённого RAW совпали с PCAPNG побайтно; **0 B** прикладных команд клиент→прибор; 61 429 ADC, 15 356 TACH, 60 AUX, отсутствие выявленных разрывов последовательности; **15 725 824** откалиброванных отсчёта BIN совпали побитово с независимым расчётом; **33 600** регистровых расчётных значений VALUES совпали с AUX с учётом округления; 8 BIN/8 TSXML, корректный TABLE и 19/19 SHA-256. Статус R6.1 `EXPORTED`, `during_capture_bin_spool_verified=true`. У ADC7/ADC8 статус `0x400`: их данные не выдавать за здоровый измерительный канал.

**Основание:** [подробный отчёт Stage109](https://github.com/shonentez-afk/MVK-Reader-Web/blob/research/stage41-spectrum-chain-20261028/docs/research/STAGE109_R6_1_FIRST_REAL_LIVE_DEV84_ACCEPTANCE_RU.md), [проверенный исходный код Native R6.1](https://github.com/shonentez-afk/MVK-Reader-Web/blob/research/stage41-spectrum-chain-20261028/tools/research/native_tcp10230_stage108_live_recording_r6_1), [скрипты независимой проверки](https://github.com/shonentez-afk/MVK-Reader-Web/blob/research/stage41-spectrum-chain-20261028/tools/research/native_tcp10230_stage109_real_live_qa).

Результат «0 расхождений» означает **сверку принятых/декодированных/экспортированных данных с теми же RAW/PCAP/AUX**, а не доказательство математического совпадения самописного DSP с прошивкой. Производственные RAW, PCAPNG и BIN не публиковать в Git.

## 5. Что НЕ закрыто, но не отменяет решение о приёме

1. Полная идентичность форматов/округления/подписей BIN/TSXML/VALUES/TABLE с оригинальной MVKView **в одном и том же измерительном сеансе** ещё не доказана; важно для полной совместимости форматов, не для источника DSP.
2. Windows-приём R6.1 проверен на **одном реальном приборе №84 и коротком 30-секундном сеансе**. Длительные записи, аварийные разрывы, повторные соединения, множественные приборы и поведение при сбоях требуют дополнительных тестов.
3. Временные отметки VALUES базируются на часах компьютера; аппаратная синхронизация требует отдельной проверки.
4. Тахометрические кадры приняты, но фактический сигнал с включённым тахометром и все его особые состояния надо отдельно исследовать.
5. **Интерфейс основной программы ещё не интегрирован** с Native R6.1; его нужно разработать и принять без изменения стабильной версии v0.3.40 до регрессионных испытаний.

## 6. Обязательные действия для Stage110 и всех следующих чатов

1. **Считать приём и декодирование МВК01 (в подтверждённом режиме) базовой завершённой подсистемой, не начинать протокол и DSP заново.**
2. Строить интерфейс, архив и экспорт поверх существующего Native R6.1/Stage107, переиспользовать контракт данных и калибровки.
3. В интерфейсе приоритет отображения: *оригинальные расчёты DSP*, затем временные сигналы/локальный FFT с отдельными метками происхождения.
4. Контроль качества: явный `0x400` и другие состояния, старые AUX, пропуски кадров, K, реальный источник времени; никакой ложной «успешной» записи.
5. Новые открытия о прошивке могут уточнять **только исследования/дополнительные функции**; переход от оригинальных расчётных значений к самописным возможен лишь после **отдельного решения пользователя**, тестов и новой ADR.
6. Читать этот файл первым при каждом восстановлении контекста; любые противоречащие ему старые планы **до 2026-10-29** считать историей, а не актуальным техническим требованием.

**Итоговое решение: задача «научиться получать с прибора МВК оригинальные измерения и результаты DSP» ЗАКРЫТА по проверенному сценарию. Следующая работа — основная программа MVK Reader Web, а не повторный реверс расчётов.**

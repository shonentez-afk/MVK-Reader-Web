# MVKView 1.0.47 ↔ MVKView Compatible Stage111 — карта восстановления

**Объект сравнения:** оригинальный MVKView 1.0.47 и desktop-приложение `MVKView Compatible` в ветке `research/stage111-mvkview-desktop-20261029`. Ни веб-ридер, ни MVK Live Standalone не являются целевой реализацией.

## Приватный и публичный контуры

Полный граф оригинала строится локально на предоставленных `Projects.7z`, `mvkview.idp` (это IDR, не IDA) и ранее сформированной с помощью IDP2TXT `mvk_idr(1).sqlite`. В GitHub **не публикуются** исходники, бинарные дампы, данные прибора и подробные производные графы оригинала. Созданная в исследовательской сессии интерактивная локальная HTML-карта остаётся вне репозитория.

`tools/architecture/mvk_stage111_ast.py` строит **публичный граф только Stage111**: Python AST по `mvk_compatible/core` и `mvk_compatible/desktop`, консервативные связи импортов и прямых вызовов, а также объявления Go Native R6.1. Go не имеет здесь полного AST/call graph; динамические Python-вызовы также не разрешаются. Это не инструмент доказательства runtime или аппаратного 1:1.

## Использование

На checkout нужного SHA:

```bash
python -m unittest discover -s tools/architecture -p 'test_*.py' -v
python tools/architecture/mvk_stage111_ast.py --repo . --sha "$(git rev-parse HEAD)"
```

Результат `docs/architecture/mvkview-recovery/stage111-public-graph.json` можно безопасно объединить **локально** с приватным графом оригинала. GitHub Actions производит JSON как artifact без автоматического коммита.

В локальном интерфейсе есть два основных режима: «Архитектура» и «Связи кода»; общий контекст «Оригинал / Stage111 / Сравнение». Карточки сохраняют назначение, объяснение алгоритма, вызовы, входы/выходы, проверки, ограничения, исходные строки и статус доказательств. При пересборке нельзя терять содержательные объяснения из `docs/research`.

## Корректная трактовка

Отсутствие вызова в статическом индексе не доказывает отсутствие функции. `commented_stub` относится к реконструкции Delphi, а не к Stage111. Похожие названия не доказывают паритет: соответствия 1:1, 1:N и N:1 требуют анализа алгоритмов, состояния и тестов. Строгий файловый `--require-complete-same-raw` не заменяет подлинную парную физическую Win32/MVK01 сессию.

Открытые проверки: IP → Измерить → Task2 → RX → GetSignal/GetSpectrum → FIR/Hann/FFT/четыре режима → WriteValues/WriteData → Stop; x87/FRange, интерфейс семи страниц и трёх форм, GDI/курсор. Это вопросы доказательств, **не автоматически найденные программные дефекты**.

Документационный PR не меняет приложение, Go-приёмник, протокол MVK01 или `main`. Полные приватные данные нельзя выгружать в публичные GitHub Pages.

## Дополнение: Go AST-граф вызовов

В этой же документационной ветке добавлен `tools/architecture/mvk_stage111_go_ast.go`: **Go stdlib parser/ast** по производственным `.go` в native R6.1 (тестовые `_test.go` исключены). Он фиксирует прямые вызовы package-функций и методы, вызываемые через собственный receiver. Неоднозначные build-tag и непрозрачные selector-вызовы **не приписываются** произвольным целям. Это статический граф, не подтверждение runtime и не новая реализация Go RX.

Локальный запуск:

```bash
go run tools/architecture/mvk_stage111_go_ast.go --repo . --sha "$(git rev-parse HEAD)"
```

GitHub Actions проверяет два графа — Python AST и Go AST — и загружает их в **один workflow artifact** для последующего локального, приватного слияния. Полная приватная карта не размещается в публичном GitHub.


## Проверенный LikeC4 и карта оригинала (24.11.2026)

Редактируемый **публичный слой Stage111** находится в `likec4/model.c4` и `likec4/views.c4`. Он действительно валидируется CLI LikeC4 1.61.0 и собирается в автономный HTML как artifact задачи `public-likec4-model`. Модель содержит только известные публичные подсистемы Stage111, не приватную оригинальную архитектуру.

Технически это **отдельный проверяемый архитектурный источник**, но не конкурирующая полная карта. Основным интерфейсом сравнения остаётся приватный локальный Recovery Atlas, который использует собственную SVG-отрисовку: он **не** является LikeC4-renderer и должен показываться как таковой.

Проверка модели и сборка:

```bash
npx --yes likec4@1.61.0 validate docs/architecture/mvkview-recovery/likec4 --max-warnings 0
npx --yes likec4@1.61.0 build --output-single-file -o ./likec4-preview docs/architecture/mvkview-recovery/likec4
```

Привязанные к Stage111 ссылки исходников проверяются `tools/architecture/test_likec4_sources.py`. Все ссылки в публичной модели фиксируют **SHA `1ec074861ba5f4cc7bf11843b0f47a9f9a4dcbbc`** как документируемую рабочую Stage111.

### Последняя сводка локального анализа

- Оригинал: 25 404 функций IDR, 65 448 разрешённых call records, 27 319 без разрешённой цели в индексе (это **не дефекты**).
- 95 DFM-событий оригинала → 55 уникальных адресов обработчиков; 21 предварительная исследовательская подсказка Stage111, 34 не оценены. Подробные адресные доказательства остаются локальными.
- Stage111 по первому полному Python+Go CI snapshot: **220 файлов**, **1 451 функция**, **4 426 статических связей**; данные исходного GitHub Actions #45247330018, pinned CI merge SHA `3b985855e0a0923edbe2fae7d032ef8dd2be5944`. Это статический охват, не runtime-паритет.
- В исходном потоке записи нельзя механически сопоставлять имя `WriteValues` с отдельной Stage111 функцией: сначала следует сверять события, флаги состояния и реальный записывающий цикл.
- Отдельный локальный read-only адресный аудит собрал прямые и двухшаговые зависимости критических функций; в GitHub он не публикуется.
- Полное физическое 1:1 original Win32/MVK01 и Dhrake/Ghidra косвенные вызовы пока остаются открытыми.

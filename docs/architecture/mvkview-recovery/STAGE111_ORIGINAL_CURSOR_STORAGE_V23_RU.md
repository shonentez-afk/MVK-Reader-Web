24.11.2026. Продолжение исследования оригинальной MVKView. Не изменять рабочий Stage111, main/research/fix и приборный обмен. PR #14 остаётся отдельно. Только документационный отчёт; приватная карта и первичные источники в GitHub не публикуются.

## Масштаб и доказательства

Повторная сверка 133 PAS/DFM по SHA256, IDP SHA и SQLite quick_check. Добавлены 19 карточек, 42 направленные связи, 315 уникальных адресных опор, 11 DFM мест, 8 VMT мест Canvas. В слое v22–v23 теперь 40 карточек, 90 отношений, 14 маршрутов. Все прежние 641 кандидата сохранены; это не число подтверждённых runtime links. Оригинальный полный v15 HTML сохраняется побайтно после удаления добавленного слоя; v21 сохранён отдельно.

## Storage: оставшиеся 11 вопросов

- 3: GetNarrowbandValue привязан к четырём прямым вызовам в TMVKCalibThread.Execute; принадлежность определяется form ChannelStorage, номером канала, эпохой и reaching definition. Это не обычный ADC/SPEC таймер.
- 1: ProcessBufferChunk→InitParams исключён для рассмотренного нормального factory path Mode1/Mode2 (четыре прямых InitParams callsites предшествуют producer нового storage); не исключены все динамические/reentrant пути.
- 7: GetRawSignal остаётся без доказанного вызывающего маршрута. В исследованном машинном образе не найден прямой E8 к цели; найденная ссылка принадлежит RTTI/таблице методов, не доказывает исполнение. Не подменять GetSignal этим методом.
- Остальные 32 оценки v22 сохранены. Все 43 строки имеют явный статический статус; семь caller questions открыты.

GetRawSignal разделяет contiguous/ring и Float32/byte копирование, проверяет доступность окна; не смешивать его с обработанным extractor, который учитывает FValidPos. Калибровка: узкополосный расчёт по Fs и N, FFT/Power и ограниченная полоса. Доказательство same epoch остаётся условным.

## Графики

Из IDP прочитаны шесть таблиц: ADC H 14, ADC V 13, SPEC H 10, SPEC V linear 6, SPEC V dB 6, SPEC FFT N 6. Уточнены DFM, Tag, параметры каналов, условия перестройки меню и пересчёта. Различать перерасчёт и redraw; оба SPEC scrollbar используют один обработчик. Временная ось обращена. Курсор спектра ищет максимум в пределах пиксельного столбца; в линейной шкале подпись использует RSS соседних бинов, не RMS; логарифмическая ветвь использует максимум. Уточнена растровая агрегация min/max, преобразование координат, canvas MoveTo/LineTo для установленного класса. Верхняя граница clamp требует дальнейшей проверки; не объявлять runtime дефектом. TBackgroundProcessThread constructor/AddTask присутствуют в RTTI, прямого вызывающего producer в исследованном диапазоне не найдено. Не считать этот маршрут активным в Mode2.

## Назначение

Сопоставление **оригинальной MVKView 1.0.47** с **десктопной MVKView Compatible Stage111**. Название общего GitHub-репозитория не означает сравнение с отдельным web-reader или MVK Live.

## Публичная проверяемая инфраструктура

- `mvk_stage111_ast.py` — Python AST/импорты и проверяемые прямые вызовы; динамические вызовы не реконструирует.
- `mvk_stage111_go_ast.go` — Go stdlib AST для receiver и известных одноимённых package-вызовов; неизвестные вызовы не считать отсутствующими.
- `mvk_stage111_qt_signals.py` — 202 реальных `signal.connect(...)` и исходные строки, включая проверенные литеральные имена кнопок/условия; callback может быть динамическим.
- `mvk_stage111_merge_graphs.py` — единая модель Python + Go + Qt вместо трёх конкурирующих графов; строит узлы Qt-сигналов и связи к обработчикам.
- `mvk_stage111_address_refs.py` — 1 282 упоминания 606 разных кодоподобных адресов в публичных Python/Go исходниках; сами по себе **не доказывают** идентичность алгоритмов, а совпадение с оригинальными функциями проверяется только локально.

## Приватный контур

Оригинальные `Projects.7z`, `mvkview.idp` (проект IDR, **не IDA Pro**) и `mvk_idr(1).sqlite` (уже полученная через IDP2TXT индексная БД) используются совместно, но **не публикуются**.

Локальный граф содержит все проиндексированные функции, вызовы, формы, DFM-события, подробные пояснения и независимые доказательства, но не является runtime-трассой. По трём источникам проверена целостность доступного объёма. Не публиковать приватный HTML, CSV, JSON-перекрёстные индексы и фрагменты оригинала ни через GitHub Pages, ни через PR.

В локальном Atlas имеется **одна** карта с двумя основными режимами («Архитектура», «Связи кода») и общим переключателем «Оригинал / Stage111 / Сравнение». Новые инструменты «DFM ↔ Qt» и «Адреса ↔ код» — подробные панели этой же карты, не отдельные конкурирующие карты. Подробные описания из ранее существовавших исследований сохранены.

## Неподтверждённые зависимости и ограничения

1. В исходном индексе имеются неразрешённые/косвенные вызовы: требуется IDR/Ghidra/VMT-анализ, а не автоматическое объявление «функция не восстановлена».
2. Синтаксическая связь DFM-имени элемента с Qt signal.connect не доказывает одинаковые состояния, ошибки или результаты.
3. Упоминание Delphi-адреса в Stage111 source comment/строке не доказывает перенос вычислений или фактическое исполнение.
4. Go и Python AST не восстанавливают все динамические callback и выполнение веток.
5. `--require-complete-same-raw` — файловая проверка, не замена парной физической сессии с оригинальным Win32/MVK01.
6. Точные значения FFT/FIR, Win32/x87, FRange, графика и курсоры требуют независимого численного/визуального эталона.

## Критические сценарии дальнейшей приёмки

- IP → Измерить → Task2 → TCP/RX → GetSignal/GetSpectrum → FIR/Hann/FFT/Power/Tag0–3 → WriteValues/WriteData → Stop.
- 7 страниц и 3 формы, все реальные события DFM/Qt, состояния доступа, ошибки, повторные действия.
- Потоковая запись при запуске/остановке и при ошибках, форматы BIN/TSXML/VALUES/TABLE.
- GetValueText и исходные расчётные поля; подписи шкал, фильтры, единицы измерения, прокрутки, GDI-курсор.

Это **открытые исследовательские вопросы**, а не выявленные программные дефекты.

## Безопасность изменений

Создан только read-only аналитический инструментарий и документация в отдельной ветке. Рабочий Qt/Core/Go код, приборные команды и `main` не модифицированы.

PR: [#13](https://github.com/shonentez-afk/MVK-Reader-Web/pull/13), остаётся Draft до полной проверки карты и закрытия необходимых открытых пунктов.

# Atlas v16 — принадлежность объектов и порядок выполнения

**Дата:** 24.11.2026. **Зафиксированная рабочая ревизия Stage111Z31EB:** `dd020c4a8c1cd9d80440031730b7c4ee28bf8cef`.

Этот документ — **безопасный публичный конспект** приватного локального исследования. Он не содержит восстановленных Pascal/DFM-инструкций, исходных адресов, IDP, SQLite, пользовательских приборных данных или приватного графа. **Ни код приложения, ни `main`, ни механизм приборного обмена не изменены.**

## Что теперь проверено

Приватный источник перепроверен по SHA-256 для 133 реконструированных файлов, исходному IDP и SQLite (`quick_check=ok`). В самостоятельном слое Atlas v16 проверены **20 предметных цепочек, 57 конкретных инструкций**. Из них 3 устанавливают принадлежность внутри одного вызова, 8 подтверждают локальный порядок **при определённых условиях**, 8 требуют доказательства алиаса экземпляра/сессии, 1 остаётся открытой виртуальной целью. Это не процент завершения программы.

1. **Экземпляр потока.** Обработчик измерения создаёт `TMVKThread` для Task2 и хранит ссылку в форме. Обработчик `WriteValues` использует ссылку формы; тождество потока при смене сеанса и публикация флагов между потоками требуют отдельной проверки.
2. **RX и хранилище канала.** В одной ветви принятого кадра сохраняется один указатель `TMvkChannelStorage[channel]`, используемый при выделении и обработке порции буфера. Для утверждения «RX и график используют тот же экземпляр» требуются равенство номера канала, сохранность слота формы и непрерывность жизненного цикла.
3. **Вычисление и показ.** Потребители GetSignal/GetSpectrum выбирают хранилище по пользовательскому номеру канала. Общая форма не гарантирует, что пользователь выбрал именно RX-канал. В Stage111 отдельно проверять [условия входного окна](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/mvk_compatible/core/original_getsignal_live_source.py#L66) и [привязку полной FFT к окну](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/mvk_compatible/core/original_live_spectrum_view.py#L16).
4. **PARAM → регистры → текст.** В обработчике PARAM для Task2 последовательная проверка банков выполняется до ветви записывающего обработчика VALUES; последний зависит от определённого адреса-триггера и открытого файла. Привязка ячеек к общей области данных не равна атомарному снимку. В Stage111 используются отдельные [операторские проекции PARAM](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/mvk_compatible/core/original_live_operator_status.py#L69) и [кандидат форматирования](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/mvk_compatible/core/original_get_value_text_30.py#L183).
5. **WriteValues и состояние файла.** Команда UI изменяет намерение записи, тогда как рабочий поток открывает и закрывает файл через стадии. Момент появления активного файлового объекта нельзя подменять моментом нажатия кнопки. У Stage111 это отдельные [ledger](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/mvk_compatible/core/original_live_write_stages.py#L268) и [native receiver](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/tools/research/native_tcp10230_stage108_live_recording_r6_1/source/monitor.go); переходы Qt↔Go изображать как IPC, не как прямой CALL.
6. **Freeze/Stop.** В проанализированной ветви PARAM Freeze подавляет обработку банков **и** соответствующий VALUES-путь. Для рассмотренного пути Stop последовательность `Terminate → WaitFor → Free` доказана локально; это не доказательство отсутствия гонок во всех callback/EOF/других режимах. Stage111 [Stop](https://github.com/shonentez-afk/MVK-Reader-Web/blob/dd020c4a8c1cd9d80440031730b7c4ee28bf8cef/mvk_compatible/desktop/main_window.py#L2913) требует отдельной односеансной проверки.
7. **Виртуальная диспетчеризация.** Неразрешённые VMT/call-site не повышать до прямых рёбер без проверки динамического типа и слота.

## Почему исходные 641 пары не стали 641 доказательством

Исторический Atlas v15 содержит **641 кандидата** WRITE→READ, собранных по 231 полю и 1535 обращениям. Независимая локальная переиндексация v16 с другим классификатором и нормализацией даёт **679 кандидатов по 232 полям / 1538 обращениям**. Эти показатели **не сопоставляются как прирост/потеря**, не объединяются и не подменяют v15. Без исходной таблицы 641 кандидата отсутствует проверяемое соответствие «кандидат v15 → кандидат v16». Точечные 20 цепочек представляют дополнительный доказательный слой, а не выборочную оценку всего исходного списка.

Для любого утверждения о реальной зависимости нужны: `writer`, `reader`, смещение поля, происхождение `receiver`, идентификатор сеанса/эпоха объекта, номер канала, поток, условия ветви, порядок `happens-before`, надёжность алиаса и первичная ссылка. Учитывать `REF`/`ADDRESS` отдельно от WRITE.

## Проверка и ограничения

- Локально успешно проверены SHA источников, 57 адресных опор и структурная целостность HTML/JSON; JavaScript прошёл `node --check`. **Браузерная интерактивная проверка v16 в этой среде не выполнена**; ранее подтверждённые 18 Chromium тестов относились к **v15**, не v16.
- Приватные результаты: `MVKView_Recovery_Atlas_STAGE111_v16_ALIAS_ORDER_PRIVATE.html`, `MVK_ALIAS_V16_AUDIT_RU.md`, `MVK_ALIAS_V16_PRIVATE.json`, `MVK_FIELD_PAIR_REINDEX_V16_PRIVATE.csv`, `build_alias_v16.py`, QA JSON. Передавать их новому чату **приватно**, не коммитить.
- Полная парная original Win32/MVK01 `IP → Измерить → Task2 → RX → GetSignal/GetSpectrum → WriteData/WriteValues → Stop` на одном реальном потоке **не аттестована**. Не посылать приборных команд без согласия оператора.

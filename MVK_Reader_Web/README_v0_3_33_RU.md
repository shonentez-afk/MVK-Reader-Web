# v0.3.33 — безопасный офлайн Signal Bridge

Основа: **оригинальная v0.3.32 NETWORK GUARD**; предыдущие страницы, Collector/SQLite и методы экспорта не заменены. Новый модуль `signal_bridge/` отвечает только за обработку сохранённых пакетов TCP/10230.

## Установка и запуск

Зависимости те же, что у Reader Web v0.3.32 (см. `requirements.txt`), дополнительно SciPy для Signal Bridge. Не нужно устанавливать второй сайт. Запуск сервера — прежним `START_INTEGRATED_WINDOWS.cmd`.

Сначала импортировать PCAPNG, записанный на соответствующем приборе. В CMD в корне проекта:

```cmd
python -m signal_bridge.import_capture "C:\captures\spectr83.pcapng" --device 10.13.42.83 --output signal_data
```

Дополнительные GET API на прежнем сервере:
- `/api/signal/status` — происхождение записи, пропуски и размеры всех восьми буферов;
- `/api/signal/adc/4/waveform?seconds=1&points=2000` — осциллограмма сырых отсчётов;
- `/api/signal/adc/4/spectrum?kind=raw&nperseg=65536&low_hz=1&high_hz=1000` — PSD сырых отсчётов;
- физический спектр: параметр `kind=acceleration|velocity|displacement` требует **проверенный** положительный `gain` в единицах м/с² на единицу сырого отсчёта; *не* использовать коэффициент из другого АЦП.

Контейнерная версия не добавляет эти новые элементы на существующую главную страницу: она **добавляет API** и сохраняет текущий интерфейс без рисковой переделки. Приём с живого устройства и команда запуска потока не реализованы. Поток обрабатывается из архивов. Лимит буфера — последние четыре секунды каждого АЦП (262144 отсчёта). Импорт в `signal_data` через командную строку, без веб-загрузки пути и без команд прибору.

**Проверки:** старый регрессионный набор требует отдельный файл `MVK00000044-ADC1-2026-04-29--17-27-39.bin` для нескольких тестов. Отсутствие файла не относится к Signal Bridge. Сетевой guard v0.3.32 не изменён. Для запуска тестов из корня проекта: `set PYTHONPATH=.;reader_web` и `python -m pytest -q tests` (в Windows разделитель `;`).

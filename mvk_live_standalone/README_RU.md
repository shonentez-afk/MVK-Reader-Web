# MVK Live Standalone — независимый анализатор вибрации МВК01

**Статус:** экспериментальная программа Windows; отдельная ветка
**feature/mvk-live-standalone-20261117**, не затрагивающая основную ветку
и восстановление оригинального MVKView.

## Установка, запуск, приём

Готовый комплект Windows собирается GitHub Actions как
**MVK_Live_Standalone_Windows_Experimental**. Распакуйте ZIP и запустите
MVK_Live.exe. Точно соответствующий Native R6.1 Go EXE и его SHA256
включены в комплект. **Вручную задаётся только IP МВК01.**
При запуске в Windows программа без сетевых запросов определяет
**единственную активную физическую проводную Ethernet-карту**
и автоматически подставляет её локальный IPv4. Имя сетевой карты,
IP и индекс отображаются в главном окне; кнопка
«Обновить Ethernet» повторяет обнаружение. Wi-Fi, VPN и виртуальные
адаптеры не выбираются автоматически. Если проводной Ethernet
не обнаружен, не имеет пригодного IPv4 или на нём несколько адресов,
программа не угадывает адрес: показывает причину и допускает ручной
ввод после проверки конфигурации Windows. Программа не меняет IP,
маску, шлюз или состояние сетевой карты.

Окончательное TCP-подключение по порту 10230 происходит **только**
после нажатия «Подключить и измерять» и отдельного разрешения
оператора. Go Native повторно проверяет, что локальный IPv4
принадлежит активному интерфейсу, и в Windows привязывает сокет
к его индексу через `IP_UNICAST_IF` без молчаливого перехода
на другое сетевое соединение. Никакого SetRate, Flash, записи регистров или
дополнительного TCP/10230 к прибору MVK Live не выполняет.

Go Native владеет единственным соединением и оригинальными RAW/BIN.
GUI читает только выбранный ADC из уже существующего Go-кольца через
ограниченный аутентифицированный IPC на 127.0.0.1. Для ранее разрешённых
сеансов без IPC предусмотрен проверенный ZIP-превью.

Запуск Python из корня репозитория:
- py -3 -m pip install numpy scipy PySide6==6.11.2 pyqtgraph==0.14.0 pytest
- py -3 -m mvk_live_standalone.app
- py -3 -m mvk_live_standalone.app --capture-root C:\path\to\capture_root

## Совместимая сборка Qt

Для Python 3.11 зафиксирована **PySide6 6.11.2**: версия 6.12.0
содержит подтверждённый Qt-for-Python дефект ссылок
PYSIDE-3474 / PYSIDE-3509 (`deallocating None`), вызывающий аварийное
завершение Qt-приложения. Компоненты Windows EXE и Ubuntu CI используют
одну проверяемую версию. Нельзя считать успешным тест, у которого
пройдены проверки, но аварийно завершился процесс.

## FRange — обязательное масштабирование исходных АЦП ровно один раз

По оригинальным приватным исходникам MVKView (IDP, Pascal/DFM, IDR SQLite)
подтверждена цепочка: первая полная конфигурация МВК01 передаёт Float32
\`FRange\` каждого АЦП в \`0x0100 + канал_с_нуля × 0x0100 + 0x0E\`.
Оригинальный \`TMVKThread\` присваивает \`TMvkChannelStorage.FRange\`;
\`TMvkChannelStorage.ProcessBufferChunk\` (\`0x007D2398\`, \`ApplyRange=1\`)
умножает исходные Float32 отсчёты на \`FRange\`.

**В текущем Native R6.1 это уже сделано** в
\`LiveBinSpool.adcFrame\`: \`float32(float64(raw) × float64(gain))\`.
Те же калиброванные байты попадают в проверенные BIN и Go ring/IPC.
**MVK Live никогда не умножает повторно** при отображении сигнала,
FFT, Welch PSD, спектра огибающей, ВС или ВП. При отсутствии начального
коэффициента, нечисловом/нулевом FRange или изменении в ходе записи
приёмник не подменяет коэффициент единицей и не выдаёт такой фрагмент
за подтверждённую калибровку.

Поле \`adc_frange_from_config\` штатного локального Go-статуса
содержит **ровно 8 коэффициентов только после принятой полной
конфигурации**. GUI показывает использованный приборный \`FRange\`
для выбранного АЦП отдельно от 43-полосного \`AUX4700\` и
от производных результатов \`APP_DERIVED\`. Это отображение
коэффициента, а не ещё одна операция умножения.

Контрольный пример из ранее восстановленной оригинальной MVKView:
\`FRange = 0x43FF4853 = 510,5650329589844\`. Сырой отсчёт
\`1,25\` преобразуется Native в \`638,2063\`, и второе применение
\`FRange\` не допускается. Регрессионные тесты проверяют исходный
регистр, откалиброванный файл, байты кольцевого буфера и спектр
с заданной физической амплитудой. Эталонные измерения для этих
**программных тестов формулы** не нужны.

## Полностью без TACH и без эталонных измерений

**Тахометр не подключается, не декодируется и не используется.**
Существующие исходные 10 Go-колец, включая исходные TACH хранилища,
не модифицируются ради этого интерфейса.

Частоту вращения **1×** можно ввести **вручную** или получить
**предложение по спектру виброскорости (ВС)**. Кнопка
«Предложить 1× из ВС» находит низшую заметную гармонику, проверяет
2×–5×, локальный SNR, разрешение FFT и уровень уверенности.
Только отдельная кнопка «Применить 1×» принимает предложение.
При неоднозначных спектрах обороты могут быть определены неверно:
предложение не эквивалентно тахометру.

**Никакой сверки с внешними эталонными измерениями не добавлено.**
Тесты используют лишь самостоятельно сформированные синтетические
сигналы для проверки математических и программных инвариантов.

## Исторические тренды и наложение сохранённых измерений

Добавлены отдельные рабочие вкладки **«Тренды»** и **«Сравнение»**.
Общий набор теперь: «Спектр», «Временной сигнал», «Расчётные
данные», «Тренды», «Сравнение», «Доп. анализ».

В **«Трендах»** непосредственно на вкладке выбирают АЦП 1–8,
источник показателя (приборные 43 третьоктавные СКЗ, 24 позиции
СКЗ/пик/размах или APP_DERIVED из сохранённого АЦП), конкретную
частоту/позицию
и период. Ось X — исходное время приборного AUX4700 либо
сохранённую метку UTC создания NPZ (у новых файлов) либо подтверждённое время импорта старого NPZ; единицы Y не смешиваются. Время сохранения/импорта не объявляется временем исходного сигнала МВК01.
Точка исторического тренда связана с записью в разделе «Сравнение».

В **«Сравнении»** прямо на этой вкладке выбирают АЦП и до **8 записей разных дат этого канала**
и строят их на одном графике: обычные FFT ВУ/ВС/ВП/дБ,
сохранённые осциллограммы, оригинальные третьоктавные
характеристики AUX4700 и 24 исходные позиции СКЗ/Пик/Размах.
Цвет и легенда показывают дату каждого измерения. При разной Fs
для FFT отображается общий физически возможный участок частот
без подмены сетки интерполяцией. Сырые исходные 24 позиции
не получают выдуманной частотной привязки и единиц.

В сравнении отмеченные записи **закрепляются между переключениями UTC-периода**:
можно выбрать старый пакет, затем перейти на другую дату и добавить новый,
даже если между ними больше 500 записей. Закреплённые записи остаются в
таблице и на общем графике при переключении совместимых видов FFT/осциллограмм
или приборных 43/24 позиций. Кнопка «Выбрать 2 последних» относится к
активному фильтру; «Снять выбор» очищает закрепление. Выбор другого АЦП
или переход между приборным AUX4700 и локальным NPZ сбрасывает сравнение,
не смешивая происхождение и единицы.

**Архив постоянный**, не зависит от текущего Go-кольца:
Windows — стандартный каталог «Документы/MVK_Live_Archive»,
в нём `measurements.sqlite` и проверенные по SHA
`windows/*.npz`. Каталог можно заменить ключом
`--archive-root C:\\путь\\к\\каталогу` или переменной
`MVK_LIVE_ARCHIVE_DIR`. При сохранении обычного NPZ он также
индексируется. Есть отдельные кнопки **«Сохранить окно АЦП
в архив»**, **«Добавить NPZ»**, **«Импорт AUX4700»**
из предыдущего каталога сеанса.

Native Go **уже** сохраняет все исходные расчётные кадры
(8 каналов × 115 значений) в `aux4700.jsonl`. Их не нужно
получать новым TCP: импорт выполняется по завершённым строкам
инкрементально с сохранением последней прочитанной позиции.
Оригинальные расчёты не подменяются локальной FFT. Дополнительные
локальные тренды включают амплитуду спектрального максимума ВУ/ВС/ВП
в физических единицах и частоту максимума в Гц, вычисленные из
8192 фактически сохранённых отсчётов; без эталонных измерений.
Сохранённые NPZ можно повторно анализировать без прибора; FFT
строится заново из калиброванного буфера и помечается
**APP_DERIVED**, а не исходным приборным FFT или внешним эталоном.

Обоснование по SKF @ptitude, VibCloud, Dewesoft и
примерам GitHub: [HISTORY_TRENDS_OVERLAY_DESIGN_RU.md](HISTORY_TRENDS_OVERLAY_DESIGN_RU.md).

## Рабочие вкладки — не смешивать временные и спектральные настройки

Интерфейс организован в **шесть верхних вкладок**, по аналогии с
вибрационными анализаторами, а не аудиоанализаторами:

- **«Спектр»**: выбор логарифмического/линейного ВУ/ВС/ВП,
  частотного предела X, физической высоты Y и отдельного спектрального
  фильтра. Спектральные CSV/PNG, курсор, RPM/1× и расширенные
  параметры оставлены здесь.
- **«Временной сигнал»**: собственная осциллограмма исходного
  калиброванного ускорения. Развёртка по X в **10–500 мс / 1–30 с**,
  симметричная ось Y с **Авто** или **±м/с²**;
  **собственные** ФВЧ, ФНЧ, полосовой, режекторы 50/60 Гц и отсутствие
  фильтра по умолчанию. Подписи СКЗ, пик, пик-пик относятся к
  **локально рассчитанному временному окну** (APP_DERIVED), не к
  исходному DSP прибора. Если 262 144 сохранённых GUI отсчётов
  недостаточно для запрошенного окна на текущей Fs, показывается
  **фактически доступная длительность**. Никаких придуманных samples.
- **«Расчётные данные»**: собственный синхронизированный выбор
  АЦП 1–8. Нажатие «Тренд выделенного показателя» открывает
  сразу ту же приборную частоту/позицию или локальную метрику
  в архивной вкладке «Тренды», не заставляя искать показатель
  повторно; 1/1 сводка не выдаётся за приборный тренд.
  Три вложенных вида: 43 исходные 1/3-октавные приборные
  СКЗ с переключением на **сводные 1/1 октавы** (APP_DERIVED,
  RSS трёх исходных значений, не оригинальная FIR-фильтрация);
  исходные 24 позиции СКЗ/пик/размах без придуманных единиц;
  таблица локальных APP_DERIVED с единицами, статистикой
  и отдельно прочитанным **FRange**. Недоступные значения — пропуск,
  не ноль. После остановки последний исходный DSP снимок обозначен
  **НЕ Live**.
- **«Тренды»** и **«Сравнение»**: отдельные архивные рабочие страницы
  со своим АЦП, периодом и выбором исходных приборных/локальных записей.
- **«Доп. анализ»**: семь независимых вложенных страниц:
  **Водопад**, **Тренд СКЗ**, **STFT**, **CWT Morlet**,
  **Кепстр**, **Подшипники**, **Редукторы**.
  Общий АЦП выбирается непосредственно в этом разделе.
  Водопад/СКЗ имеют отдельные ограничения истории. STFT — размер
  сегмента; CWT — число масштабов и нижнюю частоту; кепстр — предел
  кэфренции. Подшипники — геометрию, 1× и полосу огибающей;
  редукторы — 1×, число зубьев и таблицу рассчитанных частот GMF.
  Переключение метода не уничтожает его график. Изменение АЦП
  сбрасывает короткие результаты прежнего канала, не затрагивая архив.

Общие элементы в верхней части: единственный физический Ethernet
с автоматически найденным IPv4, IP прибора, кнопки измерения/остановки,
статус Native; общие заморозка и просмотр истории и сохранение
снимка NPZ. Код переключения страниц не открывает новый TCP.

Сравнение интерфейсов и причины решений:
[WORKSPACE_UX_AUDIT_RU.md](WORKSPACE_UX_AUDIT_RU.md).

## Главный экран: четыре вида, отдельный фильтр и правильные оси

Главный экран построен в привычном операторском порядке:
**АЦП → Вид спектра → Фильтр → Предел X → Масштаб Y**.
Один выбор вида заменяет три независимых переключателя:

1. **Логарифмическая (ВУ, дБ)** — спектр виброускорения; значения Y
   в дБ относительно указанной опоры (ISO 1683, 10⁻⁶ м/с²).
2. **Линейный ВУ** — Y = м/с² СКЗ спектральной линии.
3. **Линейный ВС** — Y = мм/с СКЗ спектральной линии.
4. **Линейный ВП** — Y = мкм СКЗ спектральной линии.

Частоты X всегда в **физических Гц** (ось X линейная).
Выбор X: **50, 100, 200, 500, 1000, 2000, 4000, 8000,
10000, 12800, 16000, 25600 Гц**. Реальный предел ограничен
частотой Найквиста выбранного АЦП (Fs/2). При Fs=8192 Гц
даже выбор X=25600 означает просмотр только **до 4096 Гц**,
с явным сообщением. Выбор X не изменяет Fs, NFFT и прибор.

Масштаб Y: **Авто** или конкретная высота оси в соответствующих
**дБ, м/с², мм/с, мкм**. Линейные спектры начинаются с Y=0,
для дБ ширина окна отсчитывается от вычисленного максимума.
Логарифмический режим означает **уже рассчитанные децибелы**,
без второй логарифмической трансформации оси Y.

Фильтр по умолчанию **«Без фильтра»**. Доступны ФВЧ, ФНЧ,
полосовой фильтр, режекторы 50/60 Гц и **выбираемые готовые полосы
1/1, 1/3 и 2 октавы**. При выборе семьи фильтра непосредственно
появляется список номинальных центральных частот; границы рассчитываются
автоматически, оператор их не вводит. Спектр и осциллограмма имеют
**раздельные списки и настройки**. Это локальные Butterworth-полосы,
**не** доказанная оригинальная фильтрация МВК01/IEC-класс.
Дополнительно восстановлен **оригинальный каталог названий 32 пунктов
меню MVKView** по `mvkview.idp`, Pascal/DFM и `mvk_idr(1).sqlite`:
«Без фильтра», 19 третьоктавных вариантов (400 Гц–25 кГц),
6 однооктавных (500 Гц–16 кГц), 6 двухоктавных (400 Гц–13 кГц).
Пункт «Как в MVKView · оригинальное меню 32 полос» открывает именно
эти варианты без ручного ввода границ. **Подтверждены имена пунктов,
но не оригинальные коэффициенты или характеристики заводского FIR**:
при выборе полоса рассчитывается локально с соответствующей пометкой.
Сама октавная полоса и многополосный октавный **анализ** — разные
операции: исходные 43 расчётные полосы AUX4700 сохраняются отдельно. Кнопка **«Настроить
фильтр…»** показывает лишь необходимые границы (Гц) и
проверяет их относительно реальной частоты Найквиста.
Фильтрация выполняется локально до FFT; исходный AUX4700
и FRange не изменяются. У обычного FFT без фильтра удаляется
только DC, но нет скрытого ФВЧ 2 Гц. Защита от дрейфа 2 Гц
в дополнительных методах широкополосного интегрирования
отдельна от обычного FFT.

Кнопка **«Дополнительные расчёты и настройки»** открывает
FFT N, опору дБ, сглаживание, PSD/ASD, 1/3 октавы,
спектр огибающей, диагностику подшипников и другие методы.
**Огибающая не выбрана по умолчанию**: её фильтр появляется
только при явном выборе специального режима. Технические
поля Native EXE и SHA256 также перенесены туда.

## Режимы спектрального анализа

| Режим | Линейная ось Y | Логарифмическая ось Y |
| --- | --- | --- |
| FFT виброускорение ВУ | м/с² СКЗ спектральной линии | дБ отн. опоры м/с² |
| FFT виброскорость ВС | мм/с СКЗ спектральной линии | дБ отн. опоры мм/с |
| FFT виброперемещение ВП | мкм СКЗ спектральной линии | дБ отн. опоры мкм |
| PSD Welch ВУ/ВС/ВП | (единица)²/Гц | 10 log10(PSD / ref²) |
| ASD Welch ВУ/ВС/ВП | (единица)/√Гц | 20 log10(ASD / ref) |
| 1/3-октавы | физическая СКЗ каждой полосы | 20 log10(СКЗ / ref) |
| Огибающая Hilbert | м/с² СКЗ спектральной линии | 20 log10(СКЗ / ref) |

Физические опоры дБ: 10⁻⁶ м/с², 10⁻⁶ мм/с, 10⁻⁶ мкм
(соглашение ISO 1683) либо 1 соответствующая физическая единица.
Они всегда явно указываются. Это не приборный дБ и не dBFS;
вторая логарифмическая трансформация Y не выполняется.

ВУ → ВС/ВП по 1/(2πf), 1/(2πf)²; DC исключается, для
широкополосного интегрирования используется ограничение HP ≥2 Гц.
PSD интегрируется по частоте для реальной широкополосной СКЗ,
а не для пика отдельной линии. Butterworth SOS и выбираемый
Notch 50/60 Гц работают **локально**; notch по умолчанию отключён,
чтобы не скрыть механическую гармонику. Доступны готовые полосы
и собственные частотные границы с явной проверкой Nyquist.

## Диагностика подшипников и редукторов

Оператор задаёт 1× и геометрию подшипника. Рассчитываются
теоретические **BPFO, BPFI, BSF, FTF** с их гармониками;
реальные пики огибающей сопоставляются только с локальным
фоном текущего сигнала (SNR в дБ), **не с эталоном**.
Превышение порога SNR — не самостоятельный диагноз.

Полоса демодуляции — ручная или **автопоиск по ограниченному
двоичному фильтробанку с куртозисом огибающей**.
Это *kurtogram-like* приближение, не полный Fast Kurtogram Антони;
уровень уверенности и выбранные границы показываются.

По заданному числу зубьев редуктора формируются маркеры
**GMF, 2–3 GMF, GMF±1×…±3×**. Реальные обороты по
датчику TACH никогда не утверждаются.

Справочная историческая диаграмма ISO 10816-3 запускается
**только по инициативе оператора**, требует известного класса
машины, RPM 120–15000 и полного диапазона ВС 10–1000 Гц.
Это не оценка соответствия ISO 20816, не диагноз,
не внешнее эталонное измерение. Класс оборудования не угадывается.

## Графики, история, сохранение

- Временной сигнал ВУ: диапазон развёртки 0,1–30 с, пиково-
  сохраняющая децимация без интерполяции.
- **Заморозить графики** — останавливает только отображение.
  **Приём и RAW-запись продолжаются**. Доступен просмотр
  ранее накопленных отсчётов со сдвигом по времени.
- Спектры с линейным или логарифмическим X,
  дБ или физической линейной Y, курсор, ручные пределы осей.
- Водопад последовательных подтверждённых FFT/PSD;
  тренд СКЗ ВУ по новым порциям данных.
- STFT (частота–время), CWT Morlet (**качественная**),
  реальный кепстр (ось кэфренции, секунды). Тяжёлые
  представления запускаются отдельной кнопкой.
- Признаки: RMS, peak, peak-to-peak, crest, Pearson kurtosis,
  skewness, impulse, shape, clearance; широкополосная ВС СКЗ.
- **Оригинальные AUX4700** полностью отображаются для каждого АЦП
  во вкладке «Оригинальный DSP»: отдельно **43 третьоктавных
  значения СКЗ виброускорения** с известными центрами 0,63–10000 Гц,
  а также **24 исходные позиции × 3 значения** — СКЗ (`band_rms`),
  пик (`band_peak_equiv`), размах/пик-пик
  (`band_span_equiv`). То есть декодер Go передаёт **115 значений
  на канал**. Для 24 позиций исходники пока не подтверждают однозначные
  частоты, единицы и точную физическую трактовку peak/span, поэтому
  интерфейс показывает номера позиций и значения *без выдуманных частот
  и пересчётов*. Состояние «не готово»/NaN отличается от нуля.
  Регистровые смещения в исходном AUX4700 соответственно:
  `base+0x02`, `base+0x60`, `base+0xA0`, `base+0xE0`.
  Оригинальные значения **никогда не подменяются** результатами
  локального расчёта APP_DERIVED.
- «Сохранить окно» — NPZ, проверка локального SHA256;
  «Открыть запись» — OFFLINE анализ без соединения с МВК01;
  «Экспорт спектра» — CSV с физической единицей/шкалой;
  «Сохранить график» — PNG.
  NPZ — не криптографическое доказательство подлинности
  оригинального приёма. IP, токены и регистры не экспортируются.

## Ограничения и приёмка

Автоматические тесты выполняются на синтетических сигналах и
без физического МВК01. Производительность IPC на конкретном ПК,
точность обнаружения 1×, длительная запись, ошибки
сети и рабочие режимы прибора требуют эксплуатационной
проверки **без сверки с отсутствующими эталонными измерениями**.
Успешный GitHub CI и Windows EXE не означают промышленную
метрологическую аттестацию.

# MVK Live Standalone · независимый анализатор

Отдельная экспериментальная программа для Windows, отделённая от оригинального
восстановления MVKView. База: исходный Native R6.1 / Stage111Z31FI.
**Ветка** `feature/mvk-live-standalone-20261117`. Ни `main`, ни
`research/stage111-mvkview-desktop-20261029` не изменяются.

## Запуск из исходников

Установить Python 3.11/3.12, `numpy`, `scipy`, `PySide6`, `pyqtgraph`.
Из корня репозитория:

```cmd
py -3 -m pip install numpy scipy PySide6 pyqtgraph pytest
py -3 -m mvk_live_standalone.app
```

Приложение может **только наблюдать** за уже разрешённым сеансом Native:

```cmd
py -3 -m mvk_live_standalone.app --capture-root C:\\path\\to\\mvk_live_or_mvk_r6_session_root
```

Для непосредственного подключения нужны точно выбранные IPv4 прибора и
Ethernet компьютера, путь к собранному `MVK_Native_R6_1_Stage108_Windows_x64.exe`
и отдельный файл с ожидаемым SHA256. Затем оператор должен вручную
подтвердить каждое подключение. **Никакого автоматического TCP при запуске**.
Native запускается отдельным процессом, выполняет `TCP Connect → Read` без
`SetRate` / `Flash` / Modbus write; «Остановить» создаёт штатный локальный
stop-файл, а не убивает процесс. Сохраняются штатные RAW и экспорт R6.1.

Работает с текущим проверенным `MVK_NATIVE_LIVE_STATUS.json` и
`MVK_NATIVE_LIVE_PREVIEW.zip`: используется валидация Python Core из
`mvk_compatible` (SHA256 каждого ADC, timestamp, session ID, sample indices,
source domain, calibrated gain). **Никакой второй TCP-сокет не создаётся.**

## Показания и единицы

| Вид | Расчётная Y | Единица (СКЗ амплитуда на спектральную линию) |
| --- | --- | --- |
| ВУ: спектр виброускорения | a(f) | м/с² |
| ВС: спектр виброскорости | a(f)/(2πf)×1000 | мм/с |
| ВП: спектр виброперемещения | a(f)/(2πf)²×10⁶ | мкм |

При `f=0` интегрирование **не определено**: DC исключается из ВС/ВП.
В `log Y` физические единицы не меняются. При выборе `дБ` используется
**явный опорный уровень 1 единица выбранного типа** (1 м/с², 1 мм/с,
1 мкм RMS), не dBFS и не приборные dB. Децибелы — отдельное представление,
не физическая шкала. Рядом указан FFT `N`, `Δf=Fs/N`, пики и источник.

`Hann` + coherent-gain correction выдаёт one-sided **RMS amplitude per
FFT bin** для тонального гармонического сигнала, **не PSD/ASD и не
широкополосное RMS**. Для широкополосной диагностики следует реализовать
дополнительно Welch PSD и band integration с правильной ENBW.

Все полосовые пресеты — **локальные цифровые Butterworth SOS фильтры
нулевой фазы, применяемые перед FFT к временному сигналу**. Их результаты
`APP_DERIVED`, **не штатные фильтры прибора**. Нет возможности утверждать,
что `10–3000 Hz` локального спектра побитово совпадает с исходным
проприетарным DSP. Оригинальные значения AUX4700 имеют приоритет как
`MVK_DSP`; в этой первой версии вывод AUX4700 не интегрирован.

## Дальнейшее развитие

Текущий интерфейс принимает **атомарные проверенные ZIP превью R6.1
примерно раз в секунду** и пересчитывает FFT на отдельном потоке, не
мешая записи RAW. Для более плавного обновления графиков 20–30 fps
нужен локальный IPC с безопасным on-demand считыванием участков уже
существующего кольца `2^21` (8 ADC + 2 TACH) и без копирования 68 МиБ.
Текущий MVP не обеспечивает такую частоту отрисовки — это отдельная
задача производительности и тестирования.

Требуются аппаратные проверки на нескольких МВК01, длительный непрерывный
захват, FFT/фильтры с эталонным калиброванным источником, работа с
неисправными каналами, корректное поведение при обрыве/смене Fs, проверка
тахометра с импульсным датчиком и измерение задержки.
Без этих проверок приложение нельзя считать промышленно аттестованным.

## Независимые проекты и идеи

- Friture: <https://github.com/tlecomte/friture> — компоновка живого спектра,
  waterfall и разных временных представлений.
- QSpectrumAnalyzer: <https://github.com/xmikos/qspectrumanalyzer> —
  пользовательское управление спектром и масштабами.
- pyqtgraph: <https://github.com/pyqtgraph/pyqtgraph> —
  реактивная отрисовка больших графиков Qt.
- SciPy: <https://github.com/scipy/scipy> —
  SOS Butterworth, Hann/FFT, цифровая обработка.

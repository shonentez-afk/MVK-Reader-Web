# MVK Live — каталог методов автоматического анализа и диагностики (D01–D44)

**18.11.2026 | ветка `feature/mvk-live-standalone-20261117` | источник для единой матрицы.** В предыдущей матрице были 82 позиции **обработки сигнала** (L01–L19, W01–W43, A01–A20), но отдельный систематический список автоматической диагностики отсутствовал. **Теперь добавлен блок D01–D44 = 44 самостоятельные диагностические функции**. Вместе **126 позиций**. Часть D пересекается с W32/A20 как технологический компонент — это **функциональные требования к единому диагносту**, а не 44 новых независимых научных алгоритма.

**Принцип:** MVK Live — **собственный анализатор на основе реальных физических отсчётов МВК01**, не копия интерфейса MVKView. Новый диагностический слой всегда `APP_DERIVED`, никогда не выдавать его за исходный AUX4700. Сетевой приём Native Go/TCP/10230, ADC/Fs и оригинальный FRange не менять. Нет реального FFT/NPZ → НЕ формировать диагностические пики из OEM скаляров.

## 1. Что считать автоматической диагностикой

- **Обнаружение**: численно извлечённая амплитуда, частота, sideband, пик, удар, аномальное изменение в архиве.
- **Сопоставление**: реально обнаруженные *независимые пики* ↔ расчётные семейства и допуски, с конфликтами и известной неопределённостью RPM.
- **Гипотеза**: несколько физически согласованных свидетельств и корректный контекст измерения; вывод «возможные признаки» + доказательства. Ни одного процента вероятности дефекта из ненастроенных эвристик.
- **Нельзя выдавать за диагноз**: одну линию 1×/2×/GMF/BPF, высокий Kurtogram score, суммарный RMS, один удар, отсутствие линии при слишком коротком T, чужой NPZ без source/mount/RPM.
- **Состояния анализа**: `OBSERVED`, `NOT_OBSERVED_IN_VALID_WINDOW`, `AMBIGUOUS`, `INSUFFICIENT_DATA`, `NOT_EVALUATED`, `OUT_OF_DOMAIN`. Категория `NORMAL` возможна только в отношении проверенных критериев, не как утверждение «машина исправна».
- **LIVE**: лёгкое предупреждение по верифицированному потоку и заранее обученным значениям; тяжёлые циклические методы и ML — после записи или по замороженному окну без новых TCP. **АЦП сам по себе не гарантирует одну и ту же физическую точку.**

## 4. Обязательный экран «Автоматический анализ»

**Главная страница:** `Автодиагностика` (добавить в рабочее пространство на уровне анализа окна и архива), общий источник: АЦП, session, valid NPZ/SHA, Fs, physical T, метка времени сохранения или приобретения, quality status, RPM provenance. Сверху выбран режим `[Одно окно] [Серия архива]`, фильтры `[Подшипники] [Редукторы] [Валы/опоры] [Вентиляторы] [Насосы] [Электродвигатели] [Аномалии]`.

**Левая панель настроек:** чекбоксы диагностических семейств, реальные RPM/источник, геометрия без карточек оборудования, Hn/sideband count, SNR/peak prominence/tolerance, фильтр/огибающая/FFT (строго читаемый provenance), quality warnings, режим нагрузки. Для каждой гипотезы показывать скрытые/доступные параметры и почему она недоступна.

**Центральная область:** FFT/огибающая/водопад с отдельными predicted (пунктир) и measured peak (точка) метками, бэнд допусков, collision flags и подсветкой текущего `peak_id`.

**Правая панель:** `Гипотеза`, `Найденные Hn`, `Парные sidebands`, `Локальный SNR`, `Источник RPM`, `Качество`, `Ограничения`, `График первичных фактов`. Кнопки: `Проверить на другом окне`, `Показать исходное`, `Добавить к истории`, `Экспорт доказательств`. Нет кнопки «поломка подтверждена» без независимого подтверждения.

**Кнопка** `[НАЙТИ ПРИЗНАКИ]` не запускает новый TCP; расчёт на snapshot в background worker c отменой по изменению ADC/сеанса; source SHA и code_version в отчёте. Архивные методы используют только совместимые записи, а не выдуманную ось acquisition_utc.

## 5. Реальная реализация и тестовый план

- Уже существуют в MVK: FFT/Hilbert/Fast Kurtogram/часть ручных гармоник/GMF, quick RMS, archive trends/overlay, `envelope_fault_lines` с 1-пиковым `noteworthy`. **Ни один из D05–D44 не считать готовой полной автономной диагностикой**.
- **D1:** D01–D09, D12–D13, D31, D41–D42 — independent peaks, collision ledger, многогармонические проверки, Qt экран, verified source, negative tests.
- **D2:** D10, D14, D33–D34, D38–D40 — паспорт, сопоставимость, история, baseline и устойчивые состояния.
- **D3:** D11 — сравнение селекторов полос без подмены KPI диагностическими «скорингами».
- **D4:** D15–D30, D32, D35–D37 и D43–D44 — расширенные семейства по мере подтверждения физических входов и данных. Где нужна фаза/RPM(t)/supply/slip или обучение — показывать `NOT_EVALUATED` или R&D.
- **Приёмка:** повторяемые synthetic tests, CWRU/Paderborn с разделением по физическим экземплярам, проверка ложных alarm на white/impulsive noise и EMI, реальный прибор отдельно; GitHub Actions Windows/Qt/EXE, 150% DPI, no added socket, no synthesized proof of fault.

## 6. Связи с исходными 82 методами

Новый D-блок не заменяет ранее описанные W32/A20: `W32 = окно поиска`, `A20 = история/ретроспективный поиск`, `D01–D44 = конкретные проверяемые алгоритмы и страницы, которые обслуживают эти окна`. Повторяющиеся Hn/Sideband признаки — это **общий DSP**, не повторная реализация независимых графиков. Пример связи: `W02/W03 → D02/D03/D04 → D05..D09 → A08/A19/A20`; `W09/W27 → D12..D14`; `A01/A05/A06 → D33/D34`.

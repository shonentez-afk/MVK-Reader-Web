# MVK Live Standalone — структура главного окна и контракт открытия остальных окон (UX/Qt v1)

**18.11.2026 · Ветка:** `feature/mvk-live-standalone-20261117` · **Статус:** утверждаемая архитектура, не реализованный Qt-код. Цель — свой анализатор по реальным данным МВК01, без копирования MVKView и без второго TCP-приёмника.

**Связанные точные каталоги:** [главный экран v3 / 8 меню / 163 действия](MAIN_SCREEN_UX_TOP_MENUS_DETAILED_20261118_RU.md), [43 отдельных окна W01–W43](INDEPENDENT_ANALYSIS_WINDOWS_W01_W43_DESIGN_RU.md), [реестр окон W01–W43](METHOD_WINDOWS_W01_W43_20261118_RU.csv), [126 методов/диагностических требований](UNIFIED_IMPLEMENTATION_MATRIX_20261118_RU.csv), [план LIVE → запись → архив](IMPLEMENTATION_PHASES_LIVE_RECORDING_OFFLINE_ARCHIVE_TOP_MENU_RU.md), [машинный контракт маршрутизации](WINDOW_ROUTING_CONTRACT_V1_20261118_RU.json).

## 1. Главное решение: «один пульт + независимые окна»

**Главное окно `LiveWindow` существует одно** и отвечает за приём, измерение, один глобальный АЦП и четыре основные LIVE-страницы:
**Обзор · Спектр · Временной сигнал · Расчётные данные.**

**Дополнительные методы W01–W43 — отдельные немодальные окна, каждое со своими графиками и параметрами**; они не находятся внутри общей вкладки и могут работать одновременно. Всего **43 типа окон**, но не 43 окна, создаваемых при запуске. W32 — окно общего поиска признаков. Оставшиеся диагностические D01–D44 — преимущественно внутренние алгоритмы и доказательства, объединённые в самостоятельные окна семейств, а не 44 пустых окна.

**Архив** открывает собственные окна каталога сеансов, трендов, наложения спектров, исторического водопада и проверки записей. **Вид → Открытые окна анализа…** — отдельный список всех открытых окон со значком метода, АЦП, источником, режимом вычисления и кнопкой «Перейти». **Настройки / выбор источника / подтверждения** — диалоги, не постоянные вкладки главного окна.

Схема **не показывает вымышленные спектры**: пока нет подтверждённых отсчётов, оба графика пустые, числа «—», QC «не оценено». Метрики из AUX4700 на отдельной вкладке «Расчётные данные» и не выводятся как результат FFT.

| Зона | Элементы | Правило |
|---|---|---|
| **A. Верхнее меню** | Файл, Измерение, Анализ, Диагностика, Архив, Вид, Настройки, Справка | Qt `QMenuBar`, маршрут на существующий `QAction` либо менеджер окон; не 43 вкладки |
| **B. Панель управления измерением** | имя профиля, Измерить, Стоп, Freeze, Сохранить окно, **один АЦП 1–8**, статус приёма/RAW; компактный счётчик открытых окон | IP/local IPv4/Native EXE SHA редактируются только в настройках; смена профиля ≠ TCP Connect |
| **C. Четыре вкладки** | Обзор, Спектр, Временной сигнал, Расчётные данные | никаких «История» и «Доп. анализ» в этом ряду |
| **D. Рабочие графики** | Обзор: FFT над осциллограммой, 4 основных показателя; Спектр и Время: подробный график | один источник LIVE/ADC; графики внутри каждой страницы свои объекты Qt и один общий результат расчёта, не физическое перемещение одного `PlotWidget` |
| **E. Контекстный инспектор справа** | настройки только выбранного графика; для FFT — ВУ/ВС/ВП, FFT/PSD/ASD, полоса/фильтр, NFFT, курсоры; для времени — T, фильтр, A/B, масштаб | `QDockWidget` с разворачиванием и скрытием; не настройки W01–W43 и не геометрия редуктора на главной |
| **F. Строка состояния** | Ethernet, Native phase, RAW и свободный диск, источник Fs/ADC/RxPos, сообщения, QualityGate | отдельный `QStatusBar`, без многострочного технического лога поверх графиков |

При 1920×1080 обе диаграммы доступны одновременно, правый инспектор обычно 270–330 логических px. При 1280×720 и DPI 150% инспектор может скрываться без удаления настроек; графикам отдаём приоритет и используем вертикальный `QSplitter`. Пропорции и положение сохраняем через `QSettings` с проверкой геометрии текущих мониторов.

| Главная вкладка | Показ/настройки | Переходы в самостоятельные окна |
|---|---|---|

## 5. Главное правило: у каждого окна свой настоящий источник

### 5.1. Три типа привязки

1. **Главное окно**: использует глобальный `selected_live_adc`, подписанный Native session/source; смена АЦП меняет обе LIVE-диаграммы и расчётные приборные таблицы. Прибор продолжает писать **все фактически поступающие каналы**, как и раньше.
2. **Окно LIVE-инструмента** (оперативный водопад L10, короткий RMS-тренд L11): по умолчанию **следует глобальному selected_live_adc** без своего селектора; при смене АЦП сбрасывает rolling-историю и показывает новый source. Заморозка отдельного окна переводит его в pinned snapshot и прекращает auto-follow; это не STOP Native.
3. **Окно метода W01–W43 / диагностики / архивного сравнения**: **закрепляет конкретный источник при открытии**, не зависит от смены АЦП/Freeze/вкладок главного окна. В заголовке отображает метод, номер АЦП, источник/сессию, Fs, N/T, состояние качества. Кнопка «Выбрать другое окно/запись…» переводит его на другой источник **только по явному согласию**, с предупреждением о несохранённых результатах. Это не второй LIVE-селектор АЦП.

`AnalysisSource` — immutable-контракт: `source_kind`, `session_id`, `adc`, `sample_start/end` или manifest-range, `Fs`, `N/T`, `data_unit`, `sha256` и качество origin/time (не выдумывать UTC). Дополнительный `settings_hash` и `algorithm_version` принадлежат расчёту. Для short-rings источник — **копия реальных отсчётов**, для NPZ — проверенный отдельный файл, для длинной записи — **только verified BIN после EXPORTED**, с read-only range. `AUX4700` — отдельный приборный источник скаляров; FFT/Hilbert не строить из 43/24×3 чисел.

### 5.2. Что произойдёт по клику (четыре обязательных сценария)

**A. LIVE → W03 Fast Kurtogram**
1. Оператор выбрал АЦП 1 и «Анализ → Fast Kurtogram».
2. `SourceResolver` фиксирует реальное окно отсчётов из проверенного Native ring/Freeze, Fs/N и его физический origin; если отсчётов мало — показывает диалог «Нужен фрагмент/NPZ», без выдуманных графиков.
3. `AnalysisWindowManager` ищет открытое W03 **с тем же source fingerprint**. Если есть — поднимает его; если нет — создаёт одно отдельное W03.
4. Оператор рассчитывает кюртограмму/выбирает полосу, параметры живут в этом окне. «Полоса → огибающая» передает **тот же источник и выбранную полосу** в самостоятельное W02.
5. Если на главном экране выбрать АЦП 3 или остановить прибор, W03 и W02 продолжают показывать **закреплённый АЦП 1**, не запускают дополнительный TCP и не меняют друг другу настройки.

**B. Архив → открытие STFT**
1. В «Архив → Сеансы» выбрать NPZ или VERIFIED BIN range, АЦП и реальный участок.
2. «Открыть в анализе → STFT (W05)» фиксирует отдельный source fingerprint; открывает W05 с полноценной картой STFT, срезами и параметрами в собственной панели.
3. Если одновременно идёт LIVE, оно **не останавливается**, рабочий `_gui_ring` не очищается. Это требует нового функции открытия независимого архивного источника; текущий `_open_snapshot()` сознательно запрещает подменять LIVE ring во время Native.
4. Кнопка «Вернуться к измерению» активирует главное окно; W05 остаётся доступно через список окон.

**C. Диагностика → проверка доказательств**
1. W32 «Поиск признаков» работает по закреплённому источнику; подтягивает независимые пики, допуски и геометрию только при наличии.
2. По клику на кандидат BPFO/BPFI открыть **W08 или W02** с тем же source и указанным Hn/пиком/полосой, не переключая главный FFT. У результата есть source SHA и точные вычислительные параметры.
3. При неизвестном RPM/недостаточной длительности показывать «НЕ ОЦЕНЕНО», а не «здоров/неисправен».

**D. Несколько окон и закрытие**
1. Если W05 и W03 уже открыты на разных источниках — оба самостоятельные, можно расположить рядом на нескольких мониторах.
2. Повторный вызов W03 по *той же* записи поднимает существующее; вызов по новой записи открывает другой экземпляр W03. Есть явная команда «Открыть второй экземпляр» для сравнения.
3. Закрытие W03 **не закрывает главное окно**, не отправляет STOP и не удаляет исходный NPZ/BIN. При несохранённом анализе спросить «Сохранить результаты / Закрыть без результатов / Отмена».
4. Закрытие главного окна при работающем Native остаётся запрещено до штатного STOP и завершения финализации. После этого закрыть дочерние окна/воркеры корректно, сохранив их настройки/геометрию.

## 6. Жизненный цикл окон, размер и память

| Операция | Политика |
|---|---|
| Первое открытие метода | создать Qt top-level `QMainWindow` (немодальное) с собственными `PlotWidget`, inspector и `QStatusBar`; размер как сохранённый или разумный по текущему экрану |
| Повторный вызов того же метода/источника | восстановить, `raise_()`, `activateWindow()`; **не стирать существующий расчёт** |
| Новый источник того же метода | новый экземпляр с отдельным result/settings hash; существующий анализ не заменять молча |
| Переключение главного АЦП | только главные страницы/следящие LIVE tools; **открытые W/диагностика/архив не трогать** |
| Freeze главного окна | не прекращает Native RAW; метод W продолжает работать по уже сделанной копии |
| Завершение Native | RAW финализируется независимо; открытые окна W остаются доступны по собственной копии/NPZ/verified BIN |
| Тяжёлый расчёт | отдельный bounded worker (общий scheduler), отмена при смене input/settings **этого окна**, source hash/job generation; интерфейс и кнопка Stop Native не блокируются |
| Скрытое/свёрнутое окно | не перерисовывать периодически; persistent расчёт остаётся, новые дорогостоящие job не запускаются сами |
| Сохранение анализа | `analysis_run`: исходный SHA, ADC/range/Fs, параметры, версия алгоритма и QC, не менять NPZ V1 |
| Повторный запуск приложения | восстанавливать только размер/расположение/предпочтения/список **ранее открытых сохранённых** методов по желанию; не восстанавливать «live» с якобы активным TCP |
| Несуществующий монитор | ограничить геометрию доступными desktop screens; окно должно остаться видимым после отключения внешнего монитора |
| Горячие клавиши | `Ctrl+S` в главном сохраняет окно, в активном анализе — **его** результат; `F5` только в главном окне и через подтверждение TCP. `Ctrl+W` закрывает только активное окно (главное проверяет Native). Использовать `Qt.WindowShortcut` вместо опасного глобального повторного запуска |

## 8. Правила для неполных и исследовательских методов

43 Window ID зарезервированы на все W, но активными становятся только после реальной реализации. Если W19 (LMS), W20 (FRF), W31 (TSA), W40 (order) не имеют опорного синхронного канала/RPM(t), показать в каталоге **«Нужны дополнительные данные»**, а не пустые графики. Равно для W35–W43 (R&D) — карточка метода/ссылка на описание, без кнопки «Рассчитать» до тестов. Любое окно, вычисляющее физические признаки, должно различать `SOURCE_GAP`, `INSUFFICIENT_N`, `NOT_EVALUATED` и реальные нули.

## 9. Приёмка пользовательских сценариев

1. На старте видны только четыре главные вкладки; восемь меню доступны; IP/local Ethernet/SHA не занимают главное поле; глобальный ADC только один.
2. LIVE 8 ADC: при переключении общий FFT и осциллограмма обновляются согласованно, AUX не смешивается с APP_DERIVED. Native продолжает сохранять все реально пришедшие каналы.
3. W03/W02/W05 одновременно открыты по разным закреплённым источникам, без смены их данных при выборе нового АЦП на главной панели.
4. STFT из архива NPZ можно открыть во время текущей Native-записи без вызова `_open_snapshot` и без удаления/замены `_gui_ring`.
5. W03 «полоса → W02» передаёт сохранённый source+band, новый канал не подключает, проверяемый source_id остаётся тем же.
6. Повторный вызов того же method_id+source_uid поднимает окно, а новый источник даёт отдельный экземпляр; каталог «Открытые окна» точно отображает оба.
7. Недоступный R&D/FRF/TSA не превращается в пустой работающий график и не создаёт синтетические измерения.
8. `Ctrl+S` в ребёнке не вызывает `_archive_capture_window` главного; `F5` в ребёнке не инициирует TCP; Escape закрывает только диалог.
9. Закрытие дополнительного окна не останавливает RAW; закрытие главного при активном Native блокируется; после STOP cleanup корректен.
10. 1280×720, 1920×1080, Windows DPI 100/150%, два монитора/отключение внешнего экрана, переполнение подсказок и шрифтов, не создаются «невидимые» окна.
11. Оперативный водопад и короткий тренд — **LIVE tools** без отдельного выбора ADC, в отличие от pinned snapshot W.
12. Архивная и диагностическая серия на разных сохранённых точках не меняет глобальный Live АЦП, source saved_utc не выдаётся за acquired_utc.

**Начальный интеграционный пакет:** единый главный shell + маршрутизация окон + перенос восьми существующих внутренних прототипов (водопад, короткий тренд, кюртограмма, STFT, CWT, кепстр, подшипники, редукторы). Отдельно затем реализовывать новые W/D методы по их физической готовности. **Здесь пока только проект, реального запуска Windows/Qt и изменений `app.py` нет.**

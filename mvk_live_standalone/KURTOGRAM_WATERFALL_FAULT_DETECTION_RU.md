# MVK Live — кюртограмма, водопад и объяснимый поиск признаков дефектов

**Исследование от 18 ноября 2026.** Ветка: `feature/mvk-live-standalone-20261117`.
**Статус:** принято как UX/DSP-проектное решение, **не заявление о готовой реализации**. Данный коммит затрагивает **только документацию**. Карточки агрегатов, подшипников и редукторов не нужны и НЕ входят в план.

## 1. Точное состояние MVK Live — проверено по исходникам

- **Водопад уже есть**: `app.py` создаёт отдельную страницу `waterfall_page`, `waterfall_img` и выбор количества кадров 20/50/120/240. `_update_waterfall` добавляет *новый* FFT/Welch/ASD кадр только при новом RxPos, а не при повторной отрисовке. **Ограничение:** по Y сейчас *номер полученного кадра*, не настоящая метка времени; уровни заданы статически, нет штатной шкалы цвета, выделения момента, выгрузки архивных спектров, объединённого просмотра сохранённых дат. Статус «готов как полноценный исторический водопад» **неподтверждён**.
- **Реальная Fast Kurtogram добавлена после первоначального исследования**:
  `_pysdkit_kurtogram.py` содержит исходную численную реализацию PySDKit
  с сохранением лицензии MIT (удалена только функция Matplotlib-графика),
  `kurtogram.py` — проверяющий адаптер реальных АЦП; отдельная вкладка
  `Кюртограмма` показывает карту, позволяет выбрать клетку/максимум и
  передать полосу в уже существующую локальную Hilbert-огибающую.
  Метод PySDKit **не подменяет** оригинальные аппаратные DSP-карты.
- **Автовыбор полосы по импульсности уже есть**: `advanced.py::select_envelope_band()`, `app.py` предлагает «Авто по импульсности (картограмма)». Это ограниченный двоичный банк полос с `Butterworth(4) + Hilbert + Pearson kurtosis`, который возвращает `DemodulationBand(low, high, score, tested)`, но **не** хранит/рисует двумерную карту результатов. Авторский комментарий в коде честно помечает `KURTOGRAM_LIKE...`, не настоящий Fast Kurtogram. Полноценной вкладки **«Кюртограмма» пока нет**.
- **Огибающая и начальный поиск линий подшипника есть**: `vibration.py` и `advanced.py::envelope_fault_lines()` ищут линии BPFO/BPFI/BSF/FTF рядом с 1× из введённых параметров, сравнивают с локальным фоном. Текущий флаг `noteworthy` срабатывает при **хотя бы одной** гармонике >=6 dB над локальным фоном. Этого **недостаточно для самостоятельной постановки диагноза**. На странице корректно написано «не диагноз».

## 2. Кюртограмма: добавить отдельную страницу — полноценный Fast Kurtogram

**Предпочтительный математический ориентир:**
- J. Antoni, *Fast computation of the kurtogram for the detection of transient faults*, MSSP 21 (2007), 108–124; авторское Matlab: https://www.mathworks.com/matlabcentral/fileexchange/48912-fast-kurtogram .
- Реализация на Python с доступными исходниками MIT: https://github.com/wwhenxuan/PySDKit/blob/main/pysdkit/utils/_kurtogram.py ; описание https://pysdkit.readthedocs.io/en/latest/auto_examples/utils/fast_kurtogram.html . Использует бинарную/троичную аналитическую FIR-декомпозицию, возвращает **полную** 2D-карту `frequency × decomposition level`, оптимальные `fc` и `Δf`. Возможность интеграции зависит от проверки версии/лицензии/численных тестов и Windows упаковки; **код не копировался в этом коммите**.
- Ещё один Python инженерный пример: https://github.com/akshatverma1602/Signal-Processing-on-CWRU-Bearing-Dataset/blob/main/kurtogram.py — на деле простой dyadic Butterworth+Hilbert scan; название Fast Kurtogram в README **не делает этот метод эквивалентным** дереву Антони. Такое же различие есть в текущем MVK.

**UX отдельной страницы в «Доп. анализ»:**
- слева/сверху: выбранный АЦП 1–8 (общий с измерением), подтверждённая Fs, длина *реального* окна (обычно 8192–32768), число уровней, границы допустимой полосы, метод/документированные параметры;
- в центре большая тепловая карта: **X центр полосы, Гц; Y ширина полосы Δf, Гц / уровень; цвет — excess spectral kurtosis (безразмерно)**; легенда цвета; незаполненные клетки обозначены как `недоступно`, не 0;
- курсор и выбор клетки → `f_low, f_high, fc, Δf, K`; рядом короткое объяснение, что это **информативность полосы, а не диагноз**;
- **кнопка «Использовать полосу в огибающей»** переносит выбранные границы в исследование текущего АЦП (без записи команд прибору, без повторного FRange и без изменения исходных AUX4700);
- в нижней связанной панели: спектр огибающей выбранной полосы, при известных RPM/геометрии — линии BPFO/BPFI/BSF/FTF; оператор может сравнить другие выделенные полосы;
- вычисление в отдельном worker, с отменой/отбрасыванием результатов при смене `session_id, adc, source RxPos, Fs`. Не пересчитывать каждую перерисовку и не смешивать `LIVE` с замороженным/архивным окном.

**Физическая осторожность:** высокий SK/K может выделять случайный удар, EMI/VFD или процессный шум; необходимо проверять повторяемость импульсов, гармоники огибающей и устойчивость на нескольких реальных окнах. Источники: https://www.mdpi.com/2076-3417/10/8/2657 ; https://pmc.ncbi.nlm.nih.gov/articles/PMC13074464/ . Отсутствие пиков не доказывает исправность оборудования.

## 3. Водопад — улучшение существующей реализации, не создание второго графика

- Различать `Live waterfall` из новых `RxPos` и `Archive waterfall` из **сохранённых записей с подтверждёнными timestamps**.
- Сохранить существующий `waterfall_page` и вход в него. На Y показывать реальное время (в Live секунды относительно начала/последней записи; в архиве UTC/локальное) **только если метка подтверждена**. Если нет — «Номер кадра», не выдуманная дата.
- X физические Гц, шкала цвета с диапазоном, видом данных и физическим/относительным референсом. Нельзя смешивать в одном waterfall величины `FFT amplitude`, `Welch PSD`, `ASD` и разные единицы.
- Выбор строки/времени → **спектр для этого кадра**, курсор частоты → **изменение уровня на этой частоте во времени** (если есть исходные данные).
- Динамический диапазон цвета/палитра, частотный участок, количество кадров/временной диапазон; регулировать отображение без повторной обработки устройства. Не нормировать каждый кадр относительно своего максимума без явного согласия оператора.
- Большой архив с различной Fs: показать разделы/несовместимость; ресэмплировать/интерполировать только при явно выбранной операции с отметкой APP_DERIVED. Реальные пропуски времени должны быть заметны.
- Можно вывести водопад отдельной панелью раскладки 1/2/4 вместе со спектром, временным сигналом и трендом.

## 5. UX «Поиск признаков неисправностей»: объяснения вместо фальшивых диагнозов

**Предлагаемая самостоятельная вкладка «Диагностические признаки»**, с таблицей:
`Гипотеза | Выявленные признаки | Пики/частоты | Основание/окно/АЦП | Ограничения | Открыть график`.
Блоки не являются самостоятельными карточками оборудования. Все настройки физики вводятся **непосредственно в методе**, если оператору нужны.

**Набор правил, который имеет смысл независимо испытать:**
- **Подшипники:** автоматическая рекомендованная полоса Fast Kurtogram → Hilbert огибающая → спектр → 2 и более гармоник на частотах BPFO/BPFI/BSF/FTF с локальным SNR, проверка нескольких измерений/окон и sidebands. **Не утверждать «дефект есть» из одного пика/куртозиса**. Нужны ручные обороты и геометрия.
- **Дисбаланс (возможный):** 1× доминирует над соседними гармониками при известной принятой 1×, желательно повторяемость/рост по времени. Без фаз и направления датчика «неподтверждено».
- **Несоосность (возможная):** повышенная 2×/3× и сопутствующие признаки при стабильной 1×; без осевых данных и фаз с дисбалансом/ослаблением не различить надёжно.
- **Механическая разболтанность (возможная):** множественные 1×–n×/субгармоники и импульсность; не однозначное состояние из одного окна.
- **Зубчатая передача:** введённые 1×/число зубьев → GMF + боковые полосы с локальным фоном и трендом; одна теоретическая GMF не означает наличие дефекта.
- **Изменение состояния без локализации:** долгосрочные тренды RMS/crest/kurtosis/spectral centroid/flatness/HF ratio → статистические отклонения относительно адекватного baseline по тем же режиму и полосе. **Не окрашивать зелёным «исправно», если baseline отсутствует**.

**Запрещённые подмены:** пороги ISO без выбранного класса и нужных единиц; жёсткие `87%` без калибровки вероятности; диагностика «здоров» при отсутствии доказательств; абсолютное «подшипник неисправен» по куртограмме; объединение нескольких АЦП без физической привязки; расчёт из старого сеанса, если текущий не подтвердился.

**Рекомендуемые статусы:** `Не оценено` / `Данных недостаточно` / `Признак выявлен` / `Признак не выявлен в этом окне` / `Требуется проверка`. Не использовать итоговую «вероятность неисправности» до валидации.

## 6. Приёмка и порядок внедрения

A. **Waterfall v2:** настоящее физическое время, шкала цвета, выбор кадров и частот, загрузка истории без фальшивых timestamps и без повторного TCP.
B. **Кюртограмма v1:** отдельная 2D страница + реальный Fast Kurtogram (не текущая approximation), выбранная полоса переходит в огибающую; работа в worker, выдача `APP_DERIVED`, границы Fs/Nyquist; исследования на CWRU и синтетических контрпримерах (случайный удар, белый/цветной шум, AM-импульсы, EMI).
C. **Доказательный поиск признаков:** таблица с числами и ссылкой на пики/курсор, сначала подшипники/1×/2×/GMF, потом долгосрочные статистические признаки. Результат формулировать как гипотезу. Без ML и карточек оборудования.
D. **Ручная приёмка:** Windows DPI 100%/150%, 1280×720 и 1920×1080; Qt тесты плюс проверка на реальном МВК01. Тесты на синтетике не подтверждают физическую точность.

**Инварианты:** один Go Native RX, FRange только один раз до GUI; исходные AUX4700 43+24×3 сохраняются дословно, все новые результаты `APP_DERIVED`, ни одна операция анализа не шлёт команд в прибор. Без новых таблиц «агрегатов»/«подшипников»/«редукторов».

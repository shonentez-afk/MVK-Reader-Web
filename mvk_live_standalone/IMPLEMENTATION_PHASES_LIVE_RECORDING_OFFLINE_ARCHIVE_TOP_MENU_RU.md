# MVK Live Standalone — единый план внедрения 126 функций: LIVE → запись → анализ окна → архив → верхнее меню

**Дата:** 18.11.2026. **Ветка:** `feature/mvk-live-standalone-20261117`. **Тип работы:** исследовательская спецификация реализации (код приёмника/DSP/Qt ещё НЕ изменён). Объём — собственный анализатор из реальных МВК01-данных, а НЕ копия оригинального MVKView. Строго не создавать дерево оборудования, карточки подшипников/агрегатов/редукторов. Условия датчика и измерения — лёгкий необязательный паспорт окна.

**Главные каталоги:** [126 строк с источниками и статусами](UNIFIED_IMPLEMENTATION_MATRIX_20261118_RU.md), [Excel-совместимая таблица 126 строк](UNIFIED_IMPLEMENTATION_MATRIX_20261118_RU.csv), [44 диагностических правила](AUTOMATIC_DIAGNOSTICS_METHODS_AND_RULES_CATALOG_RU.md), [пять диагностических пробелов](FIVE_GAPS_AND_DIAGNOSTIC_RESEARCH_PLAN_RU.md), [рабочее пространство](WORKSPACE_V2_OPTIMAL_MAIN_AND_ANALYSIS_RU.md), [UX соединений](CONNECTION_PROFILES_SETTINGS_AND_FAULT_SEARCH_UX_RU.md).

## 1. Четыре класса вычислений и принцип очередности

| Класс | Когда работает | Что вычисляет и рисует | Чего не делает |
| --- | --- | --- | --- |
| **LIVE_LIGHT** | В период Native RECORDING: только новое подтверждённое окно выбранного ADC | осциллограмма, текущие RMS/peak/crest, FFT/PSD с регулируемой частотой обновления, исходный AUX4700, короткий тренд, водопад ограниченной истории, расчётные маркеры, лёгкий контроль качества | не запускает тяжёлую обработку на каждом отсчёте, не подменяет источник, не ставит автономный «диагноз» по одной линии |
| **CAPTURE** | Начинается подтверждённым оператором действием «Измерить»; RAW и AUX уже пишутся Native Go | сохраняет реальную историю сеанса, проверяет завершение, SHA, отдельные окна NPZ и пользовательские метки | не считает ring текущего GUI долговременной записью и не создаёт второе TCP |
| **WINDOW** | Freeze/A–B/зафиксированное NPZ или проверенный, позднее выделенный из полного BIN фрагмент | огибающая, SES, Fast Kurtogram, STFT/CWT, кюртозис, независимые реальные пики, Hn/sidebands, спектральные диагностики | не блокирует Native Go и не заставляет LIVE постоянно строить много тяжёлых карт |
| **ARCHIVE** | Только сохранённая запись или физически сопоставимая серия | наложение 2–8 спектров, тренды, повторяемость, adaptive baseline, гистерезис, отчёт по источникам | не выдумывает старые выборки/временные отметки из AUX4700, не смешивает разные условия |

**Управление:** всё производное создаётся над единой `AnalysisInput` (session, ADC, Fs, physical N/T, window source range, checksum, unit, FRange provenance, method version). Единицы, окно FFT, PSD/ASD и локальный фильтр должны быть частью параметров расчёта. Триггеры в UI могут только сохранять/отмечать **реальные** окна; не создавать поток «наблюдений» с синтетическими значениями.

## 2. Отправная точка: что именно уже сохраняется

| Уровень | Проверено в исходниках | Физические ограничения |
| --- | --- | --- |
| **Native RAW** | Native Go `main.go`, `monitor.go`: один сеанс уже сохраняет `incoming.raw` и `frames.csv`; `app.py::start_native()` начинает Native с `-seconds 0 -max-mb 2048 -export true -live-status true -live-ipc true` и отдельным подтверждением подключения | **2048 МиБ — текущий явный предел RAW-сеанса**, не «неограниченное хранение». Заказчик должен видеть лимит/остаток и прекращение по ограничению |
| **Native AUX4700** | `aux4700.jsonl` + импорт в SQLite `vendor_frames`: 43 1/3 полосы и 24×3 исходных параметра на ADC, timestamp из реальных сообщений | 43+24×3 — не временные отсчёты и не 115 спектральных частотных точек; FFT/огибающую из этих чисел не создавать |
| **Native calibrated BIN** | `live_bin_spool.go` делает непрерывный пишущийся `.bin.partial`; `session_export.go` только **после закрытия/верификации RAW** сверяет spool с независимым replay и публикует валидированные BIN/TSXML/таблицу в `BIN_TSXML_VALUES_TABLE_RECONSTRUCTED` | Файл `.partial` **нельзя считать завершённым архивом**. При аварии экспорт может быть `REFUSED`; сохранить `incoming.raw` и статус причины |
| **Live-кольцо** | `live_ring.py::CAPACITY=262144` Float32-отсчётов на ADC, `live_ipc.py` отдаёт до 262144 проверенных отсчётов в одном preview | при 65 536 Гц окно максимум **4 секунды**. IPC — для просмотра/ручного Freeze, **не lossless recorder** |
| **NPZ V1** | `recordings.py`: ровно 2 ZIP-записи, длина 256–262144, поддерживаемые Fs 512/2048/8192/32768/65536; SHA256 по Float32, ADC, session, `capture_end`, `saved_utc` | `saved_utc` — **время сохранения**; `capture_end` — счётчик, **не UTC**; `load_snapshot` откажет от третьего элемента ZIP. Не расширять NPZ V1 in-place |
| **Локальная история** | `measurement_history.py`: `saved_windows`, `local_values`, `vendor_frames`, `import_offsets`; `history_widgets.py` — до 8 спектров, фильтр по дате | сейчас нет паспорта датчика/монтажа, метод-версий и проверяемого сравнения одинаковых условий |

**Сохранение идёт УЖЕ при измерении:** в текущей архитектуре кнопка **«Измерить» запускает Native-сеанс и запись RAW**. При проектировании дополнительной кнопки «Записать фрагмент» нельзя обещать, что именно она включает сохранение RAW — это отдельное действие выделения операторского фрагмента из уже фиксируемого сеанса.

Центральный **обзор: спектр + осциллограмма + 4–6 значений**; подробные вкладки «Спектр», «Время», «Расчётные», «Водопад». Справа **контекстный инспектор только активного вида**, не все настройки сразу; технические поля Native EXE/SHA в «Настройки → Сервис». Существующий выбранный UX-гибрид [WORKSPACE_V2](WORKSPACE_V2_OPTIMAL_MAIN_AND_ANALYSIS_RU.md) сохранить.

Интенсивность обновления задаёт пользователь и тестируемый профиль «Экономичный/Обычный/Быстрый»: ориентир для начала benchmark 5–10 обновлений осциллограммы/с, 1–3 FFT/с на **выбранном** ADC и не больше 1 тяжелого worker одновременно. **Это проектные ориентиры, не подтверждённая производительность**. На остальных ADC можно обновлять компактные числовые индикаторы реже. Тяжёлые расчёты строго по запросу.

**Ready-критерии перед этапом II:** 8 реальных ADC без смешения; monotonic source counters/gap flags; Freeze не останавливает Native запись; смена ADC/session не вставляет устаревшую FFT; каждая цифра имеет физические units/source, no fake data, 150% DPI/1280×720 и 1920×1080, восстановленное состояние Qt, smoke + synthetic/recorded fixtures.

## 4. ЭТАП II — как записывать ВСЁ это (поток, окна, события, параметры)

### 4.1. Три разных действия оператора, никаких скрытых источников

| Команда | Физически происходит | Что записывается | Правило статуса |
| --- | --- | --- | --- |
| **ИЗМЕРИТЬ** | оператор подтверждает новое TCP-соединение Native Go; Native начинает отдельный сеанс | ВСЯ реально принятая RAW-телеметрия, AUX4700 и технический журнал. По успешной финализации — проверенные BIN по ADC | RUNNING/VERIFYING/EXPORTED/REFUSED; сам по себе старт не означает, что прибор прислал данные |
| **Сохранить окно** | копия подтверждённого ring или Freeze/A–B | immutable `MVK_LIVE_CALIBRATED_SNAPSHOT_V1` NPZ + SHA + отдельная аннотация паспорта + индекс SQLite | не менять V1; не переписывать существующий файл; отсутствующая точка=unknown |
| **Отметить/записать фрагмент** (НОВОЕ) | старт/конец как **маркеры выбранной части уже идущего сеанса**; при закрытии сеанса извлечь фрагмент из **полностью проверенного BIN** | `mark.start/end` (counter/source/quality), ссылка на Native session/ADC, optional выделенный NPZ если <=262144, для длинного — range-reference в BIN | **не** обещать абсолютное время или gap-free для одних GUI preview; если BIN export refused → маркер pending/непригоден, RAW остаётся |

**Решение:** **не копить длинную запись в `VerifiedLiveRing` или нарезать IPC-preview в якобы непрерывный фильм**. Долгий сигнал уже целиком фиксируется Native RAW, затем verified BIN. Для анализа отрезков большого BIN использовать read-only seek/memmap/chunked loader по физическим channel offsets после завершения и SHA-верификации. В будущем опциональная автоматическая нарезка на анализируемые окна не должна терять исходную длинную запись. Если очень нужна независимая `Start/Stop recording` при продолжающемся сетевом сеансе, сначала проектировать только **bookmarks по реальному Native counter**, а не менять канонический RAW; точность точки отсечки подтверждается отдельно.

### 4.2. Настройки окна «Запись измерения» (НЕ IP на главном экране)

**Раздел «Приём»:** имя сеанса/заметка, [профиль прибора] (IP/локальный Ethernet в `Настройки → Подключения`), валидность Native EXE/SHA, подтверждение. **Только информационная таблица АЦП 1–8 без галочек, выбора канала и возможности отключить запись**: канал, Fs (read-only), число принятых отсчётов, статус/ошибки, непрерывность. Native автоматически записывает все реально поступающие каналы независимо от выбранного АЦП на главном экране. Для просмотра/быстрого анализа/кнопки «Сохранить текущее окно» существует **один глобальный текущий АЦП** в верхней рабочей панели. Отдельный выбор АЦП при специальном экспорте нескольких сохранённых каналов допускается только как параметр того разового экспорта и **не меняет глобальный текущий АЦП**.

**«Хранение»:** каталог архива (постоянный, не временная `home/mvk_live_*` без каталога), свободное место, прогноз размера, session cap 2048 МиБ RAW, авто-проверка, политика хранения (ручное удаление/резервная копия), предупреждения при исчерпании, отдельный путь экспорта. Изменение каталога — только перед началом сеанса; нельзя перетаскивать рабочий RAW при активном Native.

**«Фрагменты»:** моментальный NPZ, Freeze A–B, операторские закладки start/stop, необязательные периодические **отдельные** NPZ-снимки с маркировкой **DISCRETE** (не continuous), будущие триггеры RMS/peak/events; длина ограничивается реальными N и Fs. Long BIN range экспортировать/считать offline после верификации.

**«Сопроводительная информация»:** необязательная точка измерения свободным текстом, ось H/V/A, монтаж (магнит/шпилька/ручной/неизвестно), чувствительность/калибровка если документированы, источник RPM (MANUAL/ACCEPTED_SPECTRAL/UNKNOWN), нагрузка и условия эксплуатации. Не создавать «карточки оборудования». Список последних пользовательских **шаблонов** допустим для удобства.

**«Автопроверка после остановки»:** верификация RAW SHA, framing/gaps, BIN export status, проиндексировать AUX, создать session record, показать «готовые каналы для offline», не считать экспорт окончательным пока статус !=EXPORTED.

### 4.3. Предлагаемая структура архива (после внедрения; текущие файлы оставить неизменными)

```text
MVK_Live_Archive/
  measurements.sqlite                  # индекс и контекст, SQLite WAL
  sessions/
    <session_uuid>/
      native/                           # несдвигаемый оригинальный каталог Native
        incoming.raw
        frames.csv
        summary.json
        aux4700.jsonl
        STAGE108_EXPORT_STATUS.json
        BIN_TSXML_VALUES_TABLE_RECONSTRUCTED/   # ТОЛЬКО после EXPORTED
      session_manifest.json             # APP_INDEX: flags, SHA, source, time_quality
      marks.jsonl                       # операторские BEGIN/END markers, source counters
  windows/
    <window_uuid>.npz                   # immutable исходные Float32, 2 members V1
  analysis/
    <analysis_run_uuid>.json            # version, source SHA, windows, parameters, QC/peaks
  exports/
    <user_requested_report>.pdf/.csv/.png
  presets/                              # только пользовательские настройки, без секретов
```

Расположение RAW как `native/` **проектное**: текущий Native сам создаёт каталог сеанса и Qt запускает его под временным home-путём. Изменять корневую папку только через поддерживаемый `-out` и до подключения. **Нельзя просто переименовать активную папку** и оборвать IPC/status. Для старых сеансов оставить импорт из исходного каталога без переупаковки.

**Содержимое manifest:** `session_uuid`, тип source `MVK_NATIVE_VERIFIED`, ADC, session start/end **PC UTC с явным качеством clock**, capture counters/rates, exact source hashes, APP software/protocol version, FRange_applied=once/verified, results of framing/gap/source quality, export_state, notes, disk quotas, analyzer settings, paths/exports. Избегать серийных идентификаторов, если они неизвестны. **saved_utc не равен acquisition_utc**; device time неизвестен, пока не подтверждён. Не переносить IP в NPZ паспорта без явной надобности.

**Аналитические данные:** raw waveform и AUX никогда не изменять; FFT/SES/огибающую/пики/диагностическую таблицу можно кэшировать с ключом `source SHA + channel/counter range + full settings hash + algorithm/code version`. По умолчанию вычислять повторно из исходника, если кэш устарел. Для трендов хранить конкретные derived scalar metric values с версией, units, band, исходным `analysis_run_id`.

**Сбой записи:** RAW и ошибки сохранить; `*.partial` не публиковать как готовый BIN; недостачу диска/отключение/обрыв показать оператору; автоматический новый TCP не открывать; повторять экспорт/импорт только безопасными idempotent операциями. SHA источника проверять перед открытием/экспортом. Удаление/перенос архивных файлов — только явное действие со списком зависимостей и резервной копией, не автоочистка без предупреждения.

### 4.4. Как сохраняются основные группы методов

| Результат | Что хранить | Когда |
| --- | --- | --- |
| Приборные 43+24×3 (L05–07) | исходные AUX4700, реальный ADC/update_tick/source timestamp, недоступные поля — null | по каждому Native сообщению, не выводить из FFT |
| Временной сигнал и FFT (L01–04,09–12) | исходный RAW+валидированный ADC BIN; optional NPZ window; параметры FFT/фильтра как APP metadata | автоматический Native + только явные/запланированные фрагменты |
| Живые показатели (L08,L11,L18) | выбранный оператором ряд scalar snapshots с source window key/RPM/method version; необязательно хранить каждый кадр GUI | по настроенной частоте и при реально вычисленном значении; не заменяет waveform |
| Водопад L10/A03 | **последовательность сохранённых** спектров и их настоящие source-window ranges; derived heatmap можно пересчитать | LIVE ограниченная временная память; durable — по выбранным сохранённым кадрам |

| Диагностика D01–D44 | `QualityReport`, реальный `PeakCandidate/peak_id`, `PredictedLine`, `Match/Collision`, status, метод-версия, источник RPM, evidence | при явном анализе фиксированного окна; подтверждение по независимым архивным записям |
| Тренды/сравнения A01–A20 | индексы исходных записей, metric/units/filter/geometry/RPM/load/evidence provenance, compatibility reasons | только при сопоставимой серии; missing ≠ zero |

## 5. ЭТАП III — расчёт по записанному окну и завершённому сеансу

**Входы:** (а) отдельный immutable NPZ V1, (б) точный диапазон `[sample_start, sample_end)` внутри верифицированного Native BIN (при наличии `EXPORTED`), (в) операторский Freeze/A–B на основе проверенного ring (не после его обнуления). Один `AnalysisInput` — один воспроизводимый результат; при каждом изменении параметров сохранять hash и версию алгоритма.

| Последовательность | ID | Подробности и приёмка |
| --- | --- | --- |
| **III-a. Физическое ядро** | W01–W09, W18, D02–D09, D12–D13 | FFT/PSD band energy, Hilbert-envelope, Fast Kurtogram, независимый поиск реально измеренных пиков, предсказанные BPFO/BPFI/BSF/BDF/FTF, GMF, Hn/sidebands/коллизии; `1 peak != defect` |

## 6. ЭТАП IV — архив, диагностические тренды и сравнение

**А01–А20** со всеми нужными входными индексами; D10/D14/D33–D34/D38–D40 выводят persistent признаки. Сначала контекст измерения **вне NPZ V1**, затем schema `analysis_run` и `diagnostic_evidence` в SQLite/sidecar с versioned source SHA. После этого: реальный выбор дат, 2–8 спектров со своей легендой, сравнимость `COMPARABLE/CONDITIONAL/INCOMPATIBLE/UNKNOWN`, Hn/SNR/FFT-band trend, устойчивость family на независимых записях, baseline/hysteresis с отдельными состояниями `NOT_EVALUATED`.

Показать две оси даты по факту:
- `saved_utc` (V1) → UI **«время сохранения»**;
- доказанный `acquired_utc` → только когда есть фактический проверенный source timestamp/mapping; иначе null/UNKNOWN.

**Пакет архива готов**, если старые NPZ V1 и AUX4700 импортируются без миграции, смешанные load/RPM/units не дают ложный trend improvement, checksum mismatch блокирует анализ, нет потерь в SQLite и ошибочных дубликатов, результаты открываются повторно без приборов.

## 7. ЭТАП V — расширенные исследования / без необоснованного включения

R&D приоритет после baseline и реальных архивов: Protrugram, Infogram, Spectral Gini, Autogram, cyclostationary, WPD/VMD/EMD/IMCKD/SST; ML Hotelling T²/Isolation Forest и RUL по независимой валидации CWRU/Paderborn/реального МВК01. ### 9.2. Инженерная реализация меню (не создавать вторую систему действий)

Один `ActionRegistry` в PySide6/Qt: для каждого `action_id` единый `QAction` с text/shortcut/tooltip/enabled(state) и callback к **существующему обработчику**; одна QAction может быть в меню, toolbar и в контекстном инспекторе. Не делать три разных обработчика сохранения и не связывать запись с простым переключением вкладок. UI status обновляется от общего `AppState` (Native state, source kind, ADC, verified window, saved record, worker, supported inputs), не от текста label.

**Разделение настроек:** `QSettings` — внешний вид, расположение, последние IP-профили и окна; `capture_profile.json` — политики локальной записи/архива без секретов; `analysis_preset.json` — versioned FFT/огибающая/пороговые методы; `MeasurementContextV1` — конкретное measurement source/condition в SQLite/sidecar. Пароли/авторизационные токены не хранить, аппаратные настройки автоматически не отправлять.

## 11. Непосредственные тестовые сценарии

1. **LIVE:** один ADC/8 ADC с разными Fs; замена сессии, отключение, период потерь; null vs zero; scale units, filter, epoch, stale FFT; Freeze сохраняет исходный источник; Windows DPI.
2. **RAW и BIN:** -max-mb 2048, нет места на диске, принудительный отказ в экспорте, некорректная последняя рамка, hash mismatch, остановка по пользователю, атомарная индексация, импорт старого run, отсутствие автоматического повторного подключения.
3. **NPZ:** 262144 max, 256 min, Fs whitelist, запрещён третий ZIP entry, corrupted SHA, saved_utc≠acquired_utc, старые файлы открываются, контекст отдельный и необязательный.
4. **Фрагмент:** закладки внутри Native count, exact extraction из validated BIN после EXPORTED, частично недоступные ADC, фрагмент длиннее 262144 без обрезания/выдуманного «полного NPZ».
5. **Меню:** QAction не дублирует обработчик, enable/disable при LIVE/OFFLINE/NATIVE_VERIFYING, клавиши не вызывают TCP без consent, все меню доступны при 150% DPI.
6. **WINDOW:** отдельные реальные пиковые частоты, 2+ Hn, ±sidebands/коллизии, отсутствие RPM, физическое разрешение, отличать фактическое от теории.
7. **АРХИВ:** разная физическая точка / RPM/load/source units => условно/несопоставимо; SHA/source link; 2–8 спектров и тренд; missing never 0.

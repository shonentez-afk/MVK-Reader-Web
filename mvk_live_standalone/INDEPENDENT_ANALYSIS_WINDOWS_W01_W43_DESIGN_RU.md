# MVK Live Standalone — собственное окно каждому методу анализа W01–W43

**Дата:** 18.11.2026. **Ветка:** `feature/mvk-live-standalone-20261117`. **Статус:** подробный проект рабочих окон; *не реализованные QT-окна*. Проверено по 43 строкам [исходного каталога](FULL_VIBRATION_METHODS_REALTIME_RECORDINGS_SETTINGS_SCREENS_RU.md), [единой матрице 126 позиций](UNIFIED_IMPLEMENTATION_MATRIX_20261118_RU.csv) и фактическому [app.py](app.py).

## 1. Решение по интерфейсу

**43 метода W01–W43 → 43 отдельных, именованных окна анализа.** Это отдельные не модальные `QMainWindow` (или Qt widget с `Qt.Window`), открывающиеся из **Анализ → Дополнительные методы…** / поиска по каталогу / закреплённых избранных. Каждое окно может содержать несколько взаимосвязанных графиков *своего* метода, собственную настраиваемую панель, сохранение параметров и результатов. **Запрещено объединять разные методы W в один общий QTabWidget «Доп. анализ» или отображать STFT, CWT, кепстр, кюртограмму одним переключаемым графиком.** Сами методы остаются в отдельных рабочих окнах и не создают вкладок главного экрана. 

На главном экране только четыре LIVE-вкладки **Обзор / Спектр / Временной сигнал / Расчётные данные**. LIVE-инструменты водопада L10 и короткого тренда L11 по меню могут открываться также самостоятельными окнами. История/архивные A01–A20 используют **собственные окна архивного анализа/сравнения**, но действия без графика (например, экспорт отчёта A14) остаются диалогами. Составные диагностические пункты D01–D44 — **алгоритмы/evidence для окон Диагностики**, а не автоматически 44 дополнительных окна; отдельные диагностические окна делаем по пользовательским методам/семействам (подшипники, редуктор, вал, вентилятор, аномалии). W32 — отдельное окно общего поиска, а не «дополнительная вкладка».

**Не путать:** 43 окна в проектном каталоге ≠ 43 окна, создаваемые при запуске приложения. Окна создаются **лениво по запросу**. Не реализованный/R&D метод присутствует в каталоге с пояснением требований, но **не открывается как фальшивое работающее окно**.

## 2. Фактический код, который предстоит перенести

Текущий [app.py](app.py) содержит:
- `self.views=QTabWidget()`, внутри вкладку `self.extra_panel` с `self.extra_pages=QTabWidget()`;
- `waterfall_page`, `kurtogram_page`, `short_trend_page`, отдельные внутренние `extra_method_pages["stft"|"cwt"|"cepstrum"]`, `diagnostics_page`, `gears_page` — **все фактически вложенные страницы**, не самостоятельные окна;
- функции `_calculate_kurtogram`, `_calculate_extra`, `_run_bearing_page`, `_show_bearing_diagnostics`, `_refresh_gear_table` уже выполняют отдельные действия; их переработать в адаптеры к общему расчетному ядру, не переписывать Native RX;
- сейчас `extra_adc` и `dsp_adc` дополнительно показывают выбор канала: в новом UI оставляем **один** глобальный селектор на главной панели. **Окно метода имеет подпись исходного АЦП и одноразовое действие «Взять новый текущий источник»**, не второй переключатель LIVE-канала.

Требуемые новые интерфейсы: `AnalysisWindowManager`, `MethodWindowBase`, `MethodSettings`, `MethodResult`, `AnalysisSourceSnapshot`, `MethodWindowFactory`. Новые классы — проектные имена, ещё НЕ реализованы.

## 3. Правила источника и независимости окон

1. Открывая окно из LIVE, сначала зафиксировать **доказанный `session_id/adc/Fs/sample_range`** и реальные исходные данные `Freeze`/verified ring/NPZ; метод не подключается напрямую к прибору. При смене АЦП на главном экране **открытое окно остаётся привязанным к исходному АЦП**, пока пользователь явно не нажмёт «Взять новое окно»; визуально написано «АЦП 3 • источник 2026… • зафиксировано».
2. Все окна используют общий расчётный слой `vibration.py` / `advanced.py` / `kurtogram.py` / `quality_gate.py` после реализации и общие immutable source references. У окна свои настройки `analysis.W05.stft.nperseg` и т.д. **Нельзя делать копию DSP или новый socket на каждое окно**.
3. В каждом окне независимо: заголовок метода/ID, источник и fs/N/T/unit, `[Рассчитать]` `[Отменить]` `[Выбрать другой сохранённый источник]`, графики/таблицы, справа настройки, снизу QC + `[Сохранить анализ]` `[Экспорт]`. При невозможном входе показать «Требуется RPM(t)/двухканальная синхронизация» и статус `NOT_EVALUATED`.
4. Несколько разных окон могут быть открыты одновременно (например, **W03 кюртограмма + W02 огибающая + W05 STFT + W08 подшипник**). Для каждого результата записываются source SHA/ADC/Fs/sample range, параметры/версия; окна могут обмениваться только **проверяемыми ссылками на один и тот же источник**, например «полоса Kurtogram → открыть W02» с передачей диапазона/метода.
5. При повторном выборе того же метода из меню по умолчанию поднять существующее окно с этим методом/источником; команда «Открыть ещё одно окно с текущим источником» создаёт дополнительный экземпляр. В меню **Вид → Открытые окна анализа** есть список и закрытие активных без потери сохранённых расчётов.
6. Все тяжёлые DSP расчёты — фоновые jobs с лимитом памяти, отменой, индикацией процесса и контролем `source_id + revision`; результаты от уже заменённого источника/параметров **не перерисовывают** свежую картину. Никакого обновления всех 43 окон каждую итерацию LIVE.
7. Сохранение результатов — в будущем `analysis_run` (источник SHA, метод ID, code_version, параметры, точный участок Fs/N/T, QC + графические outputs), **не менять NPZ V1**. Оригинальные приборные AUX4700 остаются отдельными.
8. Геометрия подшипника/редуктора, текущие RPM, периодичность, фаза и другие параметры — только в собственных окнах нужных методов; **не делать карточки оборудования** и не хранить их на главном экране.
9. Существующие файлы Windows/Qt smoke tests сохранить, добавить unit тест уникальности окна для каждого W, открыть-закрыть-повторно открыть, переключение LIVE ADC, две разные NPZ с одним названием, связанные W03→W02, отсутствие source/недоступный W20, memory bounds, не блокировать Stop/Freeze, DPI 100–150%.

## 7. Что изменится в коде после реализации

Сначала мигрировать существующие **W03 (Kurtogram), W05 (STFT), W06 (CWT), W07 (кепстр), W08 (подшипники), W09 (редуктор)** из `extra_pages` в самостоятельные окна **без изменения их вычислительного ядра**, затем W02, W01/W18 и остальные. Готовые обработчики оставить совместимыми с существующими тестами, но маршруты меню будут направляться в `AnalysisWindowManager.open_method(method_id, input)`. Кнопка закрытия окна **не останавливает Native**; `Измерить/Стоп` не меняет неподтверждённый архивный источник внутри других окон.

**Принятое решение нужно учитывать при реализации MAIN-A/B/C** и при расширении P3. Это **документ/таблица для разработки, не подтверждение завершённого UI**.

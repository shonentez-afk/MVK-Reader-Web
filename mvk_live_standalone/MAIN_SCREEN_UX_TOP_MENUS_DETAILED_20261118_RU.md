# MVK Live Standalone — главный экран v3 и полный каталог верхних меню

**Дата:** 18.11.2026. **Ветка:** feature/mvk-live-standalone-20261117. **Статус:** проект компоновки/навигации; **ни один из описанных новых Qt-виджетов и меню не считается уже внедрённым**. Собственная программа по реальному потоку МВК01, НЕ копия MVKView. Каталог физического анализа 126 пунктов и дорожная карта P1–P5 остаются источниками границ реализации.

**Приоритетная спецификация реализации и жизненного цикла окон:** [MAIN_WINDOW_AND_MULTIPLE_WINDOWS_ARCHITECTURE_20261118_RU.md](MAIN_WINDOW_AND_MULTIPLE_WINDOWS_ARCHITECTURE_20261118_RU.md) и [машинный контракт маршрутов](WINDOW_ROUTING_CONTRACT_V1_20261118_RU.json). Этот документ описывает полную карту 8 меню, а при разночтениях правил открытия отдельных окон ориентироваться на новый контракт: меню «Анализ» открывает отдельные W-окна; «Архив» — отдельные архивные окна; W32 — одно окно поиска с внутренними D-правилами. Не считать текущие вложенные extra_pages готовыми внешними окнами.

## 1. Проверенное в текущем приложении

Факты по текущему [app.py](app.py) в HEAD ветки:
- Главное окно `LiveWindow(QMainWindow)` имеет 6 рабочих вкладок: **Спектр / Временной сигнал / Расчётные данные / Тренды / Сравнение / Доп. анализ**. Внутри Доп. анализа — Водопад, Кюртограмма, STFT, CWT, Кепстр, Подшипники, Редукторы, оперативный RMS-тренд; в расчётных — оригинальные AUX4700 и локальные показатели.
- **Qt QMenuBar/ QActions верхнего меню пока НЕ построены.** Настоящие обработчики (start_native, stop_native, _toggle_freeze, _archive_capture_window и т.д.) существуют, их нужно повторно использовать.
- На главном экране пока имеются `device_ip`, `local_ip`, `exe_path`, `exe_sha`, обороты/геометрия и несколько рядов кнопок. Убрать это с главной страницы, перенести в контекстные свойства/подключения/сервис.
- Есть **три разных видимых селектора**: `adc` (основной), `extra_adc` в доп. анализе и `dsp_adc` в расчётных, синхронизированных сигналами. **В новой компоновке оставить один видимый селектор LIVE-канала**; области анализа читают единый state; архивные выборки не переключают LIVE.
- Freeze останавливает **только локальный показ**, Native RAW продолжает приём/запись. `_archive_capture_window` записывает NPZ в архив; `_save_snapshot` предлагает Save As и затем индексирует. При нажатии **Измерить** уже запускается отдельный Native RAW-сеанс: повторная кнопка «Запись» не должна претендовать на запуск физического capture.

**Ключевые дополнения к макету:** [научно правильные параметры FFT/PSD/ASD и временного сигнала + современный дизайн-системный слой](MAIN_SCREEN_MODERN_UI_AND_GRAPH_SETTINGS_20261118_RU.md), [контракт настроек/палитры](MAIN_SCREEN_GRAPH_PRESETS_AND_STYLE_CONTRACT_V1_20261118_RU.json). Физическую величину ВУ/ВС/ВП, метод FFT/PSD/ASD и Y лин./дБ **развязать**. При ручном изменении масштаба ось переходит в MANUAL и не сбрасывается; X log>0; при неизвестном источнике — пустой график. Настоящий `app.py` пока этого не реализовал, хотя часть фильтров и единиц уже существуют.

### 2.1. Верхние слои и поведение

| Область | Что находится | Что убираем с главного |
|---|---|---|
| **Заголовок / QMenuBar** | 8 настоящих пунктов меню; имя окна, версия в About | 43 DSP-метода нельзя размещать как 43 верхние вкладки |
| **Панель приёма** | название **выбранного профиля** (не редактируемый IP), «Измерить», «Остановить», Freeze, сохранить текущее окно, **ОДИН** АЦП 1–8, RAW state | Device IP, Local IPv4, EXE path и SHA; отдельный выбор АЦП на каждой вкладке |
| **Вторичная навигация** | Только четыре видимые вкладки: **Обзор / Спектр / Временной сигнал / Расчётные данные**. Все экраны «История», «Тренды», «Сравнение» доступны из **Архив**, все прежние «Доп. анализ» — из **Анализ**, автоматическая диагностика — из **Диагностика**. Сохранять рабочие страницы, но убрать эти два названия из полосы вкладок. | «История» / «Доп. анализ» как отдельные соседние вкладки, длинный ряд методов |
| **Показатели** | ВУ RMS, ВС RMS при действительной полосе и интегрировании, Peak, Crest, реальная Fs и Δf; единицы/quality/tooltips | чувствительность/усиление без достоверного происхождения; случайно рассчитанный «здоров» |
| **Центр** | FFT выбранного ADC и осциллограмма **того же самого** ADC, раздельные масштабы/фильтры | отдельный второй переключатель канала и псевдоданные из AUX4700 |
| **Правая панель** | свойства активного графика, группированные «Основные/FFT/Фильтр/Курсоры/Экспорт»; сохранение параметров | параметры другого графика, RPM, Z/d/D/α, редуктор зубья на главном |
| **Нижняя строка** | реальные состояния Native, RX/счётчики, disk cap, Fs, quality, сообщения о пропусках и ходе финализации | технический длинный текст, перекрывающий осциллограмму |

**АЦП строго один:** глобальный селектор `selected_live_adc`. На страницах «Расчётные данные» и детального анализа из верхнего меню показывать заголовок «АЦП N» из этой же модели; `dsp_adc` и `extra_adc` как видимые выпадающие списки убрать. В окне записи показывать **статусы всех восьми** каналов read-only. При сравнении архивных дат отдельный выбор записей/каналов относится ТОЛЬКО к архивной выборке и не меняет Live. Ctrl+1…8 меняют тот же глобальный селектор, не второй state.

**IP-профиль:** на панели `МВК01: [Имя профиля ▾]`; в списке сохранённые имена и команда «Настроить подключения…». Нажатие на профиль **не открывает TCP**. Редактирование IP и локального IPv4 только в диалоге «Настройки → Подключения». При измерении переключение профиля запрещено; перед TCP Connect остается подтверждение с реальным IP и сетевой картой.

### 2.2. Основные показатели (не выдумывать числа)

| Метрика | Число / единицы | Условие |
|---|---|---|
| **ВУ RMS** | м/с² RMS | последнее проверенное окно и известная полоса |
| **ВС RMS** | мм/с RMS | локально из ВУ после проверенного частотного диапазона (например, 10–1000 Гц только если Fs и T реально позволяют) |
| **Пик ВУ** | м/с² | по реальным отсчётам |
| **Crest** | безразмерный | если RMS вычислим, иначе «—» |
| **Fs** | Гц | **только от Native**, не редактируемый combobox |
| **Δf** | Гц | физическая ось: Fs/NFFT и дополнительно уточнять 1/T; не считать zero padding улучшением длительности |
| **Состояние записи** | RAW статус, накопленный размер, лимит и диск | не путать CONNECTING, RECORDING-NO-ADC и VERIFIED DATA |
| **Quality** | ОК/Внимание/Недостаточно/Не оценено | только когда D01 (QualityGate) реально реализован; до того честный технический статус исходника |

Показатели из AUX4700 показываются **на отдельной странице «Расчётные»** как OEM, не как произведение новой FFT. По желанию позже можно закрепить одну выбранную приборную метрику на главном экране — только с ярлыком SOURCE=AUX4700.

### 2.3. Контекстные настройки активного графика

| Выбранный график | Сразу видимые настройки | Кнопка «Расширенные» |
|---|---|---|
| **FFT** | Вид ВУ/ВС/ВП, FFT/PSD/ASD, фильтр, Xmax, Y auto, NFFT | окно FFT (проверить фактический метод), опора дБ, сглаживание, averaging, курсоры/гармоники, хранение пресета |
| **Временной сигнал** | развертка T, local time filter, Y auto, курсоры A/B, Freeze | выделить интервал, сохранить/анализировать участок, начало/конец истинных sample counts |
| **AUX4700** | 43 полосы/24 позиции/APP derived; ввод только source и масштабы | таблица исходных значений и status/source time; **никакого выдуманного NFFT** |
| **Водопад** | X диапазон/цвет/rolling depth, выбранный ADC глобален | frame index vs проверенная UTC/счётчик, slice на курсоре |
| **Огибающая, Bearing** | полоса демодуляции, Hn, предположенный RPM и источник, геометрия без карточек оборудования | локальные raw peaks, BDF/FTF, sidebands, конфликтные гипотезы; только после D01–D09 |
| **Архивные записи** | даты, сопоставимость, список файлов/каналов архива | source SHA, acquisition_time quality, saved_utc, условия измерений |

Смена выбранного графика меняет содержимое inspector, но НЕ его свойство источник/Fs/АЦП. Параметры каждого графика сохраняются раздельно. Кнопка «Подробно» открывает нужное **отдельное окно метода** с зафиксированным исходным источником, а не ещё одну вкладку общего контейнера; она не инициирует новый IPC/TCP.

### 2.4. Решение по навигации: «Историю» и «Доп. анализ» убрать из ряда вкладок

**Утверждённый UX-подход:** непосредственно под кнопками измерения показывать только `Обзор | Спектр | Временной сигнал | Расчётные данные`. Ни «История», ни «Доп. анализ», ни ещё одна «Диагностика» не являются основными вкладками LIVE. Остальные рабочие страницы **сохраняются в коде и доступны через верхнее меню**, без потери обработчиков:

| Источник перехода | Какая рабочая страница открывается | Отображение источника |
|---|---|---|
| **Архив → Сеансы / Записи / Тренды / Сравнение** | отдельные архивные окна поверх существующих `history_ui.trend_page` / `history_ui.compare_page`, будущий браузер сеансов | отдельный архивный выбор записей и АЦП в контексте сохранённых данных, **не меняет LIVE АЦП** |
| **Анализ → Огибающая / Kurtogram / STFT / CWT / Кепстр / остальные W01–W43** | **Каждый метод открывает своё отдельное немодальное окно W01–W43**, а текущие `extra_pages`/`extra_method_pages` — лишь старый вкладочный UI, который предстоит перенести | собственные графики, параметры, источник и результаты; **не** новая вкладка главного экрана и **не** новое TCP |
| **Диагностика → Подшипники / Редукторы / Поиск признаков** | собственные окна диагностических семейств и W32; существующие `diagnostics_page` / `gears_page` — прототипы для переноса; D02–D04 остаются общими правилами, не пустыми окнами | исходные отсчёты + маркеры и доказательства, не фиктивный диагноз |
| **Вид → Обзор / Спектр / Временной сигнал / Расчётные данные** | ровно четыре видимые основные вкладки | всегда один `selected_live_adc` |

**Навигация без потери контекста:** `QStackedWidget` или аналогичный маршрутизатор используется **только для четырёх основных LIVE-страниц**. Отдельные окна W01–W43 ведёт `AnalysisWindowManager` с собственным source snapshot, параметрами и графиками. При возвращении в «Обзор» продолжается просмотр актуального источника. Выбор архивного спектра не возвращает ложное состояние подключения. В меню нужен путь «Вид → Обзор» для быстрого возврата, плюс необязательная «Недавние страницы» в будущей версии. **Никакой отдельной дублирующей панели «История/Доп. анализ» на главном экране.**

### 2.5. Уточнение: каждый метод W01–W43 — самостоятельное окно

**Обязательное правило:** 43 метода из раздела W имеют **43 уникальных window ID** и отдельные немодальные окна. Все графики одного метода (например, три графика STFT) остаются **внутри этого** окна. Конфигурация метода, источник, масштаб и сохранённый расчёт не смешиваются с соседним окном. Новое окно создаётся **по запросу**, а не все 43 при старте. Если метод пока R&D/условный, его карточка в каталоге объясняет ограничения, **не создавая пустой рабочий экран**.

- [Техническая спецификация и полная таблица 43 отдельных окон](INDEPENDENT_ANALYSIS_WINDOWS_W01_W43_DESIGN_RU.md)
- [CSV-реестр по W01–W43: название, графики, собственные настройки, источник и готовность](METHOD_WINDOWS_W01_W43_20261118_RU.csv)
- [Единая таблица всех 126 пунктов с назначением UI и 25 столбцами](UNIFIED_IMPLEMENTATION_MATRIX_20261118_RU.csv)

Старый `app.py` сегодня ещё использует `extra_pages=QTabWidget`, `extra_method_pages` и `extra_panel`: **миграцию в QMainWindow предстоит сделать**, это не существующая реализация. Лучший архитектурный пример — [pySPWB time_processing.py](https://github.com/Charette-AI-Group/pySPWB/blob/main/src/spwb/gui/time_processing.py), где разные виды анализа открываются в отдельных Qt-окнах. При выборе на главном экране другого АЦП открытое окно метода **не перепривязывается автоматически**; оператор явно выбирает новую проверенную выборку.

## 3. Состояния главного экрана и доступность кнопок

| Состояние | Верхняя строка | Графики/сохранение |
|---|---|---|
| **OFFLINE / профиля нет** | имя профиля «Не выбран»; «Измерить» неактивно, «Настроить подключения» активно | графики пустые, открытие локального NPZ доступно |
| **CONNECTING** | «Подключение…»; Stop доступен по текущей Native модели; источник ещё не подтвержден | ждать реальных отсчётов; не рисовать нули |
| **RECORDING_NO_ADC** | TCP/Native работают, RAW пишет доступные байты, но выбранный ADC ещё не подтвержден | осциллограмма/FFT «нет данных», QC «не оценено» |
| **LIVE_VERIFIED** | индикатор приема, канал/Fs/счётчик, RAW status | FFT/время/мгновенный архивный NPZ разрешены при N>=256 |
| **FROZEN_WHILE_RECORDING** | ярлык «Заморожен только экран / RAW продолжает запись» | графики из immutable freeze; кнопка возврата в live |
| **STOPPING/VERIFYING** | «Завершается RAW / проверка BIN» | старые проверенные графики можно рассматривать, не переключать на фальшивый новый Live |
| **EXPORTED / EXPORT_REFUSED** | окончательный статус и причина | ссылки на verified BIN разрешены только EXPORTED; при REFUSED RAW остается сохранен |
| **OFFLINE_NPZ** | «Архивный источник NPZ», прибор отключен | повторный анализ реально сохранённых Float32, **saved_utc** подписать как время сохранения |

Локальные состояния QC `PASS/WARN/BLOCK/UNKNOWN` описывают пригодность данных для конкретного расчета, а не готовый диагноз; BPFI/GMF/ISO-пороги не выводятся в виде «исправен/неисправен» без независимой проверки.

## 4. Полная спецификация ВЕРХНИХ МЕНЮ (8 разделов, 163 команд)

**Легенда:** **E = исходная функция уже существует**, но пункт в реальном QMenuBar еще отсутствует; **C = частично** (есть ядро/часть UX); **P = план**; **R = условно, нужны дополнительные физические входы/валидация**. Меню создаётся через `QAction`, причем кнопки toolbar и одноименные меню используют **одну и ту же QAction**. Для planned-only команд в производственной версии не отображать неработающую «активную кнопку»: сначала реализовать обработчик/тест; допустима секция «Каталог методов» с ясным статусом.

Сохранение окна есть в «Файл» и «Измерение» **как одна и та же команда**; это не вторая операция или второй АЦП. В «Вид» переключение страниц НЕ выполняет FFT заново; в «Анализ» выбор метода изменяет вычисление. В «Настройки» меняем только локальные пресеты/UX, приборный Fs/FRange не управляется без отдельно восстановленного протокола.

### 5.1. Точная адаптация UX

- **Главная панель:** OROS Home — один экран Run/Stop, видимый статус диска, отдельные раскрывающиеся настройки. У МВК01 Native уже записывает RAW при старте; отдельный «REC: включить/выключить» не нужен.
- **Обзор:** DewesoftX Measure/Analyze — отдельно текущий поток и offline, полезна мини-полоска времени для **сохранённых длинных** записей; не добавлять full-time overview на краткий ring как будто он часовой.
- **Правый инспектор:** OpenTest — группы «Получение данных / Управление измерением / Анализ сигнала» внутри одного модуля; у нас параметры источника Fs read-only, а ADC общий.
- **Qt меню:** pySPWB — проверенный пример `menuBar() → addMenu() → QAction + shortcuts`; сохранить собственную архитектуру и один ActionRegistry, а не копировать десятки самостоятельных окон.
- **Диагностика:** c-spectrum — measured spectrum рядом с теоретическими bearing markers + пояснениями оснований; но сначала D01/D02, не выводить synthetic/микрофонные метрики как МВК01.
- **Архив и тренды:** Adash DDS — сравнение нескольких кривых, легенда/курсор и переход к измерению; у нас пока **нет дерева оборудования** и создавать его не нужно.

### 5.2. Что считать оригинальным экраном

Изображения DewesoftX, OROS и Adash — UX-референсы закрытых программ (их исходный Qt-код нельзя взять). Исходники pySPWB/MIT и c-spectrum/MIT реально доступны; лицензия OpenTest Community — особая, не MIT. В репозиторий MVK не добавлять чужие скриншоты как собственные активы, а открыть их по ссылке:

## 7. Инварианты и тесты

1. Один физический TCP/10230 через Native. Выбор профиля/IP не подключает прибор автоматически.
2. Один глобальный видимый ADC 1–8, остальные UI используют тот же state; Native пишет все реально пришедшие каналы независимо от него.
3. Freeze только отображение; STOP штатно завершает Native RAW; окно записи read-only по каналам без чекбоксов отключения.
4. Никаких примеров/c-spectrum синтетических спектров в LIVE без явного DEMO fixture, никакого fake green «подключён» до реального ADC.
5. SOURCE метки: `ORIGINAL_AUX4700` vs `APP_DERIVED`; отсутствие чисел/опасного датчика → null/—, не 0.
6. Исполняемый код до этого UX-пакета НЕ менялся; Qt меню по этому документу ещё НЕ существует.
7. Настройки методов не меняют FRange/частоту прибора; RMS VS требует реальных полос/длительности, факт `saved_utc` не притворяется `acquisition UTC`.
8. Дублирующиеся по смыслу пункты меню (сохранить окно, открыть тренд, показать QC) подключать к одному action_id/handler; при наличии сервиса ошибок меню не запускает новые потоки, синтетические кейсы и бездумный reconnect.
9. Графики не обновлять «устаревшим» worker после переключения ADC/session/NPZ/source; закрытие только после завершения Native, QThreadPool safely drained.
10. Windows DPI 100–150%, масштабирование, запоминание splitter и расположения, локальные tooltip и справка, клавиатура F1 и escape без скрытой записи.

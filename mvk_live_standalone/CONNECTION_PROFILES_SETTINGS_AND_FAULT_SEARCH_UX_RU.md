# MVK Live — настройки подключения, список IP и отдельный поиск дефектов

**Аудит 18.11.2026.** Ветка feature/mvk-live-standalone-20261117. **Статус: проектирование, не готовый программный функционал.** В этом обновлении не изменяются Native Go, TCP/10230, FRange, AUX4700 и исполняемый Qt-код. **Карточки агрегатов/подшипников/редукторов не реализуем.**

## 1. Фактическое состояние программы

По исходнику [app.py](app.py) строки 146–185: на главном экране находятся два текстовых поля QLineEdit (IP прибора и локальный IPv4), описание Ethernet, кнопка обновления сетевой карты, кнопки подключения/остановки. Также на экран выведены поля пути Native EXE и SHA256-манифеста. **Списка запомненных IP, именованных профилей и использования QSettings сейчас нет.**

В [app.py](app.py), [ethernet.py](ethernet.py), [test_qt_ethernet.py](tests/test_qt_ethernet.py), [test_ethernet.py](tests/test_ethernet.py) есть важная безопасная логика: автоматически определяется один активный физический проводной Ethernet Windows, не Wi-Fi/VPN; это локальное чтение конфигурации Windows без попытки соединения с прибором. Неоднозначная сеть не выбирается случайно. IPv4 строго проверяются, локальный и приборный должны различаться. Native EXE проверяется по SHA256. **TCP Connect происходит только после отдельного явного подтверждения оператора с реальным IP прибора и IP/интерфейсом компьютера.** Эта логика остаётся неизменной.

**Ограничение:** текущий экран не имеет отдельного диалога сетевых настроек; в основном UI из-за сетевых QLineEdit теряется место для спектра/осциллограммы. Если оператор закрыл программу, ранее введённый IP прибора не восстанавливается.

## 2. Лучший вариант нового UX

Сравнение:
- OpenTest отделяет Device/Hardware Setup от Monitor и Measure: [устройство](https://github.com/crysound/OpenTest/tree/main/apps/frontend/src/modules/device), [монитор](https://github.com/crysound/OpenTest/tree/main/apps/frontend/src/modules/monitor).
- Qt [QComboBox](https://doc.qt.io/qt-6/qcombobox.html): список с редактируемым значением, validator, completer и отключением дубликатов, но **не** обеспечивает постоянное сохранение сам.
- Qt [QSettings](https://doc.qt.io/qt-6/qsettings.html): хранение пользовательских настроек по ключам, UserScope; Windows Registry или INI в AppData, поддержка массивов и миграций.

**Выбрать вариант: главное окно с компактным индикатором выбранного профиля и статусом, IP редактируется только в окне «Подключение».**

~~~text
┌ MVK Live · [МВК01: Участок А ▾] [Измерить] [Стоп] [⚙ Подключение] ┐
│ АЦП [1][2][3][4][5][6][7][8]   Получение ●  Архив ● Freeze         │
├─────────────────────── ОСНОВНЫЕ ГРАФИКИ ──────────────────────────┤
│ FFT/временной сигнал и прочие аналитические вкладки                │
├ Статус: отключено/подключение/приём/ошибка · Ethernet: OK          ┤
└────────────────────────────────────────────────────────────────────┘
~~~

**Никаких редактируемых IP и длинной справки по Ethernet в рабочей области.** Показывать название профиля и статус. Реальный IP доступен во всплывающем меню/диалоге и в ОБЯЗАТЕЛЬНОМ подтверждении, если нажали «Измерить».

Пока не выбран ни один IP, в шапке «МВК01 · не выбран»; при первом запуске можно показать ненавязчивую подсказку «Добавьте адрес прибора». **Выбор адреса в списке не устанавливает соединение**. Подключение и одобрение реальных IP/адаптера остаётся отдельным действием.

### Что означает «сразу список IP» и почему НЕ сканировать подсеть

**Да:** локальный список введённых вручную IP с именами, избранными и историей успешных подключений. Первое использование — «Добавить IP», повторные — выбрать из списка. По желанию — добавлять в «Недавние» только когда Go действительно подтвердил новую сессию RECORDING, а не сразу при нажатии кнопки/ошибке.

**Нет:** автоматический перебор 192.168.x.x, ping/TCP scan, отправка discovery-команд или второй сокет. В проекте не восстановлен безопасный протокол обнаружения устройства; даже TCP Connect способен менять его состояние. Поиск устройств по сети — отдельная будущая задача, с явным разрешением и физической проверкой по оригинальным источникам; сохранённый список адресов не должен выдавать прошлый IP за «прибор доступен сейчас».

## 3. Что и как сохраняем

Реализация, когда будет одобрена: отдельный небольшой модуль профилей подключения, использующий Qt QSettings (UserScope, организация MVK, приложение MVK_Live_Standalone), пространство ключей connections/v1 и ui/v1; тестовые INI — только во временном каталоге теста. Измерительные SQLite/RAW/NPZ не затрагиваются.

**ConnectionProfile:** внутренний UUID, nickname (<=64), канонический device IPv4, favorite, created UTC, last_success UTC (или null), source (manual/recording_confirmed). Ограничить 20 записей и 10 последних успешных. Удаление/переименование IP **не удаляет измерения**. Повторный ввод того же IP предлагает переименование, а не дублирование.

**Не сохранять как постоянный атрибут прибора:** локальный IPv4 Ethernet — он определяется при каждом запуске Windows и перепроверяется Go. Не хранить пароли, токены, командные строки с секретами. Программа не использует системные/глобальные настройки Windows и не меняет сетевые интерфейсы.

**Выбор профиля** возможен только для следующей сессии, переключение при активном Native RAW заблокировано. При ошибке подключения адрес может оставаться «добавленным вручную», но не становится «проверенно успешным». Начальный запуск никогда не соединяется автоматически. Сохраняемый последний выбранный профиль — лишь указатель для интерфейса, а не команда TCP.

**Разделы окна общих настроек**: Подключение (IP-профили, статус NIC, расширенный Native SHA); Сохранение (каталог, политика архивирования); Общие (язык, раскладка, DPI); Представление (тема, масштаб/оси по умолчанию). **Параметры DSP — справа на конкретном графике, по выбранному АЦП; не делать один глобальный фильтр на все методы.**

## 4. «Поиск дефектов» в предыдущем каталоге: почему нужна отдельная строка

Ранее каталог содержал W26 «Проверка нескольких гармоник и коллизий» и A10 «Историческая диагностика изменений». Но **самостоятельного метода с названием «Поиск признаков неисправностей» там не было**. Добавить W32 (одно окно сигнала) и A20 (сравнимый архив) в главный каталог с отдельными экранами и статусом ПЛАН.

### W32 — самостоятельная вкладка «Поиск признаков неисправностей»

Вход: реальные отсчёты ADC и подтверждённая Fs из текущего Freeze или сохранённого NPZ, выбранный временной участок/фильтр/FFT. Для физической гипотезы — подтверждённый оператором RPM/1×, а геометрию подшипника, число зубьев или лопастей спрашивать только если выбран соответствующий метод. **Никаких карточек оборудования**.

Проверять: возможный дисбаланс (1×), несоосность (2×/3× с ограничениями), ослабление (серии гармоник/субгармоник), BPFO/BPFI/BSF/FTF после выбора полосы Fast Kurtogram и локальной Hilbert-огибающей, GMF±sidebands, BPF вентилятора, импульсность RMS/crest/kurtosis. Для FFT определять **фактические пики** на фоне/в допуске, число независимых гармоник и коллизии; один совпавший пик — недостаточное основание для диагноза. Методы SES/доп. статистики помечать ПЛАН, пока не реализованы.

~~~text
┌ ПОИСК ПРИЗНАКОВ НЕИСПРАВНОСТЕЙ · ОКНО АЦП ───────────────────────┐
│ Источник [Live Freeze / NPZ]  Fs [read-only] N [8192 ▼]           │
│ [✓ Вал/1×] [✓ Подшипник] [✓ Редуктор] [✓ Вентилятор]             │
│ 1× [ручная / принятая из ВС]  Полоса [из Kurtogram / готовая]    │
│ Гармоники [2..6] Допуск [Δf / RPM] Local SNR / Collision        │
│ [Рассчитать] [Открыть огибающую/FFT] [Сохранить анализ]          │
├ ГИПОТЕЗЫ И ДОКАЗАТЕЛЬСТВА ───────────────────────────────────────┤
│ Гипотеза | линии найденные/ожидаемые | частота | SNR | ограничения│
│ BPFO     | 3 из 4                  | ...     | ... | проверить  │
│ 1×       | 1 из 1                  | ...     | ... | фаза нет  │
│ Не оц.   | не указана геометрия    | —       | —   | данные     │
└──────────────────────────────────────────────────────────────────┘
~~~

**Статусы**: «Не оценено», «Данных недостаточно», «Признаки обнаружены», «Не обнаружено в этом окне», «Требуется проверка». Без «исправно» и вымышленных процентов вероятности. Каждый результат: source, ADC, UTC/session, Fs, NFFT, filter/method, marker family, f_nom vs f_measured, amplitude+unit, local SNR, tolerance, collision, ограничения. При смене ADC/сеанса старый worker не обновляет новый экран.

### A20 — «Подтверждение признаков по архиву»

Работает ТОЛЬКО с сопоставимой серией реальных записей NPZ/сохранённых спектров с timestamps, единицами, RPM и выбранной методикой; оригинальные AUX4700-скаляры не превращаются в FFT.

~~~text
┌ ПОДТВЕРЖДЕНИЕ ПРИЗНАКОВ · АРХИВ ─────────────────────────────────┐
│ АЦП [1] Период [даты] Источники [совместимые NPZ] RPM [связь]     │
│ Гипотеза | записей | обнаружений | тренд амплитуды/SNR | перейти │
│ BPFO/H2  | ...     | ...         | ...                 | [FFT]     │
│ [Наложение спектров] [История коллизий] [Проверить режимы]        │
└──────────────────────────────────────────────────────────────────┘
~~~

Исторический отчёт показывает частоту встречаемости независимых признаков, изменения амплитуды/SNR и ссылки на реальные записи, а отсутствие данных — пропуск, не ноль. Стабильность RPM/нагрузки и сопоставимость фильтров обязательны, если делаем вывод о тренде.

Примеры источников: [c-spectrum envelope](https://github.com/arkid-lutaj/c-spectrum/blob/main/src/cs_envelope.c), [viblearn evidence](https://github.com/Liang-Guo-SD/viblearn/blob/main/src/viblearn/diagnostics.py), [REI SignalLab](https://github.com/rootcastleco/rei-signallab/blob/main/backend/app/vibration_engine.py). Жёстко прописанные confidence REI не копировать и не выдавать за статистические вероятности.

## 5. Условия приёмки перед реализацией

1. Главный экран без редактирования device/local IPv4, только краткая метка профиля/статус/управление; адрес явно показан в обязательном подтверждении подключения.
2. Список профилей переживает перезапуск, недействительные IP и повреждённый QSettings отвергаются; дубли объединяются, удаление профиля не удаляет архив.
3. Смена/редактирование адреса при активном приёме запрещена; никаких автоматических TCP, фонового сканирования, обхода SHA и согласия оператора.
4. Все проверки existing test_qt_ethernet/test_ethernet проходят; добавить тесты на INI изоляцию, недоступные NIC, пустой список/миграцию и ручное обновление Ethernet.
5. W32/A20 — отдельные вкладки настроек и результатов, тяжёлый анализ по реальному снимку в worker, никакой повторной команды МВК01, исходные ADC/FRange только из Go Native.
6. Проверить недостаток RPM/геометрии, 2+ независимых линий, один случайный импульс, пересечение гипотез и отсутствие записи; не объявлять «дефект доказан» синтетическими unit-тестами.

**Итог:** профили IP и отдельное окно подключения — следующий UX-пакет без изменения оригинального приёма. Поиск признаков дефектов — отдельный планируемый анализ окна W32 и ретроспективный A20, не замена существующих гармонических методов W26/A10.

## 2. Новые методы выбора информативной полосы — не дубли Fast Kurtogram

| Код каталога | Метод | Что реально измеряет критерий | Необходимые данные | Экран / настройки | Статус |
| --- | --- | --- | --- | --- | --- |
| **W41** | **Protrugram** | Куртозис *амплитуд спектра огибающей* по кандидату резонансной полосы. В отличие от Fast Kurtogram не максимизирует эксцесс отфильтрованного временного сигнала | Непосредственные ADC samples, Fs, полосовой фильтр, envelope FFT | ОКНО/NPZ: диапазон центров f, bandwidth, шаг сетки, тип демодуляции, длительность N, ограничение Nyquist, окно FFT, шкала, top-3 полос, открыть огибающую | **R&D, не реализован** |
| **W42** | **Infogram (SE/SES)** | Негэнтропия квадрата огибающей (SE) и её спектра (SES); отображать отдельно SE-map, SES-map и совместный selector, НЕ считать величины автоматически сопоставимыми без определённой нормировки | Реальный ADC и валидный банк полос, SE и SES с указанными DC/window/scaling | ОКНО/NPZ: decomposition level, band limits, N/df, SE или SES или combined, normalisation mode, топ полос, comparison with FK | **R&D, не реализован** |
| **W43** | **Spectral Gini band selector** | Индекс Джини для неравномерности демодулированной энергии/коэффициентов в банке полос; метод, альтернативный SK на тех же физических данных | Реальные ADC/Fs, фиксированное определение входного вектора и фильтробанк | ОКНО/NPZ: filterbank depth, channel family, bandwidth, Gini definition, normalization, sample/window length, карта f/k | **R&D, не реализован** |

**Подтверждённые источники:**
- Protrugram — оригинальная постановка: [Barszcz & Jabłoński, MSSP 2011](https://www.sciencedirect.com/science/article/pii/S0888327010001895). В статье критерий именно куртозис амплитуд **спектра огибающей**, а не временного сигнала.
- Сравнение Kurtogram, Protrugram, Infogram и других селекторов в негауссовом шуме: [Hebda-Sobkowicz et al., Applied Sciences 2020](https://www.mdpi.com/2076-3417/10/8/2657) и [Figure 4 — реальные виды карт](https://www.mdpi.com/applsci/applsci-10-02657/article_deploy/html/images/applsci-10-02657-g004.png).
- Отдельная математическая постановка Infogram и ограничений: [Applied Sciences 2020, §2.6](https://www.mdpi.com/2076-3417/10/8/2657).
- Не следует утверждать, что любой из селекторов универсально лучше: обзор фиксирует риски негауссовых одиночных ударов, EMI и посторонней цикличности.
- Для примера более сложного R&D можно прочесть [LESGIRgram, Machines 2023](https://www.mdpi.com/2075-1702/11/12/1052), но этот метод требует здорового baseline и здесь не добавляется как готовая кнопка.

### 2.1. Предлагаемая единая форма «Выбор полосы — сравнение»

~~~
┌ ПОИСК РЕЗОНАНСНОЙ ПОЛОСЫ · ОКНО АЦП / NPZ ──────────────────────┐
│ Исходник [ADC 1, Freeze, NPZ]  Fs [read-only]  N [физическое]     │
│ Метод [Fast Kurtogram | Protrugram | Infogram | Gini]            │
│ Диапазон f [____..____]  ширина [авто/фикс.]  глубина дерева [ ] │
│ Доп. для Infogram [SE | SES | combined]; нормировка [явная]      │
│ [РАССЧИТАТЬ] [Отменить] [Сравнить топ-3 полосы]                   │
├ ЦВЕТНАЯ КАРТА БАНКА ПОЛОС --------------------------------─────┤
│ X = fc, Гц; Y = bandwidth/decomposition level; цвет = score     │
│ Точка выбора = f_low..f_high; легенда и единицы критерия         │
├ [ОГИБАЮЩАЯ ВЫБРАННОЙ ПОЛОСЫ] ----------------------------------┤
│ FFT Hilbert/SES (с явно разными единицами), гармоники, пики     │
│ [Взять полосу] [Проверить BPFO/BPFI/BDF/FTF] [Сохранить анализ] │
└─────────────────────────────────────────────────────────────────┘
~~~

Рядом с каждым score обязательно показывать **название критерия**, окно, нормировку и анализируемую полосу. Не сравнивать абсолютные численные значения Kurtosis, negentropy и Gini на одной оси как взаимозаменяемые. Кнопка «топ-3 полосы» сначала показывает **три реальных независимых результата**, а не одну красивую карту.

**Нагрузочный режим:** вычисление только по кнопке на фиксированном окне, в worker с отменой старого ADC/session; подготовка FFT/filters общая по неизменённым исходным ADC, но оценки разных методов вычисляются отдельно. Оригинальный Go RX не блокируется, в прибор новые команды не уходят.

## 3. Quality gate перед любым поиском дефектов

| Проверка | Как отображать | Что НЕ делать |
| --- | --- | --- |
| Реальное происхождение | ADC, session, source_kind: ORIGINAL_AUX4700 / APP_DERIVED_LIVE / OFFLINE_NPZ | Не превращать сторонний NPZ или SHA в поверку МВК01 |
| Fs/N/Δf | Fs только из приёмника/паспорта NPZ, Δf = Fs/NFFT, реальные N и длительность | Не делать вид, что zero-padding повышает физическую разрешающую способность |
| Достоверность окна | количество полученных отсчётов, gap/drop status (когда действительно доступны), время окна | Missing/null ≠ 0, отсутствие потерь нельзя утверждать без счётчиков |
| Клиппинг/перегрузка | «подозрение на плоскую вершину» по форме, «не оценено» без исходных пределов АЦП | Не заявлять достоверное насыщение АЦП только по уже калиброванным Float32 без raw full scale |
| Огибающая | валидный band-pass, fs/2, фильтровые краевые эффекты, N до/после фильтра, удаление DC | Не трактовать полосы за пределами Nyquist как измеренные |
| RPM/геометрия | RPM MANUAL / ACCEPTED_SPECTRAL / VERIFIED_TACH (только если фактически добавлен тахометр), Z,d,D,α, uncertainty/slip | Ручной RPM не равен тахометру; без геометрии «не оценено» |
| Подтверждение | ожидаемые и measured f, local floor, SNR, prominence, width, не менее 2 независимых Hn, sideband pairs, conflict flags | Не выдавать один пик/SNR=6 dB за диагноз; при частотной коллизии не засчитывать пик двум семьям |
| Архивная сопоставимость | ADC, physical quantity, units, Fs, filter provenance, method/version, FFT scaling, RPM/load condition и качество метаданных | Не рисовать на общей диагностической оси смешанные несовместимые значения без отдельного режима |

Частотные пикеры: [SciPy find_peaks](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.find_peaks.html) предоставляет distance, prominence, width, plateau; [peak_widths](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.peak_widths.html) позволяет вывести ширину по prominence. Это **библиотечные примитивы**, не диагноз: требуются проверка местного фона, независимость гармоник и физический допуск, особенно у FTF и BDF.

### 3.1. Отделить время захвата от времени сохранения

В текущем recordings.py схема **MVK_LIVE_CALIBRATED_SNAPSHOT_V1** содержит saved_utc, которое создаётся при сохранении файла. Это **время записи NPZ**, а не доказанное acquisition_utc. Число capture_end — счётчик отсчётов, не UTC. Для архивного водопада временная ось не должна скрыто означать реальное время получения с прибора.

Предложение **без миграции и без изменения существующих NPZ**: будущий необязательный расширенный контекст (sidecar или новая версия формата, только после тестов) с полями:
- acquisition_time_utc = null, пока не доказана связь с проверенным приборным/приёмным timestamp; timestamp_quality = unknown / receiver_approx / verified_device;
- saved_utc как самостоятельный атрибут, не синоним acquisition;
- source_session, adc, rate_hz, sample_count, capture_end, checksum + явный unit;
- acquisition_point_text/placement_note как **необязательная строка**, не таблицы/карточки оборудования;
- sensor_axis, sensor_mounting, sensor_sensitivity, sensor_frequency_response, calibration_version только если есть документальное основание; иначе null;
- operator_rpm, rpm_source, rpm_uncertainty, load_note и operating_mode **опционально и с источником**, не придумывать;
- derivation: filter_chain, notch, NFFT, window, average, envelope_method, frequency_tolerance, code_version, units, source_kind.

Правило совместимости: старые NPZ V1 открываются как прежде и показывают отсутствие новых атрибутов; никакой «псевдокалибровки» в metadata. Оригинальные AUX4700 JSONL/SQLite не меняются.

### 3.2. Сравнение трендов

Оригинальные AUX4700 можно сравнивать лишь **по одному и тому же физическому полю**. Для нового APP_DERIVED признака нужны согласованные units+definition+ADC+band+window+method. Если RPM изменился — показать режим; пересчёт в порядки применять только при пригодной скорости/временной оси. Без массы условий состояние «ограниченно сопоставимо», а не «улучшилось/ухудшилось» автоматически. Для baseline/EWMA недостаточная серия = «база не сформирована».

## 5. Нормативная база: новое состояние на 18.11.2026

- [ISO 20816-3:2026](https://www.iso.org/standard/89922.html) **опубликован в октябре 2026** (издание 2) и заменил ISO 20816-3:2022. Документ касается оценки **общей вибрации машин** в заданных условиях, **не** диагностической классификации повреждения конкретного подшипника или зубьев. Нельзя использовать его «зоны» в Hilbert/BPFO без отдельного нормативного обоснования.
- [ISO 20816-1:2026](https://www.iso.org/standard/89921.html) — новые общие положения (октябрь 2026).
- [ISO 13373-1:2002](https://www.iso.org/standard/21831.html) остаётся действующим, подтверждён в 2024: общие рекомендации по процедурам измерения и сбора вибрационных данных.
- Текущая программная индикация из advanced.py/app.py с исторической ISO 10816-3 **явно названа ориентировочной**, не официальной оценкой по ISO 20816. Не переписывать нормативные таблицы по памяти: прежде выяснить тип машины, монтаж, мощность/скорость, точку измерения, фильтр/единицы, доступ к официальным изданиям и правила применения.

## 6. Приоритет исследования и приёмочные проверки

**P0 / прежде новых DSP:** раздельные теоретические/измеренные пики на bearing_plot, BDF=2BSF и BDF±FTF, BPFI±fr, multi-harmonic min-2, peak conflict ledger; Quality Gate + источники Fs/RPM/unit/window/time; проверка offline NPZ V1 как «время сохранения», не «время измерения».

**P1 / UX и архив:** единый экран сравнения полос Kurtogram/Hilbert, сохранение настроек анализа (не изменение оригинала), повторный расчёт по NPZ, архивные тренды с явно неполным контекстом; отдельный менеджер IP-профилей без автоподключения.

**P2 / R&D:** W41 Protrugram, W42 Infogram, W43 Spectral Gini. Начать с изолированных функций на копии ADC window, без новых TCP; открыть в UI только после эталонных тестов и предельной производительности. Если нет данных по датчику, тахометру, фазе или времени — показывать ограничения.

**Приёмка тестами:**
1. Контролируемый импульсный BPFO/BPFI/BDF/FTF с 1/2/3+ Hn, известные sidebands, несколько Fs/N и заведомое отсутствие линии.
2. Однократный сильный удар, EMI/50–60 Hz, белый/негауссов шум: выбранная Kurtogram/Protrugram/Gini полоса может отличаться; «высокий score» не превращается в «обнаружен дефект».
3. Коллизия BPFO×3≈BPFI×2, shaft harmonics и недостоверные RPM/геометрия: не удваивать свидетельства и не считать «не оценено» отрицательным.
4. Короткое окно/узкая полоса/Nyquist, zero-padding: тест на честную Δf и защиту фильтра/краевых эффектов.
5. Архив V1: отсутствует acquisition_time, нет датчика/монтажа/нагрузки, SHA mismatch, непригодные NPZ, смешанные units/Fs, импорт реальных AUX4700 без waveform.
6. Переключение ADC/сессии во время worker; отсутствие дополнительных TCP, отсутствие выдуманных данных, отказ от обновления устаревшим расчётом.
7. Windows 1280×720 и 1920×1080 при 100%/150% DPI, QScrollArea настроек, ограничения памяти/CPU, длинные NPZ в выделенном worker.

**Задача этой публикации — повысить полноту данных и чёткость будущей приёмки, а не выдать исследование за готовые функции.**

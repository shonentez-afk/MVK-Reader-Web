# MVK Live — UX-проект главного экрана и анализа измерений (предложение v2)

**Дата аудита:** 18.11.2026. **Ветка:** `feature/mvk-live-standalone-20261117`.
**Статус:** проектное решение для обсуждения; **интерфейс и ядро в этом коммите не изменены**.

## Решение об объёме

**НЕ РЕАЛИЗОВЫВАТЬ** карточки агрегатов, подшипников и редукторов, дерево оборудования, маршрутную структуру DREAM. Не создавать соответствующие модели данных, таблицы SQLite, формы и мастера. **Оставить** существующие временные инженерные параметры на страницах «Подшипники» и «Редукторы», где их использует алгоритм (1×/геометрия/число зубьев); это не карточки оборудования.

Не изменять: единственный приёмник Native Go, приборный TCP/10230, событие «Измерить», декодирование 8 АЦП, FRange ровно один раз в Go, аппаратные AUX4700 43+24×3, timestamps, SQLite/NPZ, алгоритмы анализа. Оригинальные заводские FIR не объявлять восстановленными из одного лишь набора названий 32 меню.

## Что уже есть и почему UX всё ещё сложен

В `app.py` сегодня шесть верхних рабочих вкладок: «Спектр» / «Временной сигнал» / «Расчётные данные» / «Тренды» / «Сравнение» / «Доп. анализ». Есть отдельные фильтры времени и FFT, 32 названия исходного меню, две истории (быстрый Live-тренд и сохранённые архивные тренды), 7 независимых страниц дополнительных методов, автоматическое определение Ethernet и быстрый IPC. Всё это сохранять.

Проблема: главный экран показывает или спектр, или осциллограмму; настройки IP, исходного FFT, оборотов, механической геометрии, сохранения и анализа находятся на нескольких широких общих панелях. При смене задачи приходится переключать страницы и искать настройки другого метода. Площадь графика мала при масштабировании Windows. Вкладок слишком много для линейного ряда.

## Выбор архитектуры: «обзор + детальные рабочие страницы»

Сравнены три варианта:
- Единственный перегруженный экран: минимальное переключение, но слишком много графиков/контролов.
- Все методы в отдельных вкладках: просто реализовать, но трудно видеть FFT и waveform одновременно.
- **Гибрид:** обзор «FFT + waveform + компактные показатели», подробные независимые страницы и настраиваемая сетка 1/2/4 графика. **Выбран гибрид.**

Двухуровневая понятная навигация вместо длинной полосы:
1. **Измерение:** «Обзор» (стартовый), «Спектр», «Временной сигнал», «Расчётные данные».
2. **История:** «Тренды» и «Сравнение» (всё ещё самостоятельные страницы; с прямыми переходами).
3. **Доп. анализ:** список методов слева: «Водопад», «Оперативный тренд СКЗ», «STFT», «CWT Morlet», «Кепстр», «Подшипники», «Редукторы». Собственные графики/контролы каждого метода сохраняются.

## Макет основного экрана «Обзор»

```text
┌ MVK Live · МВК01 ─ IP: [адрес] ─ Ethernet [..] ─ [ИЗМЕРИТЬ] [СТОП] [Freeze] ┐
│ Измерение: Обзор / Спектр / Время / Расчёты  | История | Доп. анализ         │
├──── АЦП ──────┬────────────────────────────────────┬────────────────────────┤
│ [1] [2] [3] [4]│ Спектр выбранного АЦП   [↗]       │ Вид / ВУ-ВС-ВП         │
│ [5] [6] [7] [8]│ X: Гц; Y: физическая единица      │ Фильтр/полоса         │
│               │                                    │ FFT N / окно / X / Y  │
│ Быстрые       ├────────────────────────────────────┤ [Расширенные ▸]        │
│ показатели    │ Временной сигнал       [↗]         │                        │
│ ВУ СКЗ / пик  │ X: секунды; Y: ± м/с²              │ Сохранить окно         │
│ ВС СКЗ*       │                                    │ Открыть запись         │
│ Crest / Fs    │                                    │                        │
├───────────────┴────────────────────────────────────┴────────────────────────┤
│ СТАТУС: МВК IP | поиск Ethernet | TCP | RxPos | Fs | FRange | журнал/архив  │
└──────────────────────────────────────────────────────────────────────────────┘
```

**Контекстный блок** справа содержит только настройки активного графика. Настройки осциллограммы не влияют на FFT, а фильтр локального отображения не перезаписывает приборный AUX4700. Кнопка развёртывания графика ведёт на ту же подробную страницу, но выбранный АЦП, единицы и параметры сохраняются.

**АЦП 1–8:** восемь компактных кнопок с отметкой наличия *подтверждённых данных*. Не показывать зелёный «подключён», если пришёл только локальный статус без подтверждённого TCP/потока. При смене АЦП сбросить / ясно отметить временно устаревшие Live-расчёты; **архив не очищать**. Отображение нескольких АЦП в разных панелях — только явный выбор оператора, с независимыми подписями.

**Компактные показатели:** 4–6 наиболее полезных: локальные ВУ RMS, пик, peak-to-peak, crest, проверенное ВС RMS 10–1000 Гц (только когда реально доступна вся полоса), Fs. Для каждого поддерживать tooltip с источником, единицами, датой, состоянием; missing ≠ 0. Не ставить цветовые оценки тяжести и «диагноз», пока класс машины и нормативная оценка не подтверждены.

**Соединение:** сверху только IP прибора, «Измерить/Остановить/Заморозить». Автообнаруженный проводной адаптер и статус — компактно; технические поля Native EXE/SHA, альтернативный Ethernet, подробный журнал — в «Сервис/Диагностика соединения», не поверх графиков. Нельзя подменять процесс приёма из UI. Заморозка означает *заморозку отображения*, не останов TCP и не очистку источника. Когда нажали «Измерить», интерфейс показывает рабочие окна, а отсутствие прибора отображается честным отдельным состоянием CONNECTING/NO_DATA (не мнимые нули).

**Раскладки:** 1 график (подробная работа); 2 по вертикали (стандарт на ноутбуке/при масштабировании Windows); 2 по горизонтали (широкий монитор); сетка 2×2 (большой монитор). Сначала `QSplitter` + фиксированные пресеты — проще/надёжнее, чем полноценный drag-and-drop дизайнер. Не создавать отдельные копии потоков TCP или расчётов: все представления наблюдают одну подтверждённую модель данных. Запоминать размер разделителей и раскладку отдельно от измерительного состояния.

## Как показывать основные виды измерений

### Спектр
Поле графика — главное, сетка и полезная кривая крупнее кнопок. Над ним компактная строка:
АЦП → «ВУ дБ / ВУ лин. / ВС лин. / ВП лин.» → «FFT / PSD / ASD / 1/3 / огибающая» → «Фильтр» → «Предел частоты / масштаб». Нерелевантные настройки скрыть/деактивировать, не очищать сохранённый выбор метода.
В боковом инспекторе: FFT N, разрешение Δf=Fs/N, окно/усреднение (где доступны), Nyquist, фактический фильтр (APP_DERIVED vs оригинальный пакет). Курсоры A/B, Δf, Δамплитуды, список ближайших пиков и гармоник; RPM лишь «введено вручную / подтверждено оператором по ВС», **без тахометра**. Для 1/3 исходного AUX4700 не изображать 43 регистровых значения как самостоятельный локальный FFT.

### Временной сигнал
Большая осциллограмма с ±амплитудой, разверткой и личным фильтром. Над графиком отдельные кнопки «Авто Y», «Freeze», «Участок [A–B]», «Сохранить исходное окно». Выделенный участок анализируется локально по настоящим сохранённым отсчётам; участок из одних AUX4700-полос невозможно подменять осциллограммой. При недостатке данных для 30 с показывать фактические секунды/недоступность; не добивать нулями.

### Расчётные данные
Три самостоятельные внутренние страницы с одной логикой «значение → тренд»:
- **Приборные 43 полосы:** столбчатый/точечный спектр частот по X + таблица `Центр Гц | ВУ RMS м/с² | Статус | Тренд`. Исходные 1/3 помечены `ORIGINAL_AUX4700`; 1/1 сводная RSS из трёх исходных 1/3 помечена `APP_DERIVED` и не выдаётся за оригинальную FIR.
- **Приборные 24 позиции:** таблица `№ позиции | RMS | Peak | Span | Статус | Тренд`; отдельные графики по номеру, а не по неизвестным Гц. Не выдумывать единицы и значения отсутствующих регистров.
- **Локальные показатели:** таблица `Показатель | Значение | Единица | Полоса/параметры | Источник | Время | Тренд`; группировка ВУ/ВС/ВП, формы и статистика; скрывать невычислимое, а не показывать фиктивный ноль.

## История и наложение

**Архивные тренды:** строка «АЦП / источник / показатель / центр или позиция / период», вверху длинная миниатюра всего периода с выделяемым временным окном, снизу большой тренд. Две связанные временные метки A/B; подсказки показывают дату, единицы и источник. Щелчок на точке — открыть сохранённое измерение; отдельная команда «добавить в сравнение». Отмечать реальные пропуски данных/отключения. В памяти хранить UTC, в UI дать ясный переключатель UTC/местное время. Отличать архивный тренд из SQLite/NPZ от краткого «Оперативного тренда СКЗ», который живёт только во время измерения.

**Сравнение:** по умолчанию цветное наложение двух сохранённых дат одного АЦП, с легендой дат, источников и единиц. Дать выбор до восьми, но при большом числе линий предложить «Отдельные согласованные панели» вместо нечитаемой радуги. Выбранные записи сохраняются при переключении периода (существующая функция). Сравнение допустимо **только одинаковых физических показателей и происхождения**; различия Fs/Nyquist показывать отдельно, не интерполировать тихо исходные значения. Не помечать одну запись «эталон» при отсутствии физического эталона. `Δ` и отношение включать лишь при обоснованной совместимости частотных сеток и нормировок.

## Доп. анализ: компактная навигация по методам, собственные измерения

Слева вертикальный список 7 методов, в центре график, справа *контекстная* настройка выбранного. Каждый метод сохраняет свои значения, своё изображение/график и подсказки при переключении методов; смена АЦП маркирует результаты предыдущего канала как устаревшие.

| Метод | Основное представление | Обязательные настройки и действия |
| --- | --- | --- |
| Водопад | 2D теплокарта частота×время; шкала цвета с единицами | История 20/50/120/240 реальных RxPos, диапазон частот, динамический диапазон цвета; 3D — не приоритет |
| Оперативный СКЗ-тренд | Простая линия/точки по времени Live | Размер окна истории, единица ВУ; кнопка «к архивной истории» |
| STFT | Теплокарта + **спектр в выбранный момент** + **временной ход выбранной частоты** | N исходного окна, размер STFT сегмента, перекрытие, оконная функция, ось цвета, курсоры T/F. Как в `pySPWB/src/spwb/gui/tfa_analysis.py` |
| CWT Morlet | Временная карта масштабов/псевдочастот, справа контекст | Число масштабов, min/max частота, пояснение «качественный локальный анализ»; не притворяться калиброванным FFT |
| Кепстр | Линейный график амплитуда/кэфренция (с) с курсором | Длина окна, максимальная кэфренция, показ 1/кэфренции при ненулевом значении как подсказка, без автоматического диагноза |
| Подшипники | FFT огибающей + линии ожидаемых BPFO/BPFI/BSF/FTF | Фильтр огибающей, FFT N, ввод 1× и геометрии **на этой странице**; нет отдельной карточки подшипника |
| Редукторы | Основной FFT + теоретические GMF/гармоники/боковые полосы; таблица | Ввод 1× и числа зубьев **на этой странице**; предсказанные частоты не выдавать за найденные пики, нет карточки редуктора |

## Связанные курсоры и выбор физически осмысленных данных

Одна общая модель состояния анализа: `session_id`, `adc`, `time_range`/UTC, `source_kind`, `physical_quantity`, `units`, `filter_provenance`, `Fs`, `nfft`, `cursor_time`, `cursor_frequency`. У каждого графика свой временный viewport/амплитудный масштаб; связанные панели разделяют **только совместимые** время и частоты. Курсор на STFT может изменить spectrum-at-time и level-over-time без нового запроса к прибору; курсор архивного тренда выбирает уже сохранённую запись с правильным временем. Не синхронизировать неправомерно ось времени и ось частоты по одному числу.

На выборочно открытой записи показывать статус `ORIGINAL AUX4700` / `APP_DERIVED`, формат `NPZ` или источник AUX, время, Fs и наличие проверенного FRange. При отсутствии исходного окна предлагать только реально существующие графики и показатели.

## Политика экранов и доступности

Под Windows с системным масштабированием 100–150% графики не должны иметь минимальную фиксированную ширину от множества кнопок. Все опции — в QScrollArea/контекстных инспекторах, вкладки не должны уходить за пределы окна. Подписи ФВЧ/ФНЧ/полоса и единицы — полные; термины ВУ/ВС/ВП могут иметь tooltip. Горячие клавиши — только для безопасных локальных действий; отсутствие связи не скрывать за зелёными метками. Запомнить последний режим отображения, но соединение каждый запуск проверять заново.

## Реализация крупными пакетами (не выполнялась в данном исследовании)

**Пакет A / главная компоновка:** новый обзор, компактный статус подключения, единый список АЦП, контекстная панель, 1/2/4 QSplitter, связанная модель состояния. Никакой новой связи, платы, оборудования, маршрутов и карточек.

**Пакет B / детальные рабочие виды:** табличные приборные/локальные расчёты с поиском и переходами в историю; согласованные «Тренды/Сравнение»; сохранение панели выбора; происхождение единиц/статусов.

**Пакет C / методы и курсоры:** расширение STFT до трёх взаимосвязанных графиков, сопоставимые панели для waterfall/envelope/gear, сохранение параметров методов, правильные N/Fs/units и собственная обработка ошибок.

**Пакет D / экспорт и интеграционная приёмка:** экспорт активного набора графиков в PNG и таблиц в CSV; sidecar описания исходной записи/выбранных алгоритмов; QA на Windows и реальном МВК01, не объявляя аппаратную приёмку пройденной только по CI.

## Обязательные критерии приёмки

- Спектр и временной сигнал выбранного АЦП отображаются одновременно и используют **один** проверенный Native поток; невозможно удвоить FRange в GUI.
- На экранах 1280×720 и 1920×1080 при 100%/150% UI-скейле основные кнопки и графики доступны без горизонтальной прокрутки всего окна.
- Смена АЦП, смена метода, переход в архив, Freeze, Stop, отсутствие TCP, падение sidecar, повторная попытка подключения не порождают «живых» результатов из чужого канала или прежнего сеанса.
- Дата и уровень курсора проверены на известном синтетическом сигнале; реальный прибор и заводские фильтры отдельно.
- STFT: выбор точки `(t,f)` строит спектр кадра `t` и тренд частоты `f`, без новых сообщений устройству и без выдуманных нулей. При недостаточной исходной истории — объяснение.
- Для исходного AUX4700 всегда точно сохраняются 43 третьоктавы и 24×3 позиции с пометками NaN, независимо от локальных фильтров.
- «Тренды» могут открыть дату и выбранный показатель; если в SQLite есть только AUX4700 без NPZ waveform, осциллограмма не создаётся из значений полос.
- Нет карточек/таблиц/дерева агрегатов, подшипников и редукторов. Их математические методы доступны с ручным вводом параметров.

- OpenTest: https://github.com/crysound/OpenTest; `apps/frontend/src/modules/monitor/components/monitor-graphic-grid-viewer.vue` и `apps/frontend/src/modules/test/components/channel-level-filtering.vue`. Лицензия — собственная Community License.
- pySPWB: https://github.com/Charette-AI-Group/pySPWB, `src/spwb/gui/tfa_analysis.py`, `fft_analysis.py`, `analysis_tabs.py`; описание: https://charette-ai-group.github.io/pySPWB/ (PySide6, связанный анализ временных и частотных срезов).
- DREAM/ВАСТ: использовать идею аналитического перехода «показатель → измерение → история», но **не** структуру оборудования и не диагностические карточки.
- Образцы дополнительных инструментов: https://github.com/arkid-lutaj/c-spectrum и https://github.com/electromake/AccelSpectra.

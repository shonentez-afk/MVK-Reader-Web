# MVK Live — современный главный экран и правильные настройки графиков (UX/DSP v4)

**Дата:** 18 ноября 2026. **Ветка:** \`feature/mvk-live-standalone-20261117\`. **Статус:** детальная спецификация, **не реализация** в PySide6. MVK Live — собственный анализатор **реальных** данных МВК01, не копия MVKView. Границы: [главное окно и независимые W-окна](MAIN_WINDOW_AND_MULTIPLE_WINDOWS_ARCHITECTURE_20261118_RU.md), [43 отдельных аналитических окна](INDEPENDENT_ANALYSIS_WINDOWS_W01_W43_DESIGN_RU.md), [меню](MAIN_SCREEN_MENU_REGISTRY_20261118_RU.csv), [126 пунктов](UNIFIED_IMPLEMENTATION_MATRIX_20261118_RU.csv).

## 1. Главная идея: современный профессиональный инструмент без интерфейса из 2000-х

**Выглядит как актуальное Windows-аналитическое приложение**, но метрологически строгое: чистая композиция, меньше рамок и форм, четкие единицы, высокий контраст графиков, независимые настройки спектра и времени, редкие осмысленные индикаторы, минимум шума в LIVE.

Требования:
- Верхнее **системное меню из восьми** разделов остаётся; под ним **одна компактная панель управления** (имя профиля, Измерить, Стоп, Freeze, Сохранить окно, один АЦП, короткий статус RAW). Не добавлять второй селектор АЦП ни на «Расчётных», ни в W-окнах.
- Четыре **LIVE-вкладки**: **Обзор / Спектр / Временной сигнал / Расчётные данные**. В стартовом «Обзоре» два графика друг над другом, четверка скаляров и один **контекстный инспектор справа**. Нет «История/Доп. анализ» в ряду вкладок.
- Спектр и временной сигнал — две независимые цепочки отображения, но одна база физически проверенных исходных ADC-отсчётов. Нажатие на график выбирает инспектор **этого** графика; при этом **не запускает заново анализ другого**.
- Все дополнительные 43 метода открываются **в отдельных немодальных окнах** W01–W43, графики главного окна не являются методом W05/W03. Данные, настройки и графики не смешивать.
- Технические IP/local IPv4/Native SHA и RPM/геометрия/зубья вынести в **Настройки/соответствующие окна метода**, не оставлять на главном полотне. Не строить дерево оборудования/карточки агрегатов.

**Концепция:** правый инспектор расположен в \`QDockWidget\` (280–340 логических px), **не загораживает** графики и сворачивается одним кликом. Спектр и осциллограмма — в \`QSplitter\` с изменяемым соотношением (по умолчанию 55/45). Мини-метрики не съедают больше одной строки. Скрытая по умолчанию панель «Подробности» не превращает экран в форму из сорока полей.

### 3.1. Подсказки и интерактивность

- **Один клик по графику** — помечает его «активным» тонкой границей и меняет только правый инспектор. Без внезапного запуска тяжёлой обработки.
- **Двойной клик по заголовку** / кнопка развёртывания — переходит к основной вкладке **Спектр** или **Временной сигнал**. Это **не открытие метода W01/W05**.
- **Колесо мыши** — масштабирование области фокуса; drag — панорамирование; явная кнопка «Автомасштаб»; **zoom=manual** остаётся после обновления данных; кнопка «Следить» возобновляет live-auto. Кнопки/горячие клавиши доступны без мыши.
- **Контекст ⋯ на графике:** два курсора, скопировать координаты, сохранить изображение PNG, сохранить окно NPZ (реальный источник), открыть в отдельном методе Wxx (если есть), вернуть автомасштаб.
- **Источники/состояния** подписаны рядом с графиком: \`LIVE / Заморожено / NPZ\`, \`АЦП N\`, \`Fs\`, \`N\`, \`Δf\`, \`Filter\`, \`APP_DERIVED\`; неизвестное = «—», никогда не подставлять имитацию.
- Пояснения по \`(?)\` в инспекторе **рядом с конкретным параметром**: почему параметр недоступен, когда изменение Y влияет только на отображение, а когда N/фильтр запускает новый DSP.

## 4. **Спектр на главной странице — ПРАВИЛЬНЫЕ настройки**

### 4.1. Быстрые настройки (всегда видимая часть инспектора, ≤6 полей)

| № | Поле | Допустимое поведение | Начальный проектный вариант |
|---|---|---|---|
| 1 | **Величина** | **ВУ** (м/с²), **ВС** (мм/с), **ВП** (мкм), с отдельной корректной полосой интегрирования. Независимо от шкалы Y | ВУ |
| 2 | **Спектр / оценка** | **FFT амплитуда RMS на линию**, **Welch PSD**, **ASD**. У каждого свои физические единицы; 1/3-октава — отдельная команда/режим, не скрытая «FFT» | FFT |
| 3 | **Шкала Y** | \`Линейная\` или \`дБ (с явно показанной опорой)\`. Для PSD: дБ от соответствующей плотности с \`10 log10\`; для FFT/ASD: \`20 log10\`. **Не включать второй log-Y, если данные уже дБ** | Линейная |
| 4 | **Частоты X** | \`Авто\`, \`0–100\`, \`0–500\`, \`0–1000\`, \`0–2000\`, \`0–5000\`, \`Полный 0..Fs/2\`, \`Свой\` и вариант Log X (только X>0). Пресеты **ограничить физическим Nyquist** | Последний используемый, иначе 0–min(1000, Fs/2) |
| 5 | **Амплитуда Y** | \`Авто устойчивое\` / \`Ручные min/max\` / \`Диапазон в физических единицах\`. При ручном zoom **не перебивать** обновлением LIVE | Auto |
| 6 | **Фильтр** | \`Без\`, \`ФВЧ/ФНЧ/Полосовой\`, \`50/60 Гц\`, \`1/1, 1/3, 2 октавы\`. Фильтруется **проверенная временная выборка**, не полоса готового RMS-графика | Без фильтра |

**Первые четыре параметра — операторские**, остальные можно отображать компактно: \`Фильтр: нет\` / \`⚙ подробнее\`. Число FFT, окно, сглаживание — в раскрытом блоке.

### 4.2. «Подробно → Расчёт спектра» (не показывать всё постоянно)

| Поле / метод | Реализация и строгая физика | Текущая доступность |
|---|---|---|
| **Источник** | канал АЦП из глобальной шапки, \`Fs\` только Native, \`N_actual\`, \`T=N/Fs\` и \`source/capture_end\` read-only | ЕСТЬ |
| **FFT N** | допустимые **сейчас 8192, 16384, 32768, 65536, 131072, 262144**. При малом Fs время для N может быть большим; напр. при Fs=512 Гц N=8192 означает 16 секунд, а не 16 мс. N≤реально доступных contiguous samples | ЕСТЬ |
| **Auto FFT N** | будущий \`Auto\`: выбирать N по реально доступным данным, заданной целевой длительности и вычислительному бюджету; **поддержка 256–4096 N** нуждается в отдельной реализации/валидации \`spectrum.py\`, без фальшивого zero-padding | ПЛАН |
| **Частотный шаг** | \`Δf_bin = Fs/NFFT\`. Показывать отдельно реальную длительность и эффективное разрешение окна Hann, не говорить, что zero-padding улучшил селективность | ЕСТЬ шаг; улучшить подпись |
| **Окно** | **Hann (реально фиксировано сегодня)**, coherent gain для RMS амплитуды на линию; варианты Flat-top, Rectangular, Blackman и т. д. только после тестов амплитуды/ENBW/утечек | Hann ЕСТЬ, выбор окна ПЛАН |
| **Усреднение** | сейчас FFT — один блок; Welch — среднее PSD по Hann сегментам с 50% перекрытием. Будущие Linear/Exponential/Peak hold отдельно; показывать segments/overlap, а не фиктивную «усреднить 10» | Welch ЕСТЬ, новые режимы ПЛАН |
| **Сглаживание** | текущие нечетные 1..101 bins, применены в power domain. Для диагностических измерений **по умолчанию 1 (выключено)**; курсор и пики из несглаженного результата | ЕСТЬ |
| **DC / тренд** | исходное mean detrend у текущего FFT/Welch. \`DC=0\` на спектре — удалённый DC, **не физически измеренный ноль**; отображение исходного среднего/AC RMS отдельной метрикой | ЕСТЬ алгоритм, нужен ясный UI |
| **Интегрирование ВУ→ВС/ВП** | двойная интеграция усиливает LF-дрейф; отображать реальную полосу и эффективный HP (у Welch/ASD >2 Гц), нельзя автоматически сравнивать RMS разных полос | ЕСТЬ частично, метаданные/QA дополнить |
| **Режектор 50/60** | локальный Butterworth/notch из SciPy, если частота внутри Nyquist и окно достаточно длинное; пометка о фильтрации, никаких приборных команд | ЕСТЬ |
| **Параметры dB** | референс \`ISO 1683\` в коде \`spectrum.py\` или \`1 физическая единица\`, но **всегда показывать явную опору и исходные единицы**, а не просто «dB»; любые новые нормы/классы только после научной проверки | ЕСТЬ база, уточнить интерфейс |
| **Band cursors** | диапазон \`f1..f2\`, полоса/ширина, «Интегрировать PSD» или RMS полосы с правильной нормировкой и окнами; для одиночных FFT-линий **не** суммировать Hann amplitudes как плотность без correction | ПЛАН |

### 4.3. Оси, масштаб, скролл и курсоры

- **X линейная** (Гц): начинается 0, максимум \`min(user_limit, Fs/2)\`; если Fs пока неизвестна, показывать «ожидание измерения» и не рисовать пустые физические точки, будто они измерены.
- **X логарифмическая:** **минимум строго >0**, старт от положительного первого доступного FFT бина/установленного fmin, DC не отображать, в заголовке — «X log». Не делать повторное \`log10\` к \`InfiniteLine\` и не давать ошибочные осевые диапазоны.
- **Y linear FFT/ASD/PSD:** от нуля для положительных спектральных характеристик, авто-потолок с 10–15% запасом, опционально фиксированные границы по **настоящей единице**.
- **Y дБ:** числовые дБ (включая отрицательные), обычная линейная Y-ось с диапазоном в дБ и явной опорой; display floor — значение **отрисовки**, не доказанный шум прибора.
- **Ручной zoom/pan и ручной ввод осей** переводят ось в \`MANUAL\`; сохранять её диапазон при появлении новой FFT, до явного «Авто/Сбросить» или невозможности по Nyquist (в последнем случае предупреждение и усечение без незаметного сброса).
- **Live Stable Auto Y**: быстрый рост при увеличении сигнала, медленное уменьшение после интервала стабильных обновлений (параметры hysteresis benchmark), чтобы шкала не прыгала от кадра к кадру.
- **Основные курсоры:** один crosshair при hover, **A и B** закрепляются кликом/командой; панель \`fA / yA / fB / yB / Δf / Δампл / ампл отношение\`. Перемещение мышью — snapping к реальным бинам, **не придумывать пик**, пока независимый D02 peak finder не реализован.
- **Маркеры гармоник:** \`PREDICTED\` (тонкая пунктирная линия) и \`MEASURED\` (отмеченный истинный пик) — разные формы и легенда; RPM источник \`MANUAL / ACCEPTED_SPECTRAL / UNKNOWN\`; без RPM ожидаемые линии можно скрыть. Коллизии не скрывать.
- **График при смене единиц:** сохранить физическую ось X, обновить Y единицы, пересчитать ограничения/отобразить \`—\` пока расчёт не завершился. Старые линии не переименовывать как новые единицы.
- **Осевой масштаб «экспорт/сохранить»:** в \`analysis_run\` сохранять физические Xmin/Xmax/Ymin/Ymax, scale, reference, filter/settings/source SHA, отдельно от данных/NPZ.

## 5. Временной сигнал на главной странице — ПРАВИЛЬНЫЕ настройки

| Поле | На главной (быстро) | Развёрнутые параметры |
|---|---|---|
| **Развёртка X** | \`10 мс…30 с\` из \`TIME_WINDOWS_S\`, по умолчанию **1 с** | вручную T при наличии подтверждённых contiguous samples; фактическое T доступное — отдельная метка, не продлевать 4-с ring до 30 с |
| **Вертикаль Y** | **Auto симметрично ±peak** с 10–15% запасом, \`±0.1, ±1, ±10 … м/с²\`, ручные мин/макс | подписать **м/с² мгновенное signed**, **не** FFT RMS, никогда Y=0..max |
| **Фильтр времени** | отдельная цепочка, по умолчанию «Нет», тот же набор ФВЧ/ФНЧ/полоса/октавы/50/60 | cutoff < Fs/2; zero-phase \`sosfiltfilt\`/notch только для подтверждённого окна; переходные артефакты фильтра у границ объяснять |
| **Показатели** | \`AC RMS\` (по \`x−mean\`), \`абс. пик\`, \`peak-to-peak\`, \`N/T\` | дополнительно mean/DC и total RMS — только если реально вычислены; Crest = absPeak / AC RMS при допустимом значении |
| **Курсоры** | A/B для времени, \`tA\`, \`tB\`, \`Δt\`, \`aA/aB\`; выбрать A–B на Freeze для анализа | экспорт диапазона с точными индикаторами \`sample_start/end\`, без выдуманного device UTC |
| **Отрисовка** | тонкая кривая, точки скрыты по умолчанию, min/max peak-preserving на широком масштабе | при zoom показывать оригинальные отсчёты; stats всегда считаются по полной выборке, не по 2500 точкам preview |
| **Состояние** | «LIVE»/«Freeze»/«NPZ», Fs/N, фактическая длительность, quality | подписать «Источник неполный», «менее T запроса», packet gap, no data; **нет нулевой прямой**, когда нет сигнала |

**ВАЖНО:** выбор фильтра времени **не меняет** текущий фильтр FFT. «Применить к спектру» как отдельное явное действие с видимой цепочкой условий — возможно позже, не скрытая связка.

## 6. Где держать настройки, чтобы не перегрузить главный экран

- **На карточке FFT:** только \`ВУ · FFT · Линейная · Частоты X · ⋯\` и маленькие действия \`Авто оси / Развернуть / Курсоры\`. Большинство полей — в инспекторе справа.
- **На карточке времени:** \`T=1 с · Y Auto · Фильтр: нет · ⋯\`.
- **В инспекторе:** поля активного графика; группы \`Основные\`, \`Оси и курсоры\`, \`Фильтрация\`, \`Расчёт\`, \`Сохранение пресета\`, большинство закрыты по умолчанию.
- **Расширенные группы по графику:** открывают самостоятельный непрерывный правый инспектор / компактный диалог, а не гигантскую форму под графиком.
- **Настройки → Анализ:** только **дефолтные пресеты** FFT/time для следующих измерений. Изменение активного графика не должно неожиданно менять методное W-окно.
- **Отдельные W01–W43:** собственные параметры, включая геометрию/оборотные гипотезы, но используют **тот же design system**, что главное окно.
- **Вид → Сохранить раскладку** сохраняет \`QMainWindow.saveState()\`, \`QSplitter.saveState()\` и положение инспектора; раздельные настройки каждого графика сохраняются по семантическим ключам, не по случайному порядку виджетов.

## 9. Пресеты графиков и правила хранения

**Базовый набор:** \`Сигнал ВУ FFT\`, \`ВС 10–1000 Гц\`, \`Временной ВУ 1с\`, \`Исследование HF\`; каждый пресет содержит реальное физическое quantity/estimator/scale/ref/filter/axis policy и algorithm version, а не только UI label. «ВС 10–1000» при Fs слишком низкой выдаёт «не применимо», **не** молча сравнивает с частичным диапазоном.

- Глобальный \`QSettings\`: тема, ширина инспектора, состояние \`QSplitter\`, последний открытый вид, предпочитаемая шкала, сохранённая раскладка.
- \`graph_presets.json\` с версией схемы: пресеты FFT/time; параметры конкретного расчёта и его источник будут записаны отдельно в \`analysis_run\`/SQLite. **Изменение QSettings не подменяет данные ранее сохранённого анализа**.
- На новой сессии по умолчанию применять выбранный **операторский** пресет только при известной/совместимой Fs. Не калибровать сенсор автоматически и не писать на прибор.
- Пресеты W-окон имеют отдельное пространство имён \`analysis.Wxx.settings\` и **не** меняются при изменении inspector main.

## 11. Отрицательные тесты/критерии готовности

1. Нет ADC/данных → пустые графики, единицы в подписи, числа «—»; QC не зелёный.
2. При Fs=512 и запрошенном NFFT=32768 нельзя показывать расчёт на 1-секундном окне: ожидать 64 с данных/явный выбор меньшего валидированного N.
3. NFFT больше available ring → не добавить нули и не рисовать ложное частотное разрешение.
4. Log X при min=0 → исправить на положительный доступный fmin, сохранить корректное положение cursor/overlay.
5. Y дБ при отрицательных значениях → корректная линейная координатная ось дБ; нет второго log.
6. RMS/PSD/ASD: размерность подписи, ref и power integration не перепутаны; сравнительные физические тесты vs SciPy.
7. Ручной X/Y zoom не сбрасывается очередным 75-мс IPC/FFT update; Auto можно включить явно.
8. Временная Y signed ±, авто не превращает отрицательные пики в ноль; короткие окна и фильтр с недостаточными данными показывают ошибку.
9. FFT/window/time фильтры отдельные, не изменяют сырые Native Float32/RAW/AUX4700; выбор ВУ/ВС/ВП не применяет FRange дважды.
10. Предел частоты не выше Nyquist, смена Fs/ADC показывает корректную причину ограничения.
11. Пик/курсор ищется по полному spectrum data, не по plot-decimated 2500 сегментам; отображаемая «линия» не является диагностическим заключением.
12. Режим 1280×720 @150% и 1920×1080 @100%: два графика читаемы, inspector доступен, крупный Ctrl+S/F5 не инициирует неявный TCP.
13. Единый глобальный ADC на 4 страницах; открытые W-method windows сохраняют pinned source при смене ADC и Freeze.
14. Закрытие любого графика/вспомогательного окна не останавливает Native RAW; status VERIFYING/REFUSED показывает корректную физическую правду.
